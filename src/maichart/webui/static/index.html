实验性多样性目标








Planner Guidance 的类型/时值门控模块尚未接入 forward，因此暂不提供启用开关。生成时 token 重复惩罚函数也尚未接入采样器。本分组不承诺提高音乐质量，应对比相同歌曲与生成参数。






全曲规划预测局部负荷；保存的人工曲线会指导全曲起音和配置布局。draft_revision_loss 汇总草稿与修订批次的整体目标，包含序列中的拍位/头部 token 和加权关联损失。日志另列两类任务的音符字符损失/准确率（N 字符与 END）、拍位/头部准确率（AT/P/NOTE）及每个 NOTE 后首个 N 字符准确率；EOS 不计入这些指标，准确率带有对应目标位置数。拍位/头部准确率不是音符配置准确率；图上的强弱是局部负荷目标，不是官方定数，也不只表示响度。


新增完整分数匹配和 AT/EOS 决策指标：完整拍位要求该事件所有 P 数字都预测正确；“该续写时选择续写”和“该结束时选择结束”单独统计，避免高格式准确率掩盖早停。这些都基于给定正确前缀的训练预测，不是自由生成的采音正确率；启用续写与结束学习权重后，总损失另含该辅助项，不能直接与旧损失比较。


“完整配置匹配”要求一个拍位的全部音符字符和结束标记同时正确；双押、滑条路径、时值中任一字符错误都会记为不匹配。它仍使用正确前缀，不代表自由生成正确率或可玩率。判断新谱生成能力应优先看草稿指标，修订任务可读取原稿，通常更容易。

训练集目录\
├─ 某首歌\            ← 普通训练数据（本来就是这样的）
│    maidata.txt
│    track.mp3
└─ gold\              ← 新建这个文件夹，把好谱面放进来
    ├─ GoodChart1\
    │    maidata.txt
    │    track.mp3
    └─ GoodChart2\
         maidata.txt
         track.mp3

            ③ 音频必须是 track.mp3 / track.wav / track.ogg 这三个名字之一；
            ④ 可以嵌套多层（如 gold/2024精选/GoodChart1/）；⑤ 放多少首都行，建议验证集至少 30 首。
            这些金标曲可以是新歌（不在原训练集里），程序会自动纳入。

          等级、Radar 和 Style 分别控制什么？
        
    
          先理解后调整：后端把这些值作为 GenerationCondition 的软条件发送给模型，取值范围都是 0–1。
          Radar / 复杂度描述“谱面有多少、哪里爆发、使用什么节奏动作”；Style / 表现倾向描述“这些动作在全曲中偏向怎样组合”。
          note_density 是整体 notes/sec 目标，peak 是局部爆发密度；sweep、slide_tricky、slide_sequence 与
          slide_bias 共同表达 Slide 运动倾向；chord 与 chord_bias 共同表达和弦倾向；
          jack 表达同键连打，hold_bias 表达 Hold，touch_bias 表达 Touch，directionality 表达环形轨道上的移动方向感。
          这些值不是官方机台雷达公式，也不是硬约束；当前模型可能弱化或忽略部分 Style 条件，生成后应查看质量报告。
        
    
          
    等级标签来自原谱的 &lv_x。精确小数按原值读取；13+ 会按项目规则映射为 13.7，无法恢复官方精确定数。
            单改等级不会自动改变 Radar / Style；这里的等级基准会同时同步它们。当前仍没有官方定数评分器。
    
        
    

    
          高级微调 · Radar / Style 参数
          
    
          
    组合应用后仍可逐项修改，微调值会直接用于生成并保存。之后再改等级、勾选偏好或调整偏好力度，会重新从等级基准计算。
