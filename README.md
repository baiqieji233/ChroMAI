# maimai AI Chart Lab

基于 **Composer v2（`chart_composer_v2`）** 连续事件流架构的 maimai DX 谱面生成与训练工具。直接从音乐音频续写完整 Simai 谱面（`maidata.txt`），支持自动变速识别与节拍校准、拍内声学起音参考、实时物理无理（Muri）检查与回退修复，并内置网页端谱面预览播放器。

---

## 一、 3 分钟快速上手（下载项目与模型后直接写谱）

如果你已经下载了本项目源码和训练好的 Composer v2 模型权重（`.pt` 文件，如 `composer_v2_inference.pt` 或 `composer_v2_best.pt`），只需以下三步即可生成第一张谱面：

### 第 1 步：安装环境并启动网页界面（WebUI）

**方式 A：Windows 一键启动（最省心，推荐）**

直接双击仓库根目录的 [`START_WEBUI.bat`](START_WEBUI.bat)（或在终端运行 `.\START_WEBUI.bat`）。
- 脚本会自动创建虚拟环境、检测本机 NVIDIA 显卡与驱动、自动匹配安装对应的 CUDA 版 `PyTorch` / `torchaudio` 及 `Composer v2` 全部音乐依赖，并在检查通过后启动本地 WebUI。

**方式 B：手动使用 Python 环境安装**

需要 Python `>= 3.10`。请一次性安装完整依赖（含默认 MERT 音乐编码器支持）：

```bash
python -m pip install -e ".[audio,training,composer-v2-music]"
```

> **环境小贴士：**
> 1. **NVIDIA 显卡加速**：若手动执行 `pip install`，请确保安装的是带 CUDA 的 `torch` 与 `torchaudio`（可通过 `python -c "import torch; print(torch.cuda.is_available())"` 验证是否为 `True`），否则在 CPU 上提取音乐特征与生成会非常慢。
> 2. **首次运行自动下载 MERT 音乐编码器**：第一次生成或训练时，程序会自动从 Hugging Face 下载 `m-a-p/MERT-v1-330M`（首次使用需要下载模型文件）。若国内网络下载缓慢或连接超时，可在启动前设置镜像环境变量：
>    - PowerShell：`$env:HF_ENDPOINT = "https://hf-mirror.com"`
>    - CMD：`set HF_ENDPOINT=https://hf-mirror.com`
>    - Linux / macOS：`export HF_ENDPOINT=https://hf-mirror.com`

启动 WebUI 服务：

```bash
python -m maichart.webui.server --host 127.0.0.1 --port 7860
```

在浏览器打开 `http://127.0.0.1:7860`。

---

### 第 2 步：在「生成谱面」页导入歌曲与模型

1. 点击顶部导航栏的 **「生成谱面」** 页签（首次打开默认即为此页）。
2. 在 **Step 01 · 导入歌曲与模型** 中：
   - **导入音频**：选择一首你想写谱的音乐文件（`.mp3`、`.wav`、`.flac`、`.ogg` 等），或直接粘贴本机音频绝对路径。
   - **模型 checkpoint**：上传或粘贴你下载的 `.pt` 模型路径（推荐使用体积更小的推理权重 `composer_v2_inference.pt`，或验证集最佳权重 `composer_v2_best.pt`）。
3. 在 **Step 02 · 选择目标等级** 中：
   - 拖动滑块或输入 **目标等级**（如 `13.5`）。
   - 如果想调整键型倾向（如偏星星、偏键盘、少 Touch），展开下方的 **「高级微调 · Radar / Style 参数」**，将需要干预的项从 `自动` 切换为 `手动` 并拖动滑块；保持 `自动` 的项会由模型根据音乐段落自行决定。
4. **节拍与 BPM（默认无需手动填写）**：
   - 保持 **BPM 留空** 且勾选 **「自动识别首拍偏移」**，系统会自动分析全曲节拍、识别变速段落并对齐首拍。如果你已经确知歌曲的准确恒定 BPM，也可以在 **Step 03** 中直接填入。

---

### 第 3 步：点击生成并在线预览 / 导出

1. 点击页面底部的 **「生成谱面」** 按钮，右侧「任务状态」面板会实时显示已生成的事件数与当前拍位。
2. 生成完成后：
   - **在线预览**：直接展开生成页最上方的 **「PREVIEW · 谱面预览」**，即可在浏览器中同步播放音频与生成的谱面（首次展开若未安装本地预览资源，点击「下载预览播放器」即可自动配置）。
   - **获取谱面文件**：每次生成的产物保存在独立的任务目录（默认位于 `webui_workspace/generated/<任务ID>/maidata.txt`，可在右侧任务结果中一键打开或复制路径）。将生成的 `maidata.txt` 与原音频（重命名为 `track.mp3` 或对应播放器要求的名称）放入同一文件夹，即可导入 AstroDX、Majdata 等模拟器和播放器游玩。

## 二、 WebUI 界面与核心参数说明

顶部导航包含三个主工作区：**生成谱面**、**训练模型**、**训练素材**。完整细节可参阅 [`docs/explanations/COMPOSER_V2_WEBUI_ZH.md`](docs/explanations/COMPOSER_V2_WEBUI_ZH.md)。

### 1. 生成谱面（Composer v2 常用控制）

| 参数名称 | 默认值 | 作用与调参建议 |
| --- | --- | --- |
| **目标等级** | `13.3` | 控制谱面的整体密度与复杂度基准（支持 `12.0`–`15.0` 任意小数）。作为软条件输入模型，生成后仍建议试玩确认体感难度。 |
| **高级微调 · Radar / Style 参数** | 全部 `自动` | **特意设计为逐项「自动 / 手动」独立控制**：默认全部保持 `自动`，让模型顺应音乐本身的编配决定哪里写滑条、哪里写和弦或 Touch；只有当你希望专门强化或压制某类写法（例如想写纯键盘谱、或减少 Touch）时，才把对应单项切为 `手动` 并设定软目标，避免一刀切预设锁死整首曲子的手法。 |
| **自动BPM分析** | `识别变速并校准全曲` | 当下方 `BPM` 留空时生效：自动校准全曲节拍并识别变速段（仅采用通过连续性检查的可靠变速结果，其余记入报告）。若确定歌曲不变速，可切为 `仅恒定BPM，校准全曲` 或直接在下方填入已知 BPM。 |
| **自动识别首拍偏移** | 开启 | 自动识别音乐首拍的节拍相位偏移（`&first`）。关闭后使用下方手动填写的 `首拍偏移 / 秒`。 |
| **采音温度 / 采音 Top-p** | `0.9` / `0.95` | 控制「在什么拍位落音」与「何时结束全曲」的随机度。数值越低节奏越保守规整，越高变化越丰富。 |
| **配置温度 / 配置 Top-p** | `0.9` / `0.95` | 独立控制「选中拍位后写什么按键、同拍几押、Hold/Slide 时值」的随机度。留空则沿用采音温度/Top-p；填 `0` 为贪心选择最高概率配置。 |
| **起音参考强度** | `1` | 在已经选定的整数拍内调整音符落点（需支持独立声学起音分支的模型）。`1` 为训练强度，`0` 关闭，最高 `2`；它不直接增加物量，也不补齐错过的出音入口。 |
| **拦截并清理Slide撞尾** | 开启（`200 ms`） | 生成过程中主动拦截 Slide 轨迹提前蹭爆后续按键/星头（TapOnSlide）的硬冲突，并在收尾阶段自动清理残留撞尾音符。 |
| **生成张数** | `1` | 同一首歌一次生成 `1–32` 张不同随机种子的完整谱面，共享音频分析，完成后可在顶部预览切换。 |
| **同时生成数** | `1` | `1` 为逐张生成；设为 `2` 等数值可并行生成，完成一张后自动补上排队中的下一张。每个并行进程加载一份模型，显存随并行数增加。 |
| **CPU计算线程**（高级生成设置） | `0`（自动） | CPU推理每张最多8线程，并根据可用CPU与同时生成数分配；GPU推理使用2线程。正整数指定每张使用的线程数，可先试4或8；线程数越大不一定越快。 |
| **生成方式** | `先定节奏，再选配置` | 默认先确定一段音符出现的时间和数量，再比较不同键位与动作组合；也可选「节奏与配置一起选」或速度优先的「逐步生成」。 |
| **提前试写长度 / 每次保留长度** | `4` / `2` 拍 | 例如先试写4拍，保留前2拍，再接着写；不要求音乐每4拍结束一段。 |
| **每次比较几种写法** | `2` | 尝试 `1 / 2 / 4` 种写法，再选一种；数量越多，生成越慢，不一定更好。 |
| **单步冲突重采次数**（高级） | `16` | 单个事件遇到语法或物理手法冲突时的最大重新采样次数。 |
| **单处冲突恢复次数**（高级） | `2` | 同一处连续重采仍冲突时，自动微调前序 Hold 松手时长或回退重写附近事件的恢复预算（`0` 关闭）。向前推进超过此前最远拍位后预算自动重置。 |
| **恢复仍失败时**（高级） | `继续生成并报告` | 超出重采与恢复预算后的处理方式：默认保留最佳候选继续写完谱面并在报告中列出冲突位置；选 `严格停止` 则立即中止该张生成。 |

### 2. 训练模型（自己从头训练或用个人谱面库微调）

如果你想用自己的谱面数据集训练新模型，或在已有模型基础上微调（`finetune`）：

1. **准备训练素材**：
   - 在 **训练模型 → Step 01** 将谱面根目录（内含若干歌曲子目录，每个子目录有 `maidata.txt` 和对应音频）填入「原始素材目录」，点击 **「开始预处理」** 生成数据集清单 `manifest.json`；或前往顶部 **「训练素材」** 页签勾选已有数据集并设置谱面质量权重。
2. **选择训练方式（Step 02）**：
   - **从头训练（fresh）**：新建模型训练。
   - **从断点继续训练（resume）**：选择上次训练保存的 `composer_v2_last.pt`，严格沿用原训练计划、模型结构与数据划分继续未完成的轮次。
   - **已有模型加强训练（finetune）**：选择已有的 `composer_v2_best.pt`、`composer_v2_inference.pt` 或 `composer_v2_last.pt`，**填写新的输出目录**，在新数据集或新学习率下微调模型。
3. **Composer v2 关键训练参数**：

| 参数名称 | 默认值 | 说明 |
| --- | --- | --- |
| **训练轮数 / 单卡批大小 / 梯度累积** | `50` / `8` / `8` | 每次参数更新的等效批大小为 `单卡批大小 × 梯度累积`（默认 `64` 个训练片段）。显存紧张时可调小单卡批大小并调大梯度累积。 |
| **验证集来源 / 自动留出比例** | `自动按歌曲留出` / `0.05` | 默认自动按整首歌曲留出 `5%`（`2.5%` 开发集用于每轮选出 `composer_v2_best.pt`，`2.5%` 最终留出集不参与训练），防止同一首歌的不同难度同时出现在训练集和验证集中。 |
| **音频特征** | `MERT 75 Hz＋原生频谱 100 Hz` | 默认使用 `m-a-p/MERT-v1-330M` 提取音乐表示并缓存到 `cache/chart_composer_v2`；仅在无网络或快速调试流程时才切为 `原生 log-mel`。 |
| **单次训练片段跨度 / 历史上下文 / 局部前瞻** | `16` / `16` / `4` 拍 | 每次训练切片学习 `16` 拍目标事件，回看前 `16` 拍已发生谱面历史，并额外前瞻未来 `4` 拍局部音乐。 |
| **上下文窗口推进间隔（事件）** | `16` | 连续事件序列每推进多少个事件滑动整理一次历史上下文窗口。 |
| **偏拍与节奏恢复训练** | `自动` | 训练模型在历史落点出现微小偏拍时主动拉回正常节奏网格（`causal_rhythm_v1`）。 |
| **独立声学起音参考** | `自动` | 使用轻量级高时间分辨率声学分支辅助对齐拍内细分重音（`phase_audio_v1`）。新训练与连续模型微调默认自动开启，严格续训继承原检查点设置。 |
| **节拍结构与对齐参考** | `自动` | 让模型直接分辨 16 分与 24 分等拍内细分；前文参考改为逐拍比对音乐、按整拍对齐并附带可信度，音乐不重复时不提供参考（`aligned_rhythm_v2`）。旧模型可在新目录 finetune 启用，原权重全部保留为起点。 |

新版强度曲线支持自动预测与生成页直接编辑，可分别控制出音频率和同拍物量；新训练保持「学习强度曲线」为自动。详见 [强度曲线与重新训练说明](docs/explanations/COMPOSER_V2_INTENSITY_ZH.md)。默认验证完整开发集，连续5轮验证无改善时早停。

短句试排、音乐上下文、音频编码扩层及轻量片段标注见 [短段试排与音乐理解说明](docs/explanations/COMPOSER_V2_PHRASE_AND_MUSIC_ZH.md)。新训练默认4层音频编码与最新音乐上下文；旧检查点保留原结构，新能力可在新目录微调接入。

训练素材与生成结果的预览、片段标注及人工确认示范库，见 [谱面审阅与标注说明](docs/explanations/COMPOSER_V2_PREVIEW_ZH.md)。

排查采音入口、16/24分落点及候选选优偏向，见 [采音与候选评估说明](docs/explanations/COMPOSER_V2_QUALITY_EVALUATION_ZH.md)。诊断默认关闭，不改变训练目标或生成选优方式。

训练输出目录会保存以下权重文件：
- `composer_v2_best.pt`：验证集（或训练损失）表现最好的检查点，推荐用于生成或微调。
- `composer_v2_inference.pt`：不含优化器状态的轻量级推理快照，体积最小，最适合发布分享、直接生成谱面或作为微调起点。
- `composer_v2_last.pt`：包含完整优化器与随机状态的最新检查点，用于中断后严格续训（`resume`）。
- `composer_v2_epoch_NNN.pt`：默认每5轮额外保留的完整检查点，用于回看历史版本、生成或续训。

## 三、 命令行（CLI）直接调用

Intel 核显与 NPU 的可选加速、自动测速和 XPU 训练配置，见 [Intel 加速说明](docs/explanations/COMPOSER_V2_INTEL_ACCELERATION_ZH.md)。

除 WebUI 外，也可直接在终端运行 Composer v2 的生成与训练模块（CLI 生成默认输出示例可放在 `outputs/composer_v2/`）：

```bash
# 查看生成与训练的全部命令行参数
python -m maichart.composer_v2.generate --help
python -m maichart.composer_v2.train --help

# 使用已有模型生成单张谱面（自动分析 BPM、变速与首拍偏移）
python -m maichart.composer_v2.generate \
  --checkpoint checkpoints/chart_composer_v2/composer_v2_inference.pt \
  --audio path/to/track.mp3 \
  --output outputs/composer_v2/maidata.txt \
  --level 13.5

# 一次批量生成 4 张不同种子的谱面供挑选
python -m maichart.composer_v2.generate \
  --checkpoint checkpoints/chart_composer_v2/composer_v2_inference.pt \
  --audio path/to/track.mp3 \
  --output outputs/composer_v2/maidata.txt \
  --level 13.5 \
  --count 4
```

更多技术细节与跨设备迁移说明请参见 [`docs/README.md`](docs/README.md)。
