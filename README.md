# simai_transformer

从音乐生成舞萌 DX 的 Simai 谱面。当前开发路线是 **Composer v2 连续事件模型**，在同一个本地 WebUI 里准备数据、训练、生成和预览。已有匹配的检查点时，直接导入歌曲就能生成。

## 启动 WebUI

安装 64 位 Python 3.12，在项目目录打开 PowerShell。下面的命令创建独立环境，安装 Composer v2 默认音频路线所需的依赖，然后启动网页。

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[composer-v2-music]"
.\.venv\Scripts\python.exe -m maichart.webui.server --host 127.0.0.1 --port 7860
```

打开 [本地 WebUI](http://127.0.0.1:7860)，运行任务时保持终端开启。端口占用时，把命令和浏览器地址中的 `7860` 改为同一个可用端口。第一次使用默认的 MERT 音频特征时，程序可能需要下载预训练音频模型并建立缓存。

也可以用 `.\START_WEBUI.bat --port 7860` 启动。它会显示实际Python路径，检查默认Composer v2所需的依赖，并尝试补装缺失部分；已有PyTorch会固定版本，torchaudio按对应版本安装。使用 `--check` 或 `--no-install` 时只检查。命令行启动也会检查依赖，失败时给出修复命令；检查不会下载MERT模型。CUDA安装、指定Python和环境排查见[环境与兼容性](docs/compatibility/README.md)。

仓库提供源码和小型演示数据。生成需要另外准备可信来源的 Composer v2 `.pt` 检查点，或者用自己的谱面训练一个。

## 第一次生成谱面

1. 打开 **生成谱面**。在 **导入歌曲与模型** 中上传音频或填写本机路径，选择模型文件并点击 **检查生成 checkpoint 类型**。当前路线应显示 `chart_composer_v2` 和连续事件能力。
2. 在 **对齐节拍与起点** 中填已知的 **BPM（可选）** 和 **首拍偏移 / 秒**。建议第一次用节拍容易核对的恒速歌曲。首拍偏移是谱面第 0 拍在音频中的时刻，开头是否落音仍由模型决定。
3. 填 **目标等级**，例如 `13.3`。在 **Composer v2 生成** 中保留默认采样，支持 Radar／Style 的检查点先使用自动条件。
4. 点击 **生成谱面**。任务完成后，在页面顶部展开 **谱面预览**，检查节拍、留白、密度变化和配置衔接。首次使用时可在预览区下载播放器。任务结果中可以打开对应的谱面和报告。[预览说明](docs/explanations/MIAVIEW_GENERATION_PREVIEW_20261105_ZH.md)

| 界面参数 | 第一次怎么填 |
| --- | --- |
| BPM（可选） | 已知时填准确 BPM，留空估计全曲 BPM。检测到局部变速会提示，实际变速须核对并填写 **手动 tempo map JSON（可选）**。 |
| 首拍偏移 / 秒 | 已知时手填，例如 `0.5`。不清楚时可勾选 **自动识别首拍偏移**，生成后对照音频核准。 |
| 采音温度／采音 Top-p | 默认 `0.9`／`0.95`，控制出音时间的探索范围。温度 `0` 时采用贪心。 |
| 配置温度／配置 Top-p | 连续模型可独立调整音符类型、键位、同拍组合和时值。留空沿用相应采音参数。 |
| 候选数 | 默认 `1`。连续模型的 `2` 或 `4` 在同一落点和同样的同拍音符数下尝试不同配置。 |
| 随机种子 | 对比生成结果时填写固定整数。WebUI 留空会为本次任务选一个种子。 |
| 最大事件数（0不限） | 整曲生成用 `0`。正数用于短跑，一个同拍事件可以包含多个音符。 |
| Radar／Style | 默认自动。手动值 `0` 到 `1` 表达密度、音符类型等倾向，实际结果由模型决定。 |
| 恢复仍失败时 | 连续模型默认 **继续生成并报告**，可能保留物理冲突。选择 **严格停止** 可在恢复失败时中止。 |

WebUI 会为每次生成建立独立任务目录。以任务结果中显示的路径为准。

| 文件 | 内容 |
| --- | --- |
| `maidata.txt` | 可导入支持 Simai 的编辑器或播放器。 |
| `maidata.composer_v2.json` | 本次节拍、条件、生成事件、恢复与冲突摘要。 |
| `maidata.conflicts.json` | 放行物理冲突时的详细记录，包含最终整谱检查。 |
| `maidata.failure.json` | 生成无法继续时的诊断。 |

程序能检查语法和部分硬冲突。采音、手顺、段落呼应和实际难度仍需试听和试玩。生成的完整控件、Radar／Style 含义和变速例子见 [Composer v2 使用说明](docs/explanations/COMPOSER_V2_WEBUI_ZH.md)。

## 从头训练一个模型

### 准备数据

每首歌用一个目录，放已对齐音频的 `maidata.txt` 和对应音频，例如 `track.mp3`。谱面中的 `&lv_N` 和 `&inote_N` 对应同一个难度槽，`&first` 及 BPM 应与实际音频相符。

```text
dataset/
├── song_001/
│   ├── maidata.txt
│   └── track.mp3
└── song_002/
    ├── maidata.txt
    └── track.wav
```

[演示 ZIP](examples/maimai_training_demo.zip) 可用于走通导入流程。它包含少量合成素材，正式训练需要有代表性的真实歌曲及谱面。

### 在主工作台开训

1. 打开 **训练模型**，把 **模型族** 设为 `chart_composer_v2`。
2. 展开 **导入或预处理新的素材**。上传 ZIP 或填写 **当前预处理原始目录**，点击 **预处理当前目录**。程序生成 manifest，也就是记录谱面和音频位置的训练清单。
3. 点击 **选择本次训练来源**，勾选数据，点击 **应用勾选的数据集** 和 **检查所选训练来源**。确认实际训练清单和谱面数量。
4. 在 **选择训练起点** 选 **从头训练（fresh）**，设置新的 **checkpoint 输出目录**。先确认数据和显存能跑通，再开始正式训练。验证数据建议使用 **自动按歌曲划分训练／开发／最终留出**。
5. 点击 **开始训练**。在任务日志中查看准备进度、实际学习率、吞吐和验证损失。第一次音频特征准备会花时间，后续相同设置可复用缓存。

| 常用训练设置 | 新建任务的起点 |
| --- | --- |
| 总目标轮数 | 表单默认 `50`。每轮遍历当前训练样本，实际耗时取决于样本数和每秒处理量。 |
| 批大小（batch size）／梯度累积 | 默认 `8`／`8`，通常每次更新累计约 64 个训练片段。显存不足先降批大小。 |
| CUDA 显存预算（GiB） | 默认 `0`，使用 PyTorch 默认分配。正数限制本进程的 CUDA 分配额度。 |
| 音频缓存内存预算（GiB） | 默认 `0.25`，用于训练和验证的音频特征映射缓存。反复读盘且内存有余量时，可按实际占用逐步增加。 |
| 学习率／学习率计划 | 表单默认 `0.0002`／`cosine`，预热后逐渐降低。`constant` 预热后保持填写的学习率。 |
| 训练精度 | 默认 `bf16`，由支持相应精度的设备执行。遇到兼容问题可先用 `auto` 或 `fp32`。 |
| 音频特征 | 默认 `mert`，复用预训练音乐表示和本地声学特征。`native` 是新训练可选的声学路线。 |
| 验证数据来源／总留出比例 | 默认按歌曲和相同音频分组，合计留出 `0.05`。正式训练看开发集，最终留出用于独立评估。 |
| 节奏前文纠错 | 保留 **自动（继承或使用当前默认）**。新的连续模型会加入密集／稀疏前文的选时练习，原始谱面样本继续完整学习。 |

训练目录中的 `composer_v2_last.pt` 保存最新训练状态，`composer_v2_best.pt` 按训练任务的验证指标选取，`composer_v2_inference.pt` 是精简的推理导出。从断点继续时选择通过检查的完整检查点。验证损失用来跟踪学习，完整歌曲的生成和试玩用来比较成谱质量。[训练参数和检查点说明](docs/explanations/COMPOSER_V2_WEBUI_ZH.md#训练设置)

## 当前路线怎么写谱

- 模型根据歌曲、已写的前文和难度条件，依次预测一个事件的**绝对拍位、精确分数相位和同拍音符**。写完一个事件后继续推进，真正结束整张谱面时才使用歌曲结束符。
- 训练按完整事件和 token 预算整理计算批次。生成默认保留最近 **16 拍**历史，每 **16 个事件**整理一次计算上下文，并继续跟踪正在持续的 Hold／Slide。**16 拍不是输出边界**，小节、拍号和休止可以自然跨过整理点。
- 局部音乐特征帮助模型选择具体落点和配置，整曲音频摘要提供更长范围的音乐背景。节奏前文纠错让模型练习从偏密或偏稀的历史回到合适的后续节奏。
- 同拍配置完成后，程序检查冲突，必要时重试或撤回相关事件。连续模型的候选比较以单个事件为单位。

实现、验证范围和实验记录见 [Composer v2 连续事件改造](docs/explanations/COMPOSER_V2_CONTINUOUS_EVENTS_20261104_ZH.md) 与 [节奏前文纠错](docs/explanations/COMPOSER_V2_QUALITY_REVIEW_20261105_ZH.md)。

## 命令行

在安装项目的 Python 环境中运行。把示例中的文件路径、BPM 和首拍值换成自己的。

```powershell
.\.venv\Scripts\python.exe -m maichart.composer_v2.generate --checkpoint "checkpoints/my_v2/composer_v2_inference.pt" --audio "songs/track.mp3" --output "output/maidata.txt" --bpm 180 --first 0.5 --level 13.3 --seed 0
.\.venv\Scripts\python.exe -m maichart.composer_v2.train --help
```
