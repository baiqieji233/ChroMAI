# ChroMAI

**ChroMAI** 是基于 **Composer v2（`chart_composer_v2`）** 连续事件流架构的 maimai DX 谱面生成与训练工具。直接从音乐音频续写完整 Simai 谱面（`maidata.txt`），支持自动变速识别与节拍校准、拍内声学起音参考、实时物理无理（Muri）检查与回退修复，并内置网页端谱面预览播放器。

[Composer v2 架构说明：时间表示、训练与连续事件生成](docs/explanations/CHROMAI_COMPOSER_V2_ARCHITECTURE_AND_TIMING_ZH.md)

[近期更新 · 盘面走势、Slide 轨迹与局部变速](docs/explanations/COMPOSER_V2_GEOMETRY_AND_TIMING_ZH.md)

[查看乐句手顺与启用下一组动作预判（实验）](docs/explanations/COMPOSER_V2_HAND_PLAN_ZH.md)

[训练手顺读出与反馈、预计算缓存及短训结果](docs/explanations/COMPOSER_V2_HAND_MEMORY_DESIGN_ZH.md)

**单独查看谱面手顺**　双击 [启动手顺预览.bat](启动手顺预览.bat)，选择歌曲文件夹或 Simai 谱面、难度，点击「计算并预览」。默认地址为 `http://127.0.0.1:17868/`。「手顺标注」以蓝、橙表示左、右手，证据不足时保留音符原色，盘面下方显示置信等级。切到「方案着色」可在同一拍位对照连扫与分段两种候选。批量导出标注可用 `python -m maichart.legacy_hands.batch 谱面目录 --slot 5 --mode labels --output hands.sqlite`。置信等级是候选比较得出的启发式结果，缺标记为 `hand: null`，尚未用真人手元校准。

播放器支持慢放、逐帧和手部轨迹，手顺计算使用 CPU。原生音符着色使用带手色接口的 MiaView，普通版可查看原谱和轨迹。迁移到另一台电脑时可复制完整的 `webui_workspace/preview_runtime/miaview` 目录以保留手色版。[手色渲染器源码补丁及构建方法](tools/miaview_hand_colors/README.md)

## 一、 3 分钟快速上手（下载项目与模型后直接写谱）

如果你已经下载了本项目源码和训练好的 Composer v2 模型权重（`.pt` 文件，如 `composer_v2_inference.pt` 或 `composer_v2_best.pt`），只需以下三步即可生成第一张谱面：

### 第 1 步：安装环境并启动网页界面（WebUI）

**方式 A：Windows 一键启动（最省心，推荐）**

直接双击仓库根目录的 [`START_WEBUI.bat`](START_WEBUI.bat)（或在终端运行 `.\START_WEBUI.bat`）。
- 首次启动会查找标准 Windows x64 版 Python 3.10–3.13。已有 Python 3.13 或对应的项目虚拟环境可以直接使用，启动器会安装适配的预编译音频依赖。缺少合适版本时会尝试为当前用户安装 Python 3.12。
- **更新项目**：关闭 WebUI，双击根目录的 [从GitHub更新.bat](从GitHub更新.bat)。GitHub ZIP 解压版可直接使用，无需 Git；更新时替换的项目文件会备份至 `backups/github-update/`。模型、歌曲和生成记录可留在原目录。
- 启动失败时，窗口会显示失败的步骤和解决方式。可用 `.\START_WEBUI.bat --check --cpu` 只检查 CPU 环境，或用 `.\START_WEBUI.bat --port 7861` 避开占用的端口。
- 脚本会自动创建虚拟环境、检测本机 NVIDIA 显卡与驱动、自动匹配安装对应的 CUDA 版 `PyTorch` / `torchaudio` 及 `Composer v2` 全部音乐依赖，并在检查通过后启动本地 WebUI。

**方式 B：手动使用 Python 环境安装**

需要 Python `>= 3.10`。请克隆仓库并一次性安装完整依赖（含默认 MERT 音乐编码器支持）：

```bash
git clone https://github.com/baiqieji233/ChroMAI.git
cd ChroMAI
python -m pip install -e ".[audio,training,composer-v2-music]"
```

> **环境小贴士：**
> 1. **系统音频解码工具**：在跨平台使用 `.mp3`、`.ogg`、`.flac` 等音频格式或读取非 MP3 音轨标签时，建议系统已安装 `ffmpeg`（含 `ffprobe`）并加入 `PATH`。
> 2. **NVIDIA 显卡加速**：若手动执行 `pip install`，请确保安装的是带 CUDA 的 `torch` 与 `torchaudio`（可通过 `python -c "import torch; print(torch.cuda.is_available())"` 验证是否为 `True`），否则在 CPU 上提取音乐特征与生成会非常慢。
> 3. **首次运行自动下载 MERT 音乐编码器**：第一次生成或训练时，程序会自动从 Hugging Face 下载 `m-a-p/MERT-v1-330M`（首次使用需要下载模型文件）。若国内网络下载缓慢或连接超时，可在启动前设置镜像环境变量：
>    - PowerShell：`$env:HF_ENDPOINT = "https://hf-mirror.com"`
>    - CMD：`set HF_ENDPOINT=https://hf-mirror.com`
>    - Linux / macOS：`export HF_ENDPOINT=https://hf-mirror.com`

安装 `ChroMAI` 后，可通过以下任一命令启动 WebUI 服务：

```bash
chromai-webui --host 127.0.0.1 --port 7860
# 或使用兼容别名 / 模块直启：
maichart-gui --host 127.0.0.1 --port 7860
python -m maichart.webui.server --host 127.0.0.1 --port 7860
```

在浏览器打开 `http://127.0.0.1:7860`。

---

### 第 2 步：在「生成谱面」页导入歌曲与模型

1. 点击顶部导航栏的 **「生成谱面」** 页签（首次打开默认即为此页）。
2. 在 **Step 01 · 导入歌曲与模型** 中：
   - **导入音频**：选择一首你想写谱的音乐文件（`.mp3`、`.wav`、`.flac`、`.ogg` 等），或直接粘贴本机音频绝对路径。
   - **模型 checkpoint**：上传或粘贴你下载的 `.pt` 模型路径（推荐使用体积更小的推理权重 `composer_v2_inference.pt`，或验证集最佳权重 `composer_v2_best.pt`）。
3. 在 **Step 02 · 选择目标等级** 中：
   - 拖动滑块或输入 **目标等级**（WebUI 滑块默认为 `13.3`，支持 `12.0`–`15.0`；CLI `--level` 默认 `13.0`，支持 `1.0`–`15.0`）。
   - 若模型支持 `radar_style_v1` 条件（加载检查点确认后可用），展开下方的 **「高级微调 · Radar / Style 参数」** 可将需要干预的项从 `自动` 切换为 `手动` 并拖动滑块；保持 `自动` 的项会由模型根据音乐段落自行决定。
4. **节拍与 BPM（默认无需手动填写）**：
   - 保持 **BPM 留空** 且勾选 **「自动识别第一拍起点（首拍偏移）」**，系统会自动分析全曲节拍、识别变速段落并对齐首拍。如果你已经确知歌曲的准确恒定 BPM，也可以在 **Step 03** 中直接填入。
5. **输出元数据（Step 07 · 设置输出）**：
   - 选择或上传 `.mp3` 音频后，**输出标题** 与 **曲师 / artist** 会自动尝试读取音频内嵌标签（读取为空时标题回退为音频文件名、曲师留空，两者均可手动编辑）。
   - 在 Composer v2 下，**输出等级文字** 会根据 Step 02 输入的目标定数自动换算（如 `13.5 → 13`、`13.6 → 13+`），并可在「输出元数据」中指定 **谱师名** 与导出 **难度槽位**（`3`–`6`，默认 `5` Master）。

---

### 第 3 步：点击生成并在线预览 / 导出

1. 点击页面底部的 **「生成谱面」** 按钮，右侧「任务状态」面板会实时显示已生成的事件数与当前拍位。
2. 生成完成后：
   - **在线预览**：直接展开生成页最上方的 **「PREVIEW · 谱面预览」**，即可在浏览器中同步播放音频与生成的谱面（首次展开若未安装本地预览资源，点击「下载预览播放器」即可自动配置）。
   - **获取谱面文件**：每次生成都会在所填路径的父目录内建立独立子目录，保留填写的谱面文件名。页面顶部的「生成历史」可以重新打开已完成的单张或批量结果，重启后仍可查看。将生成的 `maidata.txt` 与原音频（按播放器要求重命名为 `track.mp3` 等）放入同一文件夹，即可导入 AstroDX、Majdata 等模拟器和播放器游玩。

## 二、 WebUI 界面与核心参数说明

顶部导航包含四个主工作区：**生成谱面**、**批量生成**、**训练素材**、**训练模型**。完整细节可参阅 [Composer v2 WebUI 指南](docs/explanations/COMPOSER_V2_WEBUI_ZH.md)。

### 1. 生成谱面（Composer v2 常用控制）

| 参数名称 | 默认值 | 作用与调参建议 |
| --- | --- | --- |
| **目标等级** | `13.3` | 控制谱面的整体密度与复杂度基准（WebUI 支持 `12.0`–`15.0` 任意小数，CLI 支持 `1.0`–`15.0`），同时自动换算写入 `&lv_<槽位>` 元数据。作为软条件输入模型，生成后仍建议试玩确认体感难度。 |
| **高级微调 · Radar / Style 参数** | 全部 `自动` | **特意设计为逐项「自动 / 手动」独立控制**：默认全部保持 `自动`，让模型顺应音乐本身的编配决定哪里写滑条、哪里写和弦或 Touch；加载支持条件的模型后，才按需把想干预的单项切为 `手动` 并设定软目标，避免一刀切预设锁死整首曲子的手法。 |
| **自动BPM分析** | `识别变速并校准全曲` | 当下方 `BPM` 留空时生效：自动校准全曲节拍并识别变速段（仅采用通过连续性检查的可靠变速结果，其余记入报告）。若确定歌曲不变速，可切为 `仅恒定BPM，校准全曲` 或直接在下方填入已知 BPM。 |
| **自动识别第一拍起点（首拍偏移）** | 开启 | 自动识别音乐首拍的节拍相位偏移（`&first`）。关闭后使用下方手动填写的 `首拍偏移 / 秒`。 |
| **采音温度 / 采音 Top-p** | `0.9` / `0.95` | 控制「在什么拍位落音」与「何时结束全曲」的随机度。数值越低节奏越保守规整，越高变化越丰富。 |
| **配置温度 / 配置 Top-p** | `0.9` / `0.95` | 独立控制「选中拍位后写什么按键、同拍几押、Hold/Slide 时值」的随机度。留空则沿用采音温度/Top-p；填 `0` 为贪心选择最高概率配置。 |
| **鼓点与重音贴合强度** | `1` | 在已经选定的整数拍内调整音符落点（需支持独立声学起音分支的模型）。`1` 为训练强度，`0` 关闭，最高 `2`；它不直接增加物量，也不补齐错过的出音入口。 |
| **拦截并清理 Slide 撞尾** | 开启（`200 ms`） | 生成过程中主动拦截 Slide 轨迹提前蹭爆后续按键/星头（TapOnSlide）的硬冲突，并在收尾阶段自动清理残留撞尾音符。 |
| **生成张数** | `1` | 同一首歌一次生成 `1–32` 张不同随机种子的完整谱面，共享音频分析，完成后可在顶部预览切换。 |
| **多张同时运行数** | `1` | `1` 为逐张生成；设为 `2` 等数值可并行生成，完成一张后自动补上排队中的下一张。每个并行进程加载一份模型，显存随并行数增加。 |
| **CPU计算线程**（高级生成设置） | `0`（自动） | CPU 推理每张最多 8 线程，并根据可用 CPU 与同时生成数分配；GPU 推理使用 2 线程。正整数指定每张使用的线程数，可先试 4 或 8；线程数越大不一定越快。 |
| **生成方式** | `先定节奏，再选配置` | 默认先确定一段音符出现的时间和数量，再比较不同键位与动作组合；也可选「节奏与配置一起比较」或速度优先的「逐步生成」。 |
| **每次打草稿长度 / 每次定稿保留长度** | `4` / `2` 拍 | 例如先试写 4 拍，保留前 2 拍，再接着写；不要求音乐每 4 拍结束一段。 |
| **每次内部对比写法数** | `2` | 尝试 `1 / 2 / 4` 种写法，再选一种；数量越多，生成越慢，不一定更好。 |
| **单步冲突重采次数**（高级） | `16` | 单个事件遇到语法或物理手法冲突时的最大重新采样次数。 |
| **单处冲突恢复次数**（高级） | `2` | 同一处连续重采仍冲突时，自动微调前序 Hold 松手时长或回退重写附近事件的恢复预算（`0` 关闭）。向前推进超过此前最远拍位后预算自动重置。 |
| **恢复仍失败时**（高级） | `继续生成并报告` | 超出重采与恢复预算后的处理方式：默认保留最佳候选继续写完谱面并在报告中列出冲突位置；选 `严格停止` 则立即中止该张生成。 |

### 2. 批量生成与保存预设

打开「批量生成」，填入共用的 Composer v2 模型路径，再导入多首音频或粘贴路径。可以从「生成谱面」复制设置作为基准，也可以在批量页直接编辑。

「保存预设」只保存勾选的参数。例如把目标等级、采样温度和生成张数分别存成「高难」「稳健」「多候选」，再按需叠加。列表越靠下的预设优先级越高。单曲预设覆盖全批设置，单曲手动参数优先级最高。移除单曲手动参数即可恢复继承。预设保存在当前浏览器，也可在「生成谱面」页应用。

开始前可以点「核对参数」查看每首歌实际生效的设置。提交时固定本批参数，并按队列逐首生成。一首失败会保留报错，队列继续处理后面的歌曲。已完成的谱面可以直接打开预览。

### 3. 训练模型（自己从头训练或用个人谱面库微调）

如果你想用自己的谱面数据集训练新模型，或在已有模型基础上微调（`finetune`）：

1. **准备训练素材**：
   - 在原始素材根目录下，每首歌放置在一个独立子目录内，包含 `maidata.txt` 与音频文件；其中音频文件**必须命名为 `track.mp3`、`track.wav` 或 `track.ogg`**（`.flac` 或其他文件名在训练预处理时会被跳过）。
   - 在 **训练模型 → Step 01 · 选择训练素材** 中展开 **「导入或预处理新的素材」**，上传 `.zip` 压缩包或填入本地「当前预处理原始目录」，点击 **「预处理当前目录」** 生成清单文件（默认路径为 `manifests/training_manifest.json`）。Composer v2 的预处理仅扫描建立谱面清单，实际的 75 Hz MERT 与 100 Hz 频谱特征会在开始训练时提取并缓存到 `cache/chart_composer_v2`。也可以前往顶部 **「训练素材」** 页签勾选已有数据集并设置谱面质量权重。
2. **选择训练方式（Step 02）**：
   - **从头训练（fresh）**：新建模型训练。
   - **从断点继续（resume）**：选择上次训练保存的 `composer_v2_last.pt`，严格沿用原训练计划、模型结构与数据划分继续未完成的轮次。
   - **已有模型加强训练（finetune）**：选择已有的 `composer_v2_best.pt`、`composer_v2_inference.pt` 或 `composer_v2_last.pt`，**填写新的输出目录**，在新数据集或新学习率下微调模型。
3. **Composer v2 关键训练参数**：

| 参数名称 | 默认值 | 说明 |
| --- | --- | --- |
| **训练轮数 / 单卡批大小 / 梯度累积** | `50` / `8` / `8` | 每次参数更新的等效批大小为 `单卡批大小 × 梯度累积`（默认 `64` 个训练片段）。显存紧张时可调小单卡批大小并调大梯度累积。 |
| **验证数据来源 / 总留出比例** | `自动按歌曲留出` / `0.05` | 默认自动按整首歌曲留出 `5%`（`2.5%` 开发集用于每轮选出 `composer_v2_best.pt`，`2.5%` 最终留出集不参与训练），防止同一首歌的不同难度同时出现在训练集和验证集中。 |
| **音频特征** | `MERT 75 Hz＋原生频谱 100 Hz` | 默认使用 `m-a-p/MERT-v1-330M` 提取音乐表示并缓存到 `cache/chart_composer_v2`；仅在无网络或快速调试流程时才切为 `原生 log-mel`。 |
| **单次训练片段跨度 / 历史上下文 / 局部前瞻** | `16` / `16` / `4` 拍 | 连续训练默认每片最多学习 16 个完整事件，受 token 预算和跨度共同约束；回看前 16 拍谱面，局部音乐额外前瞻 4 拍。16 拍不是音乐段落边界。 |
| **上下文窗口推进间隔（事件）** | `16` | 连续事件序列每推进多少个事件滑动整理一次历史上下文窗口。 |
| **偏拍与节奏恢复训练** | `自动` | 训练模型在历史落点出现微小偏拍时主动拉回正常节奏网格（`causal_rhythm_v1`）。 |
| **独立声学起音参考** | `自动` | 使用轻量级高时间分辨率声学分支辅助对齐拍内细分重音（`phase_audio_v1`）。新训练与连续模型微调默认自动开启，严格续训继承原检查点设置。 |
| **节拍结构与对齐参考** | `自动` | 让模型直接分辨 16 分与 24 分等拍内细分；前文参考逐拍比对音乐、按整拍对齐并附带可信度，音乐不重复时不提供参考（`aligned_rhythm_v2`）。旧模型可在新目录 `finetune` 启用，原权重全部保留为起点。 |

新版强度曲线支持自动预测与生成页直接编辑，可分别控制出音频率和同拍物量；新训练保持「学习强度曲线」为自动。详见 [强度曲线与局部疏密编辑](docs/explanations/COMPOSER_V2_INTENSITY_ZH.md)。默认验证完整开发集，连续 5 轮验证无改善时早停。

短段试排、音乐上下文、音频编码扩层及轻量片段标注见 [短段试排、音乐上下文与片段反馈](docs/explanations/COMPOSER_V2_PHRASE_AND_MUSIC_ZH.md)。新训练默认 4 层音频编码；成对音乐上下文比较来源与当前音乐细节，并读取前方多尺度音乐摘要。旧检查点保留原结构，新能力可在新目录微调接入。

训练素材与生成结果的预览、片段标注及人工确认示范库，见 [完整谱面审阅与反馈](docs/explanations/COMPOSER_V2_PREVIEW_ZH.md)。

排查采音入口、16/24 分落点及候选选优偏向，见 [采音与候选选优评估](docs/explanations/COMPOSER_V2_QUALITY_EVALUATION_ZH.md)。诊断默认关闭，不改变训练目标或生成选优方式。

成对音乐上下文与人工确认衔接的启用方式，见 [成对音乐参考与衔接示范](docs/explanations/COMPOSER_V2_PAIRED_MUSIC_ZH.md)。

训练输出目录会保存以下权重文件：
- `composer_v2_best.pt`：验证集（或训练损失）表现最好的检查点，推荐用于生成或微调。
- `composer_v2_inference.pt`：不含优化器状态的轻量级推理快照，体积最小，最适合发布分享、直接生成谱面或作为微调起点。
- `composer_v2_last.pt`：包含完整优化器与随机状态的最新检查点，用于中断后严格续训（`resume`）。
- `composer_v2_epoch_NNN.pt`：默认每 5 轮额外保留的完整检查点，用于回看历史版本、生成或续训。

## 三、 命令行（CLI）直接调用

Intel 核显与 NPU 的可选加速、自动测速和 XPU 训练配置，见 [Intel 核显与 NPU 加速](docs/explanations/COMPOSER_V2_INTEL_ACCELERATION_ZH.md)。

除 WebUI 外，也可直接在终端运行 Composer v2 的数据准备、生成与训练模块（CLI 生成示例输出可放在 `outputs/composer_v2/`）：

```bash
# 1. 从原始谱面目录生成训练清单（歌曲子目录内音频须命名为 track.mp3 / track.wav / track.ogg）
python -m maichart.training.prepare_events path/to/raw_dataset \
  --cache-dir cache/chart_composer_v2 \
  -o manifests/training_manifest.json

# 2. 查看生成与训练的全部命令行参数
python -m maichart.composer_v2.generate --help
python -m maichart.composer_v2.train --help

# 3. 使用已有模型生成单张谱面（自动分析 BPM、变速与首拍偏移，并可读取 MP3 标签）
python -m maichart.composer_v2.generate \
  --checkpoint checkpoints/chart_composer_v2/composer_v2_inference.pt \
  --audio path/to/track.mp3 \
  --output outputs/composer_v2/maidata.txt \
  --level 13.5

# 4. 一次批量生成 4 张不同种子的谱面供挑选
python -m maichart.composer_v2.generate \
  --checkpoint checkpoints/chart_composer_v2/composer_v2_inference.pt \
  --audio path/to/track.mp3 \
  --output outputs/composer_v2/maidata.txt \
  --level 13.5 \
  --count 4
```

更多技术细节与跨设备迁移说明请参见 [`docs/README.md`](docs/README.md)。
