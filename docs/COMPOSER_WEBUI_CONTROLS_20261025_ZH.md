## 已补充的控件

生成页展开“Composer 生成参数”：

| 控件 | 默认值 / 范围 | 用法与限制 |
| --- | --- | --- |
| 抑制 Touch 历史自强化 | 开启 | 生成端策略；仅 `audio_grounded_v3` 且动作温度大于0生效。取消勾选显式传入 `--no-touch-history-guard`，用于同权重对照。 |
| Touch 历史放大上限 | 1 / 0–4 | 越小限制越强；0禁止历史相对纯音频分支额外提高Touch赔率，仍可生成Touch。1的含义是Touch/非Touch赔率最多额外乘e≈2.72，定义在温度和物理过滤前，不保证最终比例。 |

Style 的“Touch 倾向”原本已接通，仍用于风格条件；不能用上述上限替代目标倾向。任务摘要会区分请求的开关与报告中的实际生效状态。报告增加 `touch_history_bound_requested`，`touch_history_log_odds_bound` 只在策略生效时记录数值；默认1与此前实现一致。

训练页的 Composer 参数区域：

| 控件 | 默认值 / 范围 | 用法与限制 |
| --- | --- | --- |
| 允许轮中重分 batch 续训 | 关闭 / 仅resume | 先检查检查点，再勾选，调整单批和梯度累积并保持乘积，如96×4→64×6。要求max_steps=0，保持已保存的剩余样本顺序。取消勾选恢复检查点批量；fresh/finetune禁用并不会提交true。 |
| 普通 dropout | 0.1 / 0–1 | fresh可调；resume/finetune以`model_config.dropout`为准，忽略陈旧`args.dropout`，不允许替换。 |

优化器实现、精度、推理权重导出、短窗音频、历史/台账遮挡、恢复监督、采样局部性等此前已经存在于主界面，本轮没有重复添加。CUDA缓存回收阈值、重试预算等实现保护保留在代码中。

## 同时修复的界面接线问题

1. 提交训练前会再次检查检查点，原实现覆盖用户刚改的batch、梯度累积、学习率和精度。现在已检查同一检查点后，重新检查保留可编辑设置；批量仅在允许重分批时保留。普通resume继承检查点批量。
2. 检查点首次检查时，学习率优先回显实际优化器`param_groups[0].lr`，避免旧命令行参数与实际值不一致。用户后续显式修改仍会提交。
3. “恢复生成默认值”原本漏掉已有的TapOnSlide拦截开关，现将其与新增Touch控件一起重置。新字段沿用主界面设置持久化。
4. 明确训练轮数语义：Composer的epochs表示本次运行轮数，resume包含尚未完成的当前轮。第4轮中途恢复到第20轮填17；第4轮已完成则填16。未改变训练器计数逻辑。当前活动任务从第1轮中途恢复，运行日志记录end_epoch=20。
5. 新增API范围和类型检查；生成CLI增加`--touch-history-bound`。API、CLI、策略helper和报告使用同一数值。前端检查新的生成与训练能力版本，旧服务会明确拒绝提交，避免静默忽略控件。
