# 全曲结构新架构首版使用说明

日期：2026-10-12。代码位于 `codex/song-form-rebuild` 分支，模型族为 `song_form_v1`。

## 这次重构改变了什么

旧方案以固定拍数窗口同时决定采音和配置，再顺序拼接。新方案先生成全曲起音草稿，随后依据同曲段落关联与持续动作安排配置，最后可进行局部神经改稿和有预算的检测修复。

新主路径没有 `segment_beats` 参数，不要求 16 拍或四个小节构成一次创作。音乐区域来自多秒上下文变化；音频计算上限按秒控制，token 满后在同一全曲草稿上继续处理。相似关系始终属于音乐区域，不随计算块数量变化。

4/16 拍相位在新音频输入中被移除其作用，以明确拍号特征代替。拍号未知则不提供伪小节相位。原有精确时间换算与 simai 编译继续使用，可表示三等分、五等分及复合变 BPM。

## WebUI 入口

重启当前工作区的 WebUI 后，点击顶部 **全曲结构研究入口**，或进入本机服务的 `/form-lab` 页面。

1. **分析音频与节奏**：选择音频路径，设置 BPM、first；如果知道拍号，勾选并填写，支持按拍变更和 7/8 的 `2,2,3` 等分组。高级项可输入独立 tempo map。
2. 分析后页面展示音乐区域、计算块及候选相似关系。灰色表示拍号未知；关联线只是声学相似证据，不等于已经确认副歌。
3. **训练新架构**：从现有已预处理素材选择器选清单；多训练集先在原“训练素材”中组合，保留高级清单路径入口。设置独立输出目录，从头训练新模型。
4. 新架构模型之间可断点续训或加强训练。旧事件 checkpoint 继续在原工作台生成，不能直接作为新架构初始化权重。
5. **生成**：指定 `form_last.pt` 和输出路径。共享分析区的拍号、BPM、first；选择段落参考力度、起音阈值与是否开启有预算修复。
6. **修订**：指定已有 maidata、难度槽和编辑范围。范围用四分音符拍表示，可输入 `32/3`。时钟采用原谱；输出必须与源文件分开。未通过复检的候选保存在报告里，原谱保持不变。

页面保留任务日志、取消任务、报告下载。没有可直接用于专业出谱的新架构发布模型；现有微型 checkpoint 只是工程测试材料。

## 当前参数的实际作用

| 参数 | 作用 |
|---|---|
| 单次音频计算上限（秒） | 限制配置模型单次处理的音频长度；不是乐句或创作周期 |
| 段落记忆强度 | 0 屏蔽相似段落谱面参考；1 允许模型按学习到的门控制参考。不是照抄比例 |
| 谱面起音阈值 | 全曲起音模型输出分数的选择门槛。越低通常候选越多；目前分数尚未经真实数据校准 |
| max_tokens | 单次配置解码或训练目标的 token 容量；不会定义拍号或音乐段落 |
| max_memory_tokens | 每条谱面记忆分支的 token 上限，保留完整事件后截断 |
| 最多检查次数、最多编辑数、修订时限 | 限制修复搜索投入；预算耗尽保留最佳已接受谱面并报告剩余问题 |

生成使用的有理数网格会考虑 50 Hz 特征的半帧时间不确定性，优先选其中较简单的分数，避免将 1/3 拍的帧峰机械吸附到更细的二进制网格。这是起音定位启发式，不是实机判定容差，也不能保证任意微时值均可从 50 Hz 特征恢复。

## CLI

分析无需模型：

```powershell
python -m maichart.form.cli analyze --audio song.mp3 --bpm 180 --output analysis.json
```

从现有预处理清单训练新模型：

```powershell
python -m maichart.form.train --manifest training_manifest.json --checkpoint-dir checkpoints/song_form_trial --device cpu --epochs 1 --max-steps 4 --limit-charts 2
```

这是有限短跑示例，只检查工程流程；正式训练需清除限量与 step 上限，另外评估模型规模和显存，不将其当作质量训练配方。

生成与局部修订：

```powershell
python -m maichart.form.cli generate --checkpoint checkpoints/song_form_trial/form_last.pt --audio song.mp3 --bpm 180 --output generated/new_form.txt --repair
python -m maichart.form.cli revise --checkpoint checkpoints/song_form_trial/form_last.pt --audio song.mp3 --maidata draft.txt --start 32 --end 36 --output generated/revised.txt
```

需要显式拍号时，WebUI 自动生成参数文件。CLI 可使用 `--meter-map` 指向拍号数组 JSON；数据集内某曲的 `music_structure.json` 可以记录该曲的 `meter_map`。训练区“本次数据使用统一拍号”仅适合明确具有同一拍号的训练资料，默认关闭，不能把单首歌的拍号默默应用到整个 full 集。

## 当前完成度与下一步

已完成独立模型/训练/生成/修订及可操作页面的首版。默认新模型与全曲草稿网络合计约 **880.8 万参数**，可以配置扩大；此数值是工程默认，不是最优容量结论。

一首约 146.7 秒真实歌曲的有限检查得到 35 个候选区域、3 条关联，区域为 5～21 拍；尚无专业人士确认其音乐解释。该案例只用来发现并修正过短切段等工程问题，不构成结构识别准确率。

首版没有完成真实语料的正式训练或专业验收，尤其需要继续做：

1. 用含重复副歌、三拍子、12/24 分交替和变 BPM 的少量固定曲目检查结构关系与节奏草稿；无需强行划出 gold。
2. 正式训练全曲起音选择与配置/重建模型，对比“关闭参考”和“启用参考”，核实呼应与机械重复的区别。
3. 校准起音阈值，检查教师起音骨架与预测骨架的差异。现有极短工程训练明显过密，不能用于判断新架构质量。
4. 引入实际被谱师采纳的修正版，使编辑器从“恢复遮蔽内容”进一步学习“改得更好”。
5. 评估超 token 样本是否需要完整事件级训练续接；当前会明确跳过并审计，不能忽略由此可能产生的数据偏差。

旧版完整 Radar/Style、人工曲线、质量偏好训练等功能继续在原路径可用，尚未全部迁入新架构。双手仿真需要单独验证，Majdata Unity 预览延后；二者没有混入此次可玩性判断。
