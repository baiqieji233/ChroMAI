## 为什么换方法

此前每写一个事件，就重新处理大量候选和历史，再逐颗决定同拍音符。常见双押在八个位置重复学习；空白段的训练机会又比密集段少。

新路线将一次练习改成“读同一首音乐，接着已写好的内容，连续学习最多16个决定”。每步可以写一个完整事件、等待两拍，或在歌曲尾部结束。双押先决定整体形状，再决定位置，最后补时值、滑条和修饰。这样保留流式生成，同时共享计算和常规写法。

这种结构减少重复工作，也让学习目标更直接。通过代码测试并不代表谱面质量已改善，仍需正式训练、固定歌曲对照和试玩。

## 实际模型

- 每首歌建立一份默认10毫秒网格，保留5毫秒瞬态探针测出的峰值。14项额外特征描述频带和瞬态相对过去4拍的变化，不声称分离出人声或乐器。
- 全曲压缩为最多128个音乐摘要；每步读取未来8拍的13个探针。选时另外读取每个候选落点附近的音乐，先将共享银行投影为32维，再查询候选，避免重复运行编码器。
- 统一因果解码器读取已提交音符、当时音乐、拍位/秒数、持续动作与逐键负担。训练输入严格右移。64个历史决定包括WAIT，不总是64个实际音符。
- 一次前向监督最多16步。生成逐步提交，物理守卫只看真实前缀。新路线不调用旧架构重复的history/echo/quality分支。
- 常规配置采用旋转共享的整拍形状。对称配置的等价方向在历史输入、相对转移与损失中一起处理；没有人为指定左右手。细节知道实际形状、方向和同拍已选细节。
- Touch及不能安全旋转共享的内容使用原子序列回退。开发集不参与词表拟合，未知原子明确掩码并统计。
- 可学习的“继续转动、反向、停在原处”和“沿用上一间隔”得分零初始化，不强制方向、不固定惩罚，也不强制把配置推向某个扇区。
- WAIT是正式输出。均匀时间网格另学半秒内是否无起音，以及每秒事件数、音符头数。未来两拍事件率积分形成NOTE/WAIT先验，解码器仍能修正。

## Antigravity二次审查的取舍

[审查原文](COMPOSER_EVENT_SET_STREAM_REVIEW_20261030_ZH.md)中的候选音频缺口、时钟、相位、细节关联、重试和缓存建议均已落实。几个地方做了具体调整：

- 对称双押保留全部等价方向并合并概率，不强行挑一个“最近方向”。
- 半秒无起音不是未来两拍无音，因此用事件率积分形成等待先验，半秒标签单独监督。
- 旧计划预测每格计数，原计数损失并非天然缺少格宽。新版改成每秒速率，在训练和曲线两端同步换算。
- 保留每个时间窗等总权重，不直接截断到固定范围；截断会改变均衡目标。梯度裁剪是否造成某类批次吃亏需要后续测量。
- 不强制双滑条同长或双押同时Break，它们有时本来不同；学习的是相关性。
- 初审将独立短句档案放在“单段写法通过之后”。当前只支持64步内历史和全曲音乐摘要，不能称为任意远距离的谱面短句调用。DSL和两拍微段是备选路线，不与首选同时叠入。
- 两阶段控件在二审前已接入。音频重新接入是否需要预热暂无对照，默认0避免引入未经验证的切换。
- 旧报告已证实BF16注意力dropout反传问题。新模型仅在相应CUDA BF16训练场景使用安全后端，其他情况不全局关闭快速路径。

## Loss口径

主损失为“选时 + 完整配置 + 0.1×音频计划”，指定间隔再加“0.1×闭环恢复”。选时包含NOTE/WAIT/EOS和NOTE间隔；配置包括形状、方向和同拍细节的联合概率，字面回退包含原子与STOP。WAIT固定两拍，不重复学习它的长度。

最后修正了一项确切的尺度问题：每格的计数期望已经乘了格宽，若随后再次按格宽平均，网格从50毫秒变为10毫秒会使速率监督梯度缩小五倍。新 `per_second_v2` 按实际监督时长归一化，两种网格的同场景梯度相同。旧检查点保留 `cell_mean_v1`。界面单独显示速率NLL和休止BCE；速率NLL保留与格宽有关的常数，没有为了让数字好看而缩小。新版总loss可以高于旧版而梯度更加合理。

时间窗按相同总权重训练，分母保持批次×短段展开事件数（默认16），不能再除本批权重和而抵消均衡。总loss不等同于音乐质量，也不能与旧逐槽平均loss比大小。应同时看各分项、未知标签比例和固定歌曲闭环结果。
