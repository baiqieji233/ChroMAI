# 配置协同升级：实现与交接（2026-10-29）

这轮改动针对“采音已有一定效果，但多押衔接、滑条配合和短句写法仍不自然”。核心做法是补齐模型缺少的信息，让它学习配置之间的关系，而不是继续增加反重复惩罚。

本文对应 `configuration_quality_policy=cooperative_v1`。它是新训练结构，不是给旧模型套一个生成滤镜。实现和音乐效果要分开看：代码接通后，新增能力仍需要训练才能发挥作用。

**后续更新：** 同日独立审查发现的起点→终点关系、预判概率损失、辅助梯度约束和候选锚点时间已进一步修复。当前输入合同、验证数字与演进方案以[二次审查说明](../explanations/COMPOSER_COOPERATIVE_QUALITY_REVIEW_20261029_ZH.md)为准；下文保留首版实现与测量快照。

## 已实现的主线

### 1. 多押后续音符也能学习前后关系

原有明确的跨事件位置打分主要作用于首槽。现在后续按钮槽也能参考上一事件的位置；同拍已经选中的 Slide 终点，也能帮助后续音符安排位置。槽位没有被当作左右手。

这部分只在 Tap、Hold、Slide 各自内部调整选择，不直接抬高 Touch 或改变 STOP。新增权重从零开始，初始行为尽量保持原模型。训练的完整槽位、打包槽位和生成时逐槽解码使用同一规则。

### 2. 用实际时间解释滑条的等待、划行和结束

新增输入来自既有原生解析器和持续状态索引，覆盖 Slide 等待、路径穿越、终点、Hold 和 TouchHold 占用。显式等待、分段路径、秒数时值、变 BPM 都沿用已有时间解释；没有再写一套“所有 Slide 一律等一拍”的简化逻辑。

状态只来自已经提交的音符。训练索引虽然保存整首参考谱，也必须按当前前缀截断；后面的参考音符不能提前变成占用或释放信息。这些是学习提示，不把“终点旁边有 Tap”直接当作错误。

### 3. 把过去的声音与当时的配置配起来

最多选择 8 个已提交事件，一部分靠近当前，一部分覆盖更早的拍距。每个参考点同时带声音、音符和时间。这样模型可以学习“声音发生这种变化时，之前的写法应怎样变化”，不必只靠上一颗键位延续。

锚点复用已有音频缓存，没有额外运行音频模型。注意力规模是候选数乘 8，不是把完整历史为每个候选复制一次。历史表示继续限制幅度，整体符号遮挡也同时遮掉这些新增历史输入。

### 4. 预测短句写法与下一步间距

固定 4 拍窗口内，模型预测事件率、平均同拍物量、多押比例、Hold/Slide/Touch 比例、按钮分布范围和后半段强度比例。这里的 4 拍是计算窗口，不保证就是音乐上的一句。

下一步间距分为 7 档：不超过 1/8、1/4、1/2、1、2、4 拍，以及更长。它表示一个预测范围，不是强制下一颗必须落在某个位置。

解码始终使用预测值。真实后续谱只作标签，不作为输入。参考谱未知区间和曲尾没有可靠间距标签时不计算该项；自产历史恢复仍接收新增输入，但不给它硬套参考谱的短句和间距标签。

短句损失权重 0.1；间距总权重 0.1，完整分支与仅音频分支各占一半。这些指标单独记录，原有完整音符指标保留。**新增损失会改变总 loss 的数值，不能直接拿新旧总 loss 高低判断学习效率。**

### 5. 有界微前瞻

微前瞻默认关闭。开启后，仅在预测短间距衔接时，最多比较两个当前方案和一个后续位置。替代方案保持相同类型数量与物量意图，避免为了容易衔接总是退化成单 Tap。

每个方案都在独立临时守卫中提交，再检查下一步。真实历史、真实守卫和主采样随机流不会被试探污染。已有后续候选上下文只作为提议依据，不冒充“提交新事件后重新算出的模型预测”。没有无界搜索，也没有每个分支重跑主干。

这项选择确实会改变输出分布，因此应独立做 A/B。训练恢复默认不启用微前瞻，与默认生成一致；开启微前瞻属于生成侧实验。

## 主界面怎样使用

先重启 WebUI 后端，再刷新主工作台。旧进程已经导入的 Python 模块不会随文件修改自动全部更新。

本轮自动重启 7860 的操作被工具的审批审查拒绝，仅返回 `blocked by policy`；没有绕过该限制。现有 WebUI 进程仍需手动重启。启动命令可用 `& .\.scratch\python312_runtime\Scripts\python.exe -m maichart.webui.server --host 127.0.0.1 --port 7860`，应先正常停止原服务。

| 主界面术语 | 建议起始设置 | 含义 |
|---|---|---|
| 配置质量架构 | 新实验选择“配置协同：多押几何、音频配对与短句计划” | 为新目录的 fresh 或显式微调建立新增分支；自动暂不启用 |
| 配置关系强度 | 1 | 使用训练时的音频配对和持续状态影响；0关闭这两项，不关闭原有历史分支 |
| 短句计划影响 | 1 | 使用模型预测的短句计划；0移除计划对配置及间距预测的影响 |
| 微前瞻强度 | 0 | 先保留基本生成路径；之后在固定音频、条件和种子下单独对比 |

后三项只对启用了新架构的检查点生效。不要通过把旧检查点的配置字段手工改成开启来启用能力。训练的学习率、批大小等保持你选定的基线，先避免同时改变多个变量。没有把未经学习和音乐验收的新结构设成正式默认。

## 文件入口与后续工作

- `lookahead.py`：临时状态预判。
- `train.py` / `objectives.py` / `checkpoint.py`：损失、指标与保存配方。
- 主界面的 `index.html` / `app.js` 和 `composer_api.py`：控制与传参。
