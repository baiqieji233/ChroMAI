## 本轮实际定位

1. `RepeatBias._prefix`此前只覆盖精确文本，不覆盖结构类别。有限提案若全部是双押，即使终端都被减去同一惩罚，也不能产生原本不存在的单键候选。这是候选覆盖不足；softmax对常数不变本身是正确数学行为，不应通过去重或重复计算模型概率来“修复”。
2. `observed/predicted - 1.35`只能控制头密度超标，并不度量配置变化。中高密度下的机械循环、低密度的长周期循环、换键位的双Hold长串都可能被放过。
3. EOS停止新增头，不会结束已写出的Hold/Slide。原曲线的sustain通道是**头类型份额**，不是动作占用或release标签，因此不能把“没有新头”当成“已有动作必须结束”。

第三方报告还混合了两份产出：0.25采音强度的备份validation和0.35的最新e3a83e7f233b不同。validation重复引导的最后诊断在98.68s，尾部零时长Hold并没有在150–155s被该模块直接驱使；慢Slide段实际112.42–120.63s，静态参考提示也不构成“全由该段新造成”的因果证据。未据这些未经对照的因果叙述添加禁用规则。

## 实现与操作流程

### 1. 结构前缀势能

`RepeatBias._prefix`现在使用当前原子目录、完整部分的头数和仍可完成的原子，计算完整配置惩罚的log-mean-exp势能。斜杠前后、Hold分支前后及结束时都能看到结构差别；跳出结构时会撤销先前的临时势能。完整配置只按同一终端偏好评分一次。

该势能仅用于提案探索，重要性校正恢复目标分布，避免把“终端惩罚+前缀偏好”双倍计分。兼容现有Break、双押、Style、物理反馈和语法硬限制，不重新解释时值数字为键位。

### 2. 负荷与单调分开

- 保留 **长重复负荷引导强度**（`--repetition-strength`，默认0.6），继续只针对超出预测头速率的周期。
- 新增 **配置单调引导强度**（`--repetition-structure-strength`，默认0.6），不要求超负荷。匹配长周期的完整配置或头类型组合，包括换键的双Hold、单键/双押交替，以及稀疏Touch/Slide交替。
- 两项都仍需要超过 **长重复最短秒数** 默认4s和 **长重复最短拍数** 默认8拍，并保持同一拍距周期。持续长度渐进增加偏好，不设固定颗数硬禁令。
- 普通单Tap类型本身不构成结构重复：扫键/交互的确切长模式可以形成周期，但不会因“连续都是Tap”就全部被判错。真实的长交互仍可能受到有界软偏好，不能声称完全无误伤；可将配置单调强度设0。
- 当模型明确支持某种类型时，结构反馈最多衰减一半，避免它自己很确信就完全关闭保护。用户 **套路复用** 偏好越高，单调反馈进一步减弱，最多减弱75%。
- 新报告分别记录 `monotony_events`、`overload_events`，以及每次两项代价。合并惩罚上限是两项强度之和的2倍，默认2.4；不同匹配周期取最大值，不随匹配数量无限累计。

### 3. 一个受控探索候选

新增 **重复时候选探索温度**（`--configuration-exploration-temperature`，默认1）。仅重复压力存在、完整候选数大于1、且探索温度高于配置温度时，最后一个候选使用较高温度。没有新增候选行，不扩大并行K/V；其他行保留原模型提案或通常引导提案。0关闭。

对每个候选沿实际token路径同时累计原模型、通常引导、探索三种提案的log概率。重采样使用实际三种提案比例（1个原模型、N-2个通常引导、1个探索）的混合密度；候选数2时通常引导份额为0，不计算log(0)。候选数1/贪心维持旧分支，不声称能做重要性重采样。

配置报告新增 `exploration_proposals`、`mean_candidate_structures`、`all_candidates_repeat_events`。即使开了探索仍可能全是重复类，报告如实保留；不得把这些计数说成音乐质量分数。模型极度确信、有限样本未覆盖替代、或者全部合法替代都很差时，不强行塞一个低概率类型。

### 4. 持续动作单独结束上限

新增 **持续动作结束时间 / 秒（可选）**（`--sustain-end-sec`），默认留空。

- 限制正时长Hold、TouchHold、Slide/WiFi的尾端；在配置前缀可完成性和完整候选检查中共同生效。不会先生成再裁掉半条Slide。
- 普通Tap和零时长Hold不受该“持续尾端”选项额外限制；若希望头和尾全部止于某时间，使用已有 **生成结束时间 / 秒**。两个上限同时给出时均执行，取实际更严格约束。
- 时间使用原音频秒轴，保留BPM和first。非有限、非正或超过音频长度时拒绝。
- 输出增加 `action_ending`，分别列出最后头、最后动作、头后动作延伸和手动上限，明确 `musical_action_end_automatically_verified=false`。

**自动判断真实音乐尾端没有在本轮被声称解决。** 当前权重没有持续占用/动作release监督，现有四通道头曲线不具备这个语义，不能从它可靠推断158.21s的Hold是否应在更早结束。手动上限是当前有明确保证的处理方式，不是隐藏的响度阈值或新的独立EOS训练。后续若要自动化，需要单独的可靠持续动作证据/监督；用户未要求本轮增加独立结束学习，故未扩张模型族和训练合同。

完整Fraction空间继续保留；额外提案沿已写出的精确节奏步长，以及1／1/2／1/4拍给出释放之后的候选，不把释放秒数转换为巨型分母输出或量化已采样事件。时钟仍由模型消费真实token推进。若用户关闭事件重选则不启用这项恢复；重选预算和最低候选概率均保持原设置，不降低物理保护或强塞低概率Touch。记录 `committed_action_release_sec`，事件成功提交后清空恢复下界。

此策略可能放弃当前低概率Touch替代而让该事件等待手部释放，是有界恢复策略，不是音乐取舍的完美解。仍无法找到足够可信合法配置时继续明确报告未完成。没有用音频响度或固定段落时间决定跳跃。
