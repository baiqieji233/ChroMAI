# Composer 配置质量升级：整合修改方案（2026-10-29）

状态：Q1～Q3 的首版代码、数据与主界面接线已完成，实际交付范围与集中验收见[配置协同实现与交接](COMPOSER_COOPERATIVE_QUALITY_IMPLEMENTATION_20261029_ZH.md)。本文保留完整设计目标；Q4、离散家族库、NextStepAdapter 和音乐效果验收仍是后续工作。按用户要求，排除独立协作者的“突破口二”：不新增二阶角动量奖励、扇区质心反向推动或强制换区规则。

## 一、最终目标与边界

目标是提高配置的连续性、与音乐的对应关系、同拍协同和短句组织能力，同时保留已有采音与训练性能成果。

采用以下设计边界，不把它们冒充已被完整统计证明的普遍规律：

- 不用启发式给每颗音符硬标左右手；槽位顺序也不等同手的归属。
- 短 Hold/Slide 可以承担手感缓冲或动作手势，不要求其尾端必须对应声音结束。
- 保留语料原有起手方向与分布；不默认做旋转/镜像增广，也不强求按键分布均匀。
- 重复段落可能换鼓组、混音或音高。动机功能不以底层声学自相似检索成功作为前提。
- 已有物理检查继续负责确定的冲突。新增关系特征提供学习依据，不把“终点附近有 Tap”“重复了一句”等现象一律判错。
- 不继续增加通用反复读惩罚系数。现有阻尼保留为基线，在新结构验收后再评价其必要性。

## 二、核心结构

生成流程拟整理为：音频与已提交历史 → 音频/配置对应关系 → 短句写法计划 → 当前拍位与预计下一步间距 → 同拍协同动作解码 → 有限的后续可玩性预判 → 提交事件。

新增信息来自三种来源：

1. 已知输入：音频、节拍与 BPM 信息、用户等级和风格条件。
2. 因果状态：已经提交的音符及其真实持续状态。
3. 模型自己的预测：写法计划、下一事件间距、变奏选择。

真实后续谱只用于训练监督，不能直接填进部署时不存在的条件输入。训练、恢复和生成共用同一份特征定义与时间语义。

## 三、核心模块 A：同拍协同几何与持续动作生命周期

### A1. 将跨事件几何扩展到所有有效按钮槽

当前 `decode_candidate` 和 `action_slot` 只对首槽调用 `_cross_event_logits`。后槽已有共享历史上下文，但缺少这条显式位移打分通路。这个缺口应优先补齐。

实施方式：

- 首槽保留现有分支；为后续有效按钮槽增加共享的跨事件关系因子，结合已选同拍前缀和槽位角色进行条件化。
- 使用共享因子和小型角色表示，不为 33 个槽分别建立大分类器。
- 输入是上一事件的按钮集合、已选本事件按钮集合、持续动作摘要，不给集合中的音符强配左右手。
- 同步实现完整槽位训练、打包槽位训练和逐槽生成。只处理首个 STOP 前的有效槽位。
- 新增显式几何加分沿用现有按 Tap/Hold/Slide 分别守恒的方式；不直接给 Touch/STOP 增减概率，也不因桶内归一化把几何分支抵消。
- 新增后槽因子直接零初始化，使其获得有效梯度；避免“零输出再乘零门控”的双重阻断。

验收示例：`1/5 → 2/6 → 3/7`、`4/5 → 3/6 → 2/7`、连续双押与一划一拍。检查后槽梯度、同拍占用、三个执行路径的一致性及类型概率质量，而不是仅检查第二槽是否不报错。

注意：字典序使同拍槽位具有编号偏置，但第二槽并不总在 5～8 键，也不代表第二只手。

### A2. 在同拍前缀中加入滑条目标与时间阶段

保留 `atom_end_lanes`，并将已选原子的起点、终点、类型和分支信息交给后槽。终点几何用于协同，实际是否正在穿越或已到达则使用时间阶段。

复用 `SustainStateIndex`、`prefix_state.py` 和原生 Muri 解析结果，提供：

- 头部已触发、尚未起划；
- 正在划行及其进度；
- 即将/刚刚到达终点；
- Hold/TouchHold 的占用、剩余时长和释放信息。

静态词表保存时值表达式类型、参数和路径拓扑；运行时结合该事件的 BPM 与解析语义得到 `t_head / t_trace / t_end`。不能只存一个通用 `atom_slide_beats` 标量。

普通 Slide 的等待通常对应起始 BPM 下的一拍，但源码也支持显式等待、指定 BPM、秒数时值及分段路径。因此以原生解析出的秒数为比较轴，再结合 `TempoClock` 提供相对拍距；不硬写所有 Slide 都在 `b+1` 起划。

当前已存在等待、剩余时间与进度特征，工作重点是把足够的分支/起终点信息接到候选和槽位解码，避免再造另一套物理解释器。只用已提交前缀推进状态；新提议在临时状态中检查，接受后才提交。

验收必须覆盖默认等待、显式等待、变 BPM、秒数时值、零 Hold、持续动作跨窗口、同拍多个分支、已经结束的动作，以及参考谱未来事件不得提前影响释放时间。

## 四、核心模块 B：音频与历史配置配对

为少量历史事件补上当时的音频特征，让模型学习“声音怎样变化时，配置怎样变化”。它不需要把某个绝对音高固定映射到某个按键。

首版使用最多 8 个参考锚点：一部分近期事件，一部分按拍距覆盖较早窗口。先采用确定的时间覆盖，不依赖跨副歌检索。每个锚点包含：

- 当时的声音表示及其邻近时间变化；
- 已提交音符的类型、几何与真实时间；
- 当前候选与该锚点的音频差异、节奏关系和持续状态关系。

复用现有原始音频库和批内查询共享。训练时不跨优化器更新缓存可训练编码器的输出；推理时可复用已有音频缓存。所有新增历史表示进入注意力前继续使用既有尺度管理与监测。

训练保留主动作目标，同时让配对关系影响配置上下文。无需立刻增加多个辅助 loss。主要验收是在节奏、密度接近时改变音频内容，观察配置变化是否更符合声音；并比较打乱配对与正确配对，确认模型实际使用了对应关系。

## 五、核心模块 C：短句写法计划与配置家族

### C1. 持续一小段时间的写法计划

现有 Planner 的六通道仍负责事件率、物量、类型与休止。新增一个较小的配置计划分支，用少量连续描述表达：空间跨度、展开/收拢趋势、同拍数量变化、类型主次和收尾倾向。

首版采用约 4～8 拍的计算窗口，并根据已知拍号、音乐边界允许提前换句。固定拍数不能自动称为真实小节。计划在窗口内保持稳定，给逐事件解码一个持续目标。

目标描述从训练谱直接计算，不需要左右手标注。解码器训练时使用模型预测的计划；真实后续计划仅作标签。若初期需要教师计划帮助稳定，必须记录其使用比例并在正式验收前降到生成时相同的条件，不能长期依赖完美计划。

计划须可干预：同一音频改变一个计划维度，应产生可理解的变化。单看计划预测 loss 低，不能认定解码器在使用它。

### C2. 学习配置家族，同时保留具体动作监督

从真实语料归纳相对几何、同拍结构、类型序列与持续状态组成的写法家族。保留方向、起手区域和绝对位置作为独立条件，保留具体合法动作 CE。

不默认将左右镜像写法视为等质量，不把同一前缀后的八个目标键都标为正确。不新增大规模稀疏模板词表，也不要求新模型把每句压成一个固定模板；先用紧凑、可解释的描述，必要时再学习有限家族表示。

这部分旨在降低“同样组织结构却被当作大量孤立类别”的学习负担。新的家族 loss 与原动作 loss 分开记录，原有固定口径的完整音符指标继续保留。

## 六、核心模块 D：离开步长感知与有界两步协同

### D1. 学习下一事件间距分布

在选定当前事件时刻之后，利用已计算的后续音频候选及当前条件，预测下一事件间距的分布，并将其作为当前动作解码条件。

训练标签取合法、可信的下一个参考事件；未知区间和曲尾删失按现有事件视图处理。恢复阶段读取自己的前缀并使用模型预测，不能输入真实下一拍作为生成条件。

placement 峰可以帮助构造分布，但它回答附近的条件占用，不等于该声音必须写成下一个音符。不能直接把“下一个峰”硬认定为下一步，更不能据此保证 100% 消除微步倒挂。

对高置信短间距，当前动作可以偏向与后续快速衔接相容的写法。保留合法 32 分、多押和短滑条，不新增全曲 BPM 一刀切规则。

### D2. 固定两分支的后续可玩性预判

只有在短间距衔接确有必要时，比较至多 2 个当前动作方案、1 个后续事件位置。先按原分布决定主要类型/物量意图，再在相近意图的空间配置间比较，减少“永远选最容易接下去的 Tap”的偏置。

每个分支在临时状态中提交当前提议，重算下一时刻的占用、释放、同键冷却和已选前缀关系，然后调用现有守卫检查后续动作可行性。临时分支不污染真实历史、动机缓存或随机状态。

重要接口边界：当前 `candidate_context[c2]` 是在当前动作尚未提交时算出的，还包含旧历史和旧相对时距。仅更新 `previous_heads` 无法将它变成真正的下一步模型上下文。现有 `FutureAudioHorizon` 也已经提供约 8 拍的音频前瞻，因此升级点是显式的离开间距与动作协同。

首版复用候选输出作为提议依据，采用真实临时状态检查后续可玩性；不把旧上下文得分称为精确的两步条件概率。需要进一步评价后续配置质量时，再训练轻量 `NextStepAdapter`：输入可复用音频表示、新提议、真实新间距和更新后的状态，输出下一步宏观配置分布。真实下一步标签与实际完整模型路径用于训练和校准该适配器。

可安全复用原始音频、局部音频嵌入和全曲 Planner 等与分支无关的计算。混入旧历史或旧时距的特征必须更新或明确作为近似输入，不因变量叫 audio_context 就认定能原样复用。

不采用无界 beam 搜索，也不以整段联合对数似然最大作为唯一选择标准。选择器会改变输出分布，即使温度保持不变；必须检查类型、物量、多样性及耗时。`<3%` 额外开销只能作为待测设想，不能预先写成保证。

## 七、后续增强：动机变奏与整句比较器

### E. 动机再现与变奏

在核心模块有效后，让段落计划选择“沿用、发展、收束或换写法”，并把既有动机记忆作为一个可选依据。

检索综合较高层音乐特征、节奏结构和已生成配置，允许混音变化；不要求原始声学自相似矩阵成功。没有可信对应时使用当前计划正常续写。镜像/旋转是有条件的变奏选择，不是默认训练增广或必须均匀使用的规则。

所有谱面记忆来自已提交历史。先处理可可靠转换的几何，再扩展 Slide 的形状、方向、等待与分支变换。

### F. 整句比较器

对同一采音骨架给出最多 3～4 个短句配置，比较展开、衔接、收束与音乐对应。与两步预判不同，它评价整句组织，而非下一拍能否接得上。

核心方案不依赖新增人工标注。整句比较器可以从派生指标和明确的破坏样本开始，但最终应加入少量同音频、同难度的人工偏好校准；合法旋转、合理重复和罕见谱型不能自动作负例。额外生成成本单独记录，不与主模型训练吞吐混算。

## 八、实施顺序、接线与训练合同

| 里程碑 | 交付范围 | 主要代码位置 |
|---|---|---|
| Q1：配置协同基础 | 所有有效按钮槽的跨步几何；同拍起终点关系；持续动作阶段接口 | `action_factors.py`、`grounded_model.py`、`prefix_state.py`、`generation/sustain_state.py` |
| Q2：配置组织学习 | 历史音频配对；短句计划与家族描述；下一事件间距预测 | `data.py`、`device_audio.py`、`planning.py`、`grounded_model.py`、`objectives.py` |
| Q3：生成协同 | 两分支临时状态验证；必要时训练 NextStepAdapter；训练/恢复/生成统一 | `generate.py`、`recovery.py`、`train.py`、`guard.py` |
| Q4：段落质量 | 动机变奏与整句比较器 | `motif_memory.py`、评价与偏好数据工具 |

每个里程碑完成代码、数据和 UI 接线后统一测试；不在每改一个函数后反复运行大套件。核心 Q1～Q3 是主线，Q4 不阻塞主线训练验收。

所有新增输入与目标在 checkpoint/训练配方中明确记录版本。保留旧检查点作为固定基线；新增结构使用新目录进行 fresh 或显式 finetune，不伪装为等价 resume。新增残差保持单一零初始化入口，并继续使用已有历史尺度管理。

## 九、统一验收

### 实现正确性

- 完整槽位训练、打包槽位训练、逐槽生成的数值和梯度对齐。
- 并行目标中的第 s 槽只能使用当前事件的前 s 个音符；不能看见完整当前和弦。
- 新几何分支对 Touch/STOP 的直接影响、各类型总概率质量符合定义。
- 生命周期覆盖普通/显式等待、变 BPM、秒数时值、多分支、零时值和释放边界。
- 作者历史、生成历史、恢复历史的特征和时间轴一致；缓存不能泄漏未来谱面。
- 临时前瞻分支可撤销，不能修改真实状态或无意消耗主采样器的随机流。

### 学习与音乐效果

先冻结基线权重、音频、条件、曲线和随机种子，保存完整结果与哈希。统一安排短训与预先列好的消融：几何、生命周期、音频配对、计划、前瞻分别开关比较。

原有完整音符 CE、首槽/后槽 CE、宏观/细节 CE 保留；新计划/间距损失另记。不能把任务改简单后的 loss 降低当作学习加速。

生成至少覆盖：双押流、一划一拍、双滑条、短时值手势、变 BPM、合法 32 分、长休止、重复副歌、不同混音、Touch 密集段。观察重复、物量、类型比例、真实冲突、计划响应与人工听谱偏好。降低重复不作为唯一成功标准。

### 计算预算

历史音频参考首版最多 8 个；微前瞻最多 2 个当前动作 × 1 个后续位置；整句比较最多 4 个版本。优先复用已计算音频，不构造 `[B,C,H,D]` 的高维广播特征，也不递归扩展分支。

主训练吞吐额外下降不超过约 10% 作为首版工程目标，而非性能承诺；显存、准备耗时、恢复耗时和生成延迟分别测量。收益不足或开销偏大时，先去掉重复计算和冗余表示，不通过减少有效标签、缩短真实历史或降低时间精度制造提速。

## 十、主界面呈现

架构与训练配方保存后，主界面应显示实际启用的能力和继承状态。生成侧只提供少量能直接理解的控制：配置连贯性、短句计划影响、微前瞻强度、动机变奏强度。每项显示关闭时的真实行为，避免控制多个无关分支的混用滑块。

具体默认值由上述短训和生成验收决定。本方案不预先把尚未训练的新模块或未经测量的前瞻设为正式默认。
