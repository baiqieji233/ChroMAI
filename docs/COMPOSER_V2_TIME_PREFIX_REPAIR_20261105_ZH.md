# my flow 第400／900步生成复查

本轮修复推理实现，没有停止训练、修改训练参数或改变训练目标。所有复现使用独立检查点副本、CPU、原歌曲、seed 0、温度0.9和Top-p 0.95。

## 1. 第400步失败：数字前缀检查确实有错误

先只增加失败诊断，保留原采样逻辑，重新生成。175个已提交事件与原报告完全一致，再次在 `46655/192 = 242 + 191/192` 拍后失败。诊断记录的实际前缀是 `[AT], NUM:2, NUM:4, NUM:2`。

词表中第242拍的最后一个可用相位已经被使用。旧代码只判断整数242是否落在歌曲范围内，没有检查242是否还有未使用的相位，因此放行了一个无路可走的数字前缀。16次重试不能解决同一错误。

已修：先计算真正存在合法相位的整数拍范围，再决定数字前缀能否继续。这个例子的下界变成243。没有限制长休止，没有禁用三连音、五等分或七等分，没有改温度。

补充了边界测试：当前整数拍相位耗尽、跨99→100、歌曲尾部只剩部分相位、区间内没有任何可用相位，以及每一个允许的数字前缀都能完成为合法时间。失败诊断现在保存真实组件前缀、前后拍位、上下文起点和生成参数。

## 2. 修复后暴露的第二个恢复缺口

第一次修复后通过原故障点，但在346个事件后遇到真正的原生物理冲突。此前恢复仅查找仍在持续的Hold／Slide；近期普通Tap造成死路时没有撤回入口。

现在保留原生检查的涉事事件拍位，在需要撤回时优先撤回最近的已提交涉事事件及后缀，然后精确重放更早状态。没有物理冲突证据时，不随意删除普通事件。原持续动作恢复仍保留。当时界面称为“冲突撤回次数”；后续 6900 步双 Hold 故障修复将其扩展为“冲突恢复次数”，尾部微调与撤回共用预算，详见 [Hold 松手边界恢复说明](COMPOSER_V2_HOLD_RELEASE_RECOVERY_20261105_ZH.md)。

最终第400步副本成功导出387个事件。原38.7秒空白仍存在。这里证明的是恢复路径能够完成，不是音乐性或完整可玩性已经达标。

## 3. 第900步的115秒空白是另一类问题

修复后用第900步副本重跑，得到的TXT与原21事件谱面逐字节一致。因此空白不是这个语法死路造成的。

已核对：

- 生成参数与真实谱面的BPM都是157，first都是0。
- 原生拒绝记录全部位于大跳之后；没有先拒绝20拍附近的配置再被迫跳到321拍。
- 实际权重的增量缓存与完整重算，logits最大差约0.0000019。
- 20、21、23等近处整数拍仍有合法后续，没有被时间语法屏蔽。
- 模型实际选择了绝对整数321；编译器没有把一个近处时间错误转换成321。

在相同的生成前文（到20拍）上，下一整数第一位为“2”的概率，第400步约98%，第900步约93.5%。在Top-p 0.95下，400步只保留“2”，900步则把“3”也纳入候选；截断归一化后“3”约占3.7%。一旦选择“3”，后续可能继续拼成32、321。

第900步改用真实谱面前文时，同一第一位“2”的概率约99.4%。这说明真实前文与自生成前文下的行为存在差异；不能据此把整个模型判定为不会预测时间，也不能由两份单种子输出断言整体训练持续退化。

**已经定位的直接机制是：逐字符拼绝对拍号，会把一次较小的采样偏差放大成十几拍、甚至几百拍的跳跃。** token交叉熵也没有直接表达这两种错误在时间上的巨大差别。这比“模型还没训练够”更具体，但尚未进行训练干预来证明某个替代表示一定更好。

另一个需要一起评估的敏感点：选定整数后，再筛除已经过去的分数相位，会重新放大剩余相位。400步的一个探针中，第134拍合法剩余相位原本只占约19%的相位概率，筛选后被重新归一化。因此粗时间选择错误还可能表现为不断挤向当前拍末的极细分音，而不只是长空白。

## 4. 下一步应改哪里

不建议用“最长空白”“强制补音”或调低温度掩盖。更合理的下一步是验证：**下一整数拍推进量＋绝对拍内相位**，或对完整候选时间进行统一选择，避免逐字拼绝对拍号。

例如从20.75拍继续写，可以选择整数推进1、相位0，得到21拍。相位仍对齐整曲音乐时钟，不累计上一颗音符的小数误差。长休止仍可以选择较大的整数推进量，不加入每拍WAIT循环，也不回到固定16拍输出。

这需要新时间合同及小规模训练干预，不能把正在训练的模型直接按新含义解释。本轮没有实施该训练侧改造，也没有声称长空白已经修好。值得保留的对照包括：真实前文／自生成前文、同一首歌的正常休止、相邻落点错误幅度和自由生成的长跳比例。
