## 为什么要改

例如前面一段写了 `1,2,3,4`，几拍后已经连续写出对应的 `8,7,6`，人类谱师往往会接上 `5`，完成镜像呼应。旧模型虽然看得到历史，却没有直接利用“恰好几拍之前的对应位置”。因此局部动作可以合理，整句仍会缺少联系。

新增分支直接比较最近四个事件和 2、3、4、6、8、12、16 拍之前的内容，统计原样、左右镜像、半圈旋转、上下镜像是否连续成立。它学习“有多少证据时应当继续”，并让当前音乐上下文调节这个倾向。所有滞后共用证据表，没有强行规定歌曲一定是 4/4 拍。

## 实现如何接入现有架构

现有主干仍然先读取音频、历史、占用状态，选择下一个拍位，再逐槽决定该拍有哪些音符。新增分支只使用已经传给模型的历史键位、精确拍距、候选间隔和音乐上下文，不增加数据标注或缓存字段，不另跑编码器。

1. **共用证据函数。** `phase_echo_features` 同时供模型和统计报告使用。键位证据只数最近四个按钮事件，跳过纯 Touch；节奏证据包含 Touch。只读取已提交历史，屏蔽 padding 和未来来源。
2. **学习键位呼应。** 偏置作用于所有动作槽。分别在 Tap、Hold、Slide 内重新分配概率，各类总概率保持不变；STOP、Touch 和 TouchHold 不受直接偏置影响。它不会为了呼应而把 Tap 变成 Slide，也不直接复制滑条形状或多押大小。
3. **学习节奏呼应。** 把相同滞后的下一事件间隔作为预测，给选时细分数和对应时间桶增加可学习偏置，随后继续经过原有历史修正上限。`history_residual_bound` 没有改变。
4. **保持原模型起点。** 所有新增参数为零，实际参数影响乘以 8。使用线性相加，使初始输出不变但梯度能到达新参数。合成输入测试验证了从 `cooperative_v2` 迁移后主要输出逐位相同；没有另做 v23 迁移后的全开发集推理。
5. **训练与生成一致。** 整事件解码、逐槽生成、恢复采样和微前瞻都传递同一偏置。音频参考分支不读取它。微前瞻继续复用当前已提交前缀的上下文，不声称已经重新计算了分支下一步的完整预测。
6. **丢弃规则一致。** 单个历史事件的随机丢弃不改变证据统计；整段符号分支关闭时，两种呼应偏置也一起关闭。

新增参数量为 `35 × 模型宽度 + 63`，宽度 256 时是 9023 个。特征计算使用批量张量，没有训练侧逐样本 Python 循环。主要临时张量规模随 `B×7×H²` 和 `B×C×7×H` 增长，不增加随生成分支数指数增长的搜索。真实 GPU 吞吐增量尚未测量，不能把参数少等同于训练免费；下一阶段应同时记录样本/秒和显存。

选时边界的准确含义：加到音频选时上的、归一化之前的历史修正仍在 ±bound 内。最后统一归一化会加一个公共平移，因此测试比较候选间的对数几率变化（上限 2×bound），不错误要求最终每个 log 概率差都在 ±bound 内。计划中的“约 +0.76”只是一种输入量级的示例，不是所有样本的固定最大值。

每轮验证的 `validation_latest.json`、`validation_history.jsonl` 和 `composer_validation` 日志会包含 `echo_copy_mass_by_E`、`echo_timing_mass_by_R`。启用新分支时，额外输出 `echo_prior_calibration`，记录放大后的证据表和音乐调节权重范数，方便判断新参数是否学起来。呼应统计在设备端累加，报告时才转回 CPU，不增加逐批指标读取同步。生成报告的结构指标增加 `echo_evidence_profile`。teacher-forced 统计用模型可见历史窗口；生成谱统计沿用原协作者脚本的完整已生成前缀定义，并明确标记范围，二者不能直接混作同一概率。
