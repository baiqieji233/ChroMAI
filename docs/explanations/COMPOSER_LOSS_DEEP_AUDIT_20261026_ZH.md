# Composer loss平台的实测深审与缓存修复（2026-10-26）

本记录接续[前轮审查](../compatibility/COMPOSER_REVIEW_AND_PARAMETERS_20261026_ZH.md)，回应用户对loss长期停在4附近的持续疑问。前轮单batch正梯度余弦不足以排除长期学习受阻；本轮扩展了歌曲、检查点、模块梯度与短程对照，没有把“尚未证实某个机制”写成“该机制一定无害”。

正式训练仍停止，原v11和17,500步保留副本未修改。所有拟合、模型导出和诊断仅写入`.scratch/composer_loss_deep_20261026/`。本轮没有重启长程任务。

## 已确定的结论

1. **后段下降确实慢，不能只归因于累计平均。** 差分还原相邻累计和后，最近窗口约4.18–4.28，最后325个microbatch约4.219。原任务最后到17,663次更新，实际保留检查点是17,500。
2. **发现并修复动作因子评估缓存过期。** 本机fused AdamW更新不增加参数`_version`，原缓存因此可能跨训练/评估读取旧因子。它影响恢复采样和交替评估；正常训练前向不读取该缓存，不能声称它解释了全部训练loss平台。
3. **没有支持“总loss约一半是不可约底噪”的证据。** 辅助项确实抬高显示值，但量级远不足2.0；同一模型能在768行fit小集上过拟合到共同评估总loss2.25，说明实现并未把loss机械锁在4。这不提供全库或未见歌曲的损失下界。
4. **没有支持“音频动作辅助头在整体上必然反向拖拽”的证据。** 多批共享动作头梯度全部同向；音频编码器存在少数反向批次。降低辅助权重的短程试验未优于父模型探针，不据此改默认权重。
5. **本轮384行heldout probe的主要误差仍在配置选择，特别是键区及其余配置属性。** 这是真实预测误差，不是简单调整报表即可消除。它是否主要受数据多解性、跨拍几何表达或长期优化策略限制，本轮仍未得到足够的因果证据。

## 真实训练与优化器核查

源码的累积按实际窗口数除loss，包含轮尾不足4批的窗口；每窗口裁剪到norm1并做一次AdamW更新。检查点中各已初始化参数的Adam step一致为17,500，LR为2e-4、betas=(0.9,0.999)、eps=1e-8、weight decay0.01。未发现重复除累积、漏step或错误恢复学习率。原任务使用BF16，参数与优化器正常FP32；没有FP16 GradScaler并非遗漏。

训练没有学习率调度器。日志中没有非有限或跳batch警告；156次恢复采样得到259个accepted样本，149次实际附加恢复损失，已加权损失均值约0.1478。该分支确实执行，不能说恢复采样完全没参与训练。

旧版本loss不能直接比较：有效动作槽计分与旧的STOP padding计分不同，部分版本还继承了已有权重。用户观察到的学习速度差异仍值得认真对待，但单靠旧总loss数值不能隔离架构优劣。

## 多歌曲数据与口径

从完整数据中的1,405个可用源音频组随机选择128首，每首按全谱四个时间分位抽事件，再打散：

| 集合 | 范围 | 样本 / batch |
| --- | --- | ---: |
| fit | 96首，每首8个事件 | 768 / 24×32 |
| same_song probe | 同96首，每首另4个事件，与fit事件不重叠 | 384 / 12×32 |
| heldout probe | 另32首源音频，与上两组音频不重叠 | 384 / 12×32 |

父模型此前训练过这些歌曲，所以heldout仅表示**本次短拟合阶段没有使用这些歌**，不是父模型从未见过的测试集。数据仍来自同一个全量manifest，不能当作完全独立的泛化验收。

词表固定为父模型18,453个原子加STOP，在任何歌曲表构建前注入相同映射；候选96、历史128、模型容量33槽，collate按实际长度裁剪为本batch的3–5个目标槽。三组包含Tap、Chord、Hold、Slide、Touch。原始文件、音频绝对路径、事件索引、词表/父权重哈希与数据指纹均保存在`diverse_batches_provenance.json`。

另按文件内容核对了这128个源音频的SHA-256，全部不同，未发现跨组的字节重复；这仍不构成父模型未见过歌曲的证明。

## 同输入下的早晚检查点

均为BF16 eval、遮挡关闭、原共同loss权重，没有训练更新：

| 检查点 / probe | 总loss | 主选时 | 主动作 | slot0 CE / 精确准确率 |
| --- | ---: | ---: | ---: | ---: |
| 2,000 / same_song | 4.8461 | 1.1976 | 2.8756 | 3.6658 / 24.21% |
| 17,500 / same_song | 4.2411 | 1.0937 | 2.4219 | 3.1481 / 30.86% |
| 2,000 / heldout | 4.7610 | 1.2318 | 2.7706 | 3.5567 / 23.47% |
| 17,500 / heldout | 4.0313 | 1.0429 | 2.2881 | 3.0444 / 29.25% |

模型确实在学习配置，不是完全只学会采音；但15,500次更新后的精确首槽仍有很大误差。当前heldout的slot0 CE可严格分解为：类型0.5691、给定类型后的头区1.6408、给定类型和头区后的其余原子属性0.8345。这是观测损失分解，不是熵下界，也不是“多少配置没学会”的比例。

该probe总loss4.0313中：主选时1.0429、主动作2.2881、加权音频选时0.1732、加权音频动作0.4546、其他任务0.0725。辅助项合计约0.7003（17.4%），不能解释成约2.0的算法性底噪。

另在原固定256样本上，17,500步BF16与FP32总loss分别4.53809和4.53861，精确首槽准确率相同；正常训练随机性（普通dropout、历史/符号/台账遮挡）的多次均值比eval增加约0.262。它们不能代表全库，但没有支持“BF16误差或遮挡单独造成约2.0底噪”的判断。

## 多批梯度与五组GPU短程对照

24个多歌曲batch、768样本，分别在eval和正常训练遮挡下测量共享模块，主动作与未加权音频动作的梯度余弦：

| 模块 | eval均值 / 反向批次数 | train均值 / 反向批次数 |
| --- | ---: | ---: |
| 独立词表动作头 | +0.4386 / 0 of 24 | +0.6294 / 0 of 24 |
| 结构因子 | +0.4574 / 0 of 24 | +0.6233 / 0 of 24 |
| slot fusion | +0.3589 / 0 of 24 | +0.5580 / 0 of 24 |
| candidate fusion | +0.0986 / 0 of 24 | +0.3459 / 0 of 24 |
| 音频编码器 | +0.4639 / 1 of 24 | +0.4376 / 3 of 24 |

共享头加权辅助梯度范数约为主梯度的12%。这比前轮单batch证据更强，仍不证明权重0.15在所有训练阶段最优，也没有排除特定类型/稀有标签的局部冲突。模型同时有每原子独立的全词表Linear头和结构因子，不能说结构因子已经消除了稀有词表学习难度。

每组从同一17,500步权重及Adam moments独立开始，固定数据顺序和随机种子，做128次更新；microbatch32×累积4，有效batch128，原正式任务为256。所有组关闭恢复采样以隔离变量。eval统一回到原0.15音频辅助权重并关闭遮挡，避免把“降权后的数值变小”误当收益。

以下是**重新加载保存模型后的有效评分**。本轮初次进程内0→32→64→128评估受缓存问题影响，32/64分数已废弃，不用于比较或绘制收敛曲线。训练前向从不读此缓存，五组权重更新本身不受该缓存读取影响，因此保存后的模型可以重新加载评分；没有把失效曲线继续用于结论。

| --- | ---: | ---: | ---: |
| 父模型，未更新 | 4.1837 / 2.3959 | 4.2411 / 2.4219 | 4.0313 / 2.2881 |
| 原配置继续 | 2.2520 / 0.8884 | 4.5053 / 2.6700 | 4.3921 / 2.6590 |
| 仅动作音频辅助0.02 | 2.9138 / 1.4025 | 4.3150 / 2.5303 | 4.2288 / 2.5442 |
| 仅历史dropout0.1 | 2.9774 / 1.4206 | 4.2557 / 2.4489 | 4.1593 / 2.4715 |

重复拟合768样本使原配置明显过拟合；这不等于全量训练也按同样速度过拟合。它至少说明梯度和容量没有把loss机械锁在4，减小辅助或历史遮挡也没有消除本次probe的高误差。低LR对本阶段两种probe有小幅改善；12对batch配对bootstrap的总loss差值95%区间分别为[-0.0933,-0.0406]、[-0.0716,-0.0136]，但精确首槽准确率改善区间包含0，而且没有覆盖训练seed不确定性，不能包装成显著音乐质量提升。

五组128次更新均触发norm1裁剪。原配置裁剪前norm中位8.13、范围2.76–673.19，但动作头每次抽样更新的相对norm约6e-5–1.8e-4，且能快速拟合。频繁裁剪是应继续观测的风险信号，不能直接认为参数未更新；对Adam也不能把clip系数直接当成学习率折扣。没有无证据提高裁剪阈值。

## 缓存缺陷、修复与前轮数据更正

本机PyTorch为2.7.0+cu128。最小CUDA实测：普通AdamW更新后参数`_version`从0到2，fused AdamW从0到0，但两者参数值均已改变。`CompositionalActions.composed_weight()`原用版本号、device和dtype判断eval缓存有效性，训练前向虽重新计算，却没有清除先前缓存。

因此“eval建立缓存→fused训练更新→再次eval”会复用旧输出因子；恢复采样也会在多次调用间残留旧因子，虽然其历史嵌入仍使用新参数。修复为：模型切换训练/评估模式时清缓存，有梯度的合成权重查询也清缓存，兼容故意保持eval模式的无dropout优化。静态生成仍可复用缓存，不改权重、输入合同或损失公式，原模型可继续生成和resume。

三项回归在修复前全部失败、修复后通过，包含真实CUDA fused AdamW；普通权重更新缓存及原上下文测试仍通过。仓库未找到其他依赖参数`_version`的同类派生权重缓存。

前轮32样本/24步selected策略短微调也重新加载评分：总loss **5.451832→4.905069**，动作 **3.009469→2.692925**，选时 **1.588912→1.407875**，选时准确率仍 **0.5000→0.4375**。旧after总loss4.935296与动作2.719457受缓存影响，已被这次结果替代。此前固定权重生成对照没有中途更新权重，不受此缺陷影响。

## 接下来怎样训练

- **先保留辅助0.15、history dropout0.3、symbolic0.15和clip1。** 当前没有充分证据支持统一下调或拆分辅助头；主界面原“独立音频选位监督权重”也已改成准确的“音频辅助监督权重”，说明grounded中同时控制音频选位和动作两项。实验中的“仅动作辅助0.02”由scratch目标单独实现，不等同于把共用控件改成0.02。
- **当前v11优先试LR2e-5的短续训阶段。** 若只改LR、保持原数据/模型/损失合同，可显式resume并填新的学习率；旧父模型先保留，输出到新目录便于对照。LR是本轮比降辅助/遮挡更有证据的方向，仍需全量真实进展验证；不将它直接改成fresh默认值。
- **要同时试selected状态，仍选finetune和新目录。** 不与LR实验混合后单独归因；动机保持off，先单因素验证。没有自动重启20或80轮。
- **补足下一阶段验收。** 固定输入共同eval、分项动作/选时、首槽CE、真实更新/裁剪统计、固定音频双seed及试听/试玩应一起记录。生产训练当前没有独立验证集或自动早停，这是观测与模型选择上的不足；本轮并未把一个小probe伪装成已解决这一问题。

本轮证实并修复了缓存缺陷，也证实下降慢是真实现象。尚未确定整个全量平台的唯一根因，不能用一次局部bug或一个改权重后更小的数字宣称长期配置学习问题已解决。
