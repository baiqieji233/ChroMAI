# Composer 独立审查复核：BF16 注意力反向误差与历史记忆保护

日期：2026-10-26。修改前源码基准：`7363634`；实际模型：`chart_composer_v1 / audio_grounded_v3`。本文接续[退化根因调查](COMPOSER_INSTABILITY_ROOT_CAUSE_20261026_ZH.md)，优先于其中“保护尚未进入生产路径”的历史状态。机器可读结果见[本轮证据](../evidence/COMPOSER_SDPA_STABILITY_FIX_20261026.json)。

**审查最有价值的新发现已独立复现：本机 PyTorch 2.7.0+cu128 / RTX 5070 Ti Laptop GPU 的 BF16 融合注意力，在带 dropout 的反向传播中会产生错误的查询/键梯度。** 历史记忆异常放大与这个数值误差共同构成了已经验证的失稳通路。此前只比较 FP32/BF16 前向，不能排除反向算子问题；本轮补上了这项证据。

已实现两项有版本的保护：历史跨注意力局部使用 Math SDPA；历史编码器输出按事件限制 RMS。训练、恢复采样、生成共用同一模型实现，主工作台已有对应控件。旧检查点继续按旧策略解释，启用保护必须显式 finetune 到新目录。原检查点保留，正式长程任务仍停止。

## 1. 对独立报告的裁定

| 内容 | 复核结论与处理 |
| --- | --- |
| 历史编码器表示放大并高度同向，损坏配置条件 | 与上轮固定 probe、模块替换和短训干预一致；采纳历史记忆接口保护。高余弦只能说明近似同向，不能写成所有输入严格输出同一个常数。 |
| BF16 EFFICIENT_ATTENTION 的异常反向梯度 | 新增最小反例与真实模型复核后确认；采纳局部 Math 保护。未测试其他硬件，不能定性为 Blackwell 独有故障。 |
| FLASH 或 CUDNN 均可安全替代 | 不采纳。本轮强制 Flash 在该输入上没有可用内核；CUDNN 同样复现错误梯度。允许 Flash 和 Math 同时存在，不能证明实际用了 Flash。 |
| 100% 的退化来自一个模块 | 模块替换说明该模块足以严重损伤当前预测，但非线性模块存在交互，不能把全部历史错误分成互不重叠的百分比。 |
| 某一步跨越“吸引子分界线”，此后永远无法自愈 | 未证明。快照、有限日志和优化器矩不足以证明永久不可恢复，也不足以精确定位唯一触发更新。 |
| 负余弦对应 16.6σ，证明同一特征模 | 未建立独立随机向量等零假设；不作统计显著性结论。 |
| Padding 输出放大说明有效输入被污染 | 不能由此推出。padding 作为 key 已被遮罩；有效 tail 也不会取 padding。本轮将 masked 输出改成1000，旧路径所有可见输出仍完全相同。新策略在接口清零属于明确屏蔽无效记忆，不是证明旧 padding 泄漏。 |
| 直接启用现成 `self.norm`，从数学上保证所有层 RMS 永远在1–2 | 不采纳该保证。末端归一化不约束内部各层残差；带仿射参数的 LayerNorm 也无此固定上限。旧迁移模型的现存 `norm` 参数不能假定为未训练的单位变换。 |
| 同时给音频编码器归一化、关闭 attention dropout、修改 Adam betas | 暂不采用。局部修复已能处理被复现的问题；缺少支持这些额外改动的受控收益证据。 |

独立审查很好地提示了需要补做的反向数值验证，但其“100%”“永久”“彻底根治”等表述超出了证据范围。

## 2. 为什么这确实是数值误差

### 不依赖训练权重的最小反例

构造16个 query、head dimension 48、V 恒为2，attention dropout 为0.1。第一组 Q/K 使注意力在当前精度下恰好集中于一个 key。第二组只保留一个有效 key，Q/K 使用正常尺度随机数，不需要巨大激活。

对任意固定 dropout mask，单一有效 key 的 softmax 概率恒为1，输出与 Q/K 无关，所以 **Q/K 的真实导数必须为0**。不同后端的随机数消费可能不同，但不会改变这个判据，不能用“同种子必然同 dropout mask”代替证明。

| 输入 / 后端 | `||dQ||` | `||dK||` |
| --- | ---: | ---: |
| BF16，饱和单 key，EFFICIENT，dropout 0.1 | 3.078125 | 12.312500 |
| 同上，MATH | 0 | 0 |
| 同上，CUDNN | 2.665735 | 9.250000 |
| BF16，正常 Q/K，仅一个有效 key，EFFICIENT | 0.709423 | 0.655896 |
| 同上，MATH | 0 | 0 |
| FP32，饱和单 key，EFFICIENT / MATH | 0 | 0 |
| BF16，饱和单 key，dropout 0，EFFICIENT / MATH | 0 | 0 |

这证明错误不要求已经发生巨幅表示塌缩。较大的 K/V 和后续 Jacobian 可以进一步放大错误，但“梯度大”本身不是数值错误判据；这里的已知零导数才是。

### 舍入如何破坏抵消

对第一个反例，保留下来的行输出应为 `2 / 0.9 = 2.222222...`，保存为 BF16 后是 `2.21875`。令输出梯度为48维全1：

- dropout 修正后的 `dO·V / 0.9 = 106.666666...`；
- 使用已舍入输出计算的 `dO·O = 106.5`；
- softmax 反向中本应相消的两项残留约 `1/6`；
- 对16行、Q/K选中坐标32，预测 `||dQ|| ≈ sqrt(16) × 32 / sqrt(48) × (1/6) = 3.0792`，与实测 `3.078125` 相符。

固定版本的 [PyTorch 2.7 CUDA backward 源码](https://raw.githubusercontent.com/pytorch/pytorch/v2.7.0/aten/src/ATen/native/transformers/cuda/attention_backward.cu)中，delta 的外部分支对保存的输出转 FP32 后计算点积；低精度输出已经丢失的位数不能由转换恢复。[对应融合内核](https://raw.githubusercontent.com/pytorch/pytorch/v2.7.0/aten/src/ATen/native/transformers/cuda/mem_eff_attention/kernel_backward.h)也从保存的输出读取 delta 所需数据。这与本轮抵消误差的量级一致，不能推广为所有输入、硬件或后续 PyTorch 版本均有相同现象。

Math 路径保留 FP32 中间计算的行为依据 [PyTorch 2.7 SDPA 文档](https://docs.pytorch.org/docs/2.7/generated/torch.nn.functional.scaled_dot_product_attention.html)。本轮不升级依赖，也不把升级到某个未测试版本当成已验证修复。

## 3. 真实模型反向与性能检查

固定16,000检查点和12个真实 batch。为定位历史读取路径，关闭编码器及分组遮挡的随机性，保留历史跨注意力 dropout=0.1。各后端 dropout mask 不保证相同，因此表格是实际梯度范围的对照；上一节提供独立的错误判据。

| 路径 | 音频编码器梯度范数最大值 | 全模型梯度范数最大值 |
| --- | ---: | ---: |
| 旧路径 | 123.3150 | 187.6667 |
| 只保护历史跨注意力 | 3.5875 | 14.8142 |
| 只限制历史记忆 RMS | 3.2565 | 14.2827 |
| 两项保护同时启用 | 2.1151 | 14.0825 |
| 全局 Math（诊断对照，未采用） | 4.2151 | 15.0464 |

驻留32行固定 batch 的前向+反向10次计时中位数：旧路径74.85ms，仅局部 Math 72.80ms，两项保护75.35ms。当前尺寸下没有看到明显耗时恶化；这是模型计算短测，不含数据准备、优化器更新、保存和完整 epoch，不能承诺所有设备或批量均无额外开销。

与上轮保留 Adam/原样本顺序的6组实验合看，历史尺度失控确实会损害配置，限制其接口也确实能阻止测试区间的严重塌缩。本轮进一步确认融合反向误差是实际存在的放大通路；尚未证明它是此前所有 loss 平台的唯一原因。总 loss 仍是多个监督项之和，不能直接要求它像单项分类 CE 一样下降，也不能把退化解释成不可约底噪。

## 4. 实现及兼容边界

实现集中在 [stability.py](../../src/maichart/composer/stability.py) 和 [grounded_model.py](../../src/maichart/composer/grounded_model.py)，配置、检查点、训练 CLI 与主界面同步接入。

1. `history_memory_policy=rms_cap_v1`：对历史编码器每个事件输出向量计算 RMS，超过上限才缩小；小向量和方向保留。默认上限8，采用 FP32/峰值归一化计算避免平方溢出；零向量梯度也做了回归。用实际 padding/历史遮挡掩码清零无效记忆，保留全遮罩行的 dummy-key 数值保护。
2. `history_attention_policy=math_v1`：只在读取历史的 `MultiheadAttention` 调用内选择 Math，并禁止 Math 的低精度中间归约；退出或异常后恢复后端设置。保持原 attention dropout，其他注意力仍走原后端选择。CPU保持其正常实现。
3. 三个新字段写入模型配置、检查点检查、训练 runtime 和生成 `.composer.json`。没有新增学习参数、改变词表或增删 state-dict 权重键。
4. 旧字段缺省解释为 `unbounded_v1 / auto_v1 / 8`，旧行为不变。真实15,500模型与修改前完整 forward 对照：17个输出张量最大差0，259个梯度张量最大差0，loss同为3.280847；这次逐位对照范围是CPU FP32、8个真实样本。
5. fresh 的 `audio_grounded_v3` 自动选两项保护；其他架构自动沿用旧策略，不允许声明它们未实现的保护。已有模型的“自动”表示继承父策略，**不会自动升级旧模型**。
6. resume 锁定两项策略与 RMS 上限，CLI/API 同样拒绝改变。升级必须 finetune，新阶段重新初始化优化器，保留父模型。全局训练语义仍为v11，新增策略字段记录模型合同差异；旧代码若不认识新字段应拒绝读取，不能剥掉字段强行加载。

RMS上限只约束读出的历史记忆，不保证内部各层残差、投影后的K/V和整体网络永远有界；BF16转换也存在舍入。过小的上限会削弱有用历史。它不是证明长期训练不会退化的替代品。
