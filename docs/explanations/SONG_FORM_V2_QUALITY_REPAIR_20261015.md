## 2. 每项修改的证据、思路与目的

| 问题 / 证据 | 修改及目的 | 影响边界 |
| --- | --- | --- |

| 跨计算资源续接可重复使用原事件预算，重试时无本段事件还可能误用前段 history cutoff | 在所有 passes 中扣除已写事件，只有本段确有历史时才设置 continuation cutoff | 保持同一音乐区域和原有理数原点，避免重复生成和非法边界 |

| 音频查询缓存损坏重建时遗漏 `max_nodes` | 递归重建保留预算，增加损坏缓存回归 | 防止损坏后悄悄返回无限节点，破坏训练/生成一致性 |

| 97% 的混合格式准确率会掩盖一个关键数字错误或错误结束 | 新增完整 Fraction 字符串匹配、该续写时是否选 AT、该结束时是否选 EOS；另显示 Planner 预测/目标负荷均值 | 都是给定正确前缀的训练诊断，不是自由生成采音准确率；主 CE 不因新增指标改变 |
| 逐字符受限采样可能在错误分子后被迫延长分母 | 可选批量完整拍位 beam search：比较完整字符串的原始模型概率，附加可调分母复杂度成本；保留原生 Fraction | 默认搜索宽度 1，未将不确定的策略强制用于现有模型；2–8 可试验，无固定分母列表 |
| 模型主动 EOS 与代码搜索失败混在一起，WebUI 难以归因 | 新增 `form_rational_diagnostics`，记录空 EOS 段、搜索未完成段、最长间隔及大分母事件；记录初始 EOS/AT logit 差 | 大分母只是描述，不自动认定非法；长空白也可能是真实休止 |

## 3. 主 WebUI 与 CLI 的实际参数

训练 → 条件、正则化与规划学习：

- **续写与结束学习权重** / `--event-decision-loss-weight`：fresh/finetune 默认 0.25，0 关闭；在原 token CE 和关联目标外添加边界辅助项。旧检查点 resume 缺省为 0，检查后显示并锁定继承值。不能通过 resume 静默切换优化目标。
- 草稿指标增加完整分数匹配和两类事件决策；Planner 同时显示预测/目标负荷均值。总 loss 含辅助项时不能和旧数值直接横比。

生成 → 全曲规划与段落参考：

| WebUI 名称 | CLI | 默认 | 用途 / 代价 |
| --- | --- | --- | --- |
| 拍位简洁偏好 | `--position-complexity` | 0.2 | 对较复杂绝对分母和相邻间隔分母施加软成本；0 关闭，太大可能抑制合理特殊节奏 |
| 完整拍位搜索宽度 | `--position-beam-size` | 1 | 1 保留逐字符采样；2–8 用批量因果 KV 比较完整分数，增加计算量；搜索时拍位按完整概率选择，位置温度仍影响 AT/EOS |
| 过早结束抑制 | `--early-eos-penalty` | 0 | 可降低 EOS 相对 logit；不会填充显式休止，没有合法拍位时仍只允许结束；太大可能写得过密 |

这些参数均可由主页面传到 CLI，保存到 `.form.json` 的 effective settings。额外通过已有 condition JSON 传输，以兼容已运行的旧 WebUI 后端；显式 CLI 参数优先。当前 7860、7861 已确认无活动任务后重启，页面与检查模型 API 已加载新代码。

## 9. 音频尾部声明帧数不一致与 v2 显存预算

部分 MP3/VBR 文件的容器头声明帧数会略大于实际可解码帧数。原 waveform cache 和 rational audio reader 将一次读不到数据直接当作致命错误，表现为 `Audio ended before declared frame count`。现在这类明确的短读会回退到 librosa/audioread 的兼容解码路径，并继续使用受限窗口读取；真正的内存分配错误不会被吞掉或重复放大。指定上传文件已完成实际 memmap 构建验证。

song_form v1/v2 训练界面现在也显示 **CUDA 显存预算（GiB）**。0 使用总显存 60%，正数使用指定预算并封顶总显存 95%；它只控制训练进程的 CUDA 上限，不改变模型结构。v2 参数量建议优先按 `d_model → 层数 → dim_feedforward` 顺序小步增加，Planner 宽度单独调整；在 8 GB 显卡上可先试 `d_model=320、layers=6、dim_feedforward=1280、planner_width=160`，同时把 batch size 保持 2–4、梯度累积提高来维持有效批量。已有 checkpoint 的 resume 仍继承结构，不能通过该控件改变模型维度。

随后发现 PyTorch 对裸 `cuda` 设备调用显存比例接口会抛出 `Expected a torch.device with a specified index`。现已将其解析为当前默认 GPU ordinal；如果驱动不支持设置硬上限，则记录结构化 warning 并继续训练，不再在启动阶段崩溃。

准备缓存随后发现仍会因 `code_sha256` 变化把旧缓存全部判为 miss。现在迁移读取会忽略仅影响缓存实现的代码版本和绝对路径差异，仍严格比较谱面/音频哈希、运行时依赖、训练输入合同和配置；同时会查找同级数据集目录下的缓存根。当前已经开始的进程不会热加载此修改，下一次训练启动后生效。

2026-10-15 23:50 的再次审计发现 WebUI 还存在更直接的路径错误：`/api/form/train` 把 manifest 的基础缓存根错误传成了 `<cache>/audio`，导致准备缓存、Blueprint 缓存和 rational 查询缓存全部进入新目录，即使基础缓存已完整存在也会全 miss。现已改为直接传递 manifest 的基础缓存根；训练重新启动后会复用 `song_form_prepare/v1`、`blueprint_inputs/v1` 和 `rational_audio_queries_v1` 的已有内容。
