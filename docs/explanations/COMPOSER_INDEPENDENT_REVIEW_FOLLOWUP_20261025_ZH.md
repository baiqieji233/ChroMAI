本轮核对用户提供的十项审查，以当前源码和实际运行记录为准。起点为提交`b9bbe0f`。两名Sol配置子代理分别核查采样/守卫与数据/模型，主代理复核并完成入口、兼容性和回归验证。

## 1. 十项审查的核实结果

| 审查项 | 核实与处理 |
| --- | --- |
| 1. 正温度保留宏概率、零温度不连续 | 行为成立，现有实现和说明有意保留区间/类别质量。`T→0+`仍按宏概率抽样，`T=0`取联合argmax。建议的`max(T,0.7)`仍有同样的不连续，不能称为数学修复。桶间温度与截断属于待对照的策略选择，本轮不改默认。 |
| 2. 三类hard默认report、before重复分析 | 默认模式与实际hard未拦截的事实成立；最终报告已区分`remaining_hard`和`remaining_actionable_hard`，主界面也显示全部hard，不能称为未报告。收紧默认策略需评估误拦截。重复before的外层分析已做安全缓存；底层原生分析原本就有LRU。 |
| 3. 字符扫描污染历史锚定 | **确定的实现问题，已修复并保持旧模型兼容。** 中心TouchHold会读取时值数字，C/Cf回退4。内圈Touch共享粗角度不等于类型/环区消失；这些仍由原始embedding及结构因子表示。紧凑双押的完整头集合原本也在结构因子中，问题是粗角度锚只取首头。 |
| 4. relative_logits在slot0无跨拍关系 | 源码事实成立；该模块当前用于同拍前缀，跨拍还通过`action_relation`、历史与head_timing建模。增加跨拍旋转等变项是架构实验，不能只凭调用范围认定走位坍缩的直接根因。本轮未改。 |
| 5. enrich_head_timing未接入 | 未调用成立，但直接接入会改变99维输入的含义。原特征另有seen标记，近期按键不等同于从未按过；没有证据证明旧表示完全不能学习冷却。未自动改变已有权重的特征解释。 |
| 6. 音频锚分支含相对候选时间 | 成立，它是没有完整符号历史的条件候选分支，仍依赖上次事件时刻和候选查询。应注意命名/反事实实验边界；删除这些特征属于架构与数据契约变更。 |
| 7. ledger在远候选上衰减 | 符合“尚未新增事件时，候选过去窗口内已提交了多少事件”的因果定义。训练和生成使用同一定义。可能影响模型偏好，但尚未证明是错误标签或直接导致空拍，不改公式。 |
| 8. 无独立歌曲验证闭环 | 成立，是重要的后续工作。当前权重已看过全量训练曲，事后从中抽50首不能称未见歌曲验证；应使用新曲，或在下一次训练前按曲目/音频身份连同各难度一起划分。不能据缺乏验证就判定已过拟合、辅助头首轮饱和。 |
| 9. RAM、缓存键、默认配置 | `_song_tables`确实按谱面常驻，当前budget也不等于总RAM预算；但LensBank受已有context LRU管理，mmap逻辑字节不等于私有常驻RAM，系统Commit下降也不能全部归因本进程泄漏。**不能删除extent_key：它实际影响音频bank中的归一化拍位特征列。** 线程、worker和LR优劣需当前机器受控测量，本轮未覆盖用户正在运行的配置。 |
| 10. 合同频繁变化、基线未充分训练 | 运行管理上的担忧有价值。但合同变更并不强制随机重训，已有显式finetune路径。本轮用模型配置字段记录锚定策略，保持v11和旧模型续训资格，避免再次强制中断当前基线。 |

审查中的评分、“100%无损/精确复现机台”、“固定物量必对应某等级”、“辅助头首轮即饱和”等结论缺少相应覆盖或对照，未作为修改依据。`head CE≈1.43`也不能不区分类型、槽位和标签分布便直接与`ln(8)`比较并断言接近盲猜。

两份最新v10产出确实有空白和硬冲突，但它们使用step5000权重；此前v9对照是step13100的另一套权重。两份v10之间的种子、温度和Touch开关也不同。这些输出能提示症状，不能单独证明宏采样是空拍的唯一直接原因，更不能证明建议的新阈值能立即修好。

## 2. 历史角度锚定修复及兼容性

新增模型配置`history_anchor_policy`，无新增可学习参数：

- `legacy_digit_v1`：保留原字符扫描、回退和embedding运算，供已有模型兼容。
- `parsed_heads_v2`：使用项目解析器的真实音符头。中心C及中心TouchHold没有外圈角度，粗角度锚为零；不会读方括号中的分母/分子。B5/D3/E6保留5/3/6的粗角度，Touch类型与环区仍单独保留。`15`等多头使用所有头的平均角度embedding；词表缺对应普通Tap时该角度贡献零，不假定4号键。

旧checkpoint缺少字段时，加载器明确按legacy解释，不使用新配置默认值。新策略的派生buffer不进state_dict，结构因子的参数、映射身份和权重均不变；保存时会检查实际策略与model_config一致，防止错误标注。

| 入口 | 自动策略 |
| --- | --- |
| fresh | 使用parsed_heads_v2，可明确选择legacy作基线 |
| resume | 继承已有模型；请求改变策略会在数据准备前拒绝 |
| finetune | 默认继承已有模型；可显式选择parsed_heads_v2并写入新目录 |

CLI为`--history-anchor-policy auto/legacy_digit_v1/parsed_heads_v2`。主界面训练参数中新增“历史键位锚定”，resume会锁定，finetune允许明确选择；任务回显和生成报告记录实际策略。独立Composer页面仍弃用，本轮未修改。

使用真实、冻结的旧v11 checkpoint和两条真实输入，当前兼容路径与修改前源码对照：**17个输出张量及258组有梯度参数逐位一致，最大输出/梯度差均为0，仍可resume。** 这证明兼容路径未误改，不证明新策略已经改善音乐质量。新策略的效果需后续显式微调/新训练对照。

锚定策略属于模型行为配置；比较结果时应同时固定策略、权重、输入和程序版本，不能只看权重SHA-256。

## 3. 守卫前缀缓存

只缓存最近一次before分析的不可变摘要，after仍每次检测。缓存键包含有序active上下文、tempo、first、完整检测配置和TapOnSlide策略；commit清空。候选时间跨过active窗口边界，即使没有commit，也会使用不同键。

没有调整report/enforce、guided保护、同键间隔或冲突数量的定义。新增测试覆盖窗口、提交、配置/时钟变化、旧报告冲突、解析错误和拒绝事务。90次真实CPU事务对照的接受结果完全一致。底层原生分析原本有缓存，本轮不宣称整体生成获得显著提速。
