# 短段草稿与统一出音：维护说明

日期：2026-11-03。对应[已批准的方案](COMPOSER_BLOCK_DRAFT_AND_UNIFIED_TIMING_PLAN_20261103_ZH.md)。

## 这次要解决什么

以前的模型虽然逐颗预测音符，也有短句摘要，但摘要不等于一份可执行的安排。同一句里，具体写法仍容易每走一步就改变。休止判断还有另一种问题：音乐给出的出音率和短句编排倍率分别学习，最后相乘，一个分支可能把另一个分支的正确判断压掉。

这次保留流式写谱，把两件事落实到实际输出：先组织一小段，再按真实拍位读取；出音和休止由同一份最终概率决定。没有加入强制补音、最长空白限制或硬性复制模板。

草稿不是把未来官谱喂给模型。预测时只读音乐和已提交前文；真实未来配置只进入损失函数。草稿也不是先生成一张完整谱再照着输出，它提供随拍位变化的组织信息，具体动作仍由执行器结合真实占手状态决定。

首次全量启动还发现了两个小样本没有充分覆盖的问题，已在正式开训前再次处理：

1. 热状态缓存为了省内存丢弃原生索引后，草稿入口占用被错误填零。现在在释放大索引前保留很小的入口快照表，并计入原缓存预算。跨句候选使用“音乐边界＋实际可见截止点”查询，不读取尚未提交的未来Hold／Slide。冷、热缓存结果必须一致。
2. 训练为128个历史事件中许多没有监督的旧位置重复生成草稿。这些草稿不参与历史主干递推，删除它们不会删去历史理解。现在只规划有效时间决定和可信配置落点；同次前向的重复计划可共享梯度，但不同入口占用必须分开，训练更新之间不复用旧计算图。

用于发现上述问题的v49短暂全量任务已取消，目录和日志保留，不能作为本轮最终发布训练。最终fresh任务使用新的目录，见下方验收记录。

## 损失函数是否符合实际场景

### 时间：一次出音事实只算一次

候选目录会在当前拍位绕回，因此先按真实时间排序，积分后再还原候选编号。每个候选拥有一个不与邻居重复的时间单元。最终强度乘以单元秒数，得到该单元的风险量。

若第j个单元的风险量是h_j，则：

```
P(下一颗在j) = exp(-前面所有h之和) × (1-exp(-h_j))
P(整个窗口无事件) = exp(-所有h之和)
```

两者合计为1。NOTE训练目标是实际候选的负对数概率；WAIT或音频结尾的无事件使用尾概率。界面显示的“出音／等待损失”和“选时损失”只是这同一目标的分解，不再额外叠加一份Poisson计数或另一份休止BCE。

起始零拍音符拥有真实正宽度的首单元，PAD不占时间；恰好两拍后的合法音符仍在支持集内；真正音频结尾由调用方排除为NOTE，尾质量才对应EOS。用户明确编辑强度曲线时，曲线改变最终强度，然后重新导出出音、休止和落点概率。未编辑的模型曲线预览不再当作第二套命令重复干预。

这更接近“这段时间没写音，随后在这里写了一颗”的真实任务。但累计风险不等于整段预计音符数：每写一颗后历史都变了。因此日志改名为`occurrence_expected_hazard`，不拿它冒充全曲物量。

### 配置：一段共用选择，仍以真实谱为依据

每个真实短句有一个持续的写法选择。该句的时间决定与具体配置误差一起评价同一选择。出发句负责“等多久、选哪里”；真正落地的新句负责“在那里写什么”，避免跨句一颗音错误绑定两句的模式。

计算时保留原始目标权重、接缝重数校正和配置可信遮罩。有效预算明确分为“时间决定”和“可信NOTE配置”，WAIT不虚构一份空配置损失。只有一个模式时，公式严格退回原本加权的时间＋配置目标。

有序草稿的辅助权重为0.1，监督真实位置集合、持续信息和NOTE之间的顺序。其中，草稿的持续信息是同拍事件内的类型标记及最大拍长／秒长摘要，并不逐条还原每根Hold／Slide的生命周期；每个动作的精确时值仍由实际细节目标监督。它不再另算一份出音标签，也不把所有物理合法配置都当正确答案。旧摘要／未来关系辅助在新合同中关闭，避免同一信息被多个互不参与输出的头重复学习。

本轮末尾还发现一个实际错位：恢复前文已选定某个写法，原损失却仍可挑另一个模式解释后续。已承诺模式必须按实际模式计费，不能在训练里偷偷重新选优；尚未选择的真实官谱片段仍允许多种潜在解释。该字段只从已提交前缀取得，不能从待预测目标取得。

同类问题也出现在整曲选择：恢复采样的实际控制、短句先验和随后训练可能各自选了一次整曲分量。现在恢复开始前统一冻结选择和执行控制，并随恢复片段传入训练；不同前缀的冻结风格不会因为歌曲相同而被合并。后续权重更新也不能悄悄改写这段已生成前文的控制身份。

### 整曲风格：不再冒充精确联合训练

同一次训练前向中，每张谱共用一个选中的整曲分量，用它补全未知控制；普通训练下次再读该谱时可以重新抽取。生成与实际恢复前文则冻结已经选中的分量和控制，不随每颗音符重新选择。所有执行读出都使用这份相同控制。事件目标明确是“在实际选中分量条件下的学习”，不宣称一份前向同时算出了所有整曲分量的精确事件似然。

数值风格仍用全部分量的正规混合概率监督，每张谱计费一次，再加连续数值校准项。选择是按谱分组，不按音频分组；同曲不同难度谱不会被当作同一种写法。

### 仍然有边界

- 这是带长度平衡和辅助项的学习目标，总loss不是单颗音符的平均错误率，也不能和v48旧目标的数值直接比较。
- 单张真实谱仍只提供一种作者选择；没有新偏好模型证明另一种写法更好。未认证错误前文仍可能只训练时间，不能伪造具体配置答案。
- 草稿有4种选择，不代表已经学出了4种有意义的写法。短训中的模式差异和责任KL仍较小，需随正式训练跟踪；本轮不凭这个现象擅自降低责任温度。
- 整曲离散选择的先验目前主要由真实数值风格监督；事件误差训练所选条件下的执行器，不通过离散抽样直接教先验“哪一种整曲配置质量最好”。不能把它描述成已经完成的综合质量选优学习。
- 概率正确、梯度可用、loss下降，都不能替代实际审谱。完整配置的衔接、手顺、主动留白和长循环退出仍需生成后的独立质量验收。

## 效率方面做了什么

复用既有全曲音频编码，没有新增整曲编码器。训练在CPU打包唯一短句索引及损失分组，避免逐批GPU同步查唯一值；推理只构建最后实际决策的草稿，保留完整历史供主干读取。模式共用主干、细节递推和低秩读出，不运行4套大模型。

连续恢复原先还会先造出一整行，只为读取权重，然后再次构建候选状态。现在直接从既有源权重和重数取得同一预算，候选状态只在最终位置构建一次。稀疏草稿计算以真实模型核对了受监督输出、损失和全部参数梯度；历史主干隐藏状态逐位一致。

自动补全控制的可行域投影也改为预计算小矩阵、批量张量运算，避免每批把GPU结果拉回CPU做数值求解。草稿缓存只在无梯度推理期间复用，并绑定真实前缀；不跨训练更新缓存学习表示。

本轮没有执行固定音频双种子生成对照，没有据此宣布音乐质量改善。短训用于确认目标能学习、反向传播正常、实际恢复路径可运行；正式质量验收仍是下一项工作。

### 最终代码的测试结果

- 全项目Python：**4721通过、13跳过**；主界面JavaScript：**211通过**。
- 真实GPU短训：8首训练歌曲、4首独立验证歌曲，384宽度／8层、batch16×累积4、BF16、固定0.0005，共52次更新。验证每轮只取1批，因此不能视为完整开发集成绩。
- 训练loss由第1轮的10.386降到第17轮的5.113；验证loss由6.943下降到第8轮的5.954，随后回升到6.475。说明目标可学习，也说明小语料上的训练loss持续下降不能自动解释为泛化变好。
- 梯度均有限，更新跳过数为0；裁剪前最大梯度范数34.35，仍使用既有范数1的裁剪。第25次更新实际执行固定拍点恢复；第50次同时执行固定拍点恢复和8步自由选时续写。恢复结果并非都被当作配置金标签，未认证前文保留时间监督。
- 同一小样本配置下，删除无监督草稿计算后峰值已分配显存从约4.82GiB降到3.23GiB。实际全量吞吐另记，不能用这个数字替代全库性能验收。

### 正式任务

最终训练使用`checkpoints/prism_composer_v50`，主WebUI端口7861，任务`531908653435`；fresh、50轮、固定学习率0.0005，batch16×累积4。训练清单沿用v43中隔离好的2359张训练谱和57张验证谱，未重新划分或合并验证歌曲。初始化没有加载v48／v49权重。

v49是本轮发现热缓存入口错误后主动取消的试运行；v47、v48、v49的原目录及日志均保留。v48另有完整冻结副本。最终任务的最新消费窗口、恢复记录、实际日志路径见证据汇总（本地开发资料，不随源码发布）。

启动后已核实检查点配置为`beat_ordered_draft_v1`＋`unified_first_arrival_v5`，目标版本`stream_ordered_draft_first_arrival_v12`，没有resume或初始化父点。首轮前160批已执行40次更新，学习率0.0005、loss约9.362、最近裁剪前梯度范数约2.80、跳过更新0次。
