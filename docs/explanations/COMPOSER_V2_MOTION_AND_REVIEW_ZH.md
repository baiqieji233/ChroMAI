# 动作走向、候选选优与整谱评价

同样八个十六分，原地连打、两键交互和沿盘推进，听上去可以踩在同一串鼓点上，玩起来却是三个动作。重复的鼓型可以配稳定的交互，逐层展开的音色也可以用一次连续扫键表达。音乐相同，两个方案都可能成立。适合这段音乐、前后接得上、玩家愿意再玩一次，是三个需要分别检查的问题。

舞萌 DX 的按键与屏幕支持不同接触方式。双押要同时触到两个目标，Hold 有持续占用，Slide 有星头和滑行路径。ChroMAI 用这些可从谱面读取的事实描述动作。同一个轨迹可能换手，也可能单手完成，系统不指定手别。游戏操作依据见 [SEGA 官方玩法](https://maimai.sega.com/play/howto/)。

## 已有模型可以直接使用的改动

在「生成」选择「先定节奏，再选配置」，将「每次内部对比写法数」设为 **2**，「手感与选优偏好」选 **跟随音乐比较写法（默认）**。这是连续事件模型的推荐起点。更新前保存过个人设置的用户可以点「推荐稳妥写谱」套用。

每种写法仍经过任务所选的原生冲突检查。新评分比较已选音头附近的声学起音，以及同一候选中双押或 Break 音头相对普通音头是否落在更突出的瞬态上。均匀鼓点、整段同类音头和主动休止都允许出现。几个候选同样合适时保留第一个。移动距离本身没有加分或扣分。重音只是编排线索，某些长音或弱拍本来就值得强调，因此它在评分中只占小部分。

在一次真实生成的第 61.25 拍，用相同前文、八个拍点和原音频替换两拍内容，三个候选均通过原生检查。两列分数各自用于本列内比较。

| 八个音头 | 旧版省力评分 | 新版默认评分 |
| --- | ---: | ---: |
| 55555555 | 0.841 | 0.438 |
| 56565656 | 0.841 | 0.438 |
| 56781234 | 0.113 | 0.438 |

这里的平分有明确含义。三案没有额外重音，现有证据不足以挑出更贴歌的一案。原始生成使用单候选，连续交互已经来自主模型。将候选数设为 1 时，常规选优无法改变这类输出。

「参考模型预测的动作走向（实验）」在可完整比较的两拍里，额外比较候选动作与该处音乐预测的吻合程度。它使用本段预测相对于本曲平均预测的变化，平坦的预测没有偏好。旧版音乐写法模型可比较音符种类，动作与起手模型还可比较折返和路径。逐个事件比较时仍只比较当下音频。该实验需要带局部写法分支的检查点。

## 用少量标注练习从真实前文接回来

1. 在生成预览中找到“前面已经写偏，后面终于接得合适”的位置，带前文试听后圈出值得保留的后段。
2. 在「收集训练示范」选择学习内容。只认可键位和动作就选「只学配置」。连采音也认可时才勾相应项目。认可从前文跳到第一个音头的时机时，再勾「连同进入这段的第一步一起学」。把示范加入下次训练的素材。
3. 使用下节的实验训练策略和已启用的质量标注。对仅学习已确认片段的素材，训练窗口从用途发生变化的位置切开。模型看到真实生成的前文和仍在持续的动作，首次被确认的配置即可获得监督。未确认的音头只提供上下文。整谱点「好」用于评价，不会自动把整张送去训练。

只有写坏的前文、没有被认可的后续时，可以直接标「有问题」。这能记录失败，无法凭空提供正确的下一组动作。纯空白还不能独立导出成一张示范，可从覆盖前后音头的已确认片段学习留白。

## 新目录微调的实验策略

训练页选择「微调」，载入原检查点，指定新输出目录。「局部写法学习」选 **按音乐学习动作走向与起手（实验）**，**写法学习权重先用 0.05**。命令行对应 `--init-checkpoint`、`--future-configuration-policy audio_writing_v3`、`--future-configuration-weight 0.05`。旧检查点精确续训会继承原策略。已有 v3 检查点也可在新目录继续微调。新训练的「自动」维持稳定版。

- 按 0–2、2–4、4–8 拍从现有音频缓存和全曲记忆预测写法。每个区间保留前、后两组事件，区分原键连续、两步回原键、沿盘推进、折返、滑星形状和组合路径。真实的 Hold 或 Slide 释放后，记录随后第一个音头接向外键、星头还是 Touch。允许多种动作共存。
- 分别学习没有新音头、真正空闲，以及仍有长条或滑星占用。预测结果进入下一事件的整数拍选择。拍内分音和是否结束歌曲保留原决策通路。前方标签只参与训练损失，正常生成读取音频预测。
- 仅认可配置的示范可以教动作种类与走向。空白时长和持续动作的释放关系使用各自需要的审核范围。相邻查询复用区间统计，沿用普通样本原有的强度曲线练习。流式生成可以穿过任意拍号或分句。

## 用现有 WebUI 分三次验证

| 想知道什么 | 操作 | 看什么 |
| --- | --- | --- |
| 能从音乐选对写法吗 | 「生成」的「采音与选优评估」中勾选「对照音乐提示和真人写法」，选择留出清单，点「检查模型采音」 | 报告 `writing_probe.plan_brier`。同一检查点的 `local` 应优于同曲错位的 `other_music`，数值越低越好。两个策略的标签含义不同，跨策略比较其绝对误差易产生误读。 |
| 给出合适安排后能执行吗 | 同一次检查，使用相同的真实前文 | `writing_probe.execution` 单列配置和整数拍入口。比较正常预测、只在离线检查中给出真人提示、关闭提示三组的真实目标 token 平均负对数似然。只看有监督的决策。 |
| 玩家是否认可，失败有多频繁 | 在「谱面预览」清除选区，将「评价方面」留空，逐张点「好／有问题／不确定」。再到「采音与选优评估」填写批量目录里的 `batch.composer_v2_batch.json`，点「统计整谱评价」 | 同时列出计划数、整谱评好、有问题、不确定、失败、未评和待完成。片段称赞不会算作整谱好评。报告中的已确认好评比例以全部计划为分母。「可能好评比例」只是把尚未定论的版本全部算好时的上界。 |

实际选版本时，先固定待测曲目、拍网、定数、种子和候选预算，保留第一批的全部结果。小样本可优先比较“一处音乐变化”“一处应当保持”“一处收束”，连同前后文听，允许两种都合适、都不合适或无法判断。自生成前文与真人前文分开记录。最后比较各首歌的整批评价和未评张数。一个模型需要多次重抽才偶尔做好，与多数首抽就能用有实际区别。

## 本次有限验证

同一原检查点、同一批真实乐句，两种策略各微调 64 次，每组 88,327 个有效监督 token。留出的两首歌、三个短段使用相同种子，先让模型自己续写前文；两个版本的 25、48、23 个事件逐拍逐音完全相同。另一项按歌曲分散抽查的 20 段里，新版的本段预测误差为 0.20233，同曲错位为 0.20095。给真人提示后配置决策的平均损失从 0.537443 变为 0.537437，关闭提示为 0.537426。这次结果足以确认接线与旧模型兼容，还没有显示新方案提高了成谱质量。实验写法和依赖预测走向的选优均需主动选择。

真实 GPU 更新另做了交替顺序计时。预热后每组 48 次更新、66,275 个有效 token，旧版约 1,170 token/s，新版约 1,343 token/s。分别单独运行的 64 步对照，旧版约 1,321、新版约 894 token/s，峰值分别为 4.54、4.55 GiB。两种顺序的墙钟结论有差异，不能据此承诺长训提速。先在目标机器上用实际数据短测，再决定是否扩大微调。
