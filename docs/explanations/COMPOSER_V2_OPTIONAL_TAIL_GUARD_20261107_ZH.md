# Composer v2 可选撞尾门控

主界面 **Composer v2 生成** 新增：

- **拦截并清理Slide撞尾（可选）**：默认关闭，适用于已有检查点，无需重新训练。
- **撞尾检测阈值（ms）**：默认200，范围0—250，仅开启门控时影响结果。

沿用仓库内MiaCode Python判定器的 `TapOnSlide` 规则，覆盖普通Slide、Wifi及滑行路径上的提前触发。阈值是原判定器的静态参考范围，不是简单的“距尾部多少毫秒就删除”。原判定器区分硬无理与警告；警告保留，EX保护等原语义也保留。0关闭静态邻近参考，实际提前触发的运行时硬无理仍然检测。

此前v2创建守卫时固定为只报告TapOnSlide，共用守卫对静态参考也有额外排除。现在显式开启后执行硬撞尾拦截，回退重建、Hold修复和旧窗口路径都会保留开关与阈值。默认关闭的行为继续保留。

生成时先拒绝新增撞尾并尝试原有恢复。若“恢复仍失败时”允许带物理错误继续生成，导出前仍会清理残余硬撞尾：使用MiaCode给出的精确音符位置，只删除受影响子音符，保留同拍其他子音符并重新判定。不会把其他类别的冲突作为本功能的删除对象。无法安全清理的硬撞尾会明确报错，不静默导出。其他类别的冲突仍按原有策略处理。

CLI对应 `--intercept-tap-on-slide --tap-on-slide-threshold-ms 200`。API对应布尔值 `intercept_tap_on_slide` 与数值 `tap_on_slide_threshold_ms`。生成报告的 `tap_on_slide` 保存实际设置与删除记录。更新后需重启所用WebUI后台。
