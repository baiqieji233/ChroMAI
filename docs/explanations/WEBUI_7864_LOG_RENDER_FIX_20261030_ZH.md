# 7864 页面卡顿：2026-10-30

用户报告界面卡死时，7864 的首页、状态接口和任务接口均正常返回，响应约 0.15～0.40 秒。v27 训练仍在第 2 轮推进，没有因页面卡顿停止。

代码中发现了足以造成明显卡顿的显示问题：任务接口每次返回约 4MB 数据，前端每 800ms 再次读取；其中 300 行日志已占约 2.2MB，最长一行有 27 万字符。日志有变化时，前端会整体替换文本、自动换行，再立即读取滚动高度。这会让浏览器反复排版巨量文本。后端限制了行数，却没有限制每行及总显示字节数；因此不是无限增长，也不能据此说训练服务死锁。

本轮仅修改静态界面，没有重启服务、停止训练或更改模型：

- 屏显日志总量不超过 64KiB，单行不超过 2KiB，优先保留最近内容，并明确提示截断。原始日志文件和完整下载入口保留。
- 先限制文本长度，再进行比较、筛选和排版；不解析巨型 JSON 日志。
- Composer 指标未变化时不重建卡片和趋势图。
- 训练任务前台轮询间隔改为 2 秒，后台为 8 秒；前台取消中的任务仍保持快速反馈。
- 去除活动任务的一次重复登记。

Node 界面测试 174 项通过，相关 Python 生命周期及日志测试 18 项通过。已通过 HTTP 核对 7864 正在提供修改后的两个脚本，训练任务 `ebcef846c1a8` 当时仍在运行，第 2 轮、1855 次更新。

浏览器自动连接组件缺少依赖；随后 Computer Use 因无法确认当前浏览器网址而终止，未继续操作窗口。因此没有浏览器性能记录，也未直接确认刷新后的视觉状态，不能声称已经证明这是唯一卡顿来源。现有页面需要按 Ctrl+F5 加载新脚本，刷新不会终止服务端训练。

当前运行的后端接口仍会返回原来的完整任务数据；本轮修复直接减少显示和刷新负担，没有为了缩小接口而重启持有训练任务的服务。若后续仍卡，应继续记录浏览器主线程耗时，评估单独的轻量状态接口，而不是先重启训练。
