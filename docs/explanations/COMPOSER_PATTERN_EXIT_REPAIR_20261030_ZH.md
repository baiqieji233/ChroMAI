# 连续配置与出口学习修复说明

日期：2026-10-30。对应 `chart_composer_v1 / event_set_stream_v1`。这是对 [v29 根因复查](COMPOSER_V29_REPETITION_ROOT_CAUSE_20261030_ZH.md) 的实现交接。

## 为什么还要改

v29 在真实谱面历史上已经能预测不少转折，但自己一旦写进某种循环，就容易继续相信这个循环。旧运动分支会给“继续旋转、返回上一键、留在原键”直接加分；恢复训练又长期围绕极少几个场景，甚至跳过原本要教的出口。上一轮的连续计数也没有识别 ABAB、配置模板、时值变化和进入休止。

本轮把修复放在学习和决策结构中：让模型看到更准确的连续状态，直接在时间、配置和休止决定中使用它；让恢复样本确实教到出口；让运动关系作为主预测的依据，避免另加一套强制延续的分数。

## 模型现在能看到什么

旧的前 8 维状态保持原顺序，继续描述同间距、同类型、纯 Touch、逐按钮不间断出现的次数和持续时间。新增 8 维为四对次数/时长：

- **同模板**：比如连续单 Tap、连续双押、连续某种相对几何的 Hold。模板与具体时值分开。
- **完整相同配置**：包含完整音符和时值，按同拍音符无序集合比较。
- **严格两步交替**：A、B、A、B，保留类型与具体配置差别。
- **重复的旋转关系**：描述连续几步是否遵循相同圆周运动关系，不分左右手。

所有状态从已经提交的完整前缀累计，之后才切历史窗口，超过 64 个事件不会自动忘掉循环起点。当前目标与未来音符只用于训练标签，不进入这些输入特征。

新版将这些状态直接交给三个决定：下一步是音符还是休止/结束、是否沿用上一拍间距、当前写什么配置。原有 Transformer、音乐银行和同拍细节解码继续使用，不新增大编码器或多分支搜索。

## 如何保留正常流线

新版 `context_motion_v3` 保留 KEEP、REVERSE、STAY 的几何信息，将它们经过一个小投影送入主相位预测器。最终键位概率由主预测器结合音乐、历史和连续状态共同决定。旧策略中，主概率之外还会直接叠加一组运动分数；这条额外加分在新版中取消。

因此，模型仍可学习顺时针长流线或 1/8 交互，但不能再由一套独立输出奖励持续把它推回相同轨迹。WAIT、Touch 或不适用的配置之后，也不会把很久以前两个按钮的运动关系当成当前关系。

新投影零初始化，迁移时保留原有可复用权重；旧连续投影由 8 列扩展到 16 列，前 8 列复制，后 8 列为零。由于取消了额外运动加分并扩充训练目标，整个新阶段输出不可能逐位等于 v29，不能把“零初始化”说成全模型不变。旧检查点和旧策略完整保留，便于回退与对照。

`base_loss` 仍表示去掉额外转折项与恢复项后的联合训练损失，但本轮训练输入包含循环历史、权重也重新分配，因此它不等于旧模型在未扰动真实历史上的原始损失。跨版本比较应看未增广开发集分项和固定闭环生成，不能仅比较训练界面的总数。

## 恢复训练如何保证教到出口

每四个恢复槽中，三个使用新短场景，一个保留原来的持续自由轨迹。比例通过保存的游标跨调用维持，不是每次调用都重新抽到同一类。

短场景先选择官谱真实转折位置，取它前面一至两个音符，在原来的准确节拍上让模型自己选择配置。随后，在原转折到来时监督真实下一事件。生成时间没有前移，也不会先跨过出口、再倒退时间硬塞答案。如果新配置占用了目标位置，或原目标已不再可达，就跳过并记原因。长场景仍自由选择时间，只监督当前位置之后可达的事件。

WAIT/EOS 不含要写的配置，所以它们的额外出口损失只训练相应的休止或结束决定，不拿虚构的键位、形状和细节凑损失。

## 如何扩大循环历史覆盖

主批次默认尝试对约 15% 的样本做循环历史扰动，五种模式各占约五分之一。在监督块之前的 4–12 个连续音符上，同键、ABAB、纯 Touch、同配置这四种模式保留原时刻；第五种模式构造恒定间距历史，在不增删事件的前提下固定历史前边界和最终光标，选择词表可表达、时间上放得下的间距，同步重算每个事件的拍位、秒数和 delta。后续全部监督目标的内容、时刻和音乐保持不变；样本总权重保持不变，内部预算分配见下节。

这不是单独改几个输入张量。实现从真实事件重建音符编码、相位、占用和全部连续状态，并检查修改后的前缀和后续监督目标仍合法。不同样本使用独立种子，预取顺序和断点恢复不会改变消费批次的扰动内容。验证集不扰动。

“15%”是尝试比例，遇冲突会跳过，实际成功比例必须看日志。没有将恒定 `history_delta` 塞进不相符的 beat/second 中，也没有把已经不适用的原标签强行监督到任意历史上。

### 扰动后的第一步不能被后面 15 步稀释

一个短段监督 16 个决定，只有前面的决定直接接在构造的循环历史之后；后续已经逐步接回真实谱历史。如果 15% 的短段受扰动，但每个决定仍均分权重，直接学习应对循环的预算会被稀释到约 `15% / 16`。

最终版对成功扰动的样本做总量守恒的重分配：保留一半原权重分布，把另一半总权重加到首个有效监督决定。全部目标仍参与训练，每个样本权重总和不变，前缀零权重不变。首决定可以合法继续，也可以转出，没有规定它必须换配置。这样把学习预算实际用于模型刚面对循环历史时的选择，又不增加前向次数。

这套重建、筛选与首决定预算作为 `causal_window_config_time_first_decision_v3` 记录在训练参数和生成报告中，并进入数据指纹；先前实验的增广版本不能作为本版的精确续训来解释。

## 训练效率的处理

增广放在原有 CPU 预取生产者中，与 GPU 更新重叠，原行先取一次，只对成功替换的行做局部重建，最后只拼批一次。可靠的原生占用索引会找回仍活动的旧动作，因此配置模式不需要重放整首歌；一个早于当前窗口很久的长 Hold/Slide 也保留。缺少可靠索引或进行时间扰动时，用完整重放保证正确性，并单列时间重放开销。

第一次真实短训发现逐点反复编译整个原生物理窗口使开销接近翻倍。最终版保留逐事件的语法、时长、音频边界和重复头检查，将原生冲突检测合并为整个增广与目标窗口的前后两次检查；全部目标和活动旧动作仍在检查范围内，不裁掉长 Hold 或后面的目标。这是训练样本筛选，完整监督窗口可以用来确认标签是否仍适用；模型的每个输入状态依然只含当时已提交的前缀。生成端的 EventGuard 规则没有修改。简单 Touch 候选表也改为缓存。

模板与圆周关系解析使用缓存。仍保留 16 步并行监督、共享音乐银行和固定历史块。真实新增开销由最终短训对照给出，不将“没有增加 GPU 前向次数”等同于“零开销”。

由此，值得优先验证两项训练方案：完整新架构的 fresh（采用该路线原有 fresh 学习率0.0002）与保留旧权重、仅加快新增分支学习的迁移方案。前者可以消除旧权重路径偏好，后者可能保留已有局部能力；两者尚无成熟等预算对照，不能保证任意 fresh 都会解决。原损失仍以真实下一事件为主，曲段选择与结束是否合适也需闭环验证。不要将600步工程短训当成新模型成熟质量验收，也不要同时随意改变全部损失权重来追求更低数字。本次复核未更改参数或另启 fresh。
