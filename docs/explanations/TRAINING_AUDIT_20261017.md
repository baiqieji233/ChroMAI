## 已确认的问题及处理

1. **后台预取几乎不再等待，但主线程仍反复检查整批浮点张量。** 原 `train.py` 每个 batch 在 `next(iterator)` 后执行 `validate_cpu_batch`，验证通过 PyTorch CPU `isfinite`/归约调用线程池。暂停前 epoch 2/batch 4604 的日志累计 data_wait=354.746 秒，而预取器 consumer_wait=0.439 秒；两者差额不是磁盘等待，包含主线程验证和统计。将验证移到 spawn-safe 的训练 collator，使用 NumPy CPU 检查；后台预取和 DataLoader worker 均在交付 batch 前检查。没有取消非有限值和未来配置泄漏检查，额外补上 token 范围检查，避免关闭 model.validate_inputs 后非法索引直达 CUDA。
2. **各个输入分支单独补齐，再拼起来进入全部 Encoder 层。** 短音频、历史空位、没有修订稿的 draft 行仍为这些 masked query 计算 attention/FFN。本轮在 CPU 根据输入 mask 产生 gather 索引，在原始分支位置、branch embedding、精确拍位 geometry 已加入后，移除 padding。三个全局 token 保持最后，relation head 仍读取原来的关系 token。所有可见音频/历史/持续状态/曲线都保留，顺序和信息没有截断。训练默认 compact，CLI `--attention-padding dense`、WebUI“注意力补齐处理→保留空位（对照）”可回退。生成默认路径和 checkpoint shape 不变。
3. **辅助损失对遮罩位置处理不完整。** 数值节奏损失先计算 Smooth-L1 再乘 mask；多样性损失也先把整个 hidden 求和乘零。被忽略位置出现 NaN/Inf 时，0×NaN 仍能污染损失和梯度。改为损失前 masked_fill；有效位置的错误仍会暴露。属于边界数值缺陷，尚无证据表明现有正式 checkpoint 曾触发；不能解释为既有模型已经损坏。
4. **重复惩罚辅助函数的负 logit 符号错误。** 负数除以惩罚系数会提升其分数，已改为负数乘、正数除。全仓调用检索确认当前正式训练/生成没有调用这个辅助采样函数；修复是防止后续复用踩坑，不是现有质量退化的归因。
5. **诊断与搬运有重复工作。** 总准确率与分任务指标各做一次完整 argmax，现复用并显式禁用诊断梯度；Planner 密度均值由动态 masked_select 改为固定形状 masked_fill 归约；Layout 不再搬运只用于 CPU 构造标签/geometry 的时间戳与重复 padding mask。
6. **字符正确率不能显示整个配置到底有多少写对。** 增加草稿/修订的完整配置匹配率：一个事件所有 N 字符和 END 都正确才算通过。沿用独立计数聚合，日志与主 WebUI 同时显示。它依然是 teacher-forced 指标，不能作为自由生成可玩率。

## 静态审查未发现故障的主要路径

- 布局输入中 draft/right 对 task=0 禁止；解码 causal mask 明确；几何状态仅在完整拍位提交后公开坐标。此次未发现新增目标泄漏路径。
- 梯度累积按实际样本数归一化，尾批参与；checkpoint 只在完整更新后保存；采样游标与随机状态恢复。新增 compact 不改变模型/优化器形状和数据合同。
- Planner 与布局共用同一有理音频查询合同；音频位置辅助只在 draft 计算，标注只进入损失，不作为编码输入。
- 既有 CUDA 闲置缓存保护保留；本轮不再把所有慢速都归因于缓存。数据时间也不等同磁盘读取时间。
- 样本扰动按样本/epoch 独立随机，不将第一次扰动缓存下来固定重放；同源准备串行，不复制整套驻留音频。

## 质量风险：不是已证实的代码错误

- **仍未充分训练。** 暂停前日志为 epoch 2，草稿音符字符准确率约 64.1%、首音符约 28.4%、完整 Fraction 约 61.0%，修订字符约 80.5%。相对容易的修订任务不能代表从零生成已成熟。这里只是日志观察，不能从这些数字推导最终音乐质量。
- **正确前缀与自由生成历史差异。** 训练以官谱前缀为主；轻度 Tap 扰动不能覆盖错误长 Slide、错误节奏骨架和错误 EOS。不能随意把错误前缀接原谱答案当修复监督。未来值得做有限、可验证且重新匹配后续目标的改稿样本；暂不贸然改当前损失。
- **没有直接可玩性目标。** 持续动作信息和原谱模仿提供学习条件，但没有对双手占用冲突直接反传。应先用可微的有限占用目标或经过检测的局部反例训练，避免奖励投机和误杀技巧配置；完整人体模拟暂不采用。
- **曲线来自官谱，推理曲线来自 Planner。** 当前曲线噪声只近似预测误差。旧“曲线整点置零”会混淆缺失与低负荷；WebUI 已明确提示不建议，当前任务该项为 0。因已有参数明确声明置零，本轮不静默改变老训练语义。后续如加入“遮蔽曲线信息”，应另建明确的 mask 语义。
- **配置重构不等同审美改稿。** 现有修订是 30% 配置遮罩恢复（部分干净稿），可学复原但没有更好手感的偏好奖励。不能宣称它会自动把平庸配置改好。
- **固定学习率与重复模式。** 当前学习率固定，未发现调度器漏接。后期是否需要衰减应依据草稿指标/固定歌曲比较决定，不能以训练轮数直接保证质量。没有擅自提高多样性损失或反复惩罚重复：合理副歌呼应也属于重复。
- **有限历史与 Motif 检出。** 最近历史按 token 预算截断，远程呼应依赖真实音频关系；没有关系不能凭空补模板。保留全部历史会增加平方级 attention 开销，本轮优先移除 padding，不缩小语义记忆。

## 兼容与使用

- 正式训练保持暂停。后续可直接 resume 原断点；数据缓存不应因本次操作重建。
- compact 仅改变 masked 空位的计算，不新增权重或改变 loss。但 attention 浮点归约以及 Dropout 随机数的分配可能变化，因此不声称与旧 dense 训练逐位相同。需要执行级对照时选 dense。
- 主界面新增“注意力补齐处理”；默认压紧空位，可在 resume 时调整。服务端需要加载更新后的代码，页面也需刷新；测试结果区记录实际服务处理。
- 新日志显示当前 batch 的 dense→packed token 长度。这是 Encoder 长度，不能当作谱面 token 被删去。
- 没有开启正式长训练，没有变更用户 batch、梯度累积、历史上限、模型维度、损失权重、精度或全曲训练集。
