# 缓存审查与训练恢复记录

## 结论与已确认原因

本轮慢速主要是缓存读取实现问题，不能归因于模型变大、正常冷启动或 GPU 计算。用户已授权必要时停止训练并通过 7860 恢复；旧训练在数据准备阶段被停止，没有覆盖任何旧 checkpoint。

1. **WebUI 传错缓存根。** 未显式提供 `cache_dir` 时，`/api/form/train` 将 manifest 的 `E:\全量官谱\cache` 转成了 `E:\全量官谱\cache\audio`。FormDataset 的准备、Blueprint、rational 查询缓存都随之进入另一套目录。现在传递基础根目录，并有 API 回归检查。
2. **迁移查找为 O(谱面数 × 索引数)。** 每个 miss 都扫描数千个大 JSON；旧目录约 2895 份索引，合计约 608 MiB。之前单次迁移查询曾实测 15–24 秒。现在只构建一次内存索引，存储匹配键和文件路径，不保留数百 MiB 的解析结果；命中后建立当前稳定键，下次直接读取。
3. **缓存身份不稳定。** 路径和整个实现文件 hash 参与缓存命中，缓存锁、日志等改动也会失效。现在使用内容/输入合同和显式语义版本作为键。音频、谱面、结构文件、权重、first/BPM、曲线、特征策略、窗口与 token 设置仍决定复用资格。`semantics` 变更必须升级版本，旧无版本条目只映射到已知 v1，不能自动映射未来语义。
4. **跨目录查找层级错误。** 几处代码枚举了数据集内部子目录，没能找到同级数据集。现在共用有界、进程内缓存的根发现逻辑，覆盖基础目录、历史 `/audio` 子目录、同级数据集和共享目录，并跳过无访问权限的系统目录。
5. **每次新进程重复读取全部源文件计算 SHA256。** 本次源文件完整散列量约 11.3 GB。新增 `source_digests.sqlite3`：文件身份、时间戳和首/中/尾样本一致时复用完整哈希；变化后重新完整计算。该索引用于本地缓存加速，不宣称是对抗篡改校验。SQLite 写入失败时退化到完整计算，不改变训练答案。
6. **Blueprint 与音频缓存复用不完整。** Blueprint 也受绝对路径/代码 hash 影响，迁移临时文件还曾使用固定名称。现在校验所有迁移张量、使用唯一临时文件、按稳定键发布；扫描 Blueprint 索引时使用 mmap，避免先完整加载每份张量。音频特征键按内容哈希组织，兼容旧路径键；读取旧缓存后重新绑定当前源路径，resident 预检与实际加载使用相同候选。
7. **波形迁移存在并发竞态。** 迁移与新建现在共用同目录锁，使用独立不可变数组和唯一临时索引。不会替换已经被其他 worker 映射的波形文件，也不会因多线程同时迁移得到不同半成品。
8. **标注查找与内存预检额外开销。** 标注使用按来源/难度建立的候选索引，但始终保留谱面和音频哈希校验。resident 预算估算改为读取 NPZ 内 NPY 头信息，避免先解压全数据、随后加载时再解压一次；这项优化适用于下一次预加载，当前任务已完成原预检，未为此再次重启。
