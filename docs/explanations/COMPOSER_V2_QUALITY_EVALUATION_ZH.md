# 采音与候选选优评估

这些工具用于查清模型在哪里判断失误，不会改写谱面、调整训练权重或启动训练。它们保留正常舍音、休止、混合分音和合理重复；与某张参考谱相似，不等于音乐性更好。

主界面入口在「生成谱面 → 高级生成设置 → 采音与选优评估」。选择当前模型，填好音频特征缓存后，点击「检查模型采音」；结果进入现有任务区，报告可下载。评估清单留空时，只查找当前模型目录的`data_split/dev_manifest.json`，不会拿训练集代替。

| 控件 | 默认值 | 含义 |
| --- | --- | --- |
| 评估谱面数 | 2 | 读取前2张可用谱面；0全部 |
| 抽查片段数 | 8 | 从所选谱面的计算切片中抽查；0全部 |
| 独立选时检查数 | 2 | 额外检查模型能否自己选对下一个完整时刻；0跳过 |
| CPU计算线程 | 2 | 评估固定使用CPU，不占用训练GPU |
| 抽查位置 | 均匀覆盖全曲 | 确定性覆盖所选谱面；也可只检查开头 |
| 检查与原训练集是否重叠 | 关闭 | 开启后核查同模型目录的训练清单，会额外读取音频；不改变数据划分 |

「分析候选选优」读取已有的候选记录，不会再生成谱面。两项检查都可在任务区取消；默认预算只是小规模诊断，不代表全部歌曲。

## 检查采音判断

在已安装项目依赖的终端运行。评估默认只用CPU和已有音频特征，不会重新提取MERT或改变验证集。

```powershell
python -m maichart.composer_v2.evaluate teacher-forced --checkpoint checkpoints/你的模型/composer_v2_inference.pt --manifest checkpoints/你的模型/data_split/dev_manifest.json --cache-dir cache/chart_composer_v2 --limit-charts 1 --max-batches 8 --timing-rollouts 2 --output .scratch/eval/timing.json
```

默认在所选谱面上均匀抽取计算切片，覆盖开头和后段。`--limit-charts 0 --max-batches 0`评估全部；`--window-sampling prefix`只检查前面的切片。先用小预算确认路径、缓存和谱面都正确，再扩大范围。模型宽度与原检查点保持一致，不修改训练配置。

报告分开记录：

- **真实前文上的预测**：时间token、相位token的NLL和准确率。相位准确率给定了真实整数拍，不能代替完整选时正确率。
- **独立选择下一时刻**：`--timing-rollouts`默认为2；0跳过，正数指定额外检查的样本数。只给真实过去，让时间头自己选到整数拍和相位，报告漏过入口、提前出音、提前结束及秒级误差。
- **混合分音证据**：落点相位与相邻间隔分别统计。整拍、半拍属于共用位置；16/24混用不作惩罚。

重复提供`--training-manifest`可检查与这些训练清单的歌曲重叠。未核对所有父模型的训练范围时，报告仍不宣称模型从未见过这些歌。小预算结果也不代表整个验证集。

## 对照已有谱面

```powershell
python -m maichart.composer_v2.evaluate compare --reference "参考/maidata.txt" --generated "版本A/maidata.txt" --generated "版本B/maidata.txt" --difficulty 5 --duration-sec 150 --output .scratch/eval/comparison.json
```

双方各用自己的BPM、变速表和首拍偏移换算成真实秒数。报告包含10ms与25ms容差下的一对一落点匹配、每2秒的事件率与实际音符物量、开头/结尾空白和间隔、混合分音描述。区间边界附近的匹配可能跨箱，区间结果不一定能直接相加成整曲结果。

如需额外查看声学支持，加入`--audio "歌曲/track.mp3" --cache-dir cache/chart_composer_v2`，只读取已有音频缓存；未提供时不会猜声学证据。未提供音频和时长时，时长取参考谱结束位置，不是音频长度。

多种子的方差只在音频、模型哈希、条件、采样参数和时间轴来源一致时统计。旧报告缺少完整来源信息时，会标记无法核实，而不是把不同参数的版本混为稳定性对照。

## 检查候选为何被选中

主界面「生成谱面 → 高级生成设置」勾选**记录候选评估数据**。默认关闭；打开后不会改变选优公式，但会增加强制token的评分计算与报告体积。选择试写比较且至少尝试2种写法时，输出旁会产生`maidata.candidate_audit.jsonl`，保存全部候选池；常规生成报告仍只嵌入最近16池。逐步生成或只尝试1种写法时，没有试写候选池。

```powershell
python -m maichart.composer_v2.candidate_audit --input "输出/maidata.candidate_audit.jsonl" --output .scratch/eval/candidate_bias.json --markdown .scratch/eval/candidate_bias.md
```

每个token区分三种概率：模型在全词表上的概率、限制到合法语法后的概率，以及经过重试、温度、Top-p之后实际抽样的概率。强制采用的拍位和结束符也单独评分，不能假装其模型概率是1。跨过比较末尾的事件与EOS单独保存，不混入区间内的分数。

审计会比较实际选中项与同池其他完整候选的事件数、物量、编码长度、舒适度和声学支持，并计算几种只用于观察的排序。它们不会替换实际结果，也不把似然最高当作质量最好。固定拍长的候选统一除以拍数，不会消除少写偏好；固定事件数，也不能消除Slide与Tap编码长度的差别。

评估候选变化时，应同时检查遗漏、密度、配置与试听结果。先少写而降低错误数、降低温度而失去细节、统一分音而丢掉合理混用，都不能单独判定为改善。谱师和版本条件不参与这一轮评估或训练。
