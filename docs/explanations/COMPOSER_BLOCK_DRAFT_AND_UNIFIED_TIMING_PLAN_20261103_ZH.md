# Composer 修改方案：可调整的短段草稿与统一出音目标

日期：2026-11-03。状态：**方案已获批准，已实施并进入统一验收**。

实施与损失审查记录见 [本轮维护说明](COMPOSER_BLOCK_DRAFT_IMPLEMENTATION_20261103_ZH.md)。下文保留提出方案时的检查记录；其中“尚未实施”“不启动训练”等表述属于当时的权限范围。用户随后明确批准全量实施，并选择新目录 **fresh、50轮、固定学习率0.0005**，替代第11.2节的迁移训练建议。

本轮只读检查源码，与 Antigravity 进行了两轮咨询，并保存了完整回复。没有修改训练／生成代码，没有停止 v48，没有运行训练或生成实验。本文的参数是初版设计或试验起点，不是已验证的最佳默认值。

用户已确认：**默认采用可调整的短段草稿**。先组织一小段的节奏和主要动作，执行中允许因音乐变化、实际占手冲突而修改尚未提交的部分。默认仍为单分支生成；多候选是可选能力。

## 0. 目标与方案边界

希望模型能够先构思“这一小段怎样展开、怎样停顿、怎样接下一段”，再逐事件写出来。保留流式执行、原生持续动作状态和现有事件集合表示，不恢复整曲固定模板，也不规定主歌／副歌标签。

必须同时满足四点：

1. 写到一半仍知道自己原先想写什么，且能看见后面音乐和计划的衔接位置。
2. 正常主动留白与漏写后重新进入都能学习，不用补音、最大空白长度或重复惩罚替代学习。
3. 错误前文后优先选择有真实谱依据的保守续写；物理合法不能自动升级为优秀训练答案。
4. 不再逐样本重做整曲准备，不按模式数重复执行主干，不把新能力建立在指数增长的候选搜索上。

本轮会合入规划但不立即实施的工作如下：

| 编号 | 核心改动 | 地位 |
| --- | --- | --- |

## 1. 当前依据与需要纠正的推断

v48 的入口失败不是猜测：step 1000 与 1168 的同一开发入口在 16 拍观察窗口内持续 WAIT。step 1000 第 25 拍，基础音乐率给出的 NOTE 概率是 75.32%，加入编排倍率后是 46.65%。原始记录见 [v48 检查报告](COMPOSER_V48_TRAINING_AUDIT_20261103_ZH.md)。这是出音判断层的复现，不是整谱失败率。

源码还确认了 `_inherit_counterfactual_budget` 会把原窗口有效权重和转给一个目标。当前基准为 32 步、完整片段最大 64 事件，实际权重还含窗口平衡和重复目标校正。因此不能简单说“每次固定放大 16 倍”，更不能在未做分离实验前认定它是唯一根因。但将高能量休止的整窗预算集中到单次 WAIT，确实是应调整的训练选择。

当前 `W * softmin(mean_event_nll)` 有合理目的：防止长句使部署先验的学习份额过小。本方案不简单退回旧的原始总和。加强整句结构主要靠可执行的有序草稿与连续片段监督，温度调整只作为后续有限消融。

早期 `event_ctx` 的可取实现包括：带实际前文的局部有序目标序列、前后音频余量、跨窗口重叠与增量缓存。现有 `event_ctx_dataset.py` 和 `event_model.py:decode_step` 仍可核对这些实现。它们是可复用的工程经验；本轮没有证据把当时所有质量优势归因于其中单项。

## 2. P1：统一最终出音概率，消除独立倍率否决

### 2.1 一份实际出音分布

增加／重构一个最终时间读出接口，输入为当前音乐特征、完整可用控制、真实已提交 NOTE 的状态、当前草稿及候选时刻。最终只产生一套候选发生率或等价的首达概率。

`PhraseArrangementRate` 的独立整句倍率不再乘到另一套已经受计数监督的率上。草稿作为最终读出的输入，正向、负向作用都接受同一最终目标监督。初版不引入额外的倍率上限、强制 REST 开关或累计“欠音符数量”。

设同一未来查询窗口内，第 j 个候选代表不重叠时间单元，实际宽度为 Δt_j，最终非负率为 λ_j。定义：

```
hazard_j = 1 - exp(-λ_j × Δt_j)
P(下一事件在 j) = exp(-Σ[k<j] λ_k × Δt_k) × hazard_j
P(本窗口无事件) = exp(-Σ[j] λ_j × Δt_j)
```

全部候选质量与无事件尾质量之和必须为 1。候选密集区域不能因候选数量多而重复获得概率质量。具体时间宽度由真实时钟计算，包含变 BPM；以秒为单位积分，拍位仅用于音乐位置与输出。

第一颗恰在起点的事件需要明确的离散支持项，不把零宽度单元塞入积分，也不重复计算词表中的占位 0 与真实零拍候选。候选时间查询只能读取真实提交前缀；虚拟 WAIT 不更新一份额外的“越等越不出音”隐状态。

生成仍可先比较“出音总质量”和尾质量，再在出音条件下选择拍点，保持现有分层采样语义。不能把大量分散候选与单一 WAIT 直接做平面贪心，再把因此偏向 WAIT 误判为音乐留白。

WAIT 表示在当前窗口继续观察；只有到音频末尾的尾质量对应 EOS。窗口之外没有出音不等于歌曲结束。

### 2.2 损失只为同一到达事实计费一次

NOTE 的时间损失为目标候选的 `-log P(j)`；WAIT／末尾无事件使用尾质量的 `-log P(tail)`。它覆盖真实空隙与到达事件，配置继续在选定拍点后按现有事件集合概率监督。

若保留 kind/time 两个可见指标，它们只能是同一联合损失的分解，不能再叠加一份等价的出音 BCE 和局部 Poisson NLL。

连续时间对应形式是“真实空隙的条件强度积分减去到达点的对数强度”。这个概率合同有标准推导，参见 [Mei 与 Eisner 的原始论文，第 2、5 节](https://papers.nips.cc/paper/2017/file/6463c88460bd63bbe256e495c63aa40b-Paper.pdf)。这里采用其条件事件似然定义；不据此声称谱面质量已获验证。

最终率依赖历史时，冻结某个历史所得到的未来累计风险不能直接冒充整段未来事件数。训练按真实轨迹的相邻事件／无事件区间分别积分；相同区间被窗口或接缝重复读取时仍要校正重数。

全曲物量预览若仍需要辅助预测，可以保留为明确的统计任务，但其输出不再作为独立率重新否决实际落点。自动生成的预览曲线不能被模型重复当成额外真值。用户明确指定的曲线／物量要求则进入统一最终读出或同一个明确的概率变换；NOTE、WAIT 和具体拍点必须同步使用变换后的分布。

### 2.3 保留留白，恢复只面向未来

- 当前句已经错过的拍点过期，不补偿到后面的密度中。
- 后续音乐位置读取它自己的草稿与声学信息；一个入口出错不能把整句的后续入口一并降成低倍率。
- 不使用 WAIT 次数、虚拟解码步数或累计正赤字作为出音强制项。改变同一空隙的 WAIT 切分方式，不应改变同一绝对时刻的音乐判断。
- 仍允许真实 NOTE 历史、句内实际进度和持续占用参与编排；通过真实留白与漏写恢复的成对监督区分其用途。
- 不宣称这些结构条件能保证模型永不留错白，必须在实际部署路径验收。

着力点：`stream_model.py` 中 `_plan_at_cursor`、时间候选读取和 `stream_loss`；`stream_arrangement.py`；`stream_timing.py`；`stream_sampling.py`；`stream_generate.py` 的曲线接入；`stream_recovery.py` 的同分布采样。

## 3. P2：训练“进入—留白—重新进入”的连续片段

将 `_augment_authored_rest_row` 的单步替换升级为真实连续片段：休止前若干实际事件、真实休止区间、休止后的实际入口。长休止不裁成假的短休止；长度上限只控制打包，必须记录截尾，而非补写目标。

另构造对应的漏写版本：只删除已经发生的过去事件，保留后续仍可到达的真实拍点；不把错过的音符移到未来。两个版本都使用各自实际前文重建状态。

权重规则：

1. 原始样本保留既有谱面重要性、窗口平衡与重数校正；不一律覆盖成 1。
2. 每个受监督决定按其实际目标和观察区间计费，不让一个 WAIT 自动继承整段所有事件的权重。
3. 真实历史与错误历史的预算分开记录，明确混合系数和采样概率；高能量休止的抽样偏好需要记账。
4. 不通过增大总体恢复权重来替代正确的标签和预算。
5. 分别记录有声留白、句尾休止、休止后真实入口、漏写入口的概率误差与连续执行结果。

未来的分离实验至少比较“仅改片段／预算”“仅改最终时间目标”“两者一起改”，使用同一父权重和数据顺序。这个实验用于定位贡献，不提前把所有改善归给新架构。

着力点：`stream_augmentation.py`、`stream_data.py`、`stream_phrase_training.py`、`stream_train.py`。

## 4. P3：草稿具体表示什么

### 4.1 音乐拍位上的有序小计划

复用当前由音乐选出的 2、3、4、6、8 拍短句边界。内部以半拍为粗锚点，初版最多 16 个粗锚点；更长范围通过有状态的相邻短段连接，不截掉真实音符。这里不是“四拍必须是一小节”。

初始工程配置建议为宽度 96、两层轻量局部网络，沿用 4 个短句选择。每个选择产生整个短段的有序表示。模式代表随音乐与前文变化的一套神经输出，不给它预先贴“滑条流”“交互流”标签。

| 草稿内容 | 表达方式 | 应避免的丢失 |
| --- | --- | --- |
| 未来节奏与留白 | 对现有完整候选相位提供时间特征，并接入 P1 的唯一出音分布 | 不用四格二进制掩码替代 6／12／24 分 |
| 主体配置 | 原事件族、8 键集合、33 个 Touch 传感器集合 | 不把 Touch 清空；不把对称双押压成同一个圆心 |
| 槽内展开 | 每粗锚点有序的入口／出口微锚点；在真实事件拍位补充中间事件的顺序监督 | 同一半拍有 3 个以上事件时不能只保留首尾 |
| 持续动作 | 解析器给出的起点、终点、等待、持续区间与释放信息 | 不假设 Slide 永远等待一拍或短 Hold 必须对应音乐尾音 |
| 句尾与下一段接口 | 预计末尾配置、可用区域与持续动作延续意图 | 不把“计划已释放”写进真实物理状态 |

每个微锚点描述几何包络和动作意图。草稿粗锚点本身不会被直接输出成谱面拍点；具体出音仍使用现有合法绝对相位目录与精确时钟。因此粗网格不会制造五分音、异常大分母或删除合法三连音。

至少要区分 `1/5` 与 `2/6`，以及 `1→2→3→5` 与 `1→3→2→5`：前者反驳只用圆心，后者反驳只保存首尾和直方图。C 区 Touch、TouchHold 和复合动作也必须保留独立信息。

### 4.2 如何一次构思，逐步读取

句首读取：当前／后续音乐、已提交前文、实际持续状态、整曲选择和补全后的控制。轻量网络一次产生该短段的全部粗锚点与微锚点。

执行到拍位 b 时，按 b 读取当前锚点、局部微锚点与下一锚点的计划，结合实际候选时刻决定配置。拒绝或增删一个事件不会使草稿的后续下标整体偏移。

草稿可能给出“这一小段做对称展开，再收束”，执行器负责落实具体事件集合、路径、时值和修饰符。主要方向可保持，实际状态不允许的动作仍需修改。

着力点：在 `stream_phrase_model.py` 中复用音频／参考读取；新增一个明确职责的 `stream_draft.py`；在 `stream_phrase_training.py`、`stream_phrase.py` 中产生标签与索引；不另建一套整曲编码器。

## 5. P4：让模型真的学草稿并使用草稿

### 5.1 草稿必须进入实际执行

把当前静态模式偏置升级为随拍位变化的草稿条件，接入事件族／形状、键位相位及共享细节读出。训练各模式时共享主干和细节 GRU，只在低秩读出中计算模式差异，不为 4 个草稿各跑一遍大解码器。

共同趋势和模式差异继续分开参数化，保留 `centered_v2` 处理公共偏置漂移的意图。不能同时让新草稿、旧模式公共偏置和旧整句倍率重复表达同一控制。

### 5.2 只把真实草稿当标签

常规训练前向始终从因果输入预测草稿；执行器读取预测草稿，不把未来真实草稿直接塞给执行器。真实短句用于监督草稿和计算模式责任。

完整目标的基本形式：

```
E(短句, 模式) = 平均事件执行误差 + β × 平均有序草稿误差
L(短句) = -(W / D) × τ × logsumexp(log prior(mode) - E / τ)
```

W 是该短句的有效监督预算，D 是明确的批次预算。内部责任分布与外层目标使用相同 β、τ 和权重，避免再次出现后验和反传目标的系数不一致。

初版 τ=1，保留当前的长度平衡；先增加有序草稿的直接学习。β=0.1 可作为小样本试验起点，需按新草稿各组的归一化和实际梯度核实，不能直接相加旧辅助损失权重。只有明确观察到模式分工不足时，才进行 τ=1／0.5／0.25 的有限比较；不默认把“等效 4 事件”定成最优，更不直接恢复无限随句长累加的旧方案。

草稿时间内容已经通过最终到达分布学习，不再为同一时间标签叠加多份独立 NLL。草稿几何、顺序、持续动作的辅助预算替换旧摘要／关系辅助预算，并公开记录；它们不是另一个不参与生成的评分器。

### 5.3 加入短段执行与修稿训练

保留真实前文的完整短句学习，再加入有限的连续恢复段。每个恢复段从真正的提交状态起步，执行模型自身已经选择的动作后继续读取草稿，学习仍可到达的后续音乐与合法接续。

不能仅把孤立一步恢复的数量增多就称为整段学习。起步可用 4–8 个实际决定的短段，依据吞吐与失败类型增加长度；错误前文的配置标签按 P6 认证。

检验时比较预测草稿、关闭草稿，以及仅供离线诊断的真实草稿上限。真实草稿成功、预测草稿失败，说明规划器没学会；草稿正确而执行混乱，说明执行接口没有利用它；两者都失败，先查表示和目标，不开始全量训练。

着力点：`stream_phrase_execution.py`、`stream_model.py` 的事件／细节读出、`stream_recovery.py`、`stream_train.py`。主流程不新增读取未来答案的识别网络。

## 6. P5：把跨段呼应放进同一份草稿

将已经完成的历史短句编码成与新草稿同构的拍位序列。规划器在当前拍位读取参考段的对应结构，同时读取两段音乐的差异、实际段长和当前位置。

模型可以选择无参考、原样呼应、适用对象的旋转、保留节奏而改变几何，或局部改写。不能规定相似音乐必然照抄；默认不启用镜像增广。长度不同的句子携带真实拍距与跨度，不能仅按归一化位置就认定等价。

训练标签来自原谱中真实存在的对应关系。没有对应证据的参考不被伪造为正例；不把“以前自己重复过多次”当作参考质量证据。空参考分支始终可用。

该设计同时服务原创短句和历史变奏，复用现有最多数个已完成参考段；不再平行维护一个只用于统计呼应率、却不能指导实际执行的模块。

着力点：`OrderedPhraseContext`、已有历史归档与 `stream_draft.py`。保留历史顺序编码器和因果可见性限制，不能因删掉旧辅助损失而误删参考能力。

## 7. P6：保守但有用的错误前文续写

采用分级认证，不把所有物理合法事件都设成正确答案：

| 前文状态 | 允许监督什么 | 处理方式 |
| --- | --- | --- |
| 原始真实前文，或已恢复到可核对的原作接续状态 | 完整原谱配置和时间 | 保留最强、最稳定的原作监督 |
| 较早历史被扰动，但释放边界后的最近真实接缝被保留，原生持续状态与原作一致 | 接缝之后的真实短段 | 不要求整份 128 事件历史都等价；记录接缝见证与状态检查，扩大可靠恢复覆盖 |
| 已证明等价的旋转，且持续占用／路径／词表变换都成立 | 已验证的等价短段 | 对可靠候选集合做概率边缘化；不默认镜像 |
| 前文不完全等价，但某些动作属性在候选集合中一致 | 已证实的共同属性、时间、局部结构 | 仅对有证据的字段给标签，未知具体键位／路径不强训 |
| 无法认证，或原作续写与真实持续状态冲突 | 时间与可验证的状态／句法信息 | 保持配置遮罩；优先修正私有尾部、回到可认证边界，不造新金标签 |

“可验证属性”必须通过明确的候选等价关系或真实谱对应关系建立，不能因为音频相同就声称路径、时值一定相同。现有 `target_phase_mask` 只可表达认证相位集合，不能直接装入所有 guard 通过的相位。

启发式手顺代价可以排除明显别扭的候选、用于诊断或选优，但不单独决定训练正例。持续动作的真实原生状态优先于任何预测状态；不强行标左右手，也不把通过硬守卫等同于软手顺良好。

这比当前普遍关闭配置监督更细，但仍以保守可靠为先。只有证明某类恢复可以给可信标签，才扩大覆盖；普通物理合法的新写法不自动进入训练集。

着力点：`stream_target_correspondence.py`、`stream_augmentation.py`、`stream_recovery.py`、现有相位边缘化与原生物理校验。

## 8. P7：草稿、执行和撤回属于同一事务

区分三个对象：已提交真实事件、尚未提交的候选事件、尚未兑现的草稿。真实物理状态只由已提交／当前私有候选的实际事件建立，不能由计划中的 Hold 结束时间提前释放。

草稿缓存至少关联：检查点／模型版本、曲目与控制版本、短句范围、整曲／短句选择、真实前缀身份和草稿修订号。不能只使用事件数量或最后一个对象的内存地址代表全部前缀。

触发重规划的情形包括：跨音乐边界、实际持续状态使原草稿不可执行、经过确认的 Hold／Slide 编辑或撤回、用户明确改变控制。普通一次抽样失败不必重算整段；同一前缀与同一失败操作去重，仍保留总运行时间／资源预算，但不把“每句最多改一次”当成音乐规则。

撤回一处旧持续动作时，按影响范围处理：

1. 从可用快照重放实际事件，重建动作占用、物量计数、候选时刻状态与时钟。
2. 撤回受影响的短句进度、已完成参考归档和相关曲线状态。
3. 清除依赖该事件的未提交草稿及未来速率缓存，保留确实不受影响的部分。
4. 以新的真实状态重规划剩余部分；失败的候选不写回全局记忆。
5. 按既有用户授权，必要时可撤回此前的 Hold／Slide 并重新生成后续；不能只改谱面字符串而保留旧状态。

着力点：`stream_phrase_runtime.py`、`StreamInferenceContext`、`stream_proposal.py`、`stream_search.py`、恢复路径和检查点中相关状态的保存／重建。

## 9. P8：明确控制量的两个层次

核对源码发现：先验使用 `condition * known_mask`，主干和 `_condition_plan` 仍可读取完整 `batch['condition']`。这需要明确训练／部署合同，不能简单把所有读取替换为 masked 向量——未知字段变成 0 会破坏密度、Slide、Touch 等控制。

建议统一两个具名对象：

- `known_controls + known_mask`：只给整曲先验和补全器，未知真实统计不能泄入这一输入。
- `execution_controls`：显式指定字段保持原值，其他字段使用与生成时相同的预测补全。草稿、主干、时间、动作和持续特征读取同一份执行控制。

训练要包含实际的“仅给定难度”和“部分锁定”输入。未知真值用于风格损失和评分，不直接填回自动生成训练行。已有全部控制明确给定的模式继续支持。

为避免按整曲分量数重复跑主干，初版每张谱从因果先验选择一次执行控制并在该谱组内保持；整曲统计分布仍用全部分量计算自己的概率目标。不能让一份只按某个执行控制算出的事件似然冒充所有分量的精确似然。若采用共享控制的近似目标，须明确命名与记录；不能把先验加权均值、分量均值与真实生成选中分量混称为完全一致。

具体起步方式采用两类显式训练行：完整控制行保留已有的联合训练；部署模拟行按先验选定一个整曲分量，用其补全控制训练该分量下的短句执行目标。这两类损失分别记录，部署模拟行不冒充对所有整曲分量精确求和的似然。可从约 25% 的谱面组作为部署模拟行开始，在同一前向预算内替换部分条件训练行；后续比例由自动／手动两条开发路径的结果决定。这样先保住已有条件生成能力，同时实际训练自动补全后的执行路径。

这属于自动生成路径的训练对齐，不把“训练时观测真实控制”一概称为非法答案泄漏。

着力点：`stream_song_profile.py`、`stream_model.py`、`stream_generate.py`、`stream_recovery.py`、条件文件与 WebUI 传参。

## 10. P9：做减法与效率约束

### 10.1 替换清单

| 现有内容 | 计划处理 |
| --- | --- |
| 独立 `PhraseArrangementRate` 与部署乘法倍率 | 新合同中移除，由统一最终时间读出承担 |
| 四分箱短句直方图预测头 | 由有序草稿监督替换，旧统计可留作只读诊断 |
| 仅用于辅助的单向量短句预测／匹配读出 | 在草稿监督覆盖后移除重复头；保留参考序列编码器 |
| 仅用于辅助的未来两步关系头 | 将有价值的关系监督接到实际会被读取的草稿上，避免平行重复预测 |
| 静态模式细节偏置 | 改为读取草稿的动态低秩条件，保留公共／差异分离 |
| 共享动作构件、原生占用、真实音乐时钟、绝对相位目录 | 保留并复用 |
| 多候选选优 | 保持可选，默认 1；不将其作为模型学不会的遮盖层 |

细节向量归一化、dropout 等建议另列专项候选。读取当前实现、范数与实际验证后再决定；不因“多张 embedding 相加”就宣布是本轮唯一根因，也不把仍有作用的分支直接砍掉。

### 10.2 计算路径

- 音频仍每曲／每批复用一次编码；草稿只对批内唯一的短句起点和实际前缀计算一次。
- 同一曲目的不同扰动前缀不能错误共享草稿；训练不得跨优化器更新缓存带旧计算图的学习表示。
- 对每个有效事件只读取有限未来候选和局部草稿，不展开“所有历史位置 × 整曲音频”。支持 WAIT 的有效查询，但不为 padding 和无监督前导位置执行昂贵时间头。
- 模式维复用共享读出；避免 4 套主干、4 套细节 GRU。
- 标签由现有解析结果和短句索引生成，按谱缓存或映射；不逐样本重放整谱，不重建无关音频／BeatThis 缓存。
- 内存容量按最终 schema 实算。不能用“每句 64 字节、全库不足 2 MiB”的未经核对估算作保证。

工程目标：先争取正式吞吐退化不超过 10%，不将这个数字当成已实现的性能。比较相同消费样本／音频时长的真实训练窗口与完整轮次，报告数据等待、计算、预取等待、主机内存、显存及原谱事件／秒。新目标的计数口径改变时，不用虚增“监督目标数”宣称提速。

### 10.3 主 WebUI

普通生成区只增加必要的“短段组织：可调整草稿”状态／选项，沿用已有候选数量控件，默认单分支。报告显示实际启用策略、草稿修订和回退原因。

高级区按“短段规划”“错误前文恢复”“运行效率”分类，模式数、锚点宽度、责任温度等放在第二级研究设置中。默认采用检查点记录的合同，不让用户靠多个强度滑块修补未学好的模型。

新参数必须贯通主界面、API、CLI、模型配置、检查点检查和生成报告。旧检查点不能静默启用没有学过的草稿功能。训练、验证、恢复、普通生成与候选搜索要记录同一策略版本。

## 11. P10：实施顺序与统一验收

### 11.1 实施顺序

1. 写清新时间分布、草稿输入和样本预算合同，冻结对照点与数据清单。
2. 实现 P1/P2；建立一个明确版本的新目标，移除旧倍率的实际部署路径。
3. 实现 P3/P4/P5，共享草稿表示与执行接口，避免三套平行规划器。
4. 完成 P6/P7/P8，贯通真实状态、恢复、重规划及条件补全。
5. 完成 P9 的删减、缓存、主 WebUI 与元数据接线。
6. **全部基本修改完成后统一运行测试**，再进行有限的配对学习实验与真实吞吐验收。当前会话不执行这些步骤。

### 11.2 检查点与训练迁移

保留 v47、v48 和现有冻结点。新概率目标和新增计划表示不能假装是原合同直接 resume；在新目录创建新的学习阶段。

先从有保留价值的检查点迁移能对应的音乐、配置与持续动作权重。新读出的目标改变后，不承诺位级生成一致；可以在原模型表现正常的样本上用冻结教师分布做初始化对齐，明确排除已经定位的失败行为，避免把错误蒸馏回去。

初期可冻结复用的配置主体，让新时间接口与草稿先学会工作，再解冻共同适应。当前已明确的固定学习率 0.0005 不在本轮擅自改动；后续若采用分组学习率，需要在实施安排中明确。不能只降低学习率就宣布目标问题消失。

小样本建议覆盖 32–64 首代表曲目的不同手法，保持验证歌曲隔离。至少包含常规连打、连续双押、一划一拍、持续占手、Touch 混合、有声留白与真实三连音。先证明能学习并执行完整常规片段，再决定迁移训练还是全量 fresh；本方案不自动启动新的 50 轮任务。

### 11.3 验收项目

| 项目 | 必须检查的结果 |
| --- | --- |
| 时间概率 | 候选与尾质量和为 1；窗口切分、候选细化、变 BPM、末尾截尾、第一颗零拍音符处理正确 |
| 休止与恢复 | 同一 171 个内部休止、114 个真实入口、50 个漏写入口继续跟踪；修复已知索引 29 的失败，同时不压坏真实留白 |
| 草稿可辨认性 | 区分对称双押、Touch 位置与相同首尾但中间次序不同的片段；密集片段不丢中间事件 |
| 因果性 | 改未来真实谱面标签不影响草稿先验和出发点判断；动作头的比较必须固定同一候选拍位，不能要求合法的 teacher-forced 落点条件也消失 |
| 草稿确实被使用 | 预测草稿优于关闭草稿；正确参考有帮助；错误参考可被放弃；不能只凭不同模式输出不同噪声判成功 |
| 完整配置 | 连续自生成短段的顺序、接续、持续占用与句尾释放改善；教师前文 loss 下降不能单独过关 |
| 撤回事务 | Hold／Slide 编辑后，物理状态、计数、记忆、草稿、条件率缓存与重新从该前缀计算一致；私有分支不污染提交历史 |
| 自动条件 | 只给难度、部分锁定、完整条件文件均与实际推理一致；锁定字段不变，未知字段不伪装成零值 |
| 共享数据 | 没有扩大训练／验证重叠；缓存只失效真正改变的标签部分；不重建音频库 |
| 性能 | 新目标下采用相同原谱消费量计时；报告完整轮次和无并行诊断负载的对应区间 |

不能跨目标版本直接比较总 loss。另报告公共任务上的到达概率、配置概率、逐类错误与开发集结果；教师草稿或后验标签辅助的成绩单独标注。评估不以“模式互信息大于零”“硬冲突为零”替代实际手顺和音乐编排。

后续生成验收先使用开发探针、代表性短段和人工审谱；不自动重新启动此前取消的固定音频双随机种子对照。本轮没有运行任何新生成。
