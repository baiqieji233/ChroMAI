# 连续流异常空白与分音：定位、修复与实测（2026-10-17）

本轮针对最新实际产物 `webui_workspace/generated/742dc9e23537/maidata.txt`。没有覆盖原文件，没有使用 GPU，没有停止训练或 WebUI。旧 event/form 模型生成合同保持不变。

## 结论

这次不能归结为“只训练了一轮”，也不是旧 song_form 的音乐分段重新生效。产物对应 `checkpoints/Prism_stream_v1/stream_last.pt`；checkpoint 标记 epoch 30，对应训练日志最后平均 token loss 为 0.74628、token accuracy 为 0.73216。模型依然可能欠拟合或自由生成失稳，但确实存在独立于训练程度的生成缺陷。

原谱音频长 129.1755 秒，仅 35 个起音；日志结束原因是 `audio_range_exhausted`，没有 EOS，也没有计算上下文轮换。因此本次大空白不是分段 EOS 或跨块记忆问题导致。最大空白为 26.3307 秒，另有第 19 拍直接跳至第 100 拍，间隔约 26.26 秒。

## 确定问题与处理

### 1. 字符级数字选择破坏了完整拍位概率

从该 checkpoint 在原谱第 19 拍后的真实前缀，CPU 重新计算完整候选：

| 下一个拍位 | 整个候选的 log probability |
| --- | ---: |
| 20 | -1.16023 |
| 100 | -8.09540 |
| 39/2 | -3.72954 |

模型对 20 的完整概率约为 100 的 1028 倍，但原策略先选择第一位数字，再只在当前语法允许的下一位中重归一化，仍然生成了 100。被语法强制的低概率数字因此没有正确反映在整个候选排名里。

修复：stream 默认比较完整 Fraction（初始候选宽度 4）。累计原始全词表概率，再加明确的非负软代价；不使用长度平均掩盖额外数字的概率成本。逐字符模式保留为宽度 1 的可选兼容路径。

固定 beam 也不是充分修复：被早期丢掉的数字分支仍可能形成更好的完整拍位。加入概率上界审计，只有丢弃分支仍可能胜出时才自动扩大到 8 / 16 / 32。报告保留是否已证明搜索内最佳；最多 32 路，所以不声称穷举全部有理数。

搜索只接受训练时的规范 Fraction 拼写，且可达性检查也采用相同规范，避免先走进 `2/4` 这类训练中没有的写法后再追补。罕见的 `37/997` 在提高分母上限时仍可精确输出，未添加常见分音白名单。

### 2. 已训练的间隔头与字符解码相互矛盾，生成没有利用它

单独修复完整概率后仍出现长跳拍。在一项对照中，第 190 拍后完整候选 `1241/4` 获得 -4.751 的评分，略高于 192 的 -5.032，仍形成约 39 秒空白。与此同时，原已训练的辅助意图头给出的下一间隔约为 1.34 拍。字符分支与意图分支的矛盾不能靠增加候选数量完全解决。

新增“学得间隔引导强度”，默认 1。只把已有监督目标 `clip(delta, 0, 8)/8` 用于完整候选评分：

```text
cost = strength * 0.5 * (clip(candidate_delta, 0, 8)/8 - clip(predicted_interval, 0, 1))**2
```

最大代价为 `strength/2`，不会禁止长休止，不限制最大间隔，不按响度生成音符，也不会要求每个瞬态都有 note。第一起音不应用这个引导；强度 0 可关闭，宽度 1 不应用。它是利用已经存在的谱师间隔监督的推理改进，不是新训练目标，也不是“无空白”保证。

### 3. EOF 人为扩大分母

原末尾事件为 `31075/78` 拍，结束点另外近似到 `382463/960`，其拍差为 `97/12480`，编译成 `{49920}`。这一个超大分音由 EOF 选择制造，不是模型真的预测了分母 49920 的起音。

stream 的 `E` 改放在音频结束之后的下一个整数拍：本曲为 399。所有 note 拍位完全不变，E 不引入新的分母因子；额外尾部不足一个四分音符拍。这只处理终止符，不会把真实起音就近移到常见网格。

### 4. 训练块目标有重复，极端边界可能丢失 EOS

旧代码分别用“最后四分之一个计算块内最早的 AT”确定下块起点，用“整个块内最后的 AT”确定本块终点，两者可能重叠。纯 CPU 的 24 事件、64 token 上限夹具复现了 24 个重复目标 token；这会让部分事件被反复加权。末尾只剩单个 EOS 时又被 `end <= start+1` 跳过。

新实现一次性按完整事件与独立 EOS 单元划分半开区间，所有目标 token 恰好出现一次。单个事件过长时明确报错，不能偷偷从配置中间切开。事件索引用一次预计算替代每行重复扫描前缀，避免原来的二次扫描成本。

新训练语义标记为 `chart_stream_training_v2_contiguous_targets`，训练准备日志显示总目标数与 EOS 数，写入训练 args。权重结构和旧 checkpoint 的生成能力不变。已训练模型不会因源代码修改自动消除此前学到的偏差；后续训练使用修复后的样本。该项对现有权重音乐质量的影响幅度未测量。

### 5. 隐藏 EOS 惩罚与不完整结果展示

删除按剩余拍数自动增加、最多 8 logit 的隐藏 EOS 惩罚，改为 WebUI 显式“提前结束抑制”，默认 0。原输出没有 EOS，此项不是本次主要空白成因，但原规则可能强迫模型在结束位置继续写音并被位置边界挤出奇怪分数。

生成报告新增：最长间隔和具体秒数、拍位／间隔分母、最大导出分音、搜索候选及原始概率、EOS 与 AT 的原始分差、已生成事件进度。WebUI 将报告里的 incomplete 明确显示为警告，不能再把搜索失败当作正常音乐结束。

**更多起音、较小分母和较短空白不等于更好谱面。** 当前产出仍有大量四分节奏及可疑配置；完整搜索仍可能选择少量细分。不能用这次统计证明音频贴合、配置表达或可玩性已达标，也没有为了让数字好看强制所有分母为 2 的幂。
