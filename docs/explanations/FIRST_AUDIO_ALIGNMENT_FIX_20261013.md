# first、难度专属偏移与音频对齐修复

日期：2026-10-13。主模型 `song_form_v1` 与共享 Simai 解析/音频采样链路。

## 定义

谱面第 0 拍对应原音频的 `first` 秒。某拍的实际音频时间为：

```text
audio_second = first + 从第0拍开始按BPM/变BPM积分的时间
```

- `&first=0.5`：同一段谱面整体向后移动 0.5 秒；生成输入第 0 拍从原音频 0.5 秒取样。
- `&first=-1.82`：谱面时钟从原音频开始前 1.82 秒开始；负音频时间对应静音。
- `&first_5=0`：第 5 难度明确使用 0，不能因为值为零就退回全局 `&first`。
- 难度专属值优先，空值或未填写才使用全局值。两者是覆盖关系，不相加。
- 开头的 `{1},` 是额外的四拍休止。120 BPM 时四拍为 2 秒，第一枚 note 的时间还要加这 2 秒。代码不自动猜测或移除这段休止。

例如 120 BPM 的同一音频 1.0 秒起音：

| first | 对应的谱面拍位 | 原音频击打时间 |
| --- | --- | --- |
| 0 | 第 2 拍 | 1.0 秒 |
| 0.5 | 第 1 拍 | 1.0 秒 |
| -1 | 第 4 拍 | 1.0 秒 |

这说明重新生成时不是简单把原来的 note 文本再推迟一次：输入采样坐标与输出拍位同时按同一偏移转换，播放时再由 `&first` 恢复到原音频位置。

## 实际修复

### 难度专属字段

新增统一 `resolve_chart_first(chart, difficulty)`。精确 EventChart、旧 ChartIR/时序解析、统计、校验、CLI、质量预览/内容身份和 MiaCode maidata 读取都使用同一优先规则。

此前只读取全局 first，会令带 `first_难度` 的真实训练素材错位。现在 source bytes 没变也能在训练审计中看到 `first_override`，将修正后的对齐纳入原有数据合同。若旧模型在忽略难度专属值的实现下训练过同一批素材，修复后不应伪装成完全相同的数据继续 resume；需要 finetune 继承权重并使用新输出目录。

对没有难度专属覆盖值的素材，不新增这项审计字段。原有全局 first 模型权重和生成入口继续兼容。

### 音频采样

正偏移使第 0 拍采样原音频的对应位置；正偏移之前的音乐不会被折叠到第 0 帧。负偏移保留从负秒开始的时钟，音频不存在的部分填零。

前置静音的声学与派生节奏特征都为零；拍位、BPM、位置等时间上下文仍存在。短音频也能使用绝对值比音频长度更大的负偏移，不再因“必须落在 ±歌曲时长”被拒绝。

原音频文件不裁切、不重编码、不新增 WAV。虚拟时间映射等价于给模型输入裁去正偏移前的内容或在负偏移前增加静音，最终 maidata 与原音频配套使用。不会对原文件与 `&first` 各做一次实体平移而造成双重偏移。

### 曲线与休止

难度曲线此前混用了音频绝对秒和相对首拍秒，正 first 可能让曲线尾部被错误外推，负 first 可能让采音/休止指向错误位置。

新生成的曲线明确标记 `time_axis="audio_absolute_v2"`：点、休止区、编辑器时间轴与频谱都对应原音频绝对秒。规划器输出按它实际接收的音频帧时间发布，不再减 first 后铺到整首歌末尾。正 first 之前不可采的音频区不继承非零曲线预测。

旧模型内部仍按原来相对首拍的负荷 bin 约定取输入；进入配置模型前，使用 `audio_second = chart_relative_second + first` 从绝对曲线采样。保持模型形状、词表和旧训练标签，不为了修正界面时钟而随机改变权重的解释。

旧曲线缺少 time_axis 时按 `chart_relative_v1` 兼容，采音门控和休止会转换到同一轴。此前用非零 first 生成/人工编辑的旧曲线曾存在显示错位，建议重新预测，不把兼容读取宣称为恢复了当时所有编辑意图。

WebUI 保存曲线时现在保留 time_axis、四通道 components 和分辨率，避免保存后丢失时钟或退化为仅标量曲线。修改 first 后仍需重新预测曲线；仅改等级/风格时保留已有的提醒复用逻辑。CLI 也会拒绝保存曲线 first 与当前生成 first 不一致。

### 导出与诊断

生成的 `&first` 等于用户填写的数值；源谱修订使用其已解析的难度有效 first。变 BPM 下仍积分同一 tempo map，不把段落的第一拍重置为音频 0 秒。

报告新增 timing_alignment：第 0 拍音频秒数、虚拟前置静音、谱面开始前的音频长度、是否修改原音频，以及时间公式。检查点不需要重新训练才能使用修正后的生成链路。

## 操作

1. WebUI 填入已知 BPM 或明确 tempo map。
2. 在“首拍偏移 / 秒”填写与目标 `&first` 相同的正/负数。
3. 使用曲线时，修改 first 后重新生成并保存；时间轴仍是原音频秒数。
4. 生成后用原音频与输出 maidata 配套检查，无须人为再对音频文件加一次延迟。

当前正在进行的训练没有停止或改参数，已加载进程不会自动切换到新解析/生成代码。重启 WebUI 后新任务使用本轮修复。训练数据中的难度专属 first 若影响旧数据合同，应按上面的 finetune 说明迁移。

## 验证

- 131 项定向 Python 回归通过，包括 first_ 覆盖、负偏移、音频特征、精确事件与编译、曲线、起音、分音近似、训练/恢复、缓存和旧模型合同。
- 26 项 Node 参数/曲线状态测试通过，API 正负值透传与新曲线元数据保存通过。
- 120 BPM、first=0/+0.5/-1 的同一 1 秒脉冲输入，得到第 2/1/4 拍，导出回读后击打音频时间均为 1 秒。
- first=-1.82 前置 91 个 20 ms 静音帧，后续真实脉冲与变 BPM 时间积分一致；静音区仍有合法时钟上下文。
- 新曲线按正/负 first 的实际模型帧时间对齐；绝对曲线向旧输入 bin 的适配、旧相对曲线休止门控和 first_ 训练审计均有定向测试。
- 桌面浏览器确认首拍帮助说明；未通过 WebUI 提交训练或长生成任务。

这些验证确认偏移与时钟映射，不证明模型配置质量或不同第三方播放器的全部表现。音频 50 Hz 采样/起音量化仍有原本的时间分辨率，设置 first 并不消除该模型误差。
