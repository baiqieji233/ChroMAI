# ChroMAI · Composer v2 主界面（WebUI）与参数完整说明

本文档对应 **ChroMAI** 当前主路线 **Composer v2（`chart_composer_v2` / `continuous_events_v1`）** 的最新实现，帮助你在本地启动 WebUI 后快速完成谱面生成、在线预览、数据集管理与模型训练。

> **界面简洁原则**：在默认主推的 `Composer v2` 路线下，界面已自动隐藏仅属于旧模型族的控件与面板（例如训练 Step 01 中的旧版采样率 `22050 Hz` / 预处理缓存目录 / 强制重建缓存 /「当前单来源：预处理后立即训练」、训练运行区的旧版随机种子/保存间隔，以及生成页底部的旧版自动验收面板「生成后的诊断与对照」）。若需运行兼容旧模型，可在「选择训练起点 / 模型族」旁勾选 **「高级兼容设置」** 切换后恢复显示。

## 一、 启动服务与界面结构

### 1. 启动方式

- **Windows 一键脚本（推荐）**：双击或运行仓库根目录的 `START_WEBUI.bat`。脚本会自动检查/配置匹配的 CUDA 版 PyTorch 与 MERT 音乐编码器依赖并启动服务。
- **命令行启动**：
  ```bash
  chromai-webui --host 127.0.0.1 --port 7860
  # 或使用兼容命令 / 模块直启：
  maichart-gui --host 127.0.0.1 --port 7860
  python -m maichart.webui.server --host 127.0.0.1 --port 7860
  ```
  浏览器访问 `http://127.0.0.1:7860`。

### 2. 顶部工作区页签与右侧任务栏

| 区域 | 功能说明 |
| --- | --- |
| **生成谱面** | 导入音频与训练好的 `.pt` 模型权重，设置目标等级、按需微调 Radar / Style 倾向、生成 1–32 张谱面，并在顶部播放器直接在线预览。 |
| **训练模型** | 从头训练（`fresh`）、断点续训（`resume`）或在已有模型上加强训练（`finetune`）。 |
| **训练素材** | 勾选参与训练的数据集（支持多数据集混合）、搜索浏览单张谱面、试听音频并设置谱面质量权重。 |
| **右侧：任务状态** | 实时显示当前任务的进度、已生成事件数/训练指标、最近日志、历史任务切换，以及生成/训练完成后的产物路径。 |

训练开始后，在右侧「训练指标 → 训练进度」查看本轮与整个任务的预计剩余时间。进度在参数更新完成后约每 5 秒上报一次，不必等到下一条损失日志，也不为估时额外等待 GPU。断点续训只统计本次实际处理的批次；后续轮次会结合已记录的验证和保存用时估算。首次准备或验证尚无速度记录时显示「正在估算」，准备数据的用时与正式训练分开显示。预计时间会随缓存、批次长度和验证开销变化，提前结束训练也会使实际用时短于原计划。

> **提示**：页面中折叠的「高级设置」仅隐藏显示，其当前设定的数值仍会正常参与任务提交；提交前可在底部「本次生成摘要 / 本次训练摘要」中核对。

## 二、 生成谱面（已有模型直接写谱）

### 1. 推荐生成流程

1. **Step 01 · 导入歌曲与模型**：
   - 上传或填写本地音频路径（支持 `.mp3`、`.wav`、`.flac`、`.ogg` 等）。
   - 上传或填写模型检查点路径（如 `composer_v2_inference.pt`、`composer_v2_best.pt` 或 `composer_v2_last.pt`）。点击「检查生成 checkpoint 类型」可立即确认模型支持的条件与声学分支能力；未手动点击时，提交生成也会自动检查。
2. **Composer v2 生成设置**：
   - 保持默认参数即可直接生成；需要多抽几张挑优时，将 **「生成张数（抽卡挑谱）」** 设为 `2`–`8`。
3. **Step 02 · 选择等级与偏好（与 Radar / Style 微调）**：
   - 设定 **目标等级**（WebUI 滑块支持 `12.0`–`15.0`，CLI 支持 `1.0`–`15.0`）。
   - 展开 **「高级微调 · Radar / Style 参数」** 可按需调整复杂度与表现倾向（加载并检查支持 `radar_style_v1` 的模型后，支持逐项独立切换「自动 / 手动」）。
4. **Step 03 · 对齐节拍与起点**：
   - 默认留空 `BPM` 并保持勾选 `自动识别第一拍起点（首拍偏移）`，由系统自动识别节拍、变速段与首拍相位；若已知准确恒定 BPM，可直接填入 `BPM（可选）`。
5. **Step 07 · 设置输出元数据与路径**：
   - **自动读取音频标签**：选择或上传 `.mp3` 后，系统会自动尝试读取内嵌标题与曲师填充 **输出标题** 和 **曲师 / artist**（读取为空时标题回退为文件名、曲师留空，均可手动编辑）。
   - **输出等级自动换算**：在 Composer v2 下，「输出等级文字」会自动依照 Step 02 输入的目标定数换算并锁定展示（例如 `13.5 → 13`、`13.6 → 13+`）；展开「输出元数据」还可指定 **谱师名** 与导出 **难度槽位**（`3` Advanced、`4` Expert、`5` Master、`6` Re:Master，默认 `5`）。
6. **点击「生成谱面」并在线预览**：
   - 生成完成后，展开页面顶部的 **「PREVIEW · 谱面预览」** 即可在线播放试看（若尚未安装本地预览组件，点击面板内的「下载预览播放器」即可一键配置；若一次生成了多张谱面，可在「预览张」下拉框中切换）。
   - **输出文件位置**：默认单张生成（`生成张数 = 1`）直接保存至 `webui_workspace/generated/maidata.txt`（或「输出文件路径」指定的路径），同目录附带诊断报告 `maidata.composer_v2.json`；当 `生成张数 > 1` 批量生成时，会在同级目录下自动创建独立批次子目录 `maidata_batch_<id>/`，内含每张独立输出、报告及 `batch.composer_v2_batch.json`。

### 2. Composer v2 生成参数详解

| 界面字段 | CLI 参数 | 默认值 | 详细说明 |
| --- | --- | --- | --- |
| **自动BPM分析** | `--tempo-detection` | `识别变速并校准全曲`（`auto`） | 在下方 `BPM` 留空时生效：<br>• `识别变速并校准全曲`（`auto`）：分析全曲节拍并识别变速段，仅采用通过节拍连续性检查的变速表，未通过的候选仅记入报告。<br>• `仅恒定BPM，校准全曲`（`constant`）：全曲使用单一 BPM 并根据声学包络精细校准小数 BPM 与首拍。<br>• `旧版恒速估计（对照）`（`legacy`）：仅供历史对比。<br>一旦填写了下方手动 `BPM`，即固定为恒定速度；填写了手动 `tempo map JSON` 则整表最优先。 |
| **自动识别第一拍起点（首拍偏移）** | 省略 `--first` | 勾选 | 自动估计谱面第 0 拍对应的音频秒数（`&first`）。勾选时下方手动 `首拍偏移 / 秒` 输入框自动停用；取消勾选后使用手动填写的秒数（含 `0`）。 |
| **生成方式** | `--phrase-search` | `先定节奏，再选配置`（`layout`） | • `layout`：共享节奏与同拍数，比较连续多拍配置；<br>• `joint`：同时比较不同的出音时机与键位配置；<br>• `hybrid`：保留拍点并尝试不同双押物量；<br>• `event`：逐步直接生成（速度最快）。 |
| **手感与选优偏好** | `--phrase-rank-policy` | `基础手感稳定优先`（`comfort_v1`） | 对比多种候选写法时的排序偏好：可选 `comfort_v1`（手感与声学均衡）、`comfort_v2`（左右手交替与跨屏顺畅优先）或 `likelihood_veto_v1`（模型似然优先＋手感底线保护）。 |
| **每次打草稿长度 / 每次定稿保留长度（拍）** | `--phrase-beats` / `--phrase-commit-beats` | `4` / `2` | 在短段试排模式下，每次往前试写多少拍并从中定稿前几拍；后者不能大于前者。 |
| **每次内部对比写法数** | `--candidates` | `2` | 按所选 `--phrase-search` 模式在内部比较的候选数量（`1 / 2 / 4`），择优保留最佳方案。 |
| **写完后自动精修薄弱段** | `--self-refine` | `关闭`（`off`） | 设为 `worst_spans_v1` 时，整首生成完成后会回头重采样并尝试改善手感得分最低的少数局部片段（需经完整后续物理检查通过后才替换）。 |
| **下笔前双手防锁检查 / 撞尾预判范围** | `--forward-feasibility` / `--forward-tap-on-slide-ms` | `balanced_v1` / `150` | 解码期前向可行性保护：`balanced_v1` 检查按键占用并预防双手长时锁手、`hard_only_v1` 仅拦截三只手硬冲突、`off` 关闭；配合前向撞尾预判窗口（`0–250 ms`）。 |
| **Touch 手掌可达规则 / 同手兼顾半径** | `--touch-reachability-policy` / `--touch-cohold-radius` | `palm_span_v1` / `180` | 校验按住外圈 Hold / Slide 时内屏 Touch 是否在手掌可及范围内；可选 `palm_span_v1`（手掌自然兼顾）、`strict_on_slide_only` 或 `off`。 |
| **采音温度** | `--temperature` | `0.9` | 控制「何时落音」与「何时结束整曲」的采样温度。越低越趋向高概率常规节奏，越高变化越多。 |
| **配置温度** | `--action-temperature` | `0.9` | 独立控制「选中落点后写什么按键、同拍几押、Hold/Slide 时值」的采样温度。`0` 为配置贪心解码；留空则沿用采音温度。 |
| **采音 Top-p** | `--top-p` | `0.95` | 限制参与落点抽样的累计概率范围（核采样阈值，`(0, 1]`）。 |
| **配置 Top-p** | `--action-top-p` | `0.95` | 独立限制参与动作配置抽样的累计概率范围（`(0, 1]`）。留空则沿用采音 Top-p。 |
| **鼓点与重音贴合强度** | `--onset-strength` | `1` | 控制音符落点贴合音乐鼓点/重音的程度（仅对训练了独立声学起音分支的检查点启用）。<br>• `0`：关闭附加声学分数，仅用主干模型选时；<br>• `1`：使用训练标准强度（推荐）；<br>• `>1`（最大 `2`）：增强声学起音引导，使拍内细分落点更贴近明显声学重音。 |
| **拦截并清理 Slide 撞尾** | `--intercept-tap-on-slide` | 勾选 | 开启后，生成期用 MiaCode 原生判定拦截新增的硬性 Slide 撞尾（TapOnSlide），并在整谱收尾时自动清理残留撞尾音符。 |
| **撞尾保护窗口（ms）** | `--tap-on-slide-threshold-ms` | `200` | 开启撞尾拦截后生效（`0–250 ms`）。控制静态邻近撞尾参考窗口；设为 `0` 关闭额外静态邻近窗口，但实际判定模拟触发的硬撞尾仍会拦截。 |
| **音频特征缓存** | `--cache-dir` | `cache/chart_composer_v2` | 存放生成歌曲的 MERT 与 100 Hz 频谱特征缓存目录，重复生成同一首歌时直接复用。 |
| **生成设备** | `--device` | `auto` | 生成主模型解码设备：`auto` 优先使用 CUDA GPU，否则使用 CPU（Intel 核显 / NPU 加速由下方两个选项控制）。 |
| **音乐特征设备**（高级） | `--audio-device` | `auto` | MERT 特征提取设备：可选 `auto`（优先 CUDA，其次 `openvino-gpu` / `openvino-npu`，最后 `cpu`）、`cuda`、`openvino-gpu`、`openvino-npu`、`cpu`。 |
| **写谱加速引擎**（高级） | `--inference-backend` | `auto` | 增量解码推理后端：可选 `auto`（首次自动测速并选择最优后端）、`torch`、`openvino-cpu`、`openvino-gpu`。 |
| **副歌前后呼应方式** | `--reference-selection` | `按模型训练方式`（`auto`） | 已启用「节拍结构与对齐参考」的模型始终使用对齐参考，此项自动停用。旧模型可选 `对齐检索（实验）`（`aligned`）：免训练改用逐拍对齐选取参考，音乐不重复时不给参考。 |
| **最大事件数（0不限）** | `--max-events` | `0` | `0` 由模型根据音频结束位置自然停止；正整数是安全上限，达到上限时若尚未自然结束则报错，不导出截断谱面。 |
| **生成张数** | `--count` | `1` | 一次生成 `1–32` 张完整谱面，复用音频分析，随机种子逐张 `+1`；每张独立保存，可在顶部预览切换。 |
| **多张同时运行数** | `--parallel` | `1` | `1` 逐张生成并共用模型；大于 1 则启动对应数量的独立生成进程，每个进程载入一份模型，完成一张后继续下一张。实际不超过生成总数。 |
| **恢复仍失败时**（高级） | `--exhaustion-policy` | `继续生成并报告`（`auto`） | 当某处物理冲突超出重采与回退恢复预算时：<br>• `继续生成并报告`（`auto`）：保留当前最佳候选继续生成，并在 `.composer_v2.json` 报告的 `accepted_with_conflicts` 中记录位置与原因。<br>• `严格停止`（`stop`）：立即中止报错。<br>• `downgrade_or_skip`：尝试简化配置，必要时跳过该拍。 |
| **单步冲突重采次数**（高级） | `--window-retries` | `16` | 每个事件在遇到语法或物理冲突时的最大重新采样次数（`1–128`）。 |
| **CPU计算线程**（高级） | `--cpu-threads` | `0` | `0` 自动按可用 CPU 与同时生成数分配，CPU 推理每张最多 8 线程，GPU 推理使用 2 线程；填写正整数指定每张的线程数。可先试 4 或 8，更多线程不一定更快。 |
| **单处冲突恢复次数**（高级） | `--rollback-windows` | `2` | 连续模型在同一位置重采耗尽仍冲突时，可自动微调前序 Hold 松手时长（同键重击冲突时缩短前序 Hold）或回退重写附近事件，两类恢复共用该预算（`0–8`，`0` 关闭）。当生成位置推进超过历史最远拍位后，预算自动重置为满值。 |
| **输出标题 / 曲师 / 谱师 / 槽位** | `--title` / `--artist` / `--designer` / `--difficulty` | 自动 / 自动 / `AI`（CLI `Composer v2`）/ `5` | 写入导出 `maidata.txt` 与报告元数据；标题与曲师未指定时自动尝试读取 `.mp3` 标签（标题最终回退音频文件名），输出等级由 `--level` 定数自动换算；`--difficulty` 可选 `1`–`6`（WebUI 常用 `3`–`6`）。 |

### 3. 目标等级与 Radar / Style 偏好设计说明

在 **Step 02 · 选择等级与偏好** 中，Composer v2 采用**「目标等级定基调 + Radar / Style 逐项自动/手动分流」**的设计：

1. **为什么默认全部为「自动」？**
   - 真实谱面的滑条占比、和弦密度、连打或 Touch 分布与曲风、编曲段落高度相关。默认将全部 Radar / Style 设为 **「自动」** 时，模型不会受人工预设固定比例的捆绑，而是直接根据当前歌曲的音乐特征与目标等级自然安排手法。
2. **如何定向调整自己想要的风格？**
   - 加载并检查确认支持 `radar_style_v1` 的模型后，展开 **「高级微调 · Radar / Style 参数」**，每项指标旁都有一个 `自动 / 手动` 切换框。
   - **只把你想干预的指标切为「手动」**：例如觉得某首歌生成的 Touch 偏多，只需把 `Touch 倾向`（`touch_bias`）切为 `手动` 并调低；想多写滑条，只需把 `Slide 倾向`（`slide_bias`）或 `连续 Slide`（`slide_sequence`）切为 `手动` 并调高。
   - 其余未改动的指标继续保持 `自动`，由模型配合音乐自行决定。

## 三、 训练模型（Composer v2 训练与微调参数）

在「训练模型 → Step 02 选择训练起点」中，默认模型族为 **Composer v2**。需要其他兼容模型族时，勾选旁边的「高级兼容设置」。

| 界面字段 | CLI 参数 | 默认值 | 说明 |
| --- | --- | --- | --- |
| **训练方式** | `--resume` / `--init-checkpoint` | `从头训练（fresh）` | • `从头训练`：初始化新模型。<br>• `从断点继续（resume）`：读取 `composer_v2_last.pt`，严格继承原训练轮数、数据结构和超参数继续未完训练。<br>• `已有模型加强训练（finetune）`：读取已有 `.pt` 权重，在**新输出目录**中用新数据集或新参数微调。 |
| **输出目录** | `--checkpoint-dir` | `checkpoints/chart_composer_v2` | 保存 `composer_v2_best.pt`、`composer_v2_inference.pt`、`composer_v2_last.pt` 与 `training_history.jsonl`。 |
| **总目标轮数** | `--epochs` | `50` | 训练目标轮数。严格 `resume` 时继承检查点保存的原计划总轮数；`finetune` 时从 0 开始计算本次微调轮数。 |
| **单卡批大小 / 梯度累积** | `--batch-size` / `--grad-accumulation` | `8` / `8` | 每次参数更新合并 `8 × 8 = 64` 个训练片段。显存不足时可减小单卡批大小并同比例增大梯度累积。 |
| **CUDA 显存预算（GiB）** | `--cuda-memory-budget-gb` | `0` | `0` 使用 PyTorch 默认分配；填写正数则限制当前训练进程的 CUDA 显存占用上限。 |
| **音频缓存内存预算（GiB）** | `--audio-cache-gb` | `0.25` | 内存（RAM）中常驻的最近歌曲音频特征上限；`0` 表示每步直接从磁盘缓存读取。 |
| **学习率 / 学习率计划** | `--lr` / `--lr-schedule` | `0.0002` / `cosine` | 默认 `2e-4` 配合余弦退火（`cosine`），可选恒定学习率（`constant`）。 |
| **训练设备** | `--device` | `auto` | 训练主模型使用的计算设备：支持 `auto`、`cuda`、`xpu`（Intel 核显）与 `cpu`；`auto` 优先依次选择 CUDA、Intel XPU、CPU。 |
| **训练精度** | `--precision` | `auto` | 默认 `auto`，在支持 BF16 的 CUDA 或 Intel XPU 设备上自动选用 `bf16`，否则自动回退 `fp32`；也可手动指定 `bf16`、`fp16`（仅 CUDA）或 `fp32`。 |
| **批次分组** | `--batch-layout` | `auto` | 新训练按完整输入长度分组，续训沿用检查点设置。完整长度包含历史、参考和目标，可以减少批内补齐。 |
| **验证数据来源 / 总留出比例** | `--validation-source` / `--holdout-fraction` | `auto` / `0.05` | 默认自动按整首歌曲划分 `95%` 训练集、`2.5%` 开发验证集（定期保存检查点及每轮结束时评估并选出 `best`）、`2.5%` 最终留出集，并在输出目录 `data_split/` 下写入划分清单。 |
| **音频特征 / MERT 模型** | `--audio-backend` / `--mert-model` | `mert` / `m-a-p/MERT-v1-330M` | 正式训练与发布模型均使用 `MERT 75 Hz＋原生频谱 100 Hz`；首次运行会自动下载并缓存到 `cache/chart_composer_v2`。 |
| **单次训练片段跨度（拍）** | `--window-beats` | `16` | 每个训练样本切片覆盖的目标谱面拍数（正整数）。 |
| **历史上下文（拍）** | `--history-beats` | `16` | 模型回看的近期已发生谱面历史跨度（正整数）。 |
| **局部音乐额外前瞻（拍）** | `--future-beats` | `4` | 局部音频窗口额外向前读取的未来音乐拍数（非负整数）。 |
| **上下文窗口推进间隔（事件数）** | `--refresh-events` | `16` | 连续事件序列每推进多少个事件滑动整理一次上下文窗口。 |
| **偏拍与节奏恢复训练** | `--timing-recovery` | `auto` | 训练模型在历史出现轻微偏拍时主动拉回正常节奏网格（`causal_rhythm_v1`）。新训练默认开启，续训继承。 |
| **独立声学起音参考** | `--onset-readout` | `auto` | 启用拍内高时间分辨率声学读出分支（`phase_audio_v1`），辅助拍内细分位置对齐音乐重音。新训练与连续模型微调默认自动开启，严格续训继承原检查点。 |
| **节拍结构与对齐参考** | `--rhythm-structure` | `auto` | ① 每个音符位置和音频帧都带上"属于哪种拍内细分"的特征，模型能直接分辨 16 分（1/4）与 24 分（1/3、1/6）；② 前文参考改为逐拍比对音乐后按整拍对齐，显示在即将书写的位置上，并附带可信度；音乐没有真正重复时不提供参考（`aligned_rhythm_v2`）。新训练与连续模型微调默认开启，严格续训继承原检查点。 |
| **学习强度曲线** | `--intensity-curve` | `auto` | 新训练／微调学习局部事件率与同拍物量，续训继承检查点；支持生成页编辑。 |
| **验证最大批数** | `--validation-max-batches` | `0` | `0` 验证开发集的全部可评估片段，正数设置验证批次预算。 |
| **验证无改善早停（轮）** | `--early-stopping-patience` | `5` | 连续指定轮数验证 CE 未改善时结束，`0` 关闭；无验证时不生效。 |
| **每隔多少轮保留检查点** | `--save-every` | `5` | 保留完整 `composer_v2_epoch_NNN.pt`，`0` 关闭。 |
| **训练随机种子** | `--seed` | `0` | 控制权重初始化与样本顺序的可复现随机种子。 |
| **模型宽度 / 层数 / 注意力头 / 前馈宽度**（高级） | `--d-model` / `--layers` / `--nhead` / `--dim-feedforward` | `384` / `8` / `8` / `1536` | Transformer 主干容量配置。微调或续训已有模型时自动从检查点继承。 |
| **词表网格基准 / 组件 token 上限**（高级） | `--ticks-per-beat` / `--max-tokens` | `48` / `2048` | 时间网格基准分辨率与单样本最大 token 容量（其中一半用于历史与参考前文）。 |
| **最大更新尝试数 / 谱面限制**（高级） | `--max-steps` / `--limit-charts` | `0` / `0` | `0` 表示跑完完整数据集；填正整数仅用于短跑冒烟测试。 |

续训时需要调整批大小，可以将「批次分组」选为「按完整输入长度」，并保持「批大小 × 梯度累积」等于原设置。例如，`2 × 16` 可以改为 `4 × 8`。训练会保留优化器、学习率进度和当前轮次位置，同一次更新所用的样本保持一致。验证仍采用原来的批大小和抽样范围。

训练指标中的累计 loss 会被早期样本稀释。判断是否退步时，同时看「最近固定片段验证」的验证 loss、非相位时序 loss 和拍内落点 loss。当前版本会在定期保存检查点时复用固定验证片段，无须等整轮训练结束；验证批数仍由「验证最大批数」控制。非相位时序包含数字拍位和时间控制符，不包含 `F:` 拍内相位。新建模型还默认启用 Q/K 幅度归一化，旧检查点按其原策略加载。

从头训练会收录训练谱中的精确拍位，微调会在原词表末尾追加训练谱里新出现的拍位和组件。开发集沿用训练词表。遇到超出词表的谱面时，训练日志和 `dataset_audit.json` 会记录谱面与首个无法编码的拍位，覆盖统计会列出排除数量。开发集没有可评估片段时，用训练 loss 选 `best`，验证早停停止生效。

### 按拟合定数、标称定数和难度槽位筛选

1. 在「训练模型 → 训练定数与谱面筛选」，把「训练定数来源」选为「拟合定数（Chart;Gate）」。
2. 第一次使用时点「初始化 Chart;Gate」。已有文件可以自动找到，也可以在「已有 Chart;Gate 文件」中手动指定目录。**`Chart;Gate` 初始化需要安装 `.NET SDK >= 9` 与系统 `git` 命令**，首次运行时还会自动通过 `pip` 准备所需的辅助依赖（如 `pandas`）。
3. 设置拟合定数的上下限，留空使用 **12–16**（可设范围为 `1–20`）。再设置「最低标称定数」，默认 **1** 可排除 MajNet 上标称为 **0** 的特殊谱面；填 **12** 可进一步排除标称低于 12 的谱面，填 **0** 则关闭标称校验。
4. 在「使用的难度槽位」中勾选要训练的谱面位置。**默认勾选 `5 MASTER` 与 `6 Re:MASTER`（`4 EXPERT` 默认不勾选，可按需开启）**；选择 `Chart;Gate` 时同样仅支持并展示 **MASTER 和 Re:MASTER**。

谱面要同时满足定数和槽位条件。比如拟合范围为 `12–16`、最低标称定数为 `1` 时，标称 `0`、拟合 `13` 的 MASTER 谱仍会被筛掉。

训练和验证使用同一套筛选条件。入选谱面的拟合定数会交给模型作为难度，估分结果在本机缓存。训练输出目录的 `dataset_audit.json` 中，`condition_level` 显示实际通过数据准备的定数来源、谱数和范围。逐谱的 `declared_level` 与 `fitted_level` 可用于核对原标和估分。使用自动留出时，`data_split/split_report.json` 也会统计分组前按标称定数和槽位排除的谱面。

「谱面原标定数」与「拟合定数（open-mdp）」也可以继续选用。**注意：`open-mdp` 没有自动下载初始化器**，使用前需自行准备好对应上游仓库目录并在「open-mdp 目录」填写路径（或设置环境变量 `MAICHART_OPEN_MDP_DIR`），且需要本机安装 **`.NET SDK >= 8`**。断点续训沿用检查点的筛选条件，想调整条件可以用新目录微调。

感谢 Chart;Gate 与 MajSimai 提供的估分工具与谱面解析器。 [在线试算](https://chart.ratinggate.cn/) · [Chart;Gate 项目](https://github.com/inm2002/chartgate) · [MajSimai 项目](https://github.com/TeamMajdata/MajSimai) · [open-mdp 项目](https://github.com/RightSG/open-mdp)

### 已有模型升级到「节拍结构与对齐参考」

旧检查点（未启用该选项）仍按原方式正常生成，结果不变。想让已有模型获得新能力，用 **已有模型加强训练（finetune）**：

1. 训练方式选 `已有模型加强训练（finetune）`，检查点选现有的 `composer_v2_last.pt` 或 `composer_v2_inference.pt`。
2. **输出目录填新的文件夹**（原模型目录保持不动）。
3. 「节拍结构与对齐参考」保持 `自动`，其余参数沿用原训练即可。

新增的输入全部从零开始，所以微调开始时模型的输出与原模型逐位一致，已有的写谱能力完整保留，再在此基础上学习新信息。

## 四、 训练素材管理与跨设备路径配置

### 1. 导入与勾选训练素材

- 在 **训练模型 → Step 01 · 选择训练素材 → 导入或预处理新的素材** 中：
  - 原始素材目录下每首歌子目录须包含 `maidata.txt` 与音频文件，且音频文件**必须命名为 `track.mp3`、`track.wav` 或 `track.ogg`**（`.flac` 或其他文件名在训练预处理时会被跳过并记为缺失音频）。
  - 可上传包含歌曲子目录的 `.zip` 压缩包，或填写本地目录路径后点击 **「登记当前目录到训练素材」** 或 **「预处理当前目录」**，默认生成 `manifests/training_manifest.json`（Composer v2 的预处理仅扫描建表，实际 75 Hz MERT 与 100 Hz 频谱特征在开始训练时提取并缓存到 `cache/chart_composer_v2`；若预检查因 `<12` 级标记筛选过滤，只要在训练页调低「最低定数」即可实际入训）。
- 切换到顶部 **「训练素材」** 页签：
  - **多数据集联合训练**：勾选一个或多个已完成预处理的数据集卡片，点击「应用勾选的数据集」，系统会自动合并清单并按歌曲路径与难度去重。
  - **谱面浏览与质量权重**：点击任意数据集卡片即可按曲名、谱师、难度搜索排序，在线试听音频，并对选中的谱面设置「优秀加权 / 减权 / 排除」标注。

### 开训前核对排除与片段权重

在「训练模型 → 选择训练素材」勾选本次来源，设好难度和验证划分，再点「检查所选训练来源」。下方的「开训前预览」可按曲名、来源、路径或难度搜索。

想要仅让部分素材使用自动体检时，先勾选所有要训练的素材，并保持「训练时启用质量标注、训练示范与自动体检结果」开启。将「自动分段质检策略」设为「自动采用已有体检结果」，然后在「采用正式体检的来源」中只勾选要使用正式体检的普通数据集。其余已选训练素材照常入训，不会应用各自未勾选的自动体检结果。人工标注、示范库的确认范围、难度筛选和留出仍按原设置执行。

若要确认某来源的正式体检已经就绪，可选「强制要求使用自动体检结果」（抽查预览不能供训练采用）。点「检查所选训练来源」核对实际采用的来源，再开始训练。已开始的任务继续沿用启动时的范围，改变范围可开始新训练或在新目录微调。

- **整谱排除**列出被质量规则排除的谱面和原因。若同一谱面仍由另一来源提供，行内会提示查看「重新纳入」。
- **上下文或单项屏蔽**列出时间区间和采音、配置权重。两项都是 `0×` 时，这段只作上下文。只有一项为 `0×` 时，另一项仍可参与监督。
- **重新纳入**显示提供内容的来源、谱面路径、区间和恢复的学习项。需要排除某段时，在这里找到仍提供它的来源，取消勾选该来源，或在该来源保存排除，再点一次检查。
- **待确认**列出标注失效、素材缺失或估分缓存缺失等情况。自动验证划分沿用本次训练的比例与种子。续训按父检查点的训练清单预览。

预览不会启动训练。结果随勾选来源、质量开关和训练筛选设置变化。最终的谱面及音频准备与窗口生成由开训流程完成。

### 2. 跨设备继续训练与路径映射

将训练目录（包含 `composer_v2_last.pt` 与 `data_split/`）和数据集搬运到另一台电脑后，如果新电脑上的数据集盘符或目录路径发生变化，无需手动修改清单文件，只需创建一份 `path_map.json`：

```json
{
  "E:/旧电脑数据集目录": "D:/新电脑数据集目录",
  "E:/ChroMAI": "D:/ChroMAI"
}
```

在启动 WebUI 或命令行训练前设置环境变量 `MAICHART_PATH_MAP` 指向该文件即可自动映射路径：

```powershell
$env:MAICHART_PATH_MAP = (Resolve-Path .\path_map.json).Path
.\START_WEBUI.bat
```

### 逐拍参考证据与交叉熵监督策略

「节拍结构与对齐参考」的自动选项在新建训练、连续模型微调时使用 `aligned_rhythm_v2`。旧版 `aligned_rhythm_v1` 仍可明确选择，断点续训始终继承原策略；从旧版本检查点升级请使用新目录微调，原检查点保留。

新版会核对参考实际展示范围内的音乐，在每个参考位置分别提供音乐内容、起音排列、局部强弱及源段／目标段拍内起音支持。参考后半段与当前音乐不同时，模型能看到这种差异。低于检索门槛的训练负参考只使用剩余空间，不挤掉真实历史。

生成仍逐事件推进，正常休止和任意有理数拍位保持可用。超过当前参考范围后，会在事件提交后整理计算上下文；允许一次跳过长休止，不会在整理点添加音符或结束符。训练切片使用同样的整理规则。

当前所有新训练（`fresh`）与微调（`finetune`）任务均默认使用 **`authored_mixed_context_proper_ce_v2` 标准等权逐 token 交叉熵**，不再对混合 16 分／24 分样本、长空隙或结束符做时间权重重分配（避免改变时间采样的概率标定）；仅在严格断点续训（`resume`）旧检查点时，才继承原有的时间权重重分配规则。正常休止、16/24 分混用、谱面质量权重与节奏纠错样本（保留节奏纠错、屏蔽配置监督）继续照常生效，声学峰也不会自动成为必须出音的标签。

训练状态中的「拍内落点 loss」和「验证拍内落点 loss」可帮助观察细分选择，但仍需结合实际成谱试听判断效果。旧权重加载后新分支采用零初始化；参考组织和训练目标的变化仍需微调适应，不代表整谱质量已获保证。

### 按轮次保留检查点

主界面训练侧「验证、性能与保存 → 每隔多少轮保留检查点」默认 `5`，设为 `0` 关闭。每完成对应轮次，在输出目录额外保留 `composer_v2_epoch_005.pt`、`composer_v2_epoch_010.pt` 等完整权重，含优化器与续训状态，可用于生成或断点续训。中途按更新步保存仍覆盖 `last`，不会生成不完整的轮次备份。此项在续训时可以调整，不改变模型或学习合同。每份备份占用与 `composer_v2_last.pt` 相近的磁盘空间。

新版可学习强度曲线与局部疏密编辑见 [强度曲线与局部疏密编辑](COMPOSER_V2_INTENSITY_ZH.md)。训练页新建任务的强度曲线保持自动；生成页直接展开 Composer v2 的强度曲线控件即可预览编辑。

## 五、 一键预设与舞萌 DX 素材自动体检

### 1. 三大工作流一键预设（零基础推荐直接点预设）

- **生成谱面预设**：
  - `推荐稳妥写谱（默认）`：先定节奏再对比 2 种按键配置，开启防 Slide 撞尾与前置防锁手保护。
  - `高质精雕细琢（左右手顺畅）`：每次对比 4 种写法，开启 `comfort_v2` 左右手顺畅打分、防星头抢拍，并在整首写完后自动复盘重写薄弱段（`worst_spans_v1`）。
  - `快速试写预览（最快）`：逐步直接生成，适合先听整首歌的定速与节奏框架。
  - `一次抽 4 张挑最好`：一次生成 4 张独立谱面，在顶部「谱面预览」下拉框随时切换对比。
- **训练模型显存预设**：
  - `8G–12G 显卡省显存（推荐）`（批大小 `4 × 16` 加激活重算）、`16G+ 显卡标准速度`（批大小 `8 × 8`）、`1 轮快速跑通测试`（最多 20 张和 32 步更新）。从短跑切回显卡预设会恢复原训练计划。严格续训沿用检查点的计划，可调整显存优化和缓存预算。
- **自动体检预设**：
  - `标准体检（推荐）`：屏蔽硬冲突片段，并将疑似整谱偏移、微时差、高速连打、局部漂移与留白记入复核提示（保留原学习权重，不自动整谱排除）。
  - `严格排错`：同时屏蔽撞尾警告与内屏硬冲突，屏蔽时长超过 35% 时排除整谱。

### 2. 训练素材体检与复核

在 **「训练素材」** 页签顶部（或 **「训练模型 → 素材自动体检与人工反馈学习」** 面板内）可以运行体检。打开谱面目录时，素材页检查当前库；在素材列表和训练页检查勾选的训练来源。体检对象会在按钮下显示。

1. **默认扫描范围为 `12–15` 级的 `5 MASTER` 与 `6 Re:MASTER`（仅当在训练页勾选了 `4 EXPERT` 时才包含 Expert）**。正式体检按配置处理硬冲突；遇到 Tap 撞上未划完的 Slide 轨迹（TapOnSlide）时，除在训练中屏蔽该处按键配置权重外，还会按标准／非标准拍网格将采音权重降为 `0.5×` 或 `0.0×`。疑似整谱偏移、局部漂移、音乐活跃处留白、可疑拍点与高速连打进入复核提示，保留原学习权重。强制声学核对遇到音频缺失或无法读取会列为待核对。
2. **更多体检设置**中的自动优选提权、手顺降权分位门槛默认关闭。可按需开启实验设置，获选片段分别使用 1.20 倍采音权重和 1.35 倍配置权重，分位值决定候选分数门槛。
3. 在体检看板选择 **「查看待核对」**，打开有提示的谱面，点击片段定位试听。需调整学习决定时保存人工标注。
   - 抽查和正式结果可以分别查看、筛选和试听。打开一张谱，在预览侧栏点击片段定位，再点「循环试听这一段」。组合清单的报告绑定检查时的清单版本，查看组合结果后可回原库保存人工标注。
   - 自动体检结果与人工标注分开保存。人工片段标注优先用于对应区间，解除自动整谱排除需在素材目录明确保存整谱标签。新训练或微调按训练页的质量标注开关和体检采用策略读取正式标注，续训沿用检查点的规则。
