# Composer v2 使用说明

本指南针对主工作台的 `chart_composer_v2` 连续事件模型。启动及首次操作见[项目 README](../../README.md)。浏览器会保留上次填写的参数，表内是新表单的起始值，实际执行值以任务参数和报告为准。

## 生成设置

在 **生成谱面 → 导入歌曲与模型** 选择音频和 `.pt`，点击 **检查生成 checkpoint 类型**。界面按检查点显示控件，也会注明它是连续模型还是早期固定窗口模型。检查点的音频特征由它的训练设置决定。使用 MERT 检查点时，生成环境也要能读取相匹配的 MERT 模型。

| 分组 | 控件 | 含义 |
| --- | --- | --- |
| 导入歌曲与模型 | 音频路径 | 音频文件，上传后可自动填写。更换歌曲后重新检查时钟。 |
| 导入歌曲与模型 | 模型 checkpoint | 可用的 `.pt` 文件。首次生成可用较小的 `composer_v2_inference.pt`。 |
| 对齐节拍与起点 | BPM（可选） | 每分钟的拍数。填准确值或留空估计全曲 BPM。 |
| 对齐节拍与起点 | 首拍偏移 / 秒 | 谱面第 0 拍在音频中的时间。默认自动识别；关闭自动识别后可手填，例如 `0`。 |
| 对齐节拍与起点 | 手动 tempo map JSON（可选） | 指定从各拍位开始生效的 BPM，填了会优先使用整张表。 |
| 对齐节拍与起点 | 生成拍号表 meter map JSON（可选） | 记录已知拍号、切换位置和可选分组。当前连续模型按绝对拍位生成，拍号表用于记录设置。 |

| Composer v2 生成 | 配置温度／配置 Top-p | 默认 `0.9`／`0.95`，连续事件检查点可单独控制音符类型、键位、同拍组合和时值。每项留空时沿用对应的采音值。 |
| Composer v2 生成 | 起音参考强度 | 仅已启用独立声学读出的检查点可见。`0`关闭附加分数，`1`沿用训练强度，最大`2`。实验功能，不是物量控制器。 |
| Composer v2 生成 | 自动BPM分析 | 默认识别变速并校准全曲；也可只校准恒速或使用旧版对照。自动变速请将BPM留空，手动BPM及tempo map优先。[逐曲测试](COMPOSER_V2_VARIABLE_TEMPO_20261108_ZH.md) |
| Composer v2 生成 | 拦截并清理Slide撞尾（可选）／撞尾检测阈值（ms） | 默认开启，阈值200，范围0—250。开启后使用MiaCode硬撞尾规则拦截及清理；警告保留。0关闭静态邻近参考，实际触发的硬撞尾仍检测。无需重训。[验证说明](COMPOSER_V2_OPTIONAL_TAIL_GUARD_20261107_ZH.md) |
| Composer v2 生成 | 音频特征缓存 | 默认 `cache/chart_composer_v2`。相同音频和匹配的特征设置可以复用缓存。 |
| Composer v2 生成 | 生成设备 | 默认 `auto`。优先使用可用的 CUDA，亦可明确选 `cpu` 或 `cuda`。 |
| Composer v2 生成 | 最大事件数（0不限） | 默认 `0`。正数用于快速查看一部分结果。 |
| Composer v2 生成 | 单张配置候选数 | 默认 `2`。`2` 或 `4` 为连续模型在同一拍位、相同同拍音符数上比较配置，额外候选会增加耗时。 |
| 高级生成设置 | 恢复仍失败时 | 连续模型默认 **继续生成并报告**。恢复后仍有物理冲突时，可导出完整谱面与诊断。需要严格检查可选 **严格停止**。语法或时长错误仍会中止。 |
| 高级生成设置 | 单处冲突恢复次数 | 默认 `2`。同一生成位置的持续动作修复与事件撤回共用预算，超过此前最远拍位后重置。`0` 关闭修复与撤回。 |

| 输出设置 | 输出文件路径 | 默认 `webui_workspace/generated/maidata.txt`，WebUI 另建任务目录，实际文件路径以任务结果为准。 |

### 分开调整采音与配置

温度越高，抽样越容易选到原来概率较低的选项。Top-p 则决定有多少概率范围内的选项参与抽样。若采音已经合适，可以保留原采音设置，只提高配置温度。例如 **采音温度** `0.65`、**采音 Top-p** `0.93`，**配置温度** `1.0`、**配置 Top-p** `0.93`。CLI 分别对应 `--temperature`、`--top-p`、`--action-temperature`、`--action-top-p`。

连续模型在填入任一配置采样参数后，采音和配置使用独立随机序列。做对照时两次都显式填写配置值，并固定检查点、歌曲、时钟和种子。新配置会作为后续前文，持续动作和物理恢复也可能影响后续落点。两项配置参数都留空可复现原共用采样方式。任一温度为 `0` 时，对应部分采用贪心。

### 节拍与分音

恒速时，`音频秒数 = 首拍偏移 + 谱面拍位 × 60 / BPM`。例如 BPM 为 120 且偏移为 0.5 秒，第 4 拍对应音频 2.5 秒。谱面可从更晚的拍位才开始落音。

“自动BPM分析”默认选择“识别变速并校准全曲”：先校准恒速误差，再对通过检查的段落应用连续变速表；其余候选保留在报告中。还可选择“仅恒定BPM，校准全曲”或“旧版恒速估计（对照）”。检测变速时请将BPM留空，手动BPM锁定恒速，手动tempo map整表优先。自动偏移只对齐节拍相位，整拍编号、小节起点和前奏留白需要结合原谱或试听确认。全曲越来越错拍时先核对 BPM，整体偏移几乎相同时先核对首拍，只有部分段落错位时检查是否确实变速。[逐曲测试和限制](COMPOSER_V2_TIMING_AUDIT_20261105_ZH.md)

下面的变速表从第 0 拍以 180 BPM 开始，在第 32 拍起改为 150 BPM。拍位以四分音符拍为单位，可填写精确分数。

```json
[
  {"beat": "0", "bpm": 180},
  {"beat": "32", "bpm": 150}
]
```

如果已经核对了 7/8 拍号，可这样填写拍号表。它和 BPM 分别描述拍组组织和行进速度。

```json
[
  {"beat": "0", "numerator": 7, "denominator": 8, "grouping": [2, 2, 3]}
]
```

### Radar 与 Style

检查点声明 `radar_style_v1` 后，展开 **高级微调 · Radar / Style 参数**。只有勾选 **手动指定** 的项会作为已知值送入模型。未勾选的项由模型结合音乐和已写前文生成。界面的参考数值帮助选择手动起点，实际条件以报告里的 `overrides` 为准。显式 `0` 表示传入零值，取消勾选才恢复自动。

| 分组 | 参数 | 提高数值表达的倾向 |
| --- | --- | --- |
| Radar | 整体密度 | 整首每秒的音符头较多。 |
| Radar | 峰值密度 | 最密的一秒内有更多独立起音事件。 |
| Radar | 滑条量（sweep） | Slide 较多，端点跨越的范围较大。 |
| Radar | 滑条复杂度 | 更多在路径或时值统计上较复杂的 Slide。 |
| Radar | 连续滑条 | 更倾向相邻时刻连续使用 Slide。 |
| Radar | 同键连打（jack） | 相邻起音组在短时间内较常重复同一按钮。 |
| Radar | 和弦比例 | 较多同刻含两个及以上音符的事件。 |
| Style | Tap 倾向 | Tap 音符头比例较高。 |
| Style | Slide 倾向 | Slide 音符头比例较高。 |
| Style | Hold 倾向 | Hold 和 TouchHold 的比例较高。 |
| Style | Touch 倾向 | Touch 和 TouchHold 的比例较高。 |
| Style | 和弦倾向 | 与 Radar 的和弦比例取自同一个训练统计。 |
| Style | 节奏贴合（非旋律） | 更多谱面起音靠近检测到的音频起音。 |
| Style | 模式复用 | 短配置签名较常重复。 |
| Style | 方向性 | 单键转移的旋向更一致，顺逆方向由生成决定。 |

这些值都是 `0–1` 的条件，实际音符数量和写法由模型决定。首次生成建议全部保留自动。比较一项设置时尽量保持歌曲、时钟、检查点和种子一致。

### 查看结果

展开生成页顶部 **谱面预览**。缺少组件时点击 **下载预览播放器**。任务结果中的 **预览这次生成** 可切换到相应的音频和谱面。[MiaView 预览接入](MIAVIEW_GENERATION_PREVIEW_20261105_ZH.md)

对照 `.composer_v2.json` 中的 `timing`、`condition`、种子、事件数和冲突摘要。发生放行时查看 `.conflicts.json`，失败时查看 `.failure.json` 及日志。诊断也会保存带独立编号的副本。查看谱面时分别检查音符时刻、长休止、连续高密度的退出位置，以及 Hold／Slide 占手期间的配置。

## 训练设置

在 **训练模型** 选择 `chart_composer_v2`。完成预处理后检查实际训练来源，再设置训练起点和输出目录。小型流程测试可用少量真实歌曲或演示 ZIP。若素材不足以划分训练、开发、最终留出三组，可为流程测试临时关闭验证。正式训练用独立验证来源。

### 独立起音参考（实验）

在主界面的 **训练模型 → 模型与上下文 → 独立起音参考（实验）** 中选择：

- **自动：新训练启用最新读出，续训继承检查点**：fresh以及连续事件模型的finetune启用拍内声学读出；resume严格继承旧合同。早期固定窗口检查点保持原方式。
- **关闭**：使用原有选时方式。
- **启用拍内声学读出**：增加一个轻量声学分支，直接比较同一整数拍内不同候选附近的起音。仍然允许16分与24分混用。

从 v6 启用时选择 **加强训练／finetune** 和一个新的输出目录。模型宽度、层数、音频条件和原词表从旧点继承。新增声学输出零初始化，原检查点保留；启用它需要训练，不能把选项本身视为质量提升。`resume` 保持检查点合同，不用于开启或关闭此训练分支。

生成侧检查支持此能力的新检查点后，**Composer v2 生成 → 起音参考强度** 会保持可用：`0` 关闭附加声学分数，`1` 使用训练时的强度，`1–2` 加强声学参照。它只调整拍内位置，不直接改变休止、EOS或配置分支；时间改变仍可能间接改变后续配置与物量。旧 v6 没有训练该分支，控件保留显示但会停用。

训练 CLI 对应 `--onset-readout phase_audio_v1`，生成对应 `--onset-strength 1`。参数、检查点能力和实际强度会记录到任务设置与生成报告。更新后端代码后，需要重启正在使用的 WebUI 服务，才能提交这些新参数。

方案依据和限制见[独立声学读出可行性](COMPOSER_V2_ACOUSTIC_READOUT_FEASIBILITY_20261106_ZH.md)。

### 训练起点

| 训练方式 | 使用场景 |
| --- | --- |
| 从头训练（fresh） | 使用新权重和当前连续序列策略。填新输出目录。 |
| 从断点继续（resume） | 恢复完整检查点的权重、优化器、随机状态和训练进度。继承原数据与训练合同，并通过一致性检查。 |
| 已有模型加强训练（finetune） | 以兼容权重初始化新阶段，可改训练素材和学习率。填新输出目录，词表、序列和模型结构需通过检查。 |

`composer_v2_last.pt` 是最新完整状态。`composer_v2_best.pt` 初期可以是临时点，完成验证后按开发集指标选取，未启用验证则按训练指标选取。`composer_v2_inference.pt` 与最新保存对应，适合生成或兼容的微调初始化。要精确续训请用完整状态。模型族、时间词表、数据身份和训练目标一起决定兼容性。[旧检查点与迁移](../compatibility/README.md#检查点与旧模型)

### 命令行短跑

可直接使用 WebUI 准备出的 manifest。下面的例子使用本地声学特征和小批次，只检查读数据、训练更新及保存链路。

```powershell
.\.venv\Scripts\python.exe -m maichart.composer_v2.train --manifest "manifests/training_manifest.json" --checkpoint-dir "checkpoints/v2_smoke" --audio-backend native --precision auto --batch-size 2 --grad-accumulation 1 --max-steps 5
```

正式训练可以传入 `--validation-manifest` 指定独立开发清单。只测歌曲时钟时可运行 `python -m maichart.composer_v2.tempo --audio "songs/track.mp3"`，程序会输出BPM、首拍相位、实际应用的变速表和未采纳候选；可加 `--tempo-detection constant` 或 `--tempo-detection legacy` 对照。


## 一次生成多张与预览

在 **Composer v2 生成 → 生成张数** 填入数量。它与 **单张配置候选数** 不同：前者决定保存几张成品，后者在单张谱面内比较不同配置，保留相同的落点与同拍音符数。

批量任务只载入一次检查点、准备一次音频，并顺序生成，避免多份模型争用显存。每张从空白谱面开始，使用连续的独立 seed。结果存入 `maidata_batch_随机编号/01_seed_数字/maidata.txt` 等独立目录，批量报告记录每张状态、检查点哈希、seed和谱面哈希。某张失败会继续其余谱面；全部失败时任务明确报错，部分失败不会显示为全部成功。取消会停止整批，已经落盘的谱面仍保留。

任务完成后，顶部 **谱面预览** 下拉框显示“第几张／总张数”和 seed。切换时会停止旧播放器并载入所选谱面，保持暂停；重新载入时保留当前选择。服务重启后也能从历史日志恢复整批结果。播放区域最大宽度为720像素，小屏会随可用宽度收缩。

本版首次读取旧浏览器设置时，会更新自动首拍、撞尾检测、独立配置采样及配置候选的旧默认；此后手动修改会正常保存。手动BPM、条件偏好、文件路径、学习率和断点合同不受这次默认值迁移影响。所有最新版控件打开界面就会显示，提交时会自动检查模型；旧检查点不支持的控件保留显示并停用。起音参考只对已经训练该分支的检查点生效；Radar／Style保持自动，手动勾选才覆盖。多候选和新默认不等于音乐质量已经通过人工验收。
