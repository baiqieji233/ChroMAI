# Composer v2 主界面（WebUI）与参数完整说明

本文档对应当前主路线 **Composer v2（`chart_composer_v2` / `continuous_events_v1`）** 的最新实现，帮助你在本地启动 WebUI 后快速完成谱面生成、在线预览、数据集管理与模型训练。

---

## 一、 启动服务与界面结构

### 1. 启动方式

- **Windows 一键脚本（推荐）**：双击或运行仓库根目录的 `START_WEBUI.bat`。脚本会自动检查/配置匹配的 CUDA 版 PyTorch 与 MERT 音乐编码器依赖并启动服务。
- **命令行直接启动**：
  ```bash
  python -m maichart.webui.server --host 127.0.0.1 --port 7860
  ```
  浏览器访问 `http://127.0.0.1:7860`。

### 2. 顶部工作区页签与右侧任务栏

| 区域 | 功能说明 |
| --- | --- |
| **生成谱面** | 导入音频与训练好的 `.pt` 模型权重，设置目标等级、按需微调 Radar / Style 倾向、生成 1–32 张谱面，并在顶部播放器直接在线预览。 |
| **训练模型** | 从头训练（`fresh`）、断点续训（`resume`）或在已有模型上加强训练（`finetune`）。 |
| **训练素材** | 勾选参与训练的数据集（支持多数据集混合）、搜索浏览单张谱面、试听音频并设置谱面质量权重。 |
| **右侧：任务状态** | 实时显示当前任务的进度、已生成事件数/训练指标、最近日志、历史任务切换，以及生成/训练完成后的产物路径。 |

训练开始后，在右侧「训练指标 → 训练进度」查看本轮与整个任务的预计剩余时间。进度在参数更新完成后约每 5 秒上报一次，不必等到下一条损失日志，也不为估时额外等待 GPU。断点续训只统计本次实际处理的批次；后续轮次会结合已记录的验证和保存用时估算。首次准备或验证尚无速度记录时显示「正在估算」，准备数据的用时与正式训练分开显示。预计时间会随缓存、批次长度和验证开销变化，提前结束训练也会使实际用时短于原计划。

> **提示**：页面中折叠的「高级设置」仅隐藏显示，其当前设定的数值仍会正常参与任务提交；提交前可在底部「本次生成摘要 / 本次训练摘要」中核对。

## 二、 生成谱面（已有模型直接写谱）

### 1. 推荐生成流程

1. **Step 01 · 导入歌曲与模型**：
   - 上传或填写本地音频路径（支持 `.mp3`、`.wav`、`.flac`、`.ogg` 等）。
   - 上传或填写模型检查点路径（如 `composer_v2_inference.pt`、`composer_v2_best.pt` 或 `composer_v2_last.pt`）。点击「检查生成 checkpoint 类型」可立即确认模型支持的条件与声学分支能力；未手动点击时，提交生成也会自动检查。
2. **Composer v2 生成设置**：
   - 保持默认参数即可直接生成；需要多抽几张挑优时，将 **「生成张数」** 设为 `2`–`8`。
3. **Step 02 · 选择目标等级（与 Radar / Style 微调）**：
   - 设定 **目标等级**（`12.0`–`15.0`）。
   - 展开 **「高级微调 · Radar / Style 参数」** 可按需调整 12 项复杂度与表现倾向。
4. **Step 03 · 对齐节拍与起点**：
   - 默认留空 `BPM` 并保持上方勾选 `自动识别首拍偏移`，由系统自动识别节拍、变速段与首拍相位；若已知准确恒定 BPM，可直接填入 `BPM（可选）`。
5. **点击「生成谱面」并在线预览**：
   - 生成完成后，展开页面顶部的 **「PREVIEW · 谱面预览」** 即可在线播放试看（若尚未安装本地预览组件，点击面板内的「下载／更新播放器」即可一键配置；若一次生成了多张谱面，可在「预览张」下拉框中切换）。
   - 生成产物默认保存在 `webui_workspace/generated/<任务ID>/` 目录下，包含可直接导入外部模拟器的 `maidata.txt` 与诊断报告 `maidata.composer_v2.json`。

### 2. Composer v2 生成参数详解

| 界面字段 | CLI 参数 | 默认值 | 详细说明 |
| --- | --- | --- | --- |
| **自动BPM分析** | `--tempo-detection` | `识别变速并校准全曲`（`auto`） | 在下方 `BPM` 留空时生效：<br>• `识别变速并校准全曲`（`auto`）：分析全曲节拍并识别变速段，仅采用通过节拍连续性检查的变速表，未通过的候选仅记入报告。<br>• `仅恒定BPM，校准全曲`（`constant`）：全曲使用单一 BPM 并根据声学包络精细校准小数 BPM 与首拍。<br>• `旧版恒速估计（对照）`（`legacy`）：仅供历史对比。<br>一旦填写了下方手动 `BPM`，即固定为恒定速度；填写了手动 `tempo map JSON` 则整表最优先。 |
| **自动识别首拍偏移** | 省略 `--first` | 勾选 | 自动估计谱面第 0 拍对应的音频秒数（`&first`）。勾选时下方手动 `首拍偏移 / 秒` 输入框自动停用；取消勾选后使用手动填写的秒数（含 `0`）。 |
| **采音温度** | `--temperature` | `0.9` | 控制「何时落音」与「何时结束整曲」的采样温度。越低越趋向高概率常规节奏，越高变化越多。 |
| **配置温度** | `--action-temperature` | `0.9` | 独立控制「选中落点后写什么按键、同拍几押、Hold/Slide 时值」的采样温度。`0` 为配置贪心解码；留空则沿用采音温度。 |
| **采音 Top-p** | `--top-p` | `0.95` | 限制参与落点抽样的累计概率范围（核采样阈值，`(0, 1]`）。 |
| **配置 Top-p** | `--action-top-p` | `0.95` | 独立限制参与动作配置抽样的累计概率范围（`(0, 1]`）。留空则沿用采音 Top-p。 |
| **起音参考强度** | `--onset-strength` | `1` | 控制音符落点贴合音乐鼓点/重音的程度（仅对训练了独立声学起音分支的检查点启用）。<br>• `0`：关闭附加声学分数，仅用主干模型选时；<br>• `1`：使用训练标准强度（推荐）；<br>• `>1`（最大 `2`）：增强声学起音引导，使拍内细分落点更贴近明显声学重音。 |
| **拦截并清理Slide撞尾** | `--intercept-tap-on-slide` | 勾选 | 开启后，生成期用 MiaCode 原生判定拦截新增的硬性 Slide 撞尾（TapOnSlide），并在整谱收尾时自动清理残留撞尾音符。 |
| **撞尾检测阈值（ms）** | `--tap-on-slide-threshold-ms` | `200` | 开启撞尾拦截后生效（`0–250 ms`）。控制静态邻近撞尾参考窗口；设为 `0` 关闭额外静态邻近窗口，但实际判定模拟触发的硬撞尾仍会拦截。 |
| **音频特征缓存** | `--cache-dir` | `cache/chart_composer_v2` | 存放生成歌曲的 MERT 与 100 Hz 频谱特征缓存目录，重复生成同一首歌时直接复用。 |
| **生成设备** | `--device` | `auto` | `auto` 在检测到可用 CUDA GPU 时使用显卡加速，否则使用 CPU。 |
| **前文参考选择** | `--reference-selection` | `按模型训练方式`（`auto`） | 已启用「节拍结构与对齐参考」的模型始终使用对齐参考，此项自动停用。旧模型可选 `对齐检索（实验）`（`aligned`）：免训练改用逐拍对齐选取参考，音乐不重复时不给参考。验证集上旧模型用此方式的交叉熵略高于默认（0.328 对 0.319），仅供试听对比。 |
| **最大事件数（0不限）** | `--max-events` | `0` | `0` 由模型根据音频结束位置自然停止；正整数是安全上限，达到上限时若尚未自然结束则报错，不导出截断谱面。 |
| **生成张数** | `--count` | `1` | 一次生成 `1–32` 张完整谱面，复用音频分析，随机种子逐张 `+1`；每张独立保存，可在顶部预览切换。 |
| **同时生成数** | `--parallel` | `1` | 1逐张生成并共用模型；大于1则启动对应数量的独立生成进程，每个进程载入一份模型，完成一张后继续下一张。实际不超过生成总数。 |
| **单张配置候选数** | `--candidates` | `2` | 单张谱面在每个已选定的落点与同拍音符数下，并行采样的合法动作配置候选数（`1 / 2 / 4`），按模型分数择优保留。 |
| **恢复仍失败时**（高级） | `--exhaustion-policy` | `继续生成并报告`（`auto`） | 当某处物理冲突超出重采与回退恢复预算时：<br>• `继续生成并报告`（`auto`）：保留当前最佳候选继续生成，并在 `.composer_v2.json` 报告的 `accepted_with_conflicts` 中记录位置与原因。<br>• `严格停止`（`stop`）：立即中止报错。 |
| **单步冲突重采次数**（高级） | `--window-retries` | `16` | 每个事件在遇到语法或物理冲突时的最大重新采样次数（`1–128`）。 |
| **CPU计算线程**（高级） | `--cpu-threads` | `0` | 0自动按可用CPU与同时生成数分配，CPU推理每张最多8线程，GPU推理使用2线程；填写正整数指定每张的线程数。可先试4或8，更多线程不一定更快。 |
| **单处冲突恢复次数**（高级） | `--rollback-windows` | `2` | 连续模型在同一位置重采耗尽仍冲突时，可自动微调前序 Hold 松手时长（同键重击冲突时缩短前序 Hold）或回退重写附近事件，两类恢复共用该预算（`0–8`，`0` 关闭）。当生成位置推进超过历史最远拍位后，预算自动重置为满值。 |

### 3. 目标等级与 Radar / Style 偏好设计说明

在 **Step 02 · 选择目标等级** 中，Composer v2 采用**「目标等级定基调 + Radar / Style 逐项自动/手动分流」**的设计：

1. **为什么默认全部为「自动」？**
   - 真实谱面的滑条占比、和弦密度、连打或 Touch 分布与曲风、编曲段落高度相关。默认将全部 12 项 Radar / Style 设为 **「自动」** 时，模型不会受人工预设固定比例的捆绑，而是直接根据当前歌曲的音乐特征与目标等级自然安排手法。
2. **如何定向调整自己想要的风格？**
   - 展开 **「高级微调 · Radar / Style 参数」**，你会看到每项指标旁都有一个 `自动 / 手动` 切换框。
   - **只把你想干预的指标切为「手动」**：例如觉得某首歌生成的 Touch 偏多，只需把 `Touch 倾向`（`touch_bias`）切为 `手动` 并调低；想多写滑条，只需把 `Slide 倾向`（`slide_bias`）或 `连续 Slide`（`slide_sequence`）切为 `手动` 并调高。
   - 其余未改动的指标继续保持 `自动`，由模型配合音乐自行决定。

## 三、 训练模型（Composer v2 训练与微调参数）

在 **训练模型** 页签中，确认 **Step 02 · 模型架构** 选择 `chart_composer_v2（连续事件／Composer v2，当前主路线）`。

| 界面字段 | CLI 参数 | 默认值 | 说明 |
| --- | --- | --- | --- |
| **训练方式** | `--resume` / `--init-checkpoint` | `从头训练（fresh）` | • `从头训练`：初始化新模型。<br>• `从断点继续训练（resume）`：读取 `composer_v2_last.pt`，严格继承原训练轮数、数据结构和超参数继续未完训练。<br>• `已有模型加强训练（finetune）`：读取已有 `.pt` 权重，在**新输出目录**中用新数据集或新参数微调。 |
| **输出目录** | `--checkpoint-dir` | `checkpoints/chart_composer_v2` | 保存 `composer_v2_best.pt`、`composer_v2_inference.pt`、`composer_v2_last.pt` 与 `training_history.jsonl`。 |
| **训练轮数** | `--epochs` | `50` | 训练目标总轮数。严格 `resume` 时继承检查点保存的原计划总轮数。 |
| **单卡批大小 / 梯度累积** | `--batch-size` / `--grad-accumulation` | `8` / `8` | 每次参数更新合并 `8 × 8 = 64` 个训练片段。显存不足时可减小单卡批大小并同比例增大梯度累积。 |
| **CUDA 显存预算（GiB）** | `--cuda-memory-budget-gb` | `0` | `0` 使用 PyTorch 默认分配；填写正数则限制当前训练进程的 CUDA 显存占用上限。 |
| **音频缓存内存预算（GiB）** | `--audio-cache-gb` | `0.25` | 内存（RAM）中常驻的最近歌曲音频特征上限；`0` 表示每步直接从磁盘缓存读取。 |
| **学习率 / 学习率计划** | `--lr` / `--lr-schedule` | `0.0002` / `cosine` | 默认 `2e-4` 配合余弦退火（`cosine`），可选恒定学习率（`constant`）。 |
| **训练精度** | `--precision` | `bf16` | CUDA 下默认使用 `bf16` 混合精度加速；不支持时可切为 `fp32`。 |
| **批次分组** | `--batch-layout` | `自动` | 新训练按完整输入长度分组，续训沿用检查点设置。完整长度包含历史、参考和目标，可以减少批内补齐。 |
| **验证集来源 / 自动留出比例** | `--validation-source` / `--holdout-fraction` | `auto` / `0.05` | 默认自动按整首歌曲划分 `95%` 训练集、`2.5%` 开发验证集（每轮评估并选出 `best`）、`2.5%` 最终留出集，并在输出目录 `data_split/` 下写入划分清单。 |
| **音频特征 / MERT 模型** | `--audio-backend` / `--mert-model` | `mert` / `m-a-p/MERT-v1-330M` | 正式训练与发布模型均使用 `MERT 75 Hz＋原生频谱 100 Hz`；首次运行会自动下载并缓存到 `cache/chart_composer_v2`。 |
| **单次训练片段跨度（拍）** | `--window-beats` | `16` | 每个训练样本切片覆盖的目标谱面拍数（正整数）。 |
| **历史上下文拍数** | `--history-beats` | `16` | 模型回看的近期已发生谱面历史跨度（正整数）。 |
| **局部音频前瞻（拍）** | `--future-beats` | `4` | 局部音频窗口额外向前读取的未来音乐拍数（非负整数）。 |
| **上下文窗口推进间隔（事件）** | `--refresh-events` | `16` | 连续事件序列每推进多少个事件滑动整理一次上下文窗口。 |
| **偏拍与节奏恢复训练** | `--timing-recovery` | `auto` | 训练模型在历史出现轻微偏拍时主动拉回正常节奏网格（`causal_rhythm_v1`）。新训练默认开启，续训继承。 |
| **独立声学起音参考** | `--onset-readout` | `auto` | 启用拍内高时间分辨率声学读出分支（`phase_audio_v1`），辅助拍内细分位置对齐音乐重音。新训练与连续模型微调默认自动开启，严格续训继承原检查点。 |
| **节拍结构与对齐参考** | `--rhythm-structure` | `auto` | ① 每个音符位置和音频帧都带上"属于哪种拍内细分"的特征，模型能直接分辨 16 分（1/4）与 24 分（1/3、1/6）；② 前文参考改为逐拍比对音乐后按整拍对齐，显示在即将书写的位置上，并附带可信度；音乐没有真正重复时不提供参考（`aligned_rhythm_v2`）。新训练与连续模型微调默认开启，严格续训继承原检查点。 |
| **学习强度曲线** | `--intensity-curve` | `auto` | 新训练／微调学习局部事件率与同拍物量，续训继承检查点；支持生成页编辑。 |
| **验证最大批数** | `--validation-max-batches` | `0` | 0 验证开发集的全部可评估片段，正数设置验证批次预算。 |
| **验证无改善早停（轮）** | `--early-stopping-patience` | `5` | 连续指定轮数验证 CE 未改善时结束，0 关闭；无验证时不生效。 |
| **每隔多少轮保留检查点** | `--save-every` | `5` | 保留完整 `composer_v2_epoch_NNN.pt`，0 关闭。 |
| **模型宽度 / 层数 / 注意力头 / 前馈宽度**（高级） | `--d-model` / `--layers` / `--nhead` / `--dim-feedforward` | `384` / `8` / `8` / `1536` | Transformer 主干容量配置。微调或续训已有模型时自动从检查点继承。 |
| **每拍脉冲数 / 最大序列长度**（高级） | `--ticks-per-beat` / `--max-tokens` | `48` / `2048` | 时间网格基准分辨率与单样本最大 token 容量（其中一半用于历史与参考前文）。 |

续训时需要调整批大小，可以将「批次分组」选为「按完整输入长度」，并保持「批大小 × 梯度累积」等于原设置。例如，2 × 16 可以改为 4 × 8。训练会保留优化器、学习率进度和当前轮次位置，同一次更新所用的样本保持一致。验证仍采用原来的批大小和抽样范围。

### 按拟合定数、标称定数和难度槽位筛选

1. 打开「训练模型 → 训练谱面难度筛选」，把「定数来源」选为「拟合定数（Chart;Gate）」。
2. 第一次使用时点「初始化 Chart;Gate」。已有文件可以自动找到，也可以在「已有 Chart;Gate 文件」中手动指定目录。首次初始化需要 .NET SDK 9 或更新版本。
3. 设置拟合定数的上下限，留空使用 **12–16**。再设置「最低标称定数」。默认 **1**，可排除 MajNet 上标称为 **0** 的特殊谱面。填 **12** 可进一步排除标称低于 12 的谱面，填 **0** 则关闭标称校验。
4. 在「使用的难度槽位」中勾选要训练的谱面位置。默认勾选 **4 EXPERT、5 MASTER、6 Re:MASTER**，Chart;Gate 下只显示它支持的 **MASTER 和 Re:MASTER**。

谱面要同时满足定数和槽位条件。比如拟合范围为 12–16、最低标称定数为 1 时，标称 0、拟合 13 的 MASTER 谱仍会被筛掉。

训练和验证使用同一套筛选条件。入选谱面的拟合定数会交给模型作为难度，估分结果在本机缓存。训练输出目录的 `dataset_audit.json` 记录入选定数和筛除原因。使用自动留出时，`data_split/split_report.json` 也会统计分组前按标称定数和槽位排除的谱面。

「谱面原标定数」与「拟合定数（open-mdp）」也可以继续选用。断点续训沿用检查点的筛选条件，想调整条件可以用新目录微调。

感谢 Chart;Gate 与 MajSimai 提供的估分工具与谱面解析器。 [在线试算](https://chart.ratinggate.cn/) · [Chart;Gate 项目](https://github.com/inm2002/chartgate) · [MajSimai 项目](https://github.com/TeamMajdata/MajSimai) · [open-mdp 项目](https://github.com/RightSG/open-mdp)

### 已有模型升级到「节拍结构与对齐参考」

旧检查点（未启用该选项）仍按原方式正常生成，结果不变。想让已有模型获得新能力，用 **已有模型加强训练（finetune）**：

1. 训练方式选 `已有模型加强训练（finetune）`，检查点选现有的 `composer_v2_last.pt` 或 `composer_v2_inference.pt`。
2. **输出目录填新的文件夹**（原模型目录保持不动）。
3. 「节拍结构与对齐参考」保持 `自动`，其余参数沿用原训练即可。

新增的输入全部从零开始，所以微调开始时模型的输出与原模型逐位一致，已有的写谱能力完整保留，再在此基础上学习新信息。
| **更新尝试上限 / 谱面数量上限**（高级） | `--max-steps` / `--limit-charts` | `0` / `0` | `0` 表示跑完完整数据集；填正整数仅用于短跑冒烟测试。 |

## 四、 训练素材管理与跨设备路径配置

### 1. 导入与勾选训练素材

- 在 **训练模型 → Step 01 · 准备训练数据** 中，可上传包含多首歌曲目录（每首歌含 `maidata.txt` 与音频文件）的 `.zip` 压缩包，或填写本地数据集文件夹路径后点击「登记当前目录到训练素材」，随后执行预处理生成 `manifest.json`。
- 切换到顶部 **「训练素材」** 页签：
  - **多数据集联合训练**：勾选一个或多个已完成预处理的数据集卡片，点击「应用勾选的数据集」，系统会自动合并清单并按歌曲路径与难度去重。
  - **谱面浏览与质量权重**：点击任意数据集卡片即可按曲名、谱师、难度搜索排序，在线试听音频，并对选中的谱面设置「优秀加权 / 减权 / 排除」标注。

### 开训前核对排除与片段权重

在「训练模型 → 选择训练素材」勾选本次来源，设好难度和验证划分，再点「检查所选训练来源」。下方的「开训前预览」可按曲名、来源、路径或难度搜索。

- **整谱排除**列出被质量规则排除的谱面和原因。若同一谱面仍由另一来源提供，行内会提示查看「重新纳入」。
- **上下文或单项屏蔽**列出时间区间和采音、配置权重。两项都是 `0×` 时，这段只作上下文。只有一项为 `0×` 时，另一项仍可参与监督。
- **重新纳入**显示提供内容的来源、谱面路径、区间和恢复的学习项。需要排除某段时，在这里找到仍提供它的来源，取消勾选该来源，或在该来源保存排除，再点一次检查。
- **待确认**列出标注失效、素材缺失或估分缓存缺失等情况。自动验证划分沿用本次训练的比例与种子。续训按父检查点的训练清单预览。

预览不会启动训练。结果随勾选来源、质量开关和训练筛选设置变化。最终的谱面及音频准备与窗口生成由开训流程完成。

### 2. 跨设备继续训练与路径映射

将训练目录（包含 `composer_v2_last.pt` 与 `data_split/`）和数据集搬运到另一台电脑后，如果新电脑上的数据集盘符或目录路径发生变化，无需手动修改清单文件，只需创建一份 `path_map.json`：

```json
{
  "E:/旧电脑数据集目录": "D:/新电脑数据集目录",
  "E:/simai_transformer": "D:/simai_transformer"
}
```

在启动 WebUI 或命令行训练前设置环境变量 `MAICHART_PATH_MAP` 指向该文件即可自动映射路径：

```powershell
$env:MAICHART_PATH_MAP = (Resolve-Path .\path_map.json).Path
.\START_WEBUI.bat
```


### 逐拍参考证据与混合分音学习

「节拍结构与对齐参考」的自动选项在新建训练、连续模型微调时使用 `aligned_rhythm_v2`。旧版 `aligned_rhythm_v1` 仍可明确选择，断点继续始终继承原策略；从 v6 或 v1 升级请使用新目录微调，原检查点保留。运行此选项需要重启已在运行的旧 WebUI 后台。

新版会核对参考实际展示范围内的音乐，在每个参考位置分别提供音乐内容、起音排列、局部强弱及源段／目标段拍内起音支持。参考后半段与当前音乐不同时，模型能看到这种差异。低于检索门槛的训练负参考只使用剩余空间，不挤掉真实历史。

生成仍逐事件推进，正常休止和任意有理数拍位保持可用。超过当前参考范围后，会在事件提交后整理计算上下文；允许一次跳过长休止，不会在整理点添加音符或结束符。训练切片使用同样的整理规则。

混合16分／24分及拍型切换样本会增加拍内位置的监督权重，真实长空隙和歌曲结束继续使用原谱标签。权重只在同一片段的时间决策之间重新分配，保持原有时间权重总量和配置权重；验证 loss 使用未加强的原始权重。恢复训练还会用少量保持音符数量的错相位前文练习续写，复用已有恢复样本，不增加样本总数。声学峰不会自动成为必须出音的标签。

训练状态新增「拍内落点 loss」和「验证拍内落点 loss」，帮助观察细分选择，仍需结合成谱试听。旧权重可以加载，新分支零初始化；这仅保证相同输入的模型输出不被新分支立即改变，参考组织和训练目标的变化需要微调适应，不代表整谱质量已获保证。

### 按轮次保留检查点

主界面训练侧「验证、性能与保存 → 每隔多少轮保留检查点」默认 5，设为 0 关闭。每完成对应轮次，在输出目录额外保留 `composer_v2_epoch_005.pt`、`composer_v2_epoch_010.pt` 等完整权重，含优化器与续训状态，可用于生成或断点续训。中途按更新步保存仍覆盖 `last`，不会生成不完整的轮次备份。此项在续训时可以调整，不改变模型或学习合同。每份备份占用与 `composer_v2_last.pt` 相近的磁盘空间。运行中的旧训练进程需下次启动／续训才会使用修复；不会自动补回已经覆盖的历史轮次。

新版可学习强度曲线、重新训练建议与本轮目标调整见 [强度曲线说明](COMPOSER_V2_INTENSITY_ZH.md)。训练页新建任务的强度曲线保持自动；生成页直接展开 Composer v2 的强度曲线控件即可预览编辑，无需独立页面。

## 五、 一键预设与舞萌 DX 素材自动体检

### 1. 三大工作流一键预设（零基础推荐直接点预设）

- **生成谱面预设**：
  - `推荐稳妥写谱（默认）`：先定节奏再对比 2 种按键配置，开启防 Slide 撞尾与前置防锁手保护。
  - `高质精雕细琢（左右手顺畅）`：每次对比 4 种写法，开启 `comfort_v2` 左右手顺畅打分、防星头抢拍，并在整首写完后自动复盘重写薄弱段（`worst_spans_v1`）。
  - `快速试写预览（最快）`：逐步直接生成，适合先听整首歌的定速与节奏框架。
  - `一次抽 4 张挑最好`：一次生成 4 张独立谱面，在顶部「谱面预览」下拉框随时切换对比。
- **训练模型显存预设**：
  - `8G–12G 显卡省显存（推荐）`（批大小 `4 × 16` 加激活重算）、`16G+ 显卡标准速度`（批大小 `8 × 8`）、`1 轮快速跑通测试`（最多 20 张和 32 步更新）。从短跑切回显卡预设会恢复原训练计划。严格续训沿用检查点的计划，可调整显存优化和缓存预算。
- **自动体检预设**：
  - `标准体检（推荐）`处理硬冲突，并记录音画偏移等复核提示。
  - `严格排错`同时屏蔽撞尾警告与内屏硬冲突，屏蔽时长超过 35% 时排除整谱。

### 2. 训练素材体检与复核

在 **「训练素材」** 页签顶部（或 **「训练模型 → 训练素材质量与偏好」** 面板内）可以运行体检。打开谱面目录时，素材页检查当前库；在素材列表和训练页检查勾选的训练来源。体检对象会在按钮下显示。

1. 自动扫描 12–15 级 Expert、Master 和 Re:Master 谱面。正式体检按配置处理硬冲突。疑似整谱偏移、局部漂移、音乐活跃处留白、可疑拍点与高速连打进入复核提示，保留学习权重。强制声学核对遇到音频缺失或无法读取会列为待核对。
2. **更多体检设置**中的自动优选提权、手顺降权分位门槛默认关闭。可按需开启实验设置，获选片段分别使用 1.20 倍采音权重和 1.35 倍配置权重，分位值决定候选分数门槛。
3. 在体检看板选择 **「查看待核对」**，打开有提示的谱面，点击片段定位试听。需调整学习决定时保存人工标注。
   - 抽查和正式结果可以分别查看、筛选和试听。打开一张谱，在预览侧栏点击片段定位，再点「循环试听这一段」。组合清单的报告绑定检查时的清单版本，查看组合结果后可回原库保存人工标注。
   - 自动体检结果与人工标注分开保存。人工片段标注优先用于对应区间，解除自动整谱排除需在素材目录明确保存整谱标签。新训练或微调按训练页的质量标注开关和体检采用策略读取正式标注，续训沿用检查点的规则。
