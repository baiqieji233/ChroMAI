# Planner 类型提示与 Style 比例纠偏

日期：2026-10-13。适用于 `song_form_v1` 自动生成。本轮修改前备份：
`backups/planner_type_guidance_20261013/source_before_fix.zip`。

## 审核结论

此前 Planner 为起音记录生成了 `type_probabilities` 和 `sustain_seconds`，生成器只取其拍位。类型与时值头被定义为辅助预测，配置模型的 skeleton 也只有位置和配置遮罩。因此“23 个位置最倾向 Slide、最后却没有 Slide”不是起音器误删了 23 个 Slide，而是原实现没有使用这些类型提示。

按“Planner 应帮助安排配置”的目标，这属于功能链路缺口，现已补齐类型部分。23 个 argmax 不是 23 个必须执行的 Slide；多押标签按 Slide > Hold > Touch/TouchHold > Tap 取优先级，不能当作逐头比例或已确认的谱师选择。

Style 原本只通过 16 维条件投影、门控及评估生效，没有运行时比例反馈。Slide=0.125 不是保证 12.5% 音符为 Slide。新增纠偏让比例偏离可以直接影响解码概率，仍不做固定配额。

## 实际改动

- `form/type_guidance.py`：解析 checkpoint 已有音符目录，建立类别与字符前缀索引；在现有语法允许的 token 上施加软偏置。
- `form/generate.py`：把每个起音的 Planner 概率传入配置解码，共用一个全曲音符头计数器，跨音乐段落及 token 预算续写保留状态。
- `form/cli.py`：新增两个生成参数，并将实际值写入 `.form.json`。
- 主 WebUI/API：新增对应控件、范围校验、CLI 转发和任务有效参数记录。旧 event 模型不显示或发送它们。
- 每次生成最后打印 `form_type_guidance`，报告真实类型比例、目标偏差、使用的 Planner 提示、目录覆盖和缓存开销。

没有改模型权重形状、16 维顺序、训练目标、输入合同、预处理缓存依赖或训练素材。这轮修复不要求重练，也不要求因为本补丁把 resume 改成 finetune。

## 解码方式

Planner 指导参考当前位置的四类概率及全曲预测背景，背景掺入少量均匀参考，凸显局部倾向并避免所有位置的高置信同类提示完全抵消。它使用事件类别概率，**没有把音符头份额当作事件类别先验**。

比例纠偏按已完成音符头统计，与 Style 偏好比较；初始计数有 8 个虚拟头平滑，避免开头没有某一类便产生无限补偿。Hold 和 Touch 都包含 TouchHold，内部先转成五种互斥偏好。独立中位数拼出的四项合计可能小于 1，内部采样偏好会归一化并写入 `sampling_target_exclusive`；传给模型的原始 16 维条件不变，报告的 `actual_minus_requested` 仍比较原始请求。

软偏置以完整候选配置的类别分数形成字符前缀势差，分数裁剪到 -4～4，单 token 偏置绝对值不超过 8。不按路径长度累计奖励；结束当前配置和添加 `/` 的直接偏置相同，避免为了补类型主动奖励多押数量。

最终候选仍由原 grammar 决定，不能凭空创造目录没有的 Slide，也不会绕过同头重复检查。没有额外的模型前向调用。前缀兼容索引缓存限制为 8 MiB / 512 项，这只是索引数组预算，不是整个模型或目录占用的总内存上限。

## WebUI 使用

入口：生成谱面 → 设置生成方式。

| 控件 | 默认 | 范围 | 用途 |
| --- | ---: | --- | --- |
| 规划类型指导强度 | 1.0 | 0～3 | 增强当前位置的 Planner 类型倾向；0 关闭 |
| 类型比例纠偏强度 | 1.0 | 0～3 | 对已生成类型比例与 Style 偏好的偏差进行软纠偏；0 关闭 |

两项都设为 0，恢复原字符采样路径。它们只用于自动生成，不改变既有改稿流程。

默认 1.0 是功能启用的初始值，没有做谱面质量校准。先保留原 Radar/Style 和相同 seed，单独比较指导关闭与开启；若纠偏较弱，可以单独试 1.5，再根据输出决定。提高数值可能削弱配置自然性，不能用大倍率代替模型学会合理配置。

CLI 对应参数为 `--planner-type-strength` 和 `--style-balance-strength`。例如保留现有生成命令，追加 `--planner-type-strength 1 --style-balance-strength 1`；恢复原方式则两项都传 0。

已启动的 WebUI 后端通常缓存原模块；刷新页面只能加载新静态控件，须下次重启 WebUI 才能确保新参数完整转发。本轮没有重启正在承载训练的服务。CLI 与新启动的 WebUI 进程可直接使用新逻辑。
