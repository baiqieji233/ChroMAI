# ChroMAI · Composer v2：短段试排、音乐上下文与片段反馈

**ChroMAI** 的 Composer v2 采用连续事件生成，并结合短段试排、音乐上下文理解与低负担片段反馈机制。试排的几拍仅作为计算与比较范围，并非音乐分段；系统不会在试排边界强行添加音符、休止或结束符，也不会把复杂拍子改写成固定四拍小节。

## 设计思路

单颗音符合法并不意味着接下来一连串动作衔接顺手；如果仅在同一时刻、相同音符数量下更换键位，也无法在首次选错节奏后比较另一种分音或入口方式。短段试排允许在真正落笔前多向前写几拍，再保留前部、继续向后推进。

另一方面，仅靠区间平均的全曲摘要容易混淆音色接近但鼓点推进不同的段落。补充段内变化统计与起音摘要后，模型更容易判断当前应当展开、保持还是收束（不强制规定“高潮必须加密”）。

## 生成界面怎么用

生成页直接展示以下设置，无需先检查检查点即可调整：

| 控件 | 默认 | 用途 |
| --- | --- | --- |
| 生成方式 | 自动（先定节奏，再选配置） | 先确定一小段音符出现的时间和数量，再比较不同键位与动作组合 |
| 每次打草稿长度（拍） | 4 | 每次往前试写几拍来评估顺畅度，不要求音乐每 4 拍结束一段 |
| 每次定稿保留长度（拍） | 2 | 例如试写 4 拍后先定稿前 2 拍，再顺着往下写 |
| 每次内部对比写法数 | 2 | 内部比较后只保留成品，不在预览中列出试写片段 |
| 连续单键试写（实验） | 关闭 | 长单键段遇到音乐变化时，暂时省略部分重复前文，额外比较同拍点、同数量的配置 |

选择「节奏与配置一起比较」时会同时尝试不同的采音时间与键位配置，适合比较入口、混合分音与收束；「逐步生成（速度最快）」则保持逐事件直接生成。

默认先检查原生冲突，再比较候选已有音头的起音和重音。证据接近时保留原候选。「偏好省力写法」和模拟手感仍可手动选择。

试写时只提交保留的前部，未提交尾部仅用于向前评估。当前序 Hold / Slide 被修复或回退时，待提交内容会清空并从实际前文重建状态；仅因推测尾部冲突不会直接封禁共同的第一个配置。

## 连续单键试写的作用范围

这项实验适用于长时间连续单键的退化情况。它保留已生成的事件和完整占手状态，只在解码输入中省略部分重复 Tap。额外候选沿用原拍点和每拍音符数，通过原生冲突检查，并检查实际提交部分是否已有多步变化。采用后，省略效果保持到对应旧事件自然滑出历史范围，同时暂时关闭谱面参考。

已有对照显示它能减轻部分连续单键，但仍会留下长连打，也可能改变后续采音。减少连打次数和通过物理检查都不足以证明编排更好，因此默认关闭，供同一模型的生成对照使用。已保存的开关会继续恢复，使用过上一版的用户可以取消勾选或恢复生成默认参数。

## 配置学习仍需解决的问题

普通训练主要学习真实谱面前文下的下一个事件。历史缩短视图保留最近几拍，目标区间内部仍逐步提供真实前文。时间恢复训练只监督选时，配置 token 被屏蔽。旧版有序未来配置头通过辅助梯度影响解码状态，生成直接使用主解码器。

这留下一个具体缺口。模型需要学习自己已写出偏离原谱的前文以后，如何根据音乐及实际占手，完成下一组合理配置。增加重复惩罚、提高候选数或增加未来辅助权重，都需要单独证明能改善这一步。

下列接续示范与偏好方案仍需验证。局部写法条件已按后文的训练与生成一致输入方案接入。

1. 用同一段音乐检查真实前文、模型自身前文和有限遮挡前文下的续写，再保持前文不动比较有明确表达差异的音乐段。记录时间、类型和键位各自的概率，检查模型是否跟随音乐选择合理写法。任意换音频后输出变化只能证明敏感性。
2. 从少量实际自生成前文收集经过人工确认的接续。样本保留第一处改写、完整占手、后续展开和释放。只在确认的续写范围计算原有交叉熵，原有真实谱面继续参与训练。直接拼接的原谱后缀需要核对与当前前文的衔接。
3. 同时保留合理持续、变奏、转折、主动留白和自然收束。相同音乐可以有多种被接受的续写。片段短或重复多本身都不能构成负标签。
4. 若接续示范有效但相同前文下仍过度偏好明确不合适的整段写法，再研究人工偏好训练。比较双方必须使用相同音频、拍网、目标难度和实际前文。首轮优先保持拍点及同拍物量一致，同时允许双方均合理、双方均不合适。
5. 局部写法条件需要检验音频预测的方向、模型的实际执行，以及接着自行生成的前文时能否持续兑现。可以临时输入真实描述做诊断，但质量评估使用音频预测结果。

条件中的动作顺序和释放时刻要足够明确，避免仅用种类比例描述一整段。规划的时间范围可以在连续拍位上滚动读取，生成继续按精确事件推进。训练窗口结束只表示计算切片结束。

首轮验证复用音频缓存，离线生成有限前文，用同一初始检查点、数据预算和训练时间做对照。先在少量保留歌曲上检查自生成前文之后的接法，再评价完整段落。验收应同时覆盖实际转折、合理持续、休止、采音和手部衔接。只有换键、物量变少或重复率下降的结果，继续保留为诊断。

在模型自身会到达的状态下提供合适监督，有序列模仿学习研究支持。将这类方法应用到写谱仍需要可靠的接续示范。偏好学习也需要人工确认的有效比较，评分代理不能自动充当质量答案。[序列模仿学习](https://proceedings.mlr.press/v15/ross11a.html) · [直接偏好优化](https://arxiv.org/abs/2305.18290)

## 低负担反馈与片段标注

生成后可在页面顶部的「谱面预览」试听完整谱面。时间轴按 1–8 键与 Touch 自动展开并区分 Tap、Hold、Slide 与 Touch，点击音符可选中同拍组合，或直接拖选评价范围（波形默认关闭，可按需开启作对齐背景）。单张成品可直接记录「好」「有问题」或「不确定」；若同一音频有多张版本，可展开「比较另一张」在同一区间对比 A/B（切换保留位置与播放状态）。内部试排草稿不作展示；如需对比多张完整谱面，将「生成张数」设为 2 或更多。

在「训练素材」页打开数据集后，点击「预览与标注」同样可在时间轴拖选片段并记录「好」「有问题」或「不确定」（原因可选采音、配置或手感）。详细操作流程见 [完整谱面审阅与反馈](COMPOSER_V2_PREVIEW_ZH.md) 与 [审阅、标注和片段包操作指南](COMPOSER_V2_ANNOTATION_GUIDE_ZH.md)。

- 标注「好 / 值得学习」会适度提高对应区间的学习权重；标为采音有问题时可仅屏蔽采音监督而保留配置监督，反之亦然；未评价或「不确定」保持原权重。
- 标注按完整事件归属，强度曲线辅助监督也会跳过不可信区间（屏蔽监督不会把该处错误标成休止）。
- 结束符归入选时监督，避免仅屏蔽配置时误伤歌曲结束判断。
- 确认收为训练示范的片段会汇总到「人工确认示范库」，与原训练集一起在**新输出目录**微调（`finetune`）。

## 训练新增设置

| 控件 | 新训练默认 | 含义 |
| --- | --- | --- |
| 音频编码层数 | 4 | 增加局部音乐理解容量；微调旧模型时可继承 2 层或显式扩展 |
| 全曲结构层数 | 2 | 全曲编码器层数 |
| 音乐上下文 | 自动 | 新训练与微调默认启用带区间变化统计与相对拍位的最新上下文 |
| 局部写法学习 | 自动 | 新训练与连续模型微调采用新版动作走向与起手学习，断点续训继承检查点 |
| 写法学习权重 | 0.05 | 音符用法、运动方向、持续动作与释放的监督权重 |

「按音乐学习动作走向与起手」采用 `audio_writing_v3`。一个小预测器复用现有按拍音频特征、全曲编码和目标定数，描述前方 0–2、2–4、4–8 拍的动作倾向。不同区间保留顺序，普通持续、转折、主动留白都由真实谱面提供监督。按拍更新只控制信息读取，事件时间仍使用原有精确分数表示。

训练和生成均向主解码器输入音频预测结果，未来谱面只用于计算损失。模型在决定动作配置及下一事件的整数拍入口时使用这些预测。新接入的投影从零初始化。实际前文与 Hold／Slide 占用仍由主解码器读取，预测器不会强制换键、添加音符或截短持续动作。

已有连续事件模型可以选择「微调」、新建输出目录，保持「局部写法学习」为「自动」并使用写法学习权重 `0.05`。命令行使用 `--init-checkpoint`，策略可保留 `auto` 或显式指定 `audio_writing_v3`。旧版选项仍可用于对照。后续断点续训继承保存的策略及权重。

动作先后、释放衔接及整数拍入口的验证方法见[动作走向、候选选优与整谱评价](COMPOSER_V2_MOTION_AND_REVIEW_ZH.md)。

新增计算集中在训练窗口实际涉及的拍位，复用全曲编码与有上限的 CPU 派生特征缓存，增量生成只补算新拍位。接入和兼容性验证通过后，仍需用留出歌曲的实际续写判断音乐表达是否改善。

新的全曲音乐摘要在原有最多 160 个区间基础上补充频带变化量与子区间起音统计，复用已提取的音频特征，仅增加极小的派生摘要文件。新增投影采用零初始化，扩层时新增音频编码层从恒等映射开始；旧检查点保留原结构，严格 `resume` 继承原合同，如需启用新上下文或扩层请在**新输出目录**微调（`finetune`）。在不同硬件或 CPU 注意力内核间可能存在微小的浮点舍入差异。

独立起音读出仍仅作用于已经选中的整数拍内位置，不会充当强制出音的检测器；全曲音乐信息通过主解码器统一参与下一时刻、键位配置与结束判断。

## 资源开销与使用建议

- 仅启用 `song_paired_v2` 上下文对训练吞吐的影响极小；若同时将音频编码层数由 2 层扩至 4 层，前向／反向计算与显存占用会有所上升。显存紧张时可适当减小 `batch_size`、提高 `grad_accumulation`，并保持「训练显存优化」为自动。
- 启用短段试排（如 `layout` / `joint`）或提高「每次内部对比写法数」会增加单张生成耗时，以换取提交前对多步手法衔接与声学贴合度的比较。
- 从旧模型微调启用新增音乐上下文或音频编码扩层后，建议结合实际生成谱面的采音、留白、混合分音与手感试听结果来评估改善效果。
