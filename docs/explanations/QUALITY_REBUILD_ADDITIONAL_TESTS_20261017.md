## 已通过

- **149 项 Python 定向回归、50 项 Node 测试**，覆盖新位置辅助的 mask/梯度、质量合同迁移、物理时值、负 first、Motif、曲线身份和 WebUI 参数传递。
- 新增 **1 项增强合同中断续训回归**：在梯度累积完整更新后人为中断，再 resume；主模型、Planner 所有权重与不中断训练逐位一致，合同、任务能力、优化步数和游标也相同。包含 dropout、曲线与历史扰动、位置辅助目标。
- **真实 31.9M 旧权重→32.08M 增强模型 GPU 微调→严格 resume**：两张官谱，微调和续训各 1 次 Planner、2 次配置更新，BF16，无 NaN/OOM/合同异常。续训准备缓存 2/2、Blueprint 2/2 命中。
- **完整音符目录生成**：使用来源 checkpoint 的全部 **26,382** 条配置目录，旧模型与增强模型各连续生成两个片段、8 拍，均输出 **19 个事件**，有 Slide；精确编译/回读通过，没有资源截断。第二段确实读取前段事件和持续动作。此项补上上一轮只用基础音符目录完成的验证缺口。
- **跨音乐段修订**：修改范围跨过段边界，提出 5 个事件，解码没有 fallback，范围外谱面保持一致。本例提案与原稿相同，按 `no_change` 拒绝；没有为通过测试而强行接受修订。
- **复杂时钟输入**：3/4、150→180 BPM、`first=-0.35`，在后续音乐区域两个片段共生成 21 个事件，事件、tempo map 与首拍偏移精确回读一致。只验证时钟合同，不证明模型已学会该歌曲应使用三拍子。
- **实际 7860 HTTP 检查**：旧 checkpoint 返回 legacy、2 秒曲线、0 秒时序范围；增强 checkpoint 返回新合同、1 秒曲线、1 秒时序范围和已训练的辅助目标。两者均可加载生成。

## 保留的失败案例与质量边界

1. 将原曲**开头**人为改为 3/4、beat 3 从 150 改 180 BPM、`first=-0.35`，请求 `[0,3)`、`[3,6)` 两个短片段时，模型在有合法位置的情况下都主动选 EOS，空谱被后端明确拒绝。本轮没有将 EOS 保护调高来掩盖它。后续区域同类时钟探针成功，但不能据此消除这个失败案例；提前结束仍需充分训练和实际音乐比较。
2. 完整目录短片段仍有无理审计：旧模型 3 条、增强模型 4 条。两者条件分布及新增分支训练程度不同，这不是质量提升或退化的可靠比较。
3. 新位置辅助头在本轮 4 次配置更新后，采样草稿行的匹配覆盖率为 1.0，指针准确率仍为 0。这说明标签和梯度接线可用，**新增能力没有在几步内学好**；不能拿旧主模型已有的低 token loss 代替新目标训练完成度。
4. 本次只生成指定短范围。诊断器按完整音频计算时会把未请求生成的区域计为空白，不将这些人工保留范围用于判断模型异常长空白。没有做全曲音乐质量验收，也没有重复全项目测试。
