# chart_stream_v1：尾部与重复配置的训练根因审查

日期：2026-10-18。审查基线：`4f77334`。

本轮是全链路定位和受控推理实验，没有改变模型结构、损失函数、采样规则或正式权重，
也没有把构造的错误前缀写入训练集。当前未发现仍在运行的训练进程；最后保存为
`Prism_stream_v3_fresh_20261018/stream_step_00011000.pt`，epoch33、batch1216/2710，完成32整轮。

## 结论

存在明确的“正确前文依赖”与生成反馈问题，不能把本次现象全部解释成训练轮数不足。
当前模型能读取前面的配置；问题是它可以依靠前文套路、语法和时间数字拿到较低 loss，
却没有同样强的机制把每个事件与眼下音乐相联系。进入非原谱的重复前缀后，连结束判断都会退化。

这不是已证实的“错歌串样本”或“训练把段落末尾标成 EOS”。在已检查路径中，音频合同一致，
EOS 只在整谱末尾，持续状态取已提交前缀，没有发现新的未来目标泄漏。

生成端也参与了放大：本次前40事件的独立对照确认 Style 配置平衡偏置是开头32连点的触发因素，
手感可行性偏置不是该段触发因素。音频倒序会改变自由生成，因此不能说模型完全没读音频。

## 实验设计与边界

固定 step11000，不更新参数。种子381从正式 manifest 抽取48个歌曲条目，筛得32张合格谱面；
每张取中间和末尾计算块，共64块、51,958个目标token。原来源不存在质量标注文件，
因此抽取清单没有遗漏本次实际启用的标注。GPU只运行推理；本轮没有启动训练。

这是对训练来源的诊断抽样，不是独立验证集，不估计泛化水平，也不宣称这些比例代表全部语料。
删除历史、清零或置换声学内容是反事实输入；它们可能超出训练分布，不能把 loss 变化比当作
各分支的贡献百分比。构造前缀仅用于诊断，不附接原谱后续配置来进行训练。

## 1. 学得最多的是正确前文，不是音频的发生顺序

所有声学干预保留原时间坐标和条件向量；倒序仅作用于前102个声学/节奏通道。

| 输入 | 总体 CE | 配置字符 CE | 总体 token 准确率 | 真实末尾 EOS 准确率 |
| --- | ---: | ---: | ---: | ---: |
| 原输入 | .33368 | .69631 | 88.40% | 26/32 |
| 声学倒序，保留坐标 | .34306 | .71220 | 88.09% | 22/32 |
| 换成其他歌曲声学，保留坐标 | .34865 | .72371 | 88.00% | 23/32 |
| 声学置零，保留坐标 | .39152 | .78369 | 86.70% | 29/32 |
| 删除跨块历史 | .75241 | .74511 | 78.45% | 0/32 |
| 条件小数舍入至2位，level保留 | .33372 | .69637 | 88.39% | 26/32 |

这是“声学顺序影响偏弱、正确前缀影响很强”的证据，不能扩大为“完全没有音频影响”。
条件小数舍入几乎不改变结果，**没有证据支持本轮猜测的条件末位小数被当成谱面ID**。

对应代码：`stream/data.py`直接使用原谱前缀；`stream/train.py`正常监督没有历史遮罩/恢复课程。
`condition_null`虽然有接口，但当前 dataset/训练循环没有实际采样它。普通 Dropout 不等于这些课程。

## 2. 结束判断和“前文长得像原谱”纠缠

在上述32张谱面的真实末尾保持音频、事件拍位、BPM/first和请求条件不变：

| 末尾之前的配置 | EOS被选为最高概率 | EOS−AT均值 |
| --- | ---: | ---: |
| 原谱 | 26/32 | +1.252 |
| 全谱按键旋转一格，保持类型与时值 | 23/32 | +0.874 |
| 所有已发生事件改成同拍位单Tap `4` | 0/32 | -8.492 |

单Tap干预同时改变了配置类型、token长度和持续动作，因此它不是孤立某个类型的因果归因。
但它直接显示：音乐和拍位已经到真实末尾时，重复单Tap前缀足以破坏当前结束行为。
这与用户实际生成先陷入循环、再继续在尾部写音的现象相符。

训练时始终给正确的前文，生成时读取自己生成的前文。低训练 loss 不保证模型能从错误循环中恢复。
EOS每谱只有一个，在本次正式数据10,127,145个token中占1,787个，约0.01765%。已有额外AT/EOS
目标仍按有效决策位置平均，不能仅看其很低的均值断定结束能力已好。另一方面，当前真实前缀
EOS已有26/32正确，故“完全没训练到EOS”也不成立。

尾部曲线指导只是剩余头数的Poisson零计数近似；低负荷的非零预测会积成非零剩余头数，
它不是学习过的独立“音乐已结束”分类器。继续提高该旋钮或按响度裁切都不能代替根因修复。

## 3. 总体token准确率显著高于完整配置准确率

在同一64块上，采用真实前缀、每个字符的argmax：

| 指标 | 结果 |
| --- | ---: |
| 总体token | 88.40% |
| 拍位字符 | 94.12% |
| 配置字符（含时值/符号） | 76.18% |
| 括号外按键/位置字符 | 63.64% |
| 完整拍位 | 79.61% |
| 完整配置（含结束标记） | 42.09% |
| 完整事件（拍位+配置） | 36.45% |

4,659个完整事件中只有1,698个全部预测正确。以上仍是给定正确前文的结果，不能等同自由生成。
主损失把易预测的结构标记、拍位数字、时值字符和困难的摆键混合；该设计并非数值实现错误，
但总体均值不能代表配置学习完成度。单纯延长训练是否改善完整事件，需要用同一诊断样本复查。

## 4. “任意有理数输出”没有补回被压缩掉的局部声学证据

`form/rational_audio.py:37,833`把全曲节点上限设为1024。
`stream/decoding.py:100`在生成开始编码一次；后续事件不重新查询当前拍位附近的更细波形证据。
`stream/model.py:155`加入的是token序号位置编码，没有把当前已知Fraction/秒数作为decoder查询坐标。
音频节点自身有进度、BPM、相位等数值，因此不是所有时间信息都没有；问题在解码查询与音频时间
之间缺少直接数值桥接，网络需要从字符串和上下文推断这种对应。

- 报告歌曲全曲1024节点，最大相邻节点间隔 **.32424秒**。
- 抽样32谱的起音落在某个输入节点15ms内的比例，按谱平均 **68.23%**。
- 各谱“最近节点距离的90分位数”的中位数为 **112.01ms**。
- 查询频谱窗口本身有宽度，节点距离不等同模型实际误差；但细节未必被局部测到是真实瓶颈。
- 对报告歌曲，同音频/BPM/first，训练准备15秒区域与生成准备999秒区域得到的全曲查询张量
  **逐元素完全一致**。没有证据表明此处训练/生成音频合同错位。

节点不是输出拍位网格，不能据此说模型只能写固定分音。然而输出可表达任意Fraction也不意味着
输入保留了每一个细节，更不意味着网络已经学会把数字字符串与相应声音关联。

## 5. 原设计中的几项核心能力仍是实现缺口

- `context_router`在`encode_audio`中由全曲摘要和条件计算，整曲生成只计算一次；它不是逐事件的
  近期/远期/当前音乐意图路由。Decoder自身的注意力仍然逐token变化，不能把二者混为一谈。
- summary只压缩近期history；`StreamMemoryBank`写入档案，但生成没有把其远期检索结果作为已训练
  分支输入。旧song_form的recurrence模板也没有进入此模型，循环不是由模板分支硬复制出来的。
- `plan_head`八维中，生成实际使用第0维间隔作候选偏好；类型等其他维度仅有辅助监督。
  `TypeGuidance`的planner强度固定为0，不能把它描述为完整的前瞻写作计划。
- 当前没有独立事件/音频对齐目标，没有合格的“生成错误前缀→纠正续写”课程。
- 曲线头在每个chunk重复监督整曲，chunk数受谱面文字长度影响；非均匀音频节点的曲线loss按节点
  而非时间积分平均。抽样每谱4–8块。这是需要进一步定量修正的权重风险，尚未隔离其生成影响。

因此，当前实现还不是原设计中完整的“整曲可查询音频记忆＋逐事件意图＋可检索的谱面档案”。
这是能力缺口，不能靠把已有参数维数继续放大来宣称已经补齐。

## 6. 生成Style偏置是此次开头循环的明确触发因素

固定step11000、原歌曲、原条件、原种子1458708206，分别自由生成前40事件：

| 对照 | 与原产物前40事件完全相同 | 最大连续相同配置 |
| --- | --- | ---: |
| 原参数 | 是，40/40 | 32 |
| 只关闭手感可行性偏置 | 是，40/40 | 32 |
| 只关闭Style配置平衡偏置 | 否 | 2 |
| 两项都关闭 | 与“只关闭Style”相同 | 2 |
| 声学倒序，保留时间坐标与原偏置 | 否，首拍也变化 | 1 |

这不是说“Style=0一定是更好的整曲”：关闭后也出现大量Hold，且本对照只覆盖前40事件。
但它排除了“开头32连点必然只来自训练或手感保护”的说法，并反驳“音频对生成完全无影响”。

`form/type_guidance.py:135,265,358`按整曲累计类型差额，在字符前缀上增加偏置。
其中前缀势能由可完成原子集合的平均分推算，不是模型对完整配置的真实条件概率。
即便目标只是调整类型占比，它也会改变结束配置/继续修饰/追加组合的分支选择。
一旦选择不同的首个配置，随后模型会读取该不同前缀；不能把40事件的所有变化逐项归给同一个偏置。
当前实现没有按整曲音乐阶段分配类型，也不承诺低pattern_reuse就不会出现连续单键：
`event_quality._motif_stats`明确把恒定单键模式排除在该指标外，单键重复主要由jack字段描述。

## 优先修复路线与必要验收（尚未实施）

1. **先建立严格因果的数值时钟桥接**。复用旧框架的Fraction几何思路，把已提交拍位/秒数、
   事件距离与音乐距离提供给decoder。预测拍位之前只能知道前一事件；读到`<note>`后才能使用
   当前拍位。必须用“改变未来目标，当前输入不变”的回归阻止再次引入目标时间泄漏。
2. **全曲概要与当前局部证据分开供给**。保持可看后续音乐的全曲视图，同时按当前已知时钟查询
   原生音频细节。窗口是计算/证据范围，不能成为音乐分段、不能重置EOS、不能限制可输出Fraction。
   优先复用非均匀`audio_queries`与缓存，测显存和速度后再选预算。
3. **增加按谱师选音监督的位置关联与独立结束学习**。监督选中的谱面事件与对应音乐，不要求每个
   瞬态都有音符。结束分支应能依据已知时钟及后续音频判断，不强依赖原谱的特定配置形状。
   保留完整谱面才有真实EOS；不能给任意截断段落添加EOS。
4. **加入有明确语义的前缀鲁棒性训练**。先保证时钟不随遮罩丢失，再对已知历史作遮罩或合法变体。
   错误前缀只可监督不变的结束/继续决策或明确修复目标，不能随便接上原谱后续字符。
5. **以完整事件/配置及分组指标判断训练**。考虑事件均衡的辅助目标和时间积分曲线权重，保留
   原token目标用于语法；不能仅靠重调loss比例就宣称音乐改善。
6. **单独重做Style额外指导的完整配置评分**。可用有界的完整配置候选和终态加权，避免字符前缀
   偏置扭曲配置结构；必须检验相同类型的候选相对概率、实际整曲重复、速度与类型比例。
   本轮不会用强制每N拍换类型或硬去重掩盖模型问题。

前1–4项涉及新的训练合同，旧权重应保留兼容生成，并通过显式finetune迁移或fresh学习。
当前并没有新合同训练结果，因此不能把这些计划写成“已修好”。
