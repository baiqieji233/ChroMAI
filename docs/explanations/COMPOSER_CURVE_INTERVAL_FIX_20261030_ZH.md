# 模型强度曲线周期性高低跳变：原因与修复

用户报告关键点一高一低跳变。实际查看12:57生成的 `webui_workspace/intensity_curves/1331b8e4bcce_automatic.json`，可见强度在1秒附近接近0、3秒约0.69、5秒接近0，随后周期性重复。异常已存在于保存的数值，并非画布显示问题。

## 原因

新模型预测10毫秒格内的起音事件率/头数率。即使一段音乐物量稳定，起音附近仍应高、起音之间仍应低。原 `stream_curve.profile_from_predictions` 每2秒只在中心时刻取一个格，再把它称为这两秒的强度。固定采样会轮流碰到拍点和拍间，把正常的细节律动错误显示为段落强度的高低起伏。

## 修改

对每个编辑区间先累计预测头数与事件数，再除以真实区间时长，最后转换到强度。源网格按每格实际曝光时长积分，末尾不完整区间使用实际长度；首尾控制点沿用相邻区间结果。休止诊断概率同样按时间平均，不生成新的强制休止规则。

这不是对曲线做任意平滑。区间物量严格来自原预测，训练权重、瞬时选时信号和总物量均不变。不需要重训或中断当前训练。

新输出包含 `curve_aggregation_policy=time_integrated_bins_v1`、原预测的区间边界与区间率，便于审计。强度到速率的可逆映射、曲线编辑的参考基准保持一致。

## 运行服务的生效限制

7861为用户正在使用的生成服务，7867另有训练进程。自动审批拒绝了停止7861的操作，也拒绝在7862启动新服务；两次仅返回 `blocked by policy`，没有更具体理由。没有换其他方式结束或启动服务。
