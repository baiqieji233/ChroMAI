## 实施与验证

阶段 A 已完成：

- 固定上下文上限，超过总预算的窗口直接丢弃；不使用真实目标长度扩大或缩小历史。
- 额外修正生成侧重复扣减上下文预算：完整预算现在只计一次，并输出总预算/正文余量日志。
- 按用户偏好，新训练上下文默认从 192 提高到 768；旧 checkpoint 生成继承自己的数值。加强训练可在固定模型容量内调整此上限。
- 抽样 90 个有效难度、2,332 个 16 拍窗口，历史内容最大 382 tokens，512/640/768 三种上限实际用量相同，总长度最大 662。未占满的上限不增加计算；尾部极密样本的开销仍可能增加。GPU 正被其他 Python 进程使用，未竞争运行 GPU 基准。
- 纠正原审计标签：Prism_v3 记录的 193 个所谓 token 超限实际全部是 checkpoint 词表不含目标拍位。现在将 `vocabulary_mismatch` 与 `segment_token_limit` 分开记录，二者均丢弃，不扩大词表或拆窗口。
- `input_policies` 记录池化、上下文预算、谱面过滤版本；新训练/加强训练默认修正策略，严格断点续训保留历史策略。
- `?` 星星完整原子过滤，源文件不改写，日志/审计保存删除记录。旧预处理调用保持兼容。
- 候选按解析/检测覆盖、可处理硬无理、原质量分进行分层排序；仅报告类别不作为强制处罚。
- WebUI 独立显示音频池化；验证集可留空，best 与学习率调度的依据清楚显示。

阶段 A 验证：123 项 Python 定向回归通过，5 项 Node 测试通过，JavaScript 语法检查通过。包含 CPU 微型训练/续训/加强训练闭环，不涉及现有模型或真实训练任务。

阶段 B 已完成，使用说明见 [SUSTAINED_ACTION_MEMORY.md](../compatibility/SUSTAINED_ACTION_MEMORY.md)：

- `action_state_profile=auto|none|sustain_state_v1`：自动继承，旧模型/新训练默认关闭；加强训练可明确新增。
- 将前置 Hold、Touch Hold、Slide、Wifi 的当前路径区域、等待状态、进度和剩余时值作为独立编码器输入，最多 32 个动作、每个 50 维；不改 planner 目标维数或事件词表。
- 训练按完整历史建立摘要；生成按已接受的历史谱面重建，跨窗口修复/回溯后的新历史会进入下一次生成。模型输入不使用边界时刻及之后的谱面目标。

- 已排除或零权重的历史事件不会通过摘要重新进入训练输入。偏好训练的正、反候选共享原始前置状态，修正版目标不反向改写状态。
- CFG 条件和 null 分支读取同一份动作历史；只有条件向量改变。曲线单独预测尚无谱面历史，显式使用空摘要。
- checkpoint 记录摘要合同、完整权重和有效更新次数；新增模块没有有效训练更新时允许继续训练，但拒绝直接生成。偏好更新和普通训练更新均计数，AMP 跳过的更新不计入。
- WebUI 训练选择、后端转发、checkpoint 检查、生成能力说明同步；三个离线评估工具恢复 checkpoint 的输入策略和摘要配置。
- 复核补齐修正版谱面的 `?` 过滤记录、偏好窗口预算一致性，以及前端默认上下文测试。
