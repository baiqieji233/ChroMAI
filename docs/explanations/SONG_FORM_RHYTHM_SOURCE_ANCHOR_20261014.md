# song_form 起音量化与局部节奏纠正修复

日期：2026-10-14。修改范围为生成侧；未改变模型维度、checkpoint 权重格式或训练数据合同，不需要重训。

## 已确认的问题

当前起音模型使用 50 Hz 音频帧，即每 20 毫秒一个预测位置。把秒数换算成拍数不会放大实际时间误差，但连续两次投影到不同网格可能选择错误节奏。

原流程先把音频帧峰投影为有理拍数，再执行“逐点最近”。第二次排序参照的是第一次投影后的时间，原始峰只参与容差检查。第一次投影恰好落在 16/24 候选的中点时，浮点等距误差可以使更远离原始峰的候选获胜。

实际生成 `de21847fa9df` 中：原始峰 31.280001 秒，第一次投影 31.288462 秒。16 分候选 31.269231 秒离原始峰约 10.77 毫秒；最终却选到 24 分候选 31.307692 秒，离原始峰约 27.69 毫秒。

实际生成 `295927c14ec7` 已使用“局部节奏一致”，仍有两段 16 分混入 12/24 分。原因包括相同的逐点预处理问题，以及局部规则隐藏的 20 毫秒原始峰保护、含少量缺口音列必须至少修改两个点的限制。其中一个预期 16 分位置离原始峰约 23.08 毫秒，旧的整串纠正因此跳过。

## 本次修改

- 所有逐点候选以原始峰 `source_second` 排序，保留旧投影时间与原始峰时间的双重位移保护。候选误差按纳秒精度稳定处理等距排序，避免歌曲后段浮点差异决定 16/24 选择。
- 局部纠正仍保护真正的三连、附点、混合节奏、变 BPM 边界、休止、音频边界及邻居间距。
- 允许少量缺口音列修正一个错位点，不再要求至少两个；仍检查整串拟合误差、两端位置及收益。
- 对稍超一帧的峰漂移，只有至少五个点、两端稳定、多数点独立支持网格、整串 RMS 不超过 15 毫秒且没有推翻精确原始证据时，才允许额外纠正。不会因为只看到一个偏离峰就把三连改成 16 分。
- 新增可调 `rhythm_snap_source_ms`，贯通 CLI、主 WebUI、有效配置、生成报告与 `form_rhythm_snap` 日志。

## 新参数如何使用

主 WebUI → 生成谱面 → song_form 起音与节奏设置：

| 参数 | 含义 |
| --- | --- |
| 近似到常见分音 | 开启后才执行这些网格修正 |
| 最大采音偏移（毫秒） | 相对第一次投影位置允许移动多远，原参数 `rhythm_snap_ms` |
| 原始起音允许误差（毫秒） | 修改后的候选离模型原始峰最多多远，新参数 `rhythm_snap_source_ms` |
| 分音规整方式 | 推荐“局部节奏一致”，结合前后音列；逐点只比较单个峰 |

新参数默认 **30 毫秒**，可设置 **0–50 毫秒**。两项上限同时生效，并保留变 BPM、邻居和休止等保护；局部算法还有 BPM 相关的三连分离保护，所以较大的用户上限并不意味着一定会移动到那么远。

普通局部纠正仍按当前音频帧周期保护（50 Hz 对应 20 毫秒），但它不再是所有情形固定的最终上限。明确的前后网格证据可以放宽到用户填写的新上限；填 20 会禁止本次 23.08 毫秒的纠正，填 30 才允许。逐点方式同样受新上限约束。

设为 20 更保守，30 可处理本次约 23 毫秒的局部偏移。提高原始误差时，应同时确认最大采音偏移足够，否则另一项上限仍会阻止移动。超限保留原有音符时间，不删除音符。设为 0 不移动网格候选。

复现本次音列可以沿用最大采音偏移 50、原始起音允许误差 30、局部节奏一致，以及原候选 4/8/12/16/24/32。此组合用于本次故障复核，不是所有歌曲的统一最佳参数；更小偏移可先使用 20–30。

CLI 新开关：`--rhythm-snap-source-ms 30`，与 `--rhythm-snap --rhythm-snap-mode sequence --rhythm-snap-ms ...` 配合。

## 为什么还可能出现 {48}

候选分音选择控制起音位置，不是 Simai 导出标签白名单。例如一个点在 12 分网格，下一点在 16 分网格，两点相差 `5/12` 拍。无损编译器可能使用 `{48}` 加空白过渡来编码该间隔；不代表两音符之间只有 48 分间距。

本次原谱中有 2 个 `{48}` 标签，但 48 分实际相邻起音间隔为 0。使用相同原始起音重放本次修复后，这张谱面里的 `{48}` 标签为 0；没有全局禁止或替换 `{48}`，其他合理的混合网格谱面仍可出现它。

只删除标签会移动音符，不能解决采音误差。本次保持精确编译并补充 WebUI 说明。
