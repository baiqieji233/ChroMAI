# Composer 有序短句修复说明（2026-10-31）

## 这次修什么

最近两次生成都被实际检查指出存在配置组织、手顺和句间衔接问题。能继续出音符、硬冲突少，不能代替整段写得合理。本轮针对的是：让模型参考真正写过的一段配置，并把当前短句意图和已经生成的动作联系起来。

目前只能确认代码增加了这些学习和评价路径，不能据此宣布生成质量已经改善。两次产出的参数不同，也不能直接当作严格的单因素 A/B。

旧系统并非完全没有序列监督：主事件模型一直按因果顺序学习时间与 shape、phase、detail 的联合预测。缺口在额外的短句记忆。`causal_phrase_v1` 把一段压成96维统计，虽有四个相对时间分桶，仍无法保留精确事件顺序、完整 Slide 路径和时值。统计相近的两段，实际配置和操作过程可能完全不同。

## 数据：保留有序配置，控制重复开销

新策略名为 `ordered_phrase_v2`，原来的 `off`、`causal_phrase_v1` 继续保留。

每个档案事件保存 kind、shape、phase mask、完整 codec atom IDs，以及原来的 beat、second 和两种 gap。atom IDs 保留对应音符的路径和时值。原96维统计也保留，供密度、动作族和进展等粗尺度信息使用。

每段档案最多32事件。超过32时按时间顺序覆盖整段，保留首尾；**这个上限只限制参考档案，不截断原谱、不改事件时钟，也不减少主事件自回归训练目标**。超长段进入 GRU 的是抽样档案，不能称为所有事件都被无损编码。

同一批样本中的相同参考段只存、编码一次，通过 `phrase_sequence_inverse[B,T,4]` 指向唯一段表；没有参考时为 `-1`。增强后的档案有独立身份，不能和原谱同段错误合并。段表及缓存按字节估算计入已有预算，音乐布局仍共享，不重新提取整曲音频。

参考必须已经结束，且其中最后一个事件的索引严格小于当前 query。当前段尚未提交的真谱不会进入参考表。未来完整段只出现在独立的 `target_phrase_sequence_*` 表中，由 loss 消费；forward 不读取该表。恢复和前缀增强样本关闭不可信的未来辅助目标，目标 inverse 为 `-1`。

完整、未抽样序列的 fingerprint 保留作来源诊断。对比学习的 positive ID 则依据 **GRU 实际能看到的最多32事件**：完整 atoms、配置及相对 beat/second/gap，不含绝对歌曲位置或 padding。只在未抽样事件上不同的两段，模型无法从档案中区分，必须共享 positive ID；可见配置不同才区分。另提供 visible fingerprint，方便核对这两种身份，避免把不可区分的输入硬当成负例。

## 模型：有序段、音乐与当前前缀一起参与决策

新支路用一个小 GRU 顺序编码唯一段表，复用现有 kind、shape、phase 和 atom embedding，不新增大型编码器。参考段编码和目标段编码共享参数；目标编码仅在 loss 中执行。每个事件内的多音符是一个集合，段内事件之间保留顺序。

配置音乐支路另设投影：从已有音频编码的 local 表示投影到64通道，再按段汇总。它复用原音频编码，不新增音频提取，也不把时间间隔支路当成配置音乐信息的唯一来源。

生成时整曲投影只计算一次；训练中，同一歌曲、同一起止拍位的音乐区间也只读取和汇总一次，再供多个 query 共用。旧32通道音乐支路保持原样，避免改动原模型的行为。拍位与秒数使用独立的查询时钟，不能混用缓存。

段意图继续由当前音乐、条件和已完成参考预测。decoder 得到因果历史后，再将意图、当前段进展、两者交互、真实前缀 hidden 及剩余跨度一起送入动作残差支路。这样提供了“已经写成这样，后面如何兑现意图”的学习入口；是否学会连贯配置，仍要看训练与实际产出。

新增音乐锚点、参考融合和动作交互的输出残差采用零初始化，以便升级时承接原行为。刚加载新模块时，零残差也意味着新能力尚未生效；日志中的各项 residual RMS 可帮助判断支路是否开始参与。

## 损失：沿用原预算，不再叠加一份完整辅助权重

原主事件损失继续保留。`ordered_phrase_v2` 把原短句辅助权重拆成两半：一半给96维统计预测，一半给有序配置目标。默认 `phrase_loss_weight=0.05` 时，分别是 `0.025`。

有序配置损失内部结合余弦对齐和双向多正样本匹配。余弦对齐把目标当作固定答案；匹配部分同时训练意图预测器与配置编码器，避免编码器只能靠参考侧主损失间接学习。目标不会进入预测输入；在计算损失时使用真谱答案与把未来答案送进模型，是不同的事情。样本中重复 query 的段预算由数据权重分摊，不把同一目标重复当作多份完整监督。恢复、增强等没有可信目标的样本不计算该项。日志记录编码区分度；匹配损失本身不能证明表示永远不会塌缩。

这是新增的配置学习约束，不能等同于已经证明手顺合理，也没有直接标注固定左右手。

## 生成软评价：看真实轨迹，仍不规定硬手顺

软手感评价现在读取原生路径与持续时间，覆盖 Hold、Slide/Wifi 和 Touch 的二维位置，在有限 beam 中尝试无左右手标签的两手分配。它考虑持续动作占用、移动和交接，不要求所有人采用同一种操作法，也不作为物理合法性的硬拒绝条件。

轨迹采样、有限 beam、Touch 接触分组及分数权重仍是启发式近似。报告保留覆盖范围和未知项，不能把“已知路径分数高”说成完整可玩性认证。

衔接评价只使用已经提交的动作和当前候选实际生成的后续内容；没有生成的下一句不会被假装看过。原生硬可行性仍由 guard 单独检查。

默认 `phrase_candidates=1` 时，软评分只用于诊断，不会因为分数低自动多写几份再挑。使用2或4分支时，才在同跨度、硬可行的候选之间排序。报告记录各候选分项和胜者原因，便于发现“物量变少所以评分变高”等偏差。评分尚未经过人工偏好校准。

## 已完成的验证

原 v36 第8轮、3152更新点的完整检查点与推理点均已复制到 `.scratch/ordered_phrase_repair_20261031/`。再次核对 SHA256，原文件与副本一致，没有覆盖原检查点；本轮没有启动正式训练。用户最近两次生成使用的是第3000更新点，因此这里不是对那两份旧产出的逐位复现。

Python 全量回归4379项通过、13项跳过；完成最后的辅助损失与性能修正后，相关790项再次通过，音乐时钟与输出/梯度等价专项9项通过；界面186项通过。覆盖未来目标不进入 forward、参考仅来自已完成前缀、训练与推理输入一致、增强/恢复目标关闭、持续动作撤回后重建、旧权重零步升级输出不变，以及非零新增残差下的区间共享等价性。性能优化使用FP32容差 `1e-5`；真实BF16探针的最大差为 `0.001953125`，选时/动作类型/phase的argmax一致，不能把它说成所有浮点数逐位相同。

真实短训两组都从同一 v36 权重出发、重置 Adam，使用相同64张谱、种子73、样本顺序、batch16、学习率0.0001、预热20步，各更新128次。只切换短句策略，保留原恢复、增强和其他策略。没有全量重建准备缓存。相同第一批的主配置损失均为 `1.5957259`。

在固定64个真实参考窗口上，父模型、旧方案短训、新方案短训的主配置损失分别为 `4.89580 / 4.56492 / 4.56372`。两种短训接近，不能声称新方案学习速度显著胜出。新方案调换参考段内配置顺序后，phase logits平均绝对变化约 `0.00213`；三个新增残差RMS分别约 `0.0546 / 0.0523 / 0.0177`，说明支路已参与。参考窗口已被父模型见过，这不是留出集泛化证据。

### 关于细节 loss

这批64窗口中，按动作类别看，持续动作贡献约占细节损失的93%；按编码方式看，字面量配置约占7%，两项可能重叠。这是这批窗口的结果，不代表全语料。Slide需要同时猜对路径与时值，当前细节项计算这些答案的联合概率；它不是单次“猜哪个键”的平均分类损失。主损失公式本轮未重写，也没有通过改分母让数值显得好看。

新日志把细节项拆成常规配置/字面量、原谱/扰动，并额外记录持续动作的重叠子集。前两对各自相加等于原细节项；持续动作项不能再加一遍。新的有序辅助目标改变了总loss组成，因此判断是否学得更好应先比较相同的主配置损失，不能直接比较新旧总loss。

## 下一步与尚未解决的边界

在主界面新建训练中，“短句组织与呼应”选择“有序配置短句（新版）”，或者在新阶段使用“自动”；默认短句辅助权重仍为0.05。用新目录微调或从头训练均可，原 v36 保留作对照。生成默认单分支；若要实际使用软手感选优，可显式选择2分支，但需要额外耗时，并继续检查是否偏向保守少写。这里不自动启动正式任务。

新支路提供完整顺序配置的学习入口，尚无真人手顺标签或人工偏好校准；32事件档案和最多四个参考也不是无限记忆。远段检索仍依赖粗音乐描述，可能漏掉值得呼应的段落。呼应是否出现、何时不该照抄，仍须通过训练和完整谱面验收，而不能靠给所有相似片段加复制规则。
