用户已授权架构、训练、生成、前端全量修改，并允许停止训练及 GPU 验证。旧 event 与 song_form_v1 checkpoint 继续使用原生成算法。2026-10-15 用户已允许并行审查；本次由主代理整合，子任务分别审查训练、音频缓存及主 WebUI。

## 用户注释的具体落实

1. 最初的节拍事件设计应恢复：新路径依据音乐事件和节拍查询音频，谱面时间不由固定秒数帧决定。
2. 新模型直接学习有理数事件位置，不再从 50 Hz 概率峰推断拍位。既有 Fraction codec 保留，训练与生成同时移除正确未来骨架。
3. 不保留 50 Hz 语义分支作为新路径的依赖。数字音频的原始采样点与谱面时间表示区分；读取数字音频不意味着把事件位置限制到采样点或任意固定节拍网格。

## 唯一实施方案

新模型族 `song_form_v2`，输入/规划合同独立。联合事件解码器输出 canonical Fraction 拍位与 note 配置；任意分母由数字序列表达，不建立固定分音白名单。单调性、有效音频范围、休止与 token 预算作为明确约束，禁止偷偷进行最近帧/最近分音修正。

音频依据原波形瞬态候选、节拍/变速/拍号锚点构建不等间距记忆；锚点读取原波形频谱与能量，使用真实时间及节拍相位。候选是声音证据，不是模型唯一可选事件位置。低于采样精度的信息不会被宣称存在，波形采样率也不是生成时钟。

全曲 Planner 预测负荷曲线与结构条件，不再输出逐帧起音 Gaussian。配置模型直接学习采音取舍和配置，共享歌曲结构、历史、motif、持续动作、等级、Radar/Style 与曲线。修订保持局部编辑流程。计算上限仍按音乐区域/资源分配，不能再次变成固定16拍创作单位。

旧 `song_form_v1` checkpoint 保持原音频、Planner 和解码路径；新合同不把旧权重假装成已经学会新音频/自由采音的模型。新版本需要训练，旧模型仍可用于对比和生成。

## 本轮验证与性能修复

- `PositionGrammar` 现在使用精确可达性检查、前缀缓存、等价分数 canonical rewind，以及明确的最小事件间隔和增量分母安全界限。它仍不使用 `{16}/{24}/{32}` 白名单；短跑模型输出的巨大分母会被丢弃当前未完成事件，不会把整首歌判失败。
- song-form 解码器额外缓存每层 cross-attention 的 encoder K/V；rational 音频查询保留原生瞬态与 Fraction 拍位，但生成时与训练共用有界的 1024 个最强原生证据节点，避免长音频把每个单 token 解码步骤拖到数千节点。
- Planner 负荷只提供宽松的每段事件资源预算；`0` 表示自动预算，CLI/WebUI 可设置 `max-events-per-span`。另有 `rational-min-spacing-ms`（默认 2 ms）用于阻止物理上过近的事件。这两项不把位置吸附到固定分音。
- 自动 BPM 提示改用既有全局节拍检测器的临时 onset envelope，而不是原生攻击间隔中位数；实际 `BUDDiES/10185` 从错误的约 189.4 BPM 回归到 150.0 BPM。临时 envelope 只用于提示，不能成为模型位置时钟。
- GPU 生成回归：5 秒探针、`song_form_v2` checkpoint、CUDA、`max-events-per-span=12` 成功生成 `maidata.txt` 与 `.form.json`，3 个区域共 8 个事件，报告声明 `frame_seconds=null`、`candidate_position_whitelist=false`。此前的 `No exact rational continuation` 已不再出现。该 checkpoint 只有 1 个 epoch，输出仍会有不规则 Fraction，这是训练未收敛的质量信号，不是固定帧转换错误。
