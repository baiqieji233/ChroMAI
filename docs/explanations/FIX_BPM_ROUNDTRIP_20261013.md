# BPM 导出精度与任务失败状态修复

日期：2026-10-13。

## 故障与根因

失败任务 `25ad4e826d24`，日志为
`webui_workspace/logs/20261013_075419_form_generate_25ad4e826d24.log`。
同一音频的前一次任务 `e5c054951ea6` 也出现相同错误。

自动识别后的 BPM 为 `92.54999999999788`。生成器在构造空的前置持续动作摘要时，
调用 `compile_event_points()` 临时导出 simai。导出函数 `_format_number()` 将 BPM
截为三位小数，写成 `92.55`，但严格回读校验仍与未截断的浮点值比较，导致生成开始前退出。
同一格式化函数也用于 `first`，因此高精度音频偏移有相同隐患。

WebUI 的 `api()` 又把 HTTP 200 任务记录中的 `error` 当作请求失败抛出，
使轮询器重复重试已经终止的任务，并显示“状态读取失败，正在重连”。

## 修复

- BPM 与 `first` 用可精确回读为原浮点数的十进制文本导出，科学计数法展开为普通小数，兼容 simai 指令。
- 保留音符有理数拍位、变速点位置和严格回读校验，不通过放宽容差掩盖实际时间轴改变。
- WebUI 允许成功的 `/api/task` 响应携带任务错误。终止的任务显示失败日志、释放回调并停止轮询。
  HTTP 错误、网络错误及缺少合法任务记录的错误响应仍进入原有请求错误处理。
- 不改变模型权重或训练合同，不需要重新训练。

## 验证

- 修改前用 `SustainStateIndex([], [EventTempo(0, 92.54999999999788)], 0)` 复现相同异常。
- 编译、窗口时钟、持续动作和显式 tempo map 定向测试：68 项通过。
  新增用例覆盖长小数 BPM、变速、正负高精度 `first`、极小值普通小数输出、空前缀及实际错误仍被拒绝。
- 前端轮询回归：5 项通过，覆盖任务失败、持续运行、网络重连、POST 错误和无有效任务记录的 GET 错误。
- 实际浏览器读取原失败任务：显示“失败”、保留原回溯、禁用取消按钮；3.3 秒观察期间未重试，未出现脚本异常。
- 按失败日志中的原始 CLI 参数重跑，仅改为隔离的输出路径；约 26.7 秒完成，退出码 0。
  共 1384 个起音事件、1604 个语义音符，`syntax_valid=true`，曲线应用记录保留。
  `playable_verified=false`，这次验证只证明本次生成阻断已消除，不等于音乐性和可玩性验收。

复跑产物和记录保存在 `.scratch/bpm_roundtrip_fix/`：
`maidata.txt`、`maidata.form.json`、`replay.log`、`replay_summary.json`、`browser_summary.json`。
这些是本地验证产物，不纳入 Git。

## 使用

刷新 WebUI 后重新点击生成即可。旧失败任务属于历史记录，仍会显示其原始错误；新生成子进程会加载修复后的代码。
