# Composer 下一阶段改进方案与实际边界

最初方案：2026-10-27。复核修订：2026-10-28。适用`chart_composer_v1 / audio_grounded_v3`。

本文已按源码和复现实验更正。此前关于“100%解决争抢”“loss必然快速下降”“训练15分钟以内”的说法没有相应证据，不再作为实施结论。具体修复见[实施记录](COMPOSER_SCHEME_ABC_IMPLEMENTATION_LOG_20261027_ZH.md)。

## A：让配置分支更方便地读取后续音乐

新增模块直接读取未来0到8拍内的候选音频，并结合相对位置形成残差。它为配置分支增加了明确的读取通道，但原模型的音频自注意力已经融合多个候选，不能把原架构说成只看孤立的一点。

边界是候选网格，而非连续音频帧；窗口外的信息仍可能经原编码器进入。新增模块的投影从零开始，不改变旧模型初始输出。代价需要在真实词表和GPU环境下测量，目前没有“开销小于2%”保证。

## B：把“选类型与起点”和“选具体变体”分开

将合法音符按类型及实际起始位置集合分组。独立宏观头决定组总概率，组内分布决定轨迹、终点、修饰和时值等具体变体。Touch位置也分别建组，组数由词表决定，不是固定46类。

这种分解可以避免某个组仅因内部细化分数变大，就自动增加它的总概率。生成时也必须保留相同分组，把动作温度与截断限制在组内。仅修改模型输出、继续使用原来的大类采样，不能保持这个性质。

它不保证Slide、Tap、多押和Touch的比例一定正确，更不保证生成的乐句好听、顺手。共享主干仍同时学习多项任务；组内细化仍计算全词表。当前也没有额外实现“整拍形态先验头”。需要用同数据、同预算的训练对照检验，不能从归一化公式推断学习速度。

从旧平面动作头切换到独立宏观头，需要重新学习该头。应在新目录建立阶段，保留旧模型对照，不应承诺迁移第0步所有动作输出不变。

## C：先测实际等待，再调整训练效率

条件遮挡支持已经打通，默认0，是否提高遮挡概率应另做对照。所有模型内部条件分支必须使用同一次遮挡，否则被隐藏的信息会经规划、负荷等路径返回配置头。

数据准备仍需测量。CPU累计计时包含重叠和异步等待，不能直接换算成GPU空闲比例，也不能据此保证增加线程后的收益。样本准备线程、预取深度应在固定样本顺序下比较整体吞吐、主机内存和GPU等待，再选设置。

同曲微块共享编码尚未实现。全曲规划可能有复用机会；有限长度历史窗口、位置、遮挡和动作前缀的计算则需要单独检查等价性与梯度。它不是把128个历史加上K个事件拼起来就已经完成，也没有每轮15分钟的已验证结果。

## 建议执行顺序

1. 先通过实现回归，确认真实入口、采样、精度和旧检查点行为正确。
2. 用真实数据做短训练，对比宏观选择与组内细化是否学到，记录每GPU小时的进度。
3. 固定歌曲、等级、物量条件和双随机种子，对比重复、分音、Touch、冲突，并试听试玩。
4. 有质量收益后再扩大训练；性能优化单独对照，避免把样本变化误认为架构收益。

v16已由用户因生成质量差而手工停止，本轮审查不自动重启长程训练。旧检查点保留作对照。
