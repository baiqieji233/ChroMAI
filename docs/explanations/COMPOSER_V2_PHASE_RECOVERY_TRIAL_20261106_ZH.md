# v6 分音纠错短训结果

2026-11-06。用户要求只有效果明确时才保留改动。本次试验未达到这个标准，新增训练策略及界面选项已撤回。恢复逐文件核对了修改前的字节。此前完成的采音／配置独立采样功能继续使用。

试验从 v6 的 44,200 步推理检查点初始化，原检查点校验值保持一致。两组都通过主工作台的微调参数适配器启动，各训练 200 次更新。使用训练集内的 64 张谱，其中 32 张含较多二十四分与十六分，16 张为普通节奏，16 张有明显休止。开发集与训练集按歌曲隔离。

对照组保留原有密集／稀疏前文纠错。试验组额外把部分已出现 Tap 的拍内位置改写成另一种细分，并让后续多个预测位置读到这样的错误前文。原谱目标、音符类型、持续动作和正常完整训练样本得到保留。音频查询时钟按实际输入重新计算。该改动无需增加参数、重新提取 MERT，v6 权重严格加载通过。

两组采用相同样本顺序、随机种子和训练配置，微批 4、梯度累积 8、学习率 0.00005、预热 20 步、BF16。训练吞吐为每秒 22.73 和 21.85 个片段，显存张量峰值约 4.1 GiB。两组均没有非有限更新。第二轮开发集损失分别为 0.31836 和 0.31634，微小差别不足以替代自由生成验收。

六份谱均完整导出，严格解析通过，生成器未放行硬冲突。《Strange Bar》增加了一个正确入口，同时出现更长的二十四分连续段。另两首的入口问题仍然存在。固定错误前文的概率回放也只有局部小幅改善。这轮结果支持继续排查选时如何使用音频，尚不足以采用本次分音扰动训练。试验预算为 200 次更新、一个配对生成种子，其结果限定在这个范围内。

用户希望增加“更偏歌曲实际采音／更偏前文”的生成控件。当前 v6 用同一个解码器共同读取两者，没有单独训练的音频选时分布供混合。直接削弱前文也会改变配置衔接和持续动作信息。因此，本轮未加入这一控件。独立声学读出需要另行验证，尤其要检查混合分音、主动留白与连续手法。

初次 8×4 短训的总显存占用接近 11.6 GiB，运行明显偏慢，已在开始正式对照前中止并归档。两组有效对照都采用 4×8。该调整是本机测试配置，项目训练默认值仍按现有主工作台设置。
