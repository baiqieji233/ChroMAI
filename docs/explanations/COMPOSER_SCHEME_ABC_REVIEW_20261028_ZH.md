# A / B / C 改动复核：哪些问题已修，哪些结果还没拿到

日期：2026-10-28。审查对象是基于`375c785`的未提交A/B/C改动。三名子智能体分别负责动作头与采样、未来音频视野、训练和界面接线；主智能体对照保存的修复前源码独立复测，并执行统一回归。

**评价：方案有改进价值，原版的实现和验收都不够完整。** 主要问题不在代码格式，而是模型计算、实际采样与界面入口没有落实同一套设计。原测试能通过，仍不足以支撑“100%解决概率争抢”“必然更快学习”的结论。

## 1. 找到并修复的问题

| 问题 | 实际后果与复现 | 本轮修复 |
| --- | --- | --- |
| 新宏观头仍依赖旧全词表 | Tap目标仍直接推动其他Slide组的细化分数；小例子中这些梯度绝对值之和约0.667 | 宏观组概率独立预测，旧分数仅在组内细化；同一例子变为0 |
| 生成继续使用旧的大类温度截断 | 两个起点组各占50%，仅因内部变体数量不同，温度0.5后变成80%/20% | 正式生成与恢复共用新分组采样；同一例子保持50%/50% |
| Touch只按圈分组 | A1与A2等位置混在一起，宏观头没有决定具体Touch位置 | 按解析出的真实起始位置集合分组；真实词表由35组改为91组 |
| 条件遮挡没有接通，也有旁路 | 正常CLI/API不能设置；即使手工设置，规划、负荷、占用等仍泄漏被遮挡条件 | 打通主界面与训练入口；所有内部消费者共用一次遮挡，保留等级 |
| 新控件可能被旧服务静默忽略 | 页面选择关闭A/B，旧进程仍可能忽略字段，再由新子进程启用自动默认 | 增加明确的后端能力检查，旧服务不能悄悄接受这些请求 |
| 新注意力固定取4头 | 原本合法的30维/6头模型无法启动 | 自动选择可整除宽度的小头数，补足合法尺寸回归 |

另修正了BF16输出舍入问题：分组归一化后的结果保留float32。主智能体在BF16检查中的组总对数概率误差约`2.38e-7`。同时保留了同拍、跨拍位置关系，避免这些有效分支被新的组内归一化抵消；训练批量计算与生成逐槽计算的顺序一致。

条件遮挡的独立复测也覆盖了旁路。修复前，在确保遮挡发生后改变条件尾部，配置上下文仍变化约0.0196，规划变化约0.106，占用分数变化约1.658；修复后这些差值及负荷、历史负荷差值均为0。

## 2. 需要更正的架构描述

**不是固定46组。** 当前真实词表为17,798个音符加STOP，分为91组：STOP 1、Tap 8、Hold 8、Slide 8、Touch 33、TouchHold 33。不同词表的数量可以不同，复合原子按完整起点集合处理。

**“守恒”有具体范围。** 固定宏观上下文时，改变某组内部细化分数，不应改变其他组的概率。合法过滤、Touch保护、类型调节及位置关系仍可有意改变分布；共享主干和参数也仍可能发生学习干扰。它不是音乐质量保证，也没有替代整拍编排能力。

**新头不是计算量缩成几十类。** 当前仍计算合法词表的细化分数，也没有逐个离散属性展开的完整自回归解码。它改善了目标分解，但新增了计算，是否提高每GPU小时的学习效果必须另测。

**“未来8拍”不是整个模型的硬信息边界。** 原有音频自注意力已经融合多个候选。新增模块只限制直接读取哪些候选；它读取的向量仍可能携带窗口外信息。单独打开这一残差分支可以保持迁移第0步不变；切换到独立宏观动作头则需要学习新头，不能同时保证所有旧动作输出不变。

**方案C没有完成吞吐优化。** 本轮完成的是条件遮挡接线与修复；没有实现同曲微块共享，也没有确认多开线程一定更快。小规模CPU对照中，方案A完整前后向中位数约379.9→388.0毫秒，增加约2.15%，且噪声明显；这不能外推真实词表下的CUDA吞吐，更不能保证新增开销小于2%。
