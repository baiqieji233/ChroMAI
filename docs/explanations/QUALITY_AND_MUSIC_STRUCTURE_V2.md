# 质量标注与音乐结构规划（2026-10-09）

质量管理入口是 WebUI 顶部的「训练素材」。选择已有训练集、预处理并检查后，可以搜索歌曲或谱师，勾选谱面，再批量保存优秀、普通、减权、排除或反例标签。系统自动维护标注文件，用户不需要编写 manifest。

## 质量权重与反例

默认权重为优秀 2、普通 1、减权 0.25、排除 0、反例 0，可手动设为 0–4。权重影响 decoder 的监督梯度，也影响完整窗口的 planner 监督。它与 Slide/Touch 窗口增采样共同影响实际学习分布。

局部标注使用音频绝对秒，按音符起音所在区域调整 token 权重。0 表示不学习这些目标，不会把它们改成空谱；区域交叠窗口的 planner 监督被屏蔽，避免把「少学这段」误解释为「这里应该稀疏」。边界穿越的 Hold/Slide 仍按起音归属，不能等同人工可玩性判定。

只有反例没有修正版时，它被排除或局部减权，不会让模型凭空学会相反写法。上传同曲修正版、选择其实际 Simai 槽位、保存配对后，偏好阶段使用同一音频、同一窗口、同一外部条件，将修正版与原版比较。时序、tempo map、文件内容、词表和 token 上限不兼容时会拒绝或记录原因；没有有效配对时训练会失败并提示修正。另保留修正版正向监督锚点，避免只压低反例。偏好阶段必须使用已有训练 checkpoint，fresh 只做质量加权正向学习，随后 finetune 启用配对；不把随机初始化模型当作偏好参考基线。

改变质量标签应使用 finetune（已有模型加强训练），加载已有权重并新建 optimizer。resume 用于严格延续同一数据、标注与优化状态，不能跨质量指纹。独立验证集不加权，也不使用训练的增采样倍率。

## 新规划器学习什么

旧规划器对 encoder 的整个音频 memory 平均后预测 5 个连续量和一个粗配置类别。训练侧还用响度缩放全局密度条件；曲线编辑却直接要求新的密度并事后删除音符，两侧难以对应。

music_structure_v2 分别读取局部音乐、全曲背景与条件。训练目标来自原谱而非响度：音符数量、绝对 NPS、和弦占比、Slide、Touch、Hold、最后起音位置、局部相对负荷与主要配置类别。主要配置按起音单元多数决定，单个 Touch 不会把整窗标成 Touch。

负荷是可解释统计代理：绝对密度结合同时动作、Slide/Hold、连打和较大空间跳跃。曲线 0.5 表示该谱面全曲平均负荷；它不是官方定数，也不是真实情绪标签。高质量原谱帮助模型学习「这种音乐局部，谱师通常采用何种写法」，不能保证恢复唯一创作意图。

训练时将真实局部 plan 与预测 plan 按概率空间混合供 decoder 使用（plan_teacher_mix 默认 0.5），同时 planner 自己受真实目标监督。预测分支仍参与训练，验证与生成只使用音乐预测。这让 decoder 在训练期间见过清晰的难度/配置计划，而不只见过早期不准的预测。

新模型不再把响度倍率乘进数值 null condition；其自动模式直接依赖学得的局部规划。音频输入维度保持 112，但规划器头/融合结构改变，新规划器必须 fresh 重训。auto 在 fresh 时选择 v2，在 resume/finetune 时沿用已有 checkpoint profile。旧 checkpoint 保留 legacy_v1 的原有行为。

## 曲线来源与控制

曲线来源 auto 在新规划器可用时采用模型预测，旧 checkpoint 使用音频特征参考；也可显式选择模型或音频。模型预测使用当前生成的等级、条件与节拍设置；预测粒度由训练窗口决定，编辑器更密的节点只是插值。变化等级、风格、BPM、first 或 checkpoint 后应重新分析。

控制力度 0–1 是曲线对计划的影响。0 旁路手工曲线的密度指导，显式休止区间仍生效；1 达到最大指导。

当前默认 follow 将曲线倍率限制在「强度变化范围」内，同时修改计划并在解码时抑制短段过密；hard 在解码时施加整配置密度上限。soft / strict 保留旧的规划指导 / 生成后过滤用于对照。所有模式都不能凭空补出欠密度部分，上限也不是精确定数控制。精确休止使用曲线页的「标记休止」，并人工检查跨边界的持续动作。完整说明见 [曲线密度反馈与休止](../compatibility/CURVE_DENSITY_FEEDBACK.md)。

音频参考曲线是节奏、频谱、和声与响度代理，不是人类情绪识别。新模型曲线是已学习谱面负荷预测，仍须以固定歌曲的实际生成对照与人工试玩检验。

## 重训建议

使用 full 训练集与新输出目录，例如 checkpoints/music_structure_v2，选择 fresh + music_structure_v2。沿用现有合适的网络规模（320 维、8 层、8 头、1280 前馈）、max_tokens 1024、global_frames 256、context 16 拍、音频 margin 8 拍、context_tokens 320；Touch 增采样保持 1。质量标注先少量标记可靠标杆与明显问题，不要按难度本身判好坏。

先做有限 step 的启动/显存测试，再正式训练并比较固定歌曲。短跑 checkpoint 只证明训练生成链路，不证明新结构音乐质量。记录片段密度、主要配置变化、空白段、边界越界、重复配置、曲线响应与人工可玩性；loss 和 token accuracy 不能代替这些观察。
