# v28训练效率：重复准备与无效细节计算的优化

2026-10-30。适用于 `event_set_stream_v1`。本轮在原v28上继续训练，未更换模型表示、损失定义、学习率、批次、样本顺序或BF16注意力保护。

## 慢在哪里

运行日志显示，第4轮1275批耗时486.46秒，其中取数据148.37秒、计算321.15秒，预取队列经常耗尽。1GiB音频银行缓存只能容纳约77首歌，已经淘汰1615次；随后轮次仍在重建同样的10毫秒特征。

另有两类重复工作：每个样本重新用Python循环填写最多80步的历史/目标张量，反复访问LazyAudio的duration还会触发音频缓存加载；配置细节则对8个方向全部计算，再遮掉无效方向，真实批次中1376行只有176行有效。

## 已完成的修改

1. **按歌准备符号张量。** 历史、目标、精确时钟等固定内容一次构建，样本读取切片并clone，避免调用方修改共享数据。持续状态仍按窗口补齐，避免对整首歌做巨大padding。符号缓存使用原状态缓存预算的一部分，总预算不增加。
2. **保存轻量时长与银行标识。** 每样本不用再通过LazyAudio读取duration和终点拍位；这些值在数据初始化时已经可用。
3. **音频银行持久化。** 结果写入 `cache/chart_composer_v1/event_set_stream_banks/stream_238_time_grid_peaks_v1/`，内存淘汰或重启后用NPY内存映射读取。映射使用私有写时复制，读取张量的改动不会写坏磁盘。身份含源音频/准备特征文件签名、首拍、变速表、拍号表、网格和明确策略版本，不使用无关源码的全文件哈希。临时文件原子发布，损坏缓存可重建。今后改变银行输入语义须升级 `BANK_POLICY`。
4. **只计算有效相位的细节。** CPU组批阶段给出有效索引，GPU只展开这些组合，保留原联合概率公式。旧batch仍可走完整计算路径，模型state_dict无新增参数。

曾测试替换音频摘要池化算法，但没有测到可靠收益，且会额外改变BF16舍入，因此没有保留该实验。

## 实测结果

原始日志和脚本在 `.scratch/perf_stream_20261030/`，机器可读证据见性能记录（本地开发资料，不随源码发布）。

### 数据准备与数值一致性

真实训练谱、H64/K16、10毫秒银行、2个CPU算子线程，5次中位数：16样本连同组批从259.68提升至899.22样本/秒，约3.46倍。32个样本及完整batch的全部既有张量逐位相同。

同一真实音频银行首次构建并写盘0.3507秒，再次打开磁盘映射0.00164秒，张量逐位相同、没有增加源音频加载。该读数主要是打开映射，不包含后续访问所有页面的成本；整条流程测试才包含实际组批读取。

真实8000步权重固定batch，细节计算从1376行降至176行。FP32损失相同，最大梯度差7.45e-8；BF16损失相同，最大梯度差0.001953125，是改变矩阵批形状后的有限精度差异。BF16单步中位数129.36→123.74毫秒，但短测有波动，不能单靠此值推算整轮收益。

相同8000步父权重、相同32谱清单和样本顺序、B16×累积1、64次更新，总计1024个短段和13310个有效监督目标。对照关闭恢复/验证，排除启动准备与最后写检查点；精度BF16，其他设置相同。

99项stream相关回归通过，覆盖缓存、数据/模型、梯度、恢复、检查点恢复、生成与曲线。未重跑全仓无关测试。
