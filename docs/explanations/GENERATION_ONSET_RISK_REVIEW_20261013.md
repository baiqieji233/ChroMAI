# 生成异常、起音合并与综合风险评估

日期：2026-10-13。基于最新完整诊断快照 `e0d07ff7de58`（16:19:41 生成），不是持续被覆盖的输出文件。本轮没有改变训练架构或启动新训练。

## 判断

不能把“节奏大致能对上，配置随机，结尾诡异”全部解释为训练不足。本轮分别确认导出结束拍位错误、曲线参与峰值筛选的错误，以及 Planner/配置生成之间的表达缺口。已有检查点可以继续训练和生成，不需要为本轮改动重练。

快照中有 945 个起音、984 个 note head：Tap 510、Hold 360、Slide 7、Touch 79、TouchHold 28。Hold 合计约 39.4%，Slide 约 0.7%。Planner 的类型预测最高项是 927 个 Tap、18 个 Slide，没有最高项为 Hold/Touch 的起音。两者明显不一致。

最后一个音符在约 123.078 秒，音频在 129.176 秒结束。最后六秒的异常大分音指令是空白结束区的写法，不是模型写了那些 note。

## 已修复的明确问题

### 1. 曲线放大制造多个伪峰

原代码放大当前帧分数后与未放大的邻帧比较。较宽的一次起音响应可能让两侧帧也通过局部峰值条件，随后被映射成不同拍位，产生非常近的多个起音。

现在先在原始模型分数中识别局部峰；强度曲线只影响这些峰的保留分数，不再凭放大制造峰。平顶峰保留一个代表。真实但较弱的峰可以由曲线提高到选择阈值，休止区仍会排除它。

日志保留原始分数与音频帧秒数；最终 `score` 是受曲线影响的选择分数，可能大于 1，不能当作校准概率。

### 2. 相邻起音合并

WebUI 主生成页“全曲规划与段落参考”新增 **相邻起音合并范围（毫秒）**，默认 40，范围 0～250。旧全曲研究入口同样接入，CLI 为 `--onset-merge-ms`。

候选按分数从高到低选择，附近已有更强起音则抑制；同分时优先较早候选。保留原候选拍位，不将两个时间平均成一个新拍位。算法没有把一串相邻候选通过传递关系合成一个超长区域，因此不会因为每对都相近就把整段快速节奏压成一个起音。

合并在精确分数拍位量化之后按实际秒数执行，避免量化再次制造过近时间。作用范围是全曲，计算片段边界两侧也适用；不限制同刻一个起音内部的多押数量。

| 值 | 用途与风险 |
| --- | --- |
| 0 | 关闭邻近抑制；正确的原始峰筛选仍启用 |
| 20 | 较弱抑制；在当前 20 ms 音频帧时钟下可能减少得很少 |
| 30～40 | 建议起点，用于抑制近似重复的峰 |
| 60 及以上 | 会更强地简化采音，也可能删除真实快速音符 |

例如 180 BPM 的 24 分间隔约 55.6 ms，40 通常能保留，60 可能抑制。200 BPM 的 32 分间隔为 37.5 ms，40 已可能抑制。范围按毫秒，不自动推断音乐拍号或正确的最细节奏；专业快速采音需要减小或关闭。它也不等于改变训练标签的高斯宽度。

显式传给 Python `generate_chart` 的已编写 blueprint 保持原起音集合，不自动改写；自动 planner 路径才应用该控件。局部修订仍保留原起音，不用此控件删除原谱音符。

`form_onsets` 和 blueprint.selection 记录算法、范围、原始峰数量、通过门控的候选、量化重合数、被抑制数量及处理前后最小间隔等。新的算法标识为 `raw_peaks_curve_gate_temporal_nms_v2`。

### 3. 结尾超大分母

音频的浮点结束秒数与 BPM 相乘产生巨大的分母；精确编译器将这个 EOF 锚点展开为巨大网格。本轮不修改共享编译器的精确事件合同，而只在 song_form 导出中将自动音频结束标记向上取整到 1/1920 拍。

note 的拍位、文本与 BPM 不变。修订原谱时，更晚的原谱结束点精确保留。报告新增 export_timing，显式记录结束点和延长秒数。快照的 EOF 分母由 1.2×10^18 降为 96，结束时间仅延长约 0.000053 秒，消除了巨大末尾网格。

### 4. 解码预算与修订返回合同

发现写到 token 预算但还没完成一个 note 时，函数曾只返回 points，正常路径却返回 `(points, fallback_count)`；此外局部修订调用没有拆包该返回值，可能把元组当作事件列表。现统一合同、正确拆包，并跨续写 pass 累计 fallback 数。这是密集片段的潜在运行错误，不是已证实的本次 945 起音异常来源。

### 5. 检查点身份记录

原生成报告没有记录实际读取的模型哈希；训练会原子覆盖 form_last.pt，诊断时原生成权重已经不在相同路径。本轮生成将从加载的同一文件句柄计算身份，报告记录 SHA256、大小、时间、模型结构、完成轮数和训练位置，避免把同路径的不同权重误当同一个实验。

## 除训练不足外仍存在的风险

| 成因 | 证据与影响 | 后续处理 |
| --- | --- | --- |
| Planner 类型/时值与配置解码脱节 | 类型与时值被算出并记入报告，但配置解码实际只使用起音集合；不能把过多 Hold 归因于 Planner 选了 Hold | 另做可选软引导实验；不直接把单类 argmax 当作硬限制 |
| 同刻多押被压成单一类型 | 标签以 Slide、Hold、Touch、Tap 的优先级选一个类型，时值取最大值；无法表达完整混合配置 | 若改为多标签或更多结构通道，需要新训练目标/合同，不能假装旧权重已学过 |
| 训练与生成的起音/前缀分布不同 | 训练 skeleton 来自准确官谱，前段是官谱；生成 skeleton 是预测和量化的起音，前段包含自己写的错误 | 先固定歌曲对比真实起音/预测起音和温度，再评估带可控扰动的训练；不可直接拼接错误前段与不兼容的原后续为正确标签 |
| 帧时钟与精确谱面时间不同 | 50 Hz 帧、20 ms 高斯标签，再映射到候选分数；密集音符可能合并或轻微移动 | 合并仅缓解近邻重复，不能解决音频对齐；更高分辨率或新起音表示需要单独训练验证 |
| BPM、first、变 BPM 输入不正确 | 同一音频此前生成用约 92.55 BPM，最新明确输入 185.005；时钟改变会影响量化和拍位特征 | 固定正确时钟再比较，不能将不同 BPM 的结果直接作为模型迭代效果 |
| 类型学习和序列误差累积 | 采样温度 0.7，字符式 note 解码长音/路径比 Tap 需要更多决策；前面错误会影响后面 | 固定 seed 比较 0、0.4、0.7，仅用于诊断；低温不等于高质量，还可能增加重复 |
| 关联辅助项不等于手感奖励 | relation 是弱辅助目标；没有真实双手调度、MiaCode 可玩性或审美的训练损失 | 保留可选无理检测和修订；未来需可信修正版或偏好证据，不能只依赖 token accuracy |
| 自动长音跨段占用 | 音符头不重叠不代表尾部与后续按键可完成；合并不会修 Hold/Slide | 持续动作输入提供信息但不是硬保证，需来源归因的无理检测与局部编辑 |

因此，本轮改善的是“哪些起音被误重复保留”和“如何正常导出/诊断”。它不承诺随机配置会变成成熟谱面，也不改变音频特征、词表、模型形状、训练数据、损失或已有 checkpoint 的能力。
