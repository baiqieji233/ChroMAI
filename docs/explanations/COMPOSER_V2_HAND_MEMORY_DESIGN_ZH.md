# Composer v2 手顺监督与生成记忆实施规划

Composer v2 连续事件模型已接入可选的手顺读出与反馈。下面先说明当前可用的入口、缓存和验收结果。后半部分保留设计依据及后续扩展计划。

## 如何开始训练

在 WebUI 打开「训练模型 → Composer v2 → 音乐与写法联动训练 → 下一组动作预判（实验）」。从已有连续事件检查点开始时，选择「微调」，指定父检查点和新的输出目录。

| 选项 | 生成和训练时会发生什么 |
|---|---|
| 自动 | 新模型默认关闭，已有模型沿用保存的策略 |
| 动作预判（原版） | 使用原有的落笔前预判和训练目标 |
| 动作预判＋手顺读出 | 每写完一组，增加对实际触点左右手、动作关系及证据强弱的读出。可先用这一项检验模型的理解 |
| 动作预判＋手顺读出与反馈 | 在上项基础上，把已写动作传给下一组的音符种类和位置选择。新的反馈连接从零开始 |

命令行对应 `--hand-plan-policy contact_memory_readout_v2` 和 `--hand-plan-policy contact_memory_v2`。在原有训练命令中加入其中一个，微调沿用 `--init-checkpoint`。断点续训用 `--resume`，自动继承策略和手顺标注范围。原版动作预判的权重可以迁移到两个新选项。

## 一万张谱如何计算

默认从通过训练筛选的谱面中按用途和难度槽轮流取样，为最多 **128 张训练谱、32 张验证谱**计算弱标注。其他谱面继续按原用途学习。填写「手顺标注训练谱面上限」可扩大范围，填 **0** 时，训练和验证都计算全部符合条件的谱面。CLI 参数为 `--hand-label-limit` 和 `--hand-label-workers`。默认并行进程数取 CPU 数与 4 中较小者。

训练启动时检查手顺缓存，整个训练过程中，同一张谱的不同窗口和不同轮次只切片读取已有标签。计算器在完整的连扫和分段换手方案中比较动作，共用接触点解析和已有的搜索结果，省去逐帧姿态与预览渲染。各首谱可并行计算。版本、实际规范化音符、精确拍位、BPM、偏移和难度槽共同决定缓存身份。重复导入可以共享标签，内容变化会另建缓存。每张完成后以原子替换写盘，中途退出可从完成处接着算。

也可在训练前单独准备。将下面两条路径换成本次使用的清单和缓存根目录。此命令只读取谱面，每个工作进程一次处理一张，无需音频特征和 GPU。预计算按清单声明的定数和难度槽取材，实际进入训练的范围仍由训练筛选决定。

```powershell
python -m maichart.composer_v2.hand_label_cache --manifest ".\manifests\training_manifest.json" --cache-dir ".\cache\chart_composer_v2" --limit 0 --workers 4
```

缓存位于训练缓存根目录下的 `hand_labels/head_edges_v2`。启动日志 `hand_label_cache_ready` 会给出选中谱面数、复用数、新建数、完全缺标谱面数、各字段的可评估数量和本次耗时。离线预计算与训练使用同一缓存根目录即可复用。清单包含多种写谱方言时，预计算可用 `--chart-dialect` 指定与检查点对应的规范化版本。

## 模型能读到什么

每组支持最多两个能唯一对应的 Tap、Hold、Touch 或 Touch Hold 触点，按实际键位或触区排序。手别和关系各自比较完整候选路径。两条路径分别是左左左左与右右右右时，左右可以保持未定，而两条路径都给出了「同手延续」。第一版学习三种关系，即相邻单触点、同拍两个触点，以及跨过中间一键回到原键。跨组关系只在相邻间隔不超过 0.45 秒且上下文能对齐时监督。

新读出在实际的组结束符上产生。每个预测字段有方向、至少有倾向的证据、达到较强的证据。分歧教模型弃权，只看到一边的搜索结果也只教证据不足。无法对齐的项目跳过损失。动作反馈读取模型自己之前的输出，离线答案只用于计算损失。连续几键引用同一动作时，延续证据取链中较弱的一环。置信度分支与这条反馈的梯度分开，反馈对单个配置 logit 的改变量上限为 0.25。候选回退时撤回对应状态，导出修谱后从首个失效位置按最终前文重放。

Hold 的键位和释放时刻、Slide 的等待与实际滑行阶段，来自已经写下的音符和原谱时钟。Slide 的左右手、轨迹中途交接和 Wi‑Fi 分翼继续留待专项核验。生成报告 `hand_predictions.events[].after_layout` 可查看实际动作的读数及仍在持续的动作。使用同一份带反馈权重、同一首歌和种子，额外传入生成参数 `--no-hand-memory-feedback`，可以单独关掉新反馈做对照。

生成报告公开「较强」需要通过该检查点自己的留出验证。按手别或关系字段再分纯 Tap、含 Hold、含 Touch、两类均有。在训练录音以外，至少三份不同录音各出现八次该类强判断，总计至少 64 次，合并后的方向或证据等级分歧不高于 5%，每份达到八次的录音分歧不高于 10%。这些是保守的发布门槛。数值反映对算法弱标注的符合程度，真人选择比例仍需独立标注。训练的 best 继续按原有配置中的验证依据选择。

## 本轮验证

八张完整谱共 6,188 个事件组，本机 CPU 首次计算用单进程约 11.3 秒，四进程约 7.6 秒，八张全部命中缓存时约 0.007 秒。两种并行度产生的八份压缩标签逐字节相同。预计算四张实际训练谱之后，正常训练入口四张全部命中。这里计的是手顺缓存阶段，原训练流程的音频和数据准备另计。

在八张谱中找到 149 对相邻触点，两端的绝对左右手都缺乏方向证据，完整候选却支持「同手继续」。其中 33 对达到算法的较强等级。这些关系可在两颗音的绝对手别都弃权时独立参加训练。

小型连续事件模型从旧权重微调，四首真人谱训练、另两首验证。32 次 CPU 更新内，在相同的八个验证批次上，组末手顺辅助损失从第 16 步的 0.878 到第 32 步的 0.866，194 个可评估字段中有 0 个被模型报为较强。这个规模验证了监督、弃权和训练通路。成谱手感的变化，以及 200M 模型长期微调的最优参数，仍需用同曲同种子的实际续写评估。

## 目标和边界

模型写完一组音符后，同时给出它对这组动作的解释。解释包含实际触点、与前一组的关系、对具体左右手的倾向，以及哪些部分仍不确定。写下一组时，解码器可以利用这份解释。音乐、定数、全曲编排和实际谱面前文继续决定是否出音、何时变化和怎样收束。

第一轮覆盖外键 Tap、双押、Hold 的开始与释放，以及可唯一对齐的相邻 Touch。Slide 的时间和阶段可先作为已写谱面的事实读取。Slide 归手、滑行中交接、星尾接 Touch 的反馈单独验收。Wi‑Fi 各翼缺标时保持未知。

## 第一步　建立可复用的动作关系样本

**操作。** 从已有谱库选一份小清单，按录音划分训练、校准、留出评估三部分。同曲不同难度、镜像、近重复谱和重导出文件归到同一部分。已有人工讨论过的谱例用作回归题。另留未据此调过算法的歌曲评价泛化。

现有命令可用来生成第一版绝对手别基线。在项目根目录执行，输入目录换成本轮样本目录；不同难度槽分别运行。

```powershell
python -m maichart.legacy_hands.batch ".\本轮样本" --slot 5 --mode labels --workers 2 --output ".\webui_workspace\hand_labels_pilot.sqlite"
```

该命令今天产生逐触点标注。下表中的关系字段需要扩展导出。缓存身份沿用谱面内容哈希、难度槽和求解器修订，再加入关系标签版本、解析及规范化版本。以规范化事件组、组内触点身份和动作阶段对齐训练数据。相同起始拍的双星、同拍多键和同键复合配置必须能区分。只凭键位和舍入到毫秒的时间无法唯一对齐时，记录缺标。

| 数据 | 建议内容 | 用途 |
|---|---|---|
| 谱面事实 | 事件组与触点、键位或触区、音符类型、开始拍、起滑拍、结束拍 | 由实际谱面解析得到，无需手顺置信度 |
| 手别 | 左／右／未知，较强／倾向／不确定，原因 | 训练“这个具体触点更可能交给谁” |
| 动作关系 | 成对的触点或阶段身份，关系类型与独立置信。首批做前后同手／换手、同组 Touch 共用一手、Tap 接同键 Hold 后另一键应答 | 训练“这两处动作怎样相连”，保留绝对手别未知的样本 |
| 证据可用性 | 候选有分歧、缺少对手候选、阶段不受支持、映射失败等 | 决定哪些损失有效，哪些输出应弃权 |

**关系如何得到。** 对同一对触点，在每条完整可行候选里先判断同手还是换手，再比较候选。比如两份解分别为左左左左、右右右右，它们都支持连续同手；一份左左左左、一份左左右右，则前半段有共识、交接处有分歧。不能从每颗音符单独的左右概率相乘得到这个结论。两种风格共用同一求解器，其一致只能提供初步证据。对拟标为「较强」的关系，应额外比较最佳同手解与最佳换手解，或用可核查的谱面约束支持；搜索剪枝造成另一解消失，单独不足以升为较强。相邻边高度相关，一段长扫按乐句归一化权重，避免一圈扫键贡献十几份重复监督。

**通过条件。** 打乱同拍音符文本顺序，关系和手别应随触点身份保持一致。镜像测试使用有明确镜像解的完整前后文，同时变换 Slide 形状；同手／换手关系应保持。居中的单颗 Touch、未覆盖的 Wi‑Fi 支路、无法对齐的双星能正确弃权。按歌曲和配置类型输出有效样本数、未知原因、绝对手别未知但关系可用的比例。若后一类几乎为零，先检查关系导出。

## 第二步　在实际音符上读出模型自己的手顺

**落笔前。** 保留现有选时后的预判。此时可预测下一组可能延续当前动作、需要另一只手，或适合释放。具体键位和音符类型仍在采样中。

**落笔后。** 当事件组闭合，用同一个组末隐藏状态，分别结合该组每个实际触点的键位、类型、阶段，输出手别倾向、依据强弱，以及与已写触点之间的动作关系。同拍组统一闭合，交换双押的书写顺序应得到同样的对应结果。这满足“输出 note 的同时输出手顺”的要求。结果附在同一事件组的生成记录中，Simai 语法和 token 词表保持兼容。

**训练目标分开计算。**

- 音符类型、键位、时值等主损失继续按原配方计算。缺少手顺标注的好谱仍有完整的写谱训练价值。
- 手别和关系各有监督掩码。建议第一轮采用「较强 1、倾向 0.25、不确定 0」作为辅助损失的相对权重。0.25 是试验起点，不能解释成 25% 的玩家这样打。先分别按有效监督量归一化，再记录各类样本和实际梯度占比。
- 依据强弱由单独的读出学习。候选真正分歧可教模型保留意见；文件缺失、功能不支持、触点没对齐则跳过相关监督。模型自己报低置信不能减免该样本本应承担的训练损失。
- 对同手关系较强、绝对手别未知的一串扫键，训练关系分支，屏蔽绝对手别损失。模型可以给出「同手延续较强，具体手别不确定」。不强迫它为整句任选左或右。

**置信输出的具体实现。** 每个触点输出一个左右倾向读数，每条受支持的关系另有关系读数。两者各带独立的证据等级。证据头可用两个有序目标训练，即“至少达到倾向”和“达到较强”，并约束后者不高于前者。证据头学习离线资料能支持多强的判断，侧别头学习有依据时应取哪一侧。显示为「较强」要同时满足三个条件：所属类型已经验证、证据头过线、侧别或关系候选有足够区分度。两个阈值只在按歌曲隔离的校准集上选择，然后固定到留出集。某类触点缺少独立依据时，报告可显示相对倾向，反馈强度保持低或关闭。侧别输出接近 0 或 1 本身不能提升证据等级。

## 第三步　把已写动作带入下一组

生成顺序为：确定下一拍 → 推进持续动作到该拍 → 读取音乐、配置前文与动作状态 → 生成整组音符 → 从实际成组结果读出手顺 → 提交到本候选的前文。

记忆分两部分。**确定部分**记录已写出的触点、持续阶段和时间。**推断部分**记录最近有关联的动作、仍有证据支持的同手／换手关系、可能的归手和依据强弱。第一版只保留仍在持续的动作和最近的接续关系；已有相似段配置记忆继续负责跨段呼应。远段旧手别不能充当眼前手位。

《BLRINK》的例子中，如果模型实际写了右手倾向较强的 `5h`，状态就保存“5 持续到第几拍”，并将“右手更可能负责”作为可减弱的证据。下一次 `7` 可以参考前面已经建立的分工。如果同一位置采样成 Tap，持续占用立即消失。即使两种走法只差这一个音，后面的动作状态也必须分开。长休止后清除过期的手位推断；跨过休止仍有效的 Hold 或等待起滑的 Slide 依照其实际时值保留。

**避免自信越滚越高。** 第一版用零初始化、幅度受限的附加连接，使动作状态仅能轻微调整下一组配置。手别和关系分开控制，缺乏侧别证据时侧别反馈置零，有依据的同手关系仍可用。首轮阻断配置损失通过置信开关反向优化置信读数；置信分支独立受监督。一次预测被带到后文不会因此增加可信度。占用和释放由谱面事实更新，手别推断允许被后续证据修订。首轮不让手顺通路单独决定出音、休止、EOS 或目标物量。

对于「同一只手继续，但左右未知」，最近动作保留一个局部引用，例如“延续上组的扫键”。后两颗继续引用同一动作即可，不必每颗独立抽一次手别。遇到可用的左右锚点时才更新本候选当前的归手依据，先前记录仍保留当时的置信等级。这样后面能形成呼应，回看报告时也能区分模型当时知道什么、后来才多了什么证据。

**防止偷看后文。** 离线识别器可以读真人后续以制作训练答案。模型在组末只能看到允许的音乐信息和写到当前组为止的谱面。另做前缀截断对照：删去真实后续后若某个强标签才失去依据，就不把它当作当时应当自信的答案；可在后续证据出现后评价其更新。自生成前文接真人后续时，接缝关系基于替换后的前文重标，否则屏蔽。训练和生成一律向记忆回写模型读数及已写事实，避免只在训练时获得正确手别。

**通过条件。** 同一前缀的逐步解码与整段重放给出一致的状态；固定音乐与前缀、只改未生成的答案，当前读数保持一致。同种子试写两个候选再撤回一个，保留候选的状态不受撤回者影响。刷新上下文时重建仍有效的持续动作；历史不足以还原手别则降为未知。导出修复若改了某组，从最早受影响处重放，并标记修复来源。

## 第四步　先验证读出，再验证反馈

下列预算是小规模试验起点。沿用一份已经认可的检查点，原文件只读。为新策略建立独立版本；严格续训要求策略、标签版本、数据和训练契约一致。旧权重迁移走新目录微调，复制已学到的兼容参数，新增反馈从零开始。旧检查点按原策略生成。

| 对照 | 怎么做 | 回答什么 |
|---|---|---|
| 冻结主体的读出试验 | 首批可取 32–64 张不同歌曲的谱作数据与通路核查；先冻结主干和原配置输出，只训练新增读出。按有效关系数记录预算，不能只报步数 | 已有隐藏状态中有没有比“看到 5 就猜某手”更多的接续信息？ |
| A 原配方 | 保留原动作策略，按同样数据、前文、种子、可训练范围及更新预算短训 | 普通微调本身带来多少变化？ |
| B 新监督，反馈关 | 加入手别、关系、证据读出。新动作记忆到配置的连接保持关闭 | 新监督能否改善动作理解？共享主干解冻时，辅助损失本身也可能改变成谱 |
| C 新监督，反馈开 | 与 B 从同一初始化开始，使用相同样本顺序、学习率及更新数，只打开受限反馈。再用同一份 C 权重做一次推理时关闭反馈的消融 | 模型是否真正利用自己刚写出的动作来写下一组？ |

建议 A/B/C 先各做 200–400 次更新以验证通路，主干沿用该检查点已验证稳定的短微调学习率。标签覆盖不足时先补齐有差异的乐句；短训不足以判断质量时报告结果未定。离线标注只算一次，按样本窗口索引读取。普通来源可沿用「仅练动作」，精选来源承担完整配置损失；延续现有质量范围和去重规则。先记录每千个有效事件的耗时、显存、标签覆盖和辅助梯度，再决定是否扩到全库。

## 第五步　按两道门验收

**读出验收。** 在整首留出的歌曲上，与只看键位／类型的先验、现有分支作对照。分别报告绝对手别、同手延续、换手与释放接续。每类都给出有效数、覆盖率、弃权率和已报告「较强」项的错误数；比较模型时固定覆盖率，防止靠全部弃权获胜。将部分争议题允许双解，将人工已经纠正过的题单列为回归题。训练标签和评估都来自同一求解器时，只能报告对弱标签的符合度。没有独立真人依据的类别，不发布玩家概率或真人正确率。项目现有小样本实验里，仅看键位的误差 0.06603，原始上下文读出为 0.07369，说明超过键位先验本身就是必要检验。[既有对照](COMPOSER_V2_HAND_PLAN_ZH.md)

**成谱验收。** 先固定同一段模型自写前文和音乐，再让 A/B/C 续写几个有分岔的乐句。成对挑选“键位相同但前后手位不同”“动作相同但该继续／该结束不同”的题。专门纳入连扫、合理换手、连续双押、近距离 Touch、无缝 Hold 交接、休止，16 分和 24 分分开看。检查被迫的多余换手是否减少、原本流畅的持续动作能否保留，并记录采音、物量、类型和重复段变化。少写、删去难处理的 Slide、永远选择最省动作，都不足以证明成谱改善。

**决策。** 读出没超过键位先验，先修正数据或读出。读出可靠、B/C 续写没有稳定差别，就保留报告功能，反馈保持关闭。C 在多首留出歌曲、多个种子上都改善自写前文的实际接缝，且没有靠减少物量、打断合理重复或牺牲音乐表达获利，再扩大训练。若只有个别类型退化，只关闭该类型的反馈。

## Slide 的独立验收

先做只读回放，逐条核实星头、等待、实际起滑和释放。普通星按谱面时钟处理默认一拍等待，显式等待、变 BPM、链星与同头多轨分别覆盖。测试集至少包含星头与滑行异手、跨中线但全程同手、确有交接的对穿、星尾接 Touch、Wi‑Fi 分翼缺标五类。先验时间状态必须与现有解析一致，左右分配不应改变时间；整条走线有争议时不回写单一手别。

《再現.leaper》的 `7<8` 接 Touch 扫适合检查是否保留操作方向。《Riven Pilgrimage》两条星各自跨过中线、仍由原手划完，适合检查会不会凭屏幕左右半区虚构换手。只有只读阶段通过、修复与回滚重放一致，并在留出歌曲上得到同样结果，才让这类关系参与生成。星头、整条滑行和 Wi‑Fi 各翼分别放行。
