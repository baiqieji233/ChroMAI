# Composer v2：自动变速与恒速精度改进

日期：2026-11-08。本轮只修改生成前的音频时钟分析，没有修改训练模型或检查点。

## 已完成什么

生成侧新增“自动BPM分析”：默认识别变速并校准全曲，也可只校准恒速或使用旧版作对照。BPM留空才自动识别；填写BPM即固定恒速，手动tempo map整表优先。首拍可自动估计或显式指定。实际变速表进入音频读取、事件生成、物理检查及Simai导出，生成报告会记录每次变化的拍位。

恒定175与Diamond Dust的200 BPM已有用户确认，可作为准确性基准。两者新结果分别为175和200。0.1左右的偏差主要来自节拍定位及拟合偏差，远大于普通浮点舍入误差；本轮用独立声学证据校准，没有对所有结果直接取整。

## 方法及现成方案的取舍

- 保留BeatThis节拍峰与原有缓存。它不强制固定拍号，但峰序列仍可能漏拍或切换半拍／倍拍。[官方实现](https://github.com/CPJKU/beat_this)
- 实际使用librosa支持逐时刻tempo输入的动态规划跟踪，作为复杂变速的独立对照及融合输入；BeatThis不可用时，声学fallback也使用动态tempo。[官方教程](https://librosa.org/doc/latest/auto_tutorials/03-advanced/plot_dynamic_beat.html)
- 参考madmom／BeatNet的状态转移思想，比较多个有持续证据的周期，而不是逐个相邻间隔立即改BPM。没有增加这两个项目的安装依赖，也没有声称运行过其预训练模型。[madmom源码](https://github.com/CPJKU/madmom/blob/main/madmom/features/beats.py) · [BeatNet](https://github.com/mjhydri/BeatNet)
- Essentia能输出逐拍时刻和间隔，但其标量BPM是全局统计；RhythmExtractor2013的maxTempo参数最高250，直接用于魔王的270／280段并不合适。本轮保留为参考，没有安装或实测。[官方说明](https://essentia.upf.edu/tutorial_rhythm_beatdetection.html) · [参数范围](https://essentia.upf.edu/reference/streaming_RhythmExtractor2013.html)

具体实现：复用100 Hz频谱变化特征；缺少特征时只准备native音频缓存，不下载或运行MERT。对恒速同时搜索周期与相位，用全曲起音支持抑制局部偏差。只有整数候选的累计差异不超过15毫秒、声学支持也近似相同时才归并，真实小数BPM继续保留。

变速使用持续周期候选与变点动态规划，必要时加入librosa独立跟踪。每段再做声学校准；边界以1/48拍搜索精度连接，但不假定4/4拍或固定小节。分数边界比较的是变速后拍位零点的相位，不把边界本身强当成整数拍。候选需通过相位连接和全曲覆盖检查。

## 验证与限制

已用24份真实音频执行新分析，包括17首benchmark、5首有原谱变速表的对照，以及157／205 BPM恒速对照。216项生成相关Python回归、31项JS界面测试通过，覆盖真实小数BPM、混合分音、手动参数优先级、变速连续性和Simai导出时刻一致性均有测试。

另以真实175 BPM音频运行不依赖BeatThis的librosa动态fallback，校准结果仍为175 BPM。

使用现有缓存时，单曲分析约0.2—4.2秒；冷缓存首次音频准备更慢。这不是训练吞吐测试，训练目标与参数没有改变。

目前候选主要来自8秒观察窗，段落最短约6秒；很短的连续变速和弱起音的自由速度段容易漏掉。自动接受条件也可能遗漏小幅变速；所有拒绝原因、候选段、检测器来源和实际应用的表都在报告中。搜索边界附近1.5秒不是对真实误差的置信区间。

已知局限还包括半速／倍速歧义、切分节奏造成的假变速、复杂复合节奏，以及某些音乐中不存在唯一可恢复的谱面BPM表。没有对困难歌曲强制套用错误的完整变速表。
