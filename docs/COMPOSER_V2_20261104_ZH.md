# Composer v2：为什么另开一条路线，怎样使用

更新：2026-11-04。模型族为 `chart_composer_v2`，仍在原来的主界面切换。本文中的 v2 不是旧检查点目录名中的 v2，也不是 Composer v1 的一个新开关。

最新：fresh已改为[连续事件生成](COMPOSER_V2_CONTINUOUS_EVENTS_20261104_ZH.md)。下文16拍窗口与旧默认值属于早期实现；旧检查点保留原行为，新训练不再使用固定拍数输出边界。

当日晚间补充：[窗口失败、Radar／Style与自动节拍修复](COMPOSER_V2_GENERATION_AND_CONTROLS_20261104_ZH.md)。条件与节拍的最新行为以该说明为准；早期验收记录保留其当时范围。

## 1. 本轮真正改变了什么

过去我们把选时、配置、意图、草稿和恢复拆成了很多任务。这些设计有各自的理由，但基础配置还没学稳，模型就要同时学习这些任务之间的配合。另一个问题是：输出一个音符时用到的信息，和下一步读取这个音符时用到的信息不完全相同。

v2 先把核心任务收回到一句话：**听一段音乐，读自己已经写过的谱，然后连续写出下一段。**

| 改动 | 怎么做 | 目的 |
|---|---|---|
| 音乐理解 | 冻结的 MERT 第8层音乐特征，加上 Mel、瞬态与能量；模型同时读取附近音乐和全曲摘要 | 不仅知道哪里有响声，还能区分一段音乐的内容和变化 |
| 同一种音符表示贯穿读写 | 时间、类型、位置、路径、修饰、时值组成同一条序列；输入嵌入与输出分类权重共享 | 写出 Hold 后，下一步能读到这个 Hold 的位置与准确时值，减少“会选但不会接” |
| 连续配置 | 默认每次学习16拍，读取前16拍，并能看后方4拍音频；连续写完窗口后才移到下一窗 | 给交互、流转和整段配置足够的训练跨度 |
| 历史呼应 | 额外读取一个音乐相近的已完成旧片段，保留实际音符顺序；全曲音频始终可读 | 允许模型自行决定沿用、变奏或另起写法，不要求镜像或照抄 |
| 学习目标 | 直接预测真实序列的下一个组件，损失只计算目标窗口 | 先建立可靠的基础续写能力，不再同时训练潜在模式、草稿和恢复标签 |
| 可选多候选 | 默认1条；2/4条候选保留首轮选中的时间和同拍音符数，只重写配置 | 比较配置手感，同时不靠评分器增加音符或消灭主动留白 |

16拍只是计算窗口，不代表“四拍一定是一小节”。跨窗通过实际历史、持续动作和旧片段衔接；它仍是流式自回归，不是整首歌一次性输出。

## 2. 保留的能力与没有照搬的做法

- 保留原生 Simai 解析、变速时钟、持续动作状态、物理检查、质量标注、主界面任务系统和原始检查点。
- 窗口结束符只结束当前窗口。当前窗口可以完全空白，下一窗口仍会继续生成；它不会提前结束整首歌。
- 不加最低密度、有声必须出音、固定副歌加密、重复惩罚、强制镜像或旧官谱负样本规则。
- 不把“模型认为概率高”当作候选更好的唯一理由。当前软评分只用于同节奏、同物量候选之间的原生轨迹舒适度比较；未知覆盖给中性分，分数不代表人工认可。
- 不移植 v1 的自动强度曲线、短句潜变量、草稿与配置恢复损失。Radar／Style已在当日晚间接入独立条件合同；旧level-only点没有学过这些控制，不能仅靠显示控件获得能力。

## 3. 在主界面怎样开始

必须使用含本轮代码的新 WebUI 服务。刷新页面只能刷新前端，不能让旧 Python 进程加载最新后端。正常退出原终端服务后，以原启动方式重新启动即可，不需要另开“v2页面”。

### 训练

在“训练模型”选择 **Composer v2**，选择原有数据集清单，训练方式选 **fresh**，检查点目录使用一个新目录。v1 权重不能直接续训成 v2。

界面按以下顺序提供设置。默认值是首轮起点，不是已证明最优的参数。

| 所在分组 | 控件 | 初始值与含义 |
|---|---|---|
| 常用训练设置 | 训练轮数 | 50；本轮没有替你启动这项正式训练 |
| 常用训练设置 | 每批窗口数 | 4；显存不足时先降此值 |
| 常用训练设置 | 梯度累积 | 16；默认每64个窗口进行一次更新，按真实目标组件数归一化 |
| 常用训练设置 | 学习率 | 0.0002；这是新结构的默认起点，不继承 v1 的固定0.0005实验结论 |
| 常用训练设置 | 学习率计划 | cosine；预热后逐渐下降。constant为固定学习率 |
| 常用训练设置 | 训练精度 | bf16；没有BF16支持时明确选择fp32或合适的fp16 |
| 数据与音频特征 | 独立缓存目录 | `cache/chart_composer_v2` |
| 数据与音频特征 | 音频特征 | mert；native是明确的纯声学对照，不会在MERT失败时自动降级 |
| 数据与音频特征 | 本地MERT目录（留空自动下载） | 通常留空；已有模型时填完整本地目录 |
| 数据与音频特征 | 验证数据来源 | 自动按歌曲划分训练／开发／最终留出；同曲及相同音频隔离 |
| 数据与音频特征 | 总留出比例 | 0.05；开发和最终留出合计。小数据至少各保留一组，以报告中的实际比例为准 |
| 数据与音频特征 | 手动验证 manifest | 仅手动模式使用，必须与训练集分离 |
| 数据与音频特征 | 特征准备设备 | auto；首次提取可以用GPU，训练前会释放MERT |
| 模型与上下文（高级） | 模型宽度／层数／注意力头数／前馈宽度 | 384／8／8／1536 |
| 模型与上下文（高级） | Dropout | 0.1；注意力概率内部不再单独做Dropout |
| 模型与上下文（高级） | 训练窗口／历史／前瞻音频（拍） | 16／16／4；写入检查点，生成严格继承 |
| 模型与上下文（高级） | 每拍网格 | 48，同时纳入训练谱实际出现的其他相位；不会把原谱强行吸附到网格 |
| 模型与上下文（高级） | 组件 token 上限 | 2048；完整目标放不下会明确报错，不会偷偷删音符 |
| 验证、性能与保存（高级） | CPU计算线程／训练设备 | 2／auto；限制线程争用 |
| 验证、性能与保存（高级） | 预热更新数／最低学习率比例 | 200／0.1 |
| 验证、性能与保存（高级） | 验证最大批数 | 32；0表示完整验证。32批的结果是固定子集指标，不是全部留出集成绩 |
| 验证、性能与保存（高级） | 保存更新间隔／日志间隔 | 500／20 |
| 验证、性能与保存（高级） | 训练随机种子／最大更新数／谱面限制 | 0／0／0；后两项0表示不限，短程开发测试才设置上限 |

数据当前沿用等级12～15、难度索引4～6的训练筛选范围。低等级全覆盖不是本轮已验证能力。`last` 是完整训练状态，`inference` 是生成导出，`best` 的选择依据会明确记录；关闭验证时不能把 `best` 称为独立验证最优。

### 生成

在同一主界面加载 `composer_v2_inference.pt` 或 `composer_v2_last.pt`。填写音乐、BPM、起始偏移和等级，再查看“Composer v2生成”：

| 控件 | 初始值与作用 |
|---|---|
| 温度 | 0.9；0是贪心。贪心失败只尝试一次，不会重复计算相同死路 |
| Top-p | 0.95；限制参与采样的候选概率范围 |
| 音频特征缓存 | 与训练相同的v2缓存目录 |
| 生成设备 | auto |
| 最大事件数（0不限） | 0；上限不足会报错，不会导出截断的窗口 |
| 候选数 | 1；需要比较配置时再尝试2或4，会增加耗时 |
| 高级：CPU计算线程 | 2；减少小张量运算时的线程争用 |
| 高级：持续动作撤回次数 | 2；旧Hold/Slide占用导致当前窗全部失败时，撤回相关旧窗口及后缀重写；0关闭 |

BPM／起始偏移必须与音乐对齐。现在BPM留空会实际识别，可选自动首拍相位；手动值优先，失败不会回退120。变速使用共享tempo map；meter map只记录拍号，不强制音乐为4/4。

撤回会一起重建已提交音符、物理状态和窗口记录；不会只改TXT却留下旧占用状态。原检查点完全不受影响。

## 4. 效率方面具体做了什么

MERT只在准备音频时运行一次，缓存带模型版本、音频指纹和精确时间轴。训练读取只读mmap，不反复运行大音频模型。局部音乐卷积降采样，全曲摘要最多160个位置。

训练用长度相近的窗口组成批次、单批预取和非阻塞传输；累积期间不逐样本同步GPU。每次更新按所有微批次的质量加权目标组件总数归一化，短谱不会仅因批次切分获得额外权重。日志包含tokens/s、samples/s、data_sec、compute_sec和显存峰值。

生成缓存全曲编码、窗口音频编码和已生成组件的注意力状态，多候选共用音乐编码。它仍需逐组件采样，不能把训练速度直接当作生成速度。未训练好的模型反复写出不完整组件时，会触及窗口容量并重试，生成会明显变慢。

## 5. 损失函数怎样理解

只有真实目标窗口参与下一组件的交叉熵，历史、旧参考和持续动作只作为输入。质量标注可以降低某些目标的权重；损失按实际权重总量平均。选时与配置处在同一条因果序列里，没有多个分支各自计算“最终出音率”。

日志另列选时与其他组件损失。总loss仍会受到语法组件比例影响：**下降不等于整段配置成熟，也不能与v1的加权多任务loss直接比较。** 必须检查连续自由生成、正常休止、衔接、呼应和实际手感。

## 6. 已完成的验收与真实限制

完整记录见同目录 `evidence/COMPOSER_V2_20261104.json`。

- MERT实测第8层hook与原模型 `hidden_states[8]` 完全一致；时间戳、冻结参数与缓存读取已验证。
- 实际100张训练谱、57张开发谱进行固定词表检查。发现并修复罕见时值词表缺失：时值改成精确数值组件，验证集未知组件为0，所有音符组件往返一致。
- 默认384维、8层模型实际运行GPU更新，并通过最新HTTP接口完成fresh、resume及生成。resume确实从更新2继续到更新3；不是只检查命令行字符串。
- 通过独立浏览器检查主界面的族切换、控件、默认值、持久化、实际提交payload；确认v2不显示无效的v1偏好和曲线。
- 因果输入、KV增量等价、目标mask、空窗口、变速时钟、持续动作撤回、跨族拒绝、验证隔离、参数传递等有专项回归。

仍须明确以下边界：

1. 本轮仅作链路验证，没有训练出可评价音乐质量的v2模型。测试生成使用只更新几步的权重，不能作为质量样片。
2. 本轮真实默认规模更新的峰值显存约1.30GiB；样本较短，不能据此保证最长窗口或全量吞吐。正式训练应观察完整轮次的实际目标组件数与用时。
3. 生成语法目前仍从训练集提取合法音符结构。上述开发集有112个原子、约0.28%的复杂Slide组合超出这100张训练谱覆盖的模板；它们可以编码和计算验证损失，但不能由该小词表自由生成。不要把模板覆盖等同完整Simai语法支持。
4. 固定检查点遇到训练未见过的拍位相位，读取与验证使用无损数值表示并记录审计；自由生成仍使用检查点的网格与已见相位。该覆盖差异需要在正式数据报告中检查，不能通过读取开发集扩充训练词表来隐藏。
5. 音符起点越过音频末尾的谱会被明确排除，空E尾部不会继续制造训练空窗；跨越音频尾部的长持续动作保留原值并报告风险，生成端仍会拒绝越界动作。
6. 多候选只有手感的初步自动比较，尚无人工偏好校准；没有声称它能选择“最好听”的谱面。

## 8. 环境与MERT来源

本轮可用解释器：`.scratch/python312_runtime/Scripts/python.exe`。系统Python3.15没有本项目依赖，不要混用。

新环境安装基础项目后，再安装音乐特征依赖：`python -m pip install -e ".[composer-v2-music]"`。首次准备会下载MERT权重，约1.18GiB；后续用缓存。声学 `native` 模式可以做明确的降配对照，但不会获得预训练音乐表征。

MERT来源为 [m-a-p/MERT-v1-330M官方模型卡](https://huggingface.co/m-a-p/MERT-v1-330M)，锁定版本 `5240c2708a5acaee1007f43fb9735c7dcd0b78c9`。外部权重采用CC-BY-NC-4.0；商业用途需另行确认相应授权。权重不提交到项目源码中。
