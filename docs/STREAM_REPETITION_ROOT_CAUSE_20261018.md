## 2026-10-19 复审补充：BX/双押堆积

最近两次有效生成均使用 `Prism_stream_v8/stream_last.pt`，配置温度约0.7、拍位温度0、
Style配置平衡强度0.5、配置候选数1。最新完整产物 `3b84f6f647a2` 为epoch47/step8225：
907事件中约394个事件含 `bx`，后段出现连续BX运行；双押事件也形成长段。较早的 `fa92b927495f`
为epoch45/step7875，未出现同规模BX堆积。两者使用不同随机种子，说明原始模型分布在该区域
非常敏感，但不是训练epoch单独造成。

根因审查确认：

- `decoding.py` 原先只有在 `temperature>0 and configuration_candidates>1` 时才运行配置
  terminal guidance。候选数为1时，Style和局部配置反馈全部绕过；最新报告的
  `guided_tokens=0`、`guided_events=0`、`candidate_budget=1` 已直接证明。
- `max_button_heads=2` 只限制单个事件的按钮数，不能限制连续双押。
- `local_chord_strength=0` 时 `chord_bias` 没有独立的生成反馈。
- `TypeGuidance._counts` 没有统计 `ParsedNote.is_break`，因此BX在Style统计中被当作普通Tap；
  GenerationCondition也没有独立的Break条件。
- cycle-exit loss只覆盖原谱完全重复周期后的变化，不能约束自由生成中“同类配置换键”的循环。

已完成的生成侧修复：

1. `TypeGuidance.token_bias` 增加因果、有限的 Break 与双押连续反馈。它使用已提交的
   Break头数、连续Break事件、双押事件和请求Style chord比例，不读取未来事件；配置候选数为1
   时也生效。
2. `GroundedInference` 的远期 archive 改为保存事件索引并按 `archive_events` 上限采样，
   不再随整首歌无限追加 `archive_values/archive_audio`。
3. 生成显存保护在拍位搜索前读取 CUDA 可用显存：可用显存低于6 GiB时将Beam限制为2，
   低于4 GiB时降为1并关闭配置候选扩张；报告写入 `memory_guard_events`。这避免临时Beam/KV
   复制把系统推入共享显存，但不改变正常显存充足时的用户设置。
4. overlap训练合同继续保留：训练chunk真正携带warm prefix，重放目标权重为0；生成轮换与训练
   现在使用同一类事件边界。

阶段性验证：44项定向Python测试通过；固定step9500、同一音频/参数/seed、最多220事件的短生成
 通过，报告 `guided_tokens=343`，不再是0；该短样本BX为2个、双押64个。此前同类未接通
 guidance 的短样本为BX2但双押94个，说明双押反馈已产生作用；这不是整曲音乐质量验收。

当前未声称问题已根治：音频关联仍是软目标，模型仍可能在音乐段落不合理时选择重复；完整训练
 后必须用固定歌曲和固定seed比较BX比例、双押连续run、段落密度和音频跟随度。

## 2026-10-19 训练合同复核

`Prism_stream_v8` 的训练于 overlap decoder 修复前启动。其命令虽然记录了
`training_semantics=v6` 和 `continuation_profile=overlap_v1`，但当时 `StreamDataset` 只缩短了
chunk范围，没有把 warm replay prefix 放进 `decoder_input`；因此 v8 权重不能证明 overlap
合同有效，也不能用来判断本轮修复是否改善了自由生成。后续必须使用新目录 fresh 或 finetune，
不能直接把 v8 当作已完成的新合同权重。

当前代码已将合同版本提升为 `chart_stream_training_v7_overlap_prefix_contract`，旧 v6
checkpoint 会被明确要求使用 finetune 和新输出目录，避免误 resume。

训练效率复核还发现：`input_residency=auto/resident` 原先在 mapped 工件缺失时直接跳过，
之后由随机训练 batch 分散重建全部输入，造成首次训练阶段持续读盘。当前训练启动会先执行一次
确定性 input warmup，再进行驻留；这会把准备时间集中到训练前，但避免 GPU 计算期间边训练边重建。
选择 `input_residency=mapped` 时保留旧的按需行为，适合磁盘空间或内存不足的设备。

训练传输路径还将只用于时间查询的 float64 张量压缩为 GPU 侧 float32，保留 Fraction/源缓存
中的精确表示；生成侧保留原有高精度时钟。这样减少 query/detail/archive 时间字段的传输和显存，
不改变事件位置合同。

本轮随后修正了训练 chunk：decoder 输入从 warm 边界开始，warm 到 supervised 边界的 target
quality 为0，真实监督目标仍只计算一次；plan、alignment、history clock 和 action state 对齐
到同一 warm 事件边界。

循环退出监督现在同时识别两类情况：完全相同事件周期后的变化，以及 Break/双押/Hold/Slide/
Touch 等结构形态连续重复后的变化。它仍然只监督“离开重复模式”的原谱字符，不处罚合法重复，
也不直接替代自由生成时的重复抑制。

最终阶段性验证为53项定向Python测试通过；固定 step9500、同一音频、seed和生成参数的220事件
短生成中，`guided_tokens` 从未接线时的0变为343，BX事件为2，双押事件为64。该结果证明
生成侧反馈已实际接线，但不等价于整曲质量验收。
