# 继续训练与 checkpoint 使用说明

这份说明解释 WebUI 中的三种训练方式。第一次做一百余张谱面的可行性测试时，建议先使用 **fresh + basic_v1**，确认数据、音频对齐和生成流程都正常后，再尝试 finetune。`rhythm_v2` 目前只是预留入口，尚未在后端启用。

## 三种训练方式

### fresh：从头训练

模型随机初始化，不读取已有 checkpoint。

- 不需要填写已有模型路径。
- `epochs` 表示从第 1 轮开始训练的总轮数。
- 默认学习率为 `2e-4`，页面允许调整。
- 适合首次训练一百余张谱面，或模型结构、音频特征方案发生变化时重新开始。

### resume：从断点继续

恢复 checkpoint 中保存的模型、优化器、学习率调度器、AMP 状态和训练进度。

- 必须提供包含完整训练状态的 checkpoint。
- `epochs` 表示**本次额外训练的轮数**，不是从头累计的总轮数。例如 checkpoint 已保存到 epoch 20，填写 5 表示继续训练到 epoch 25。
- 页面将学习率固定为 `2e-4`，避免用户误把断点恢复变成另一种实验。
- 不重置优化器状态。
- 适合训练被中断、电脑重启或原训练时间不够的情况。

旧版只有模型权重的 `.pt` 文件不能真正恢复 optimizer 和 epoch。WebUI 检查结果会把这种文件标记为不能 resume；这时应改用 finetune。

### finetune：已有模型加强训练

只加载已有 checkpoint 的模型权重，然后在当前 manifest 对应的新训练集或混合训练集上继续优化。

- `epochs` 表示**本次额外训练的轮数**。
- 默认学习率为 `2e-5`，比 fresh 小一个数量级。
- 默认勾选“重置优化器状态”。
- 可使用只保存模型权重的旧 checkpoint。
- 适合新加入一批谱面、修正某一类谱面，或把基础模型适配到自己的制谱风格。

finetune 仍然需要模型输入输出结构兼容。若训练集的 division、音频特征或 note vocabulary 不兼容，不能靠降低学习率解决。

## 推荐的操作顺序

1. 在训练集区域选择当前 manifest，并点击“检查训练集状态”。确认可训练难度大于 0。
2. 第一次实验选择 `fresh`，选择 `basic_v1`，将输出目录设置为新的目录，例如 `checkpoints/test_100_basic`。
3. 先训练 1 个 epoch，确认日志出现有限的 loss，并且产生 `generator_last.pt`。
4. 若要从训练中断的位置继续，选择 `resume`，上传或填写上一次产生的 checkpoint，点击“检查 checkpoint”。
5. 若要让已有模型学习新训练集，选择 `finetune`，填写已有 checkpoint，并把 checkpoint 输出目录改成新的目录，例如 `checkpoints/finetune_100_basic`。
6. 检查通过后再点击“开始训练”。不要在任务运行时覆盖原模型目录。

## checkpoint 检查内容

“检查 checkpoint”会把当前 checkpoint 和 manifest 的数据合同进行比对。返回结果包括：

- `valid`：能否用于当前检查模式；
- `can_resume`：是否保存了 resume 所需的训练状态；
- `can_init`：是否能够加载模型权重；
- `epoch`、`global_step`：保存时的训练进度；
- `model_config`：输入维度、模型宽度、层数、最大长度等；
- `data_contract`：division、采样率、特征方案、特征字段、条件字段和 note vocabulary；
- `warnings`：例如旧 checkpoint 缺少合同字段；
- `errors`：导致当前模式不能使用的具体原因。

已有模型模式下，页面会优先采用 checkpoint 中记录的模型结构，避免手动填写的 d_model、层数等参数误造出不匹配模型。检查失败时不要直接强行训练，应先查看具体字段。

## 特征方案与兼容性

### basic_v1

兼容性优先的基础音频特征。适合一百余张谱面的第一轮可行性测试，也最适合与当前旧 checkpoint 配合。

### rhythm_v2（预留）

这是后续加入节奏、局部速度和歌曲位置特征的设计入口，当前后端尚未启用。WebUI 会显示它，但选项不可用；当前实际预处理和训练均使用 `basic_v1`。

- 本阶段不要手动修改请求，也不要混用声称来自 `rhythm_v2` 的缓存。
- 未来启用后，`rhythm_v2` 将改变模型输入结构，不能直接喂给 `basic_v1` checkpoint。
- 未来切换时应重新 fresh 训练，并为音频特征缓存、manifest 和 checkpoint 使用新目录。

预处理时选择的特征方案必须和训练时发送的 `feature_profile` 一致。不同方案的产物不要直接混进同一个 manifest。

## 一百余张谱面测试建议

一百余张谱面足够测试“流程是否能学到某些模式”，不足以保证 Master/Remaster 级别的稳定质量。建议分三阶段：

1. **流程测试**：1–2 首歌、1 epoch、basic_v1、较小模型。检查是否能完成预处理、训练和生成。
2. **过拟合测试**：从一百余张中选 5–10 张，训练 10–30 epochs。目标是确认模型能记住节奏密度、基本 note 类型和条件输入，而不是评价泛化。
3. **小规模泛化测试**：按歌曲划分训练和验证，不让同一歌曲的不同难度跨集合。保存 fresh 基线，再用 finetune 比较新训练集上的生成结果。

建议保留每次实验的 manifest、checkpoint、特征方案、division、采样率、条件 JSON、随机种子和生成结果。不同实验使用不同 checkpoint 输出目录。

## 防止灾难性遗忘

如果 finetune 只使用很小的新数据集，模型可能忘记原有歌曲模式。可以采用以下顺序：

- 优先使用 `2e-5` 或更小学习率；
- 先训练 1–5 个额外 epoch；
- 新数据和旧数据合并后按歌曲划分；
- 每轮都用固定的旧歌曲和新歌曲生成样例；
- 不要覆盖原始 checkpoint；
- 若旧谱面质量明显下降，降低学习率、减少 epoch，或改用旧数据与新数据混合训练。

## 生成条件强度

生成界面的目标等级、Radar、Style 和 `guidance_scale` 都是软约束。`guidance_scale` 范围为 0–3：

- `0`：基本不强调条件；
- `1`：默认强度，适合旧模型；
- `1–2`：更强调目标条件，但可能牺牲音乐贴合或结构自然度；
- `2–3`：强约束实验值，不保证可玩或一定满足目标。

如果旧模型没有训练过条件强化，保持 `guidance_scale=1`。调高它不会补充模型没有学会的 Slide 几何、长程重复或节奏理解。

## 注意事项

- resume 和 finetune 不是同一件事：前者恢复训练状态，后者只加载权重并重新开始优化。
- `resume` 不能用只保存模型权重的旧文件。
- 当前 WebUI 不启用 `rhythm_v2`；先做一百谱可行性测试时应选择 basic_v1。
- checkpoint 输出目录最好每次使用新目录，不要覆盖原模型目录。
- `include_unusable` 不能修复缺少音频、标签或缓存的样本。
- 训练集检查中遇到格式异常的文档会被跳过，详情显示在“处理错误”区域；一个坏文档不应阻止其余文档生成 manifest。
