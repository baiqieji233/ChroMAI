# Composer 训练改进与实际验证（2026-10-27）

> 本文记录学习率与指标改进阶段，文内“原任务继续运行”属于当时快照。后续已启动v15结构训练，当前状态与参数见[当前更新说明](COMPOSER_CURRENT_CHANGES_20261027_ZH.md)。本轮审查保留了下述短实验的原始范围，不将其外推为长期音乐质量改善。

已经实现可选的学习率预热/余弦退火、正确保存续训进度的调度计划，以及区分首槽、后续真音符和 recovery 的学习指标。现有基础损失公式与默认辅助权重保持原值。实际短实验不足以支持直接把音频辅助权重从0.15降到0.05，或替换正在运行的正式训练配方。

原任务 `9a39db11c305` 的训练进程和正式检查点目录继续使用；本次所有探针、短训练和网页验证均使用独立目录。新代码由之后启动的训练进程加载，正在运行的进程不会自动热更新。

## 先纠正原分析中的推断

| 原说法 | 核实结果 |
| --- | --- |
| 新旧目标的总loss不能直接比较 | 成立。联合NLL按有效槽求和，并计入首个STOP；旧目标有不同的事件内归一化与STOP权重。 |
| 当前配置头还没有学到全局边际分布 | 不能据附件确定。附件是第1轮中途数据，后续日志第2轮首槽CE已约3.69；其引用的3.74熵来自另一份旧输入契约探针，分布、权重也不完全一致。 |
| 3.74或2.8—3.0是此模型不可突破的loss地板，因此总loss到4数学上不可达 | 不成立。边际熵是忽略输入的常数分布基线，不是利用音频、历史与条件后的不可约误差。没有测到Bayes条件熵，也没有证明这样的正下界。 |
| 音频辅助占13% loss，所以消耗13%梯度预算 | 不能这样换算。参数更新取决于梯度范数、方向、参数共享、裁剪与Adam状态。 |
| 共享音频配置分支必然把主任务往相反方向拉 | 当前三个真实批次未支持这一点。共享分类器梯度余弦为+0.490、+0.664、+0.494；共享音频层也为正。只说明这些探针未见负向冲突，不证明其他数据或训练阶段永远无冲突。 |
| 分类器只是18454选1的平面分类，重构是唯一出路 | 不完整。当前模型同时使用组合动作因子、同拍前缀、相对键位与跨事件关系。仍有全词表分类开销，但不能忽略已有因子结构就确定重构方案。 |
| 进度日志中的loss就是每个更新实际优化的全部目标 | 不完整。主循环在恢复更新时另外对加权recovery loss反向传播，基础`loss`没有包含它。 |

关于多任务冲突，应实际测梯度关系，而不是从两条loss的接近程度推导因果。可参阅原始研究：[Gradient Surgery for Multi-Task Learning](https://arxiv.org/abs/2001.06782)。本次没有引入梯度手术算法。

## 本次真实短实验

冻结正式v14第6000次更新的训练检查点，保留Adam动量。全部实验在CPU上运行，未占用正式GPU训练的设备。输入按该检查点重新构造，包括123维计时、动机输入与原动作词表，未直接把旧99维探针补零后喂入新模型。

数据限制为32张谱、25个不同音频来源；短更新采样48项、评估采样48项，双方按音频来源隔离。父模型可能已训练过评估歌曲，因此这是“本次短更新未使用的歌曲”，并非证明父模型泛化能力的全新独立验证集。包含和弦的样本被有意覆盖，不能把类型比例当作全库分布。

每组16次更新、单批8个事件，使用相同样本顺序和随机种子。正式训练有效批量为64×4=256；小批量结果只能用于筛选方向，不能直接外推正式训练。所有组在短试中都关闭recovery，评估统一使用0.15音频权重，避免只改损失系数就让结果表面下降。

| 短实验组 | 统一口径总loss | 首槽真音符CE | 后续真音符CE | 选时loss | 选时准确率 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 基线：lr=2e-4，辅助0.15 | 8.793253 | 3.580675 | 3.909714 | 1.114288 | 56.25% |
| 较低lr：5e-5，辅助0.15 | 8.694042 | 3.536072 | 3.991810 | 1.081040 | 60.42% |
| 较低辅助：lr=2e-4，辅助0.05 | 8.795083 | 3.579025 | 3.906115 | 1.117733 | 56.25% |

较低学习率改善首槽与选时，但后续槽变差；较低辅助权重没有显示出明确的综合收益。单个训练种子、少量事件与16次更新不足以支持改默认值、重构词表或重开长训练。

## 已实现的改进

### 1. 可选预热与余弦退火

网页新增“学习率变化方式”“学习率预热更新数”“末尾学习率比例”，主页面和独立Composer页面均支持。

- `auto`：新阶段保持恒定学习率，resume继承已有计划。没有把尚未证明更好的配方设成新默认。
- `cosine`：先预热，再降到初始学习率乘`min_lr_ratio`。自动预热为总计划更新数的5%，最多500次；可显式填写预热数。默认末尾比例0.1。
- 调度按成功的参数更新计数，梯度累积中的微批次不各算一步，跳过非有限更新不推进时钟。
- 完整训练检查点保存基准学习率、预热数、总步数与终值比例。resume不重新预热、不拉伸原曲线；超过原计划后保持终值。
- 旧的恒定学习率训练仍保留显式`--lr`覆盖规则；带预热或余弦的计划锁定基准，避免把退火后的数值误当新基准。
- 有调度的checkpoint缺失计划时拒绝resume，避免悄悄变成恒定学习率。改变计划应在新目录finetune。
- 网页续训显示基准学习率，不把检查点里最后一次已退火的学习率误当成新曲线基准。旧后端未加载此能力时会明确拒绝新调度，避免静默忽略参数。

例如在新目录对照试验：

```text
--lr 0.0002 --lr-schedule cosine --warmup-steps 500 --min-lr-ratio 0.1
```

预热有一般研究动机，但这些文献不证明本模型收益：[On the Variance of the Adaptive Learning Rate and Beyond](https://arxiv.org/abs/1908.03265)。本次验证了调度实现、边界和续训，不把它写成已经提高长期生成质量。

### 2. 分开看真正的配置难点

- 保留原有`action_first_slot_ce`、`action_legacy_ce`等标尺。
- 新增`action_first_nonstop_ce`与`action_later_nonstop_ce`，只统计真实音符，排除STOP与padding。
- 同时记录有效权重。跨batch聚合使用误差分子总和除有效权重总和，避免把一个和弦与十个和弦的条件均值等权平均。
- 若窗口内没有后续音符，网页显示“—”，而非把0误报为已经学会。
- 音频分支和recovery日志也能单独观察首槽/后续配置误差。

### 3. 观察近期变化及实际更新目标

- 增加日志窗口内的近期均值，不让整轮累计均值掩盖最近变化。
- 新增`optimized_loss`，按成功更新统计实际反传的主目标与加权recovery目标之和；原`loss`保持旧的基础标尺。
- 显示当前学习率与最近一次裁剪前梯度范数。原有恢复接受率、恢复自产历史长度等信息继续保留。

### 4. 显式关闭辅助时跳过无用分类

当音频辅助权重为0时，不再计算未使用的音频动作分类分支。回归测试检查训练模式下主输出、主梯度与随机数状态一致。默认0.15的正式目标没有更改；此项是关闭辅助时的计算路径优化，没有声称默认运行已因此提速。
