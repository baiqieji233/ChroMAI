## 2. 【确凿高危缺陷】为什么 Beat This! 算出的精准小节相位没能在模型里发挥最大作用？

在 `b07631395b89_track.mp3` 全曲 1,600 个查询点上实测 `structure_features`（48 维）各列的实际有效幅度（RMS）：

| 特征维度 | 物理含义 | 实测 RMS 幅度 | 相对原生周期的强度 |
| --- | --- | ---: | ---: |
| 第 `0..5` 维 | 原生 Simai `sin/cos(2π·beat / 4, 8, 16)` | **`0.7071`** | **100%（基准）** |
| 第 `6..9` 维（Slot 0 相位） | `wt * z1.imag, wt * z1.real, wt * z2.imag, wt * z2.real` | **`0.0024 ~ 0.0035`** | **仅 0.34%（被缩小 290 倍！）** |
| 第 `16..19` 维（Slot 1 相位） | 第 2 候选周期的加权一/二阶复谐波 | **`0.0015 ~ 0.0023`** | **仅 0.27%（被缩小 370 倍！）** |
| 第 `12, 22, 32, 42` 维 | 候选槽位权重 `wt` | **`0.0105 ~ 0.0145`** | 仅 1.5% |
| 第 `15, 25, 35, 45` 维 | `valid` 布尔标志（恒为 `1.0`） | **`1.0000`** | 141%（纯常数偏置！） |
| 第 `46` 维 | 段落声学新颖度 `novelty` | **`0.2806`** | 40% |
| 第 `47` 维 | `novelty * sum(wt)`（边界支持度） | **`0.0176`** | 仅 2.5% |

### 造成“信号缩小 290 倍”的 3 个源码级原因（`src/maichart/composer/structure.py`）

1. **分母被 88 个重叠候选周期严重稀释（第 218–219 行）**：
   ```python
   evidence = np.expm1(np.clip(score * 5., 0., 5.))
   weight = evidence / (8. + evidence.sum())
   ```
   `PERIODS` 共有 **88 个有理数周期**（如 `3.75, 4.0, 4.25`、`7.5, 7.75, 8.0, 8.25, 8.5`）。在 32 拍窗口内，相邻周期都会产生可观的 `evidence`，导致 88 个周期的 `evidence.sum()` 高达 `15~20`，加上常数 `8.` 后分母达 `25+`！结果哪怕 `4.0 拍` 是全场的绝对冠军，分到的 `weight`（`wt`）也只有 **`0.016`（1.6%）**！
2. **相位谐波被重复乘了两次衰减因子（第 358–360 行）**：
   - `z1` 本身的模长是 `first_harmonic_amplitude ≈ 0.326`（已经包含了信噪比衰减）；
   - 第 360 行又乘了一次 `wt = 0.016`：`wt * z1.real ≈ 0.016 * 0.326 * 0.707 = 0.0024`！
   - 于是送进线性层 `structure_projection` 的小节相位信号只有 **`0.0024`**，比同向量的原生 `sin/cos`（`0.7071`）和常数列 `valid`（`1.0`）小了 **290 倍**！线性层即使把权重学到 `3.5`，乘出来也只有 `0.008`，几乎完全被淹没！
3. **`Beat This!` 的 `downbeat` 在 `_harmonic_coefficients` 中只占 1/5 选票，且候选时刻的直接 `downbeat_prob` 未传给模型（第 99–105、147–149 行）**：
   - `signal` 拼了 5 列：`[onset, low_mel, chroma, beat_this_beat, beat_this_downbeat]`；
   - 第 103 行对 5 列做简单等权平均 `.mean(axis=1)`，导致最关键的 `beat_this_downbeat` 只占 **20%** 权重；而且第 4 列 `beat_this_beat` 在每拍都接近相等，减去每拍均值 `baseline` 后剩下的纯属残差抖动，却在除以自身 `residual_energy` 后被放大成 100% 单位能量参与平均！
   - 更可惜的是：候选时刻 `seconds` 处极其干净的 `Beat This!` 直接预测值（`beat_prob` 和 `downbeat_prob`，在真实小节首拍高达 `0.58`、其余拍仅 `0.02`）**根本没有放进 48 维特征里直接给模型看**！

## 3. 给 Astra 的具体修复要求

1. **直接暴露 `Beat This!` 局部拍/强拍概率**：
   - 将候选时刻查询到的 `beat_this` 局部 `beat_prob` 与 `downbeat_prob`（或局部峰值）直接放入 `structure_features`（例如替换掉恒为 `1.0` 的 `valid` 冗余列，或作为独立通道），让选时头和配置头能直接看到 `0.58 vs 0.02` 的强拍提示。
2. **修复 `wt * z1` 的 290 倍幅度坍缩**：
   - 不要用全部 88 个密集重叠周期的总和 `8. + evidence.sum()` 去除单个周期的 `evidence`！应当只在**选出的 4 个代表性槽位（Top-4）加一个虚拟 unknown 项**上做归一化（或者直接输出归一化方向 `z1 / max(|z1|, 1e-8) * conf`，幅度保持在 `0.2 ~ 0.7` 量级，与前 6 维的 `0.707` 同量级）。
3. **停止在 `_harmonic_coefficients` 中把 `beat_this_beat` 的去脉冲残差噪声放大为单位能量**：
   - `beat_this` 的第 0 列（`beat`）只应用来辅助步骤 1 的 `pulse` 估计，**绝不能在减去每拍均值后再除以 `residual_energy` 混进小节周期傅里叶系数里稀释 `downbeat`（第 1 列）**！
