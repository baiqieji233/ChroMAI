日期：2026-10-23。用户要求完整阶段全部落地后统一测试，允许修改训练合同。

## 评估结论

两份咨询在风险方向上有价值，但不能把未接触代码的推测直接写成根因事实。

| 建议 | 判断 | 本次处理 |
|---|---|---|
| 音频证据与历史竞争不对称 | 当前架构确实允许历史任意覆盖指针；是否已发生梯度饥饿需实测 | 新增结构上有界的历史残差与分组遮挡 |
| 平坦候选 softmax 受候选数影响 | 等分数时区域概率按候选数增长，是数学事实；实际坍塌幅度未知 | 新增间隔档位→档内拍点的层级概率 |
| 100–500ms 包络顺序不可见 | 当前有均值/积分及点特征，但缺少可学习的连续局部序列编码 | 新增31帧局部TCN，保留绝对动态与先后顺序 |
| 稠密谱面占用监督 | 对特定谱面和条件成立，不能称未写的声音都是错误 | ±25ms参考占用及类型辅助头，候选与均匀探针混合，未知区域mask |
| 动作字段共享 | 当前词表输出确实缺少显式字段共享，适合保留catalog改参数化 | 同合法ID上新增组合字段权重、共享历史嵌入、相对多头关系 |
| 小节/乐句规划 | 有价值，但计算块不等于真实段落，也不能保证音乐重复就应复制配置 | 四拍音频块全曲TCN规划，候选线性插值读取，不强制块边界切谱 |
| 动态Oracle恢复 | 原谱下一个事件不是任意错误前缀下的最优动作证明 | 真实短rollout、可信跨度/可达/合法检查后，仅时间监督 |
| 全删ledger、GT预算直接作输入 | 会造成新的分布差和标签捷径，块重置也可能制造跳变 | 保留因果台账，独立dropout，最终指针残差限幅；只给预测plan |
| hazard直接替换pointer | 可实现，但需处理候选测度和有限窗口生存概率，不能把空窗当EOS | 本阶段选层级指针，避免一次叠加两套时间分布 |
| D8旋转、左右镜像、CFG、DPO、8路SMC、检索 | 都需额外几何/负例/计算成本证明，不能声称零成本或必然有效 | 不捆绑上线；记录为独立后续方向 |

需明确纠正的推导：小JS不等于通路已死；CE不等于对谱面求算术平均；
softplus排序在等分或负差处也有梯度；±s残差使两候选相对log-odds最多改变2s，
并非s。代码对最终候选残差限幅，不只限制归一化前的中间层。
现有discrepancy的预测与候选未来窗口不同，教师强制下也不保证恒等于0。
MiaCode合法不等同于音乐上最优，参考恢复仍是受限弱监督。

## 新架构与功能索引

- `audio_lens.py`：复用现有20ms/native特征库，读取[-200,+400]ms的31帧、26通道。
  非因果TCN和带位置的池化保留顺序，边界清零并mask，未伪称HPSS/PCEN。
  `PlacementTargets`只使用可信事件，匹配邻域±25ms，多事件类型取并集。
- `planning.py`：四拍计算块，整曲音频+条件产生负荷/类型/休止参考。
  真实标注仅用于loss；预测plan插值后作为决策输入，训练和生成相同。
- `grounded_model.py`：新profile `audio_grounded_v3`。音频决定六档间隔先验及档内拍点；
  历史修正最终经tanh限幅。原始ledger不再能无限改变候选log-odds。
  历史旧事件可遮挡，但保留最近两个锚点；ledger独立遮挡；完整symbolic遮挡保持一致。
- `action_factors.py`：合法词表ID不变，类型、按键集合、时值、路径、相对终点、修饰符等
  字段共享参数，history和输出共用；同拍关系使用多头平均，不假设某槽或t-2属于同手。
  字段映射和词表顺序进checkpoint，重排会拒绝加载。
- `recovery.py`：真实模型回调rollout2–4步，精确拍位；重算生成前缀的全部因果输入。
  参考续写跨未知区域、候选不可达或原配置已不合法就跳过；动作/未来/EOS等标签不借用。
- `train.py`：fresh默认新profile；可选music_context_v2基线。联合损失含指针、配置、
  workload、placement、plan。每100次更新默认尝试2个两步rollout，恢复CE权重0.1；
  记录接受/拒绝原因和耗时。恢复梯度纳入同次裁剪与更新，按样本质量加权。
- `generate.py`：新模型读取相同Lens/Plan输入；plan整曲一次预测，Lens候选嵌入有界缓存。
  支持选时历史权重0–1，1保留模型完整决策、0用音频分支；动作解码仍使用完整上下文。
  报告额外记录音频/完整指针JS、预测plan和Lens缓存命中，均是诊断而非音乐质量分。
- `checkpoint.py`：显式部分迁移旧Composer权重；新模块必须学习。旧权重生成保持可用。
  新合同 `chart_composer_training_v7_audio_grounded_recovery`，不伪装为旧合同resume。
- WebUI：新profile和全部新训练/生成参数完整转发；resume继承父配置，新增数值冲突明确拒绝。

## 实现取舍与效率

先复用现有音频库而不新增整套10ms*HPSS/PCEN多路缓存，防止主机I/O再次膨胀。
训练只读取当前候选与均匀探针所需的短窗，TCN按候选块计算；生成复用相同时间的编码。
没有把整首歌的所有候选特征展开落盘。恢复训练有显式间隔/样本/步数预算，0可关闭。
它是受限参考时间监督，不是完整DAgger最优oracle；接受率很低时应看日志而非无声增大次数。

### 复核中修正的附带问题

- 最终指针残差再次限幅，避免分桶归一化后间接放大历史差异。
- symbol遮挡覆盖动作关系支路；恢复loss按原样本质量加权。
- v3→v3显式finetune会应用新的短窗宽度/dropout/限幅参数，不静默沿用父值。
- 模型在inference_mode外初始化参数，保证权重版本计数器可用；
  组合动作输出矩阵缓存会在权重更新后失效，推理重复槽位不反复重建。
- 检查点fingerprint支持字段映射的非Tensor extra_state，词表顺序必须一致。
- 主界面检查旧checkpoint时不会把用户选好的v3 finetune目标覆盖回v2。
- 恢复分支的加权loss、接受/拒绝数已单独接到训练面板，未发生时显示未知。
