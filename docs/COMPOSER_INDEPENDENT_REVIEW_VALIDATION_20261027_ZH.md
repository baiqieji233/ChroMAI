## 1. 单步过量复制的解释应撤回

同一检查点、1536行固定输入、CPU FP32独立复算：

| 口径 | 模型概率 | 真实比例 |
| --- | --- | --- |
| 首槽音符与上一事件首槽完全相同 | 7.17% | 8.53% |
| 首槽起始位置相同，区分各Touch pad | 14.20% | 14.78% |
| 原脚本九分类口径：按钮1–8加“全部Touch” | 16.61% | 17.71% |
| 过去四个首槽都是按钮头，已有ABAB时继续交替 | 38.85% | 45.90% |

原脚本把所有Touch合成一个类别，所以其“同键”也会包括不同Touch pad之间的转移。修正后仍然没有出现整体单步重复概率过高；不是靠这个口径问题否定审查的主要更正。

对前600行使用实际类别采样规则，动作温度1→0.5时，同音符概率7.25%→7.17%，最大概率39.45%→53.47%。该测试只改变给定真实历史的一次分布，未包含完整运行时约束与长程反馈。

去掉重叠历史窗口的重复计数后，等级≥13.5的真实片段中，同配置/ABA/ABAB为6.32%/8.11%/3.31%；用户指出的单份生成谱仍为15.25%/15.67%/8.91%。歌曲与种子范围不匹配，保留为方向性差距。

因此应继续查“哪些生成轨迹会把模型带入坏状态”，而不是把模型在所有真实历史上的下一步都当成过量复制。此前同输入坏前缀回放已表明，旧模型也会维持高Touch反应；这与单步平均校准并不矛盾。

## 2. 已实际测试两种架构修复

为每条历史事件补入26维音频摘要：6维动态、8个mel带均值、12维chroma，按该事件真实发生时间读取。逐行核对1536条原样本的历史ID和目标ID全部一致，原样本不被覆盖。

测试两种结构：

- **历史配对音频**：向历史表示加入一层零初始化投影，新增9984个参数。
- **显式相对关系**：用“当前音频减去上一事件音频”，与上一事件头部几何共同构造关系，只加入配置解码；新增79872个参数。

二者各有同参数量、打乱事件/音频配对的对照。连同原模型，共5组，每组48次更新，合计240次。相同父权重、重新初始化的AdamW状态、学习率0.0002、样本顺序及随机种子；CPU FP32，batch16。新增投影为零时，已验证输出与父模型完全相同。

所有实验沿用旧配置目标，恢复采样关闭，以隔离此次结构变化。使用768行更新、384行观察；观察歌曲不参与这次更新，但父模型以前见过它们。固定输入中没有动机张量，所有组一致。

| 实验 | 更新样本配置误差 | 观察样本配置误差 | 观察样本首槽误差 | 观察样本选时误差 |
| --- | ---: | ---: | ---: | ---: |
| 更新前 | 2.1185 | 1.9732 | 2.6688 | 0.9364 |
| 原模型 | 1.6805 | **1.9843** | **2.6781** | 0.8610 |
| 历史配对音频 | 1.6839 | 1.9948 | 2.6937 | 0.8677 |
| 历史音频打乱配对 | 1.6861 | 1.9925 | 2.6866 | 0.8701 |
| 显式相对关系 | **1.6731** | 1.9919 | 2.6925 | **0.8587** |
| 相对关系打乱配对 | 1.6881 | 1.9887 | 2.6866 | 0.8705 |

**两种具体修法均未在观察样本胜过基线，也没有胜过各自打乱配对对照。** 它们没有进入正式模型，未新增WebUI参数。这个结果针对从成熟模型出发的短程微调，不代表所有可能的历史音频架构都无效；它明确淘汰了“直接加进去就能明显加快配置学习”的这次实现。

下一步审查应把输入关系、训练目标、同拍排序和长历史覆盖放在一起考虑，不再仅靠增加音频分支或重复惩罚推进。有关新鲜模型训练、更多样本和长程效果，本轮没有结果。

## 3. 动机分支训练时也极少命中

按正在运行的v13使用的旧描述方法，在完整949,015个样本中，固定种子不放回抽8192个，覆盖1754/1787份谱面：

| 情况 | 样本数 |
| --- | ---: |
| 成功检索 | 19（0.23%） |
| 没有先前音频关联 | 8171 |
| 只在普通历史窗口内有可用内容 | 2 |

统计只查询关联图和已提交事件，不运行网络。对其中584个查询，另与实际生产词表的检索mask逐项核对一致。

因此仅扩大动机容量或缩短128事件排除窗口，无法针对主要缺口。样本谱面的最大候选相似度中位数约0.333，低于当前0.75门槛；但直接降低门槛也可能把不相似的乐段联系起来。

同时试了将每个描述区间的采样量提高8倍、保持描述维度和门槛不变。在32首真实歌曲中，关联总数从3变成7。这还没有经过真/假匹配验收，未启用到正式代码。

## 4. 已落地的两项修复

**修复声学平坦通道的数值放大。** 旧代码会将接近常量的音高、音色里极小的残差分别归一化到单位强度，与真实节奏变化拥有相近影响。加入10⁻⁶量级扰动，两个相同节奏的相似度可从接近1降至0.24；修复后回到接近1。静音、真正静态纹理和无关变化仍有回归检查。

修复只在归一化前排除数值精度范围内的平坦残差，没有降低0.75相似度门槛，没有加大模型。32首真实歌曲的关联总数修复前后均为3，**这项确定错误不是整体动机稀疏的完整解释**。修复后未重新扫描全部8192个查询，不能把前述0.23%写成新版全量命中率。

**补齐动机输入身份校验。** 以前数据指纹没有覆盖实际用于检索的区间、关系和相位，关联算法改变后仍可能被当成同一训练输入。本轮将这些内容纳入指纹，并记录`motif_input_policy=temporal_noise_stable_v2`。这样，动机输入发生变化时不会静默沿用原训练游标。

旧的启用动机检查点仍可用于生成或作为微调父模型；生成保留原描述解释，新点才使用修正版。下次在新版代码继续训练，需要选择 **“finetune 微调”** 和新输出目录；未启用动机的模型不受此项迁移影响。当前运行的v13没有停止，也不会自动切换目标或算法。生成报告分别记录检查点训练时及本次运行时的动机输入策略。

最后还核实：准备缓存的实际复用判断忽略源码哈希。因此本轮将描述策略显式加入缓存键，并验证旧、新策略分别重建和命中；否则仅修改算法可能不生效。

这轮正式训练没有新增音频张量、网络层或逐步搜索。改动发生在预处理与一次性输入校验；新动机策略首次准备需要建立独立缓存，不能把首次准备耗时当成迭代吞吐下降。

## 5. 验证和剩余工作

586项相关Python检查、27项前端检查通过，10项跳过；最后的缓存/兼容性定向检查35项通过。主界面实测：旧动机点拒绝直接resume，但仍可生成/微调；新点完成微调、保存、检查与resume。新验证服务为7873，原7860训练服务保留。

本轮没有重跑被独立审查拒绝的闭环生成命令，也没有用另一种启动方式绕过。已有历史音频强度/温度对照和坏前缀回放继续作为独立证据，不能冒充这份step29664模型的新生成验收。

继续排查的重点包括：长期生成历史的训练覆盖、配置目标及排序带来的偏差、多条历史通路的相互替代、音乐分段与相似度设计、拒绝采样改变历史分布的程度，以及整个基础层的时间/缓存/状态一致性。详细任务表在架构交接中；已通过的局部测试不作为这些方向的豁免理由。
