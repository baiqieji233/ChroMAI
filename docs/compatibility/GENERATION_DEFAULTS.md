### 2.1 `max_tokens` 辨析（重要）

| | 训练 `--max-tokens` | 生成 `--max-tokens` |
|---|---|---|
| 含义 | **窗口 token 上限（数据筛选）**：超过就丢弃该片段 | **每窗口解码预算** |
| 值 | **1024**（你要求并已确认） | **768** |
| 为什么 | 语料里最长目标 756 token，1024 留余量 | 必须容下跨窗口引子（最多 `context-tokens=320`）+ 窗口本身（实测 p50 155、最大 444）＝ **764**，故 768 是最小安全值 |

两者同名不同义。**若把 `context-tokens` 调大，生成侧的 768 必须同步加大**，否则尾部窗口会因预算不足被跳过（日志会打印 `skipped: context prefix ... leaves no decoding budget`）。

## 4. 逐窗口强度跟随（A）与收尾衰减（A2）

针对"段内强度不跟随音乐 + 安静收尾反而爆发"新增，默认值取自实测：

| 参数 | 默认 | 说明 |
|---|---|---|
| `--intensity-follow` / `--no-intensity-follow` | **开** | 按音频自身的 `relative_rms` 通道（1.0=全曲中位、2.0=两倍响度、0=静音）逐窗口缩放 `note_density` 与 `peak`；风格项不动 |
| `--intensity-follow-span` | **0.5** | 系数限制在 0.5×～1.5×，保证用户设定的难度档仍可辨认 |
| `--tail-damping` | **关** | 最后 N 个窗口线性压低密度（"曲子收尾该渐弱"的音乐先验） |
| `--tail-damping-windows` / `--tail-damping-strength` | **4 / 0.6** | 末窗只要求原密度的 40%，向前线性回到 100% |

实现：`src/maichart/generation/intensity.py`（系数计算 + 3 窗口滑动平均 + 尾部 taper），
在 `event_cli._decode_windows` 逐窗口应用；服务端（`server.py`）、面板
（`index.html` 的 5 个字段 + `app.js` 的收集/持久化/重置）已同步。
日志逐窗口打印 `intensity=系数` 与缩放后的 `note_density`，可审计。

### 4.1 实测：机制正确，但对当前 checkpoint 无可见效果（重要）

同一 checkpoint（第 21 轮）、同一 seed，开/关两臂在真实曲目上：

```
on : intensity=0.50..1.06，note_density 0.155..0.330
off: intensity=1.00，        note_density 0.310
两臂输出：逐窗口事件数 27/27 完全相同，总事件 726 vs 726，rms_density_correlation 0.1469 vs 0.1469
```

**原因已量化**（单次前向，无采样噪声）：

| 条件改动 | 下一步 token 分布 L1 变化 |
|---|---|
| note_density 0.31 → 0.155（安静窗口） | **1.2%** |
| 密度 0 → 1.0 | 5.6% |
| 等级 13.3 → 1.0 | **19.1%** |

即：**这个 checkpoint 几乎只听"等级"，几乎不听雷达/密度**——`--condition-mask-prob 0.5`
把雷达/风格遮掉一半是主因，叠加 23 轮训练不足。CFG 只能线性放大
（guidance 1→3 时两臂差异 2.4%→7.3%），治不了根。

**结论**：A/A2 是"把缺失的输入补上"的接口修复，**它生效的前提是模型真正听条件**。
要让"强度跟随"可见，必须修训练侧：`--condition-mask-prob 0.2`、
`--global-audio-dropout`（逼用局部音频）、`--intensity-loss-weight`（把局部强度变成必须编码的目标），
并以 lr 1e-4 / patience 10 续训。短期可用的旋钮是把面板 `guidance scale` 提到 1.5–2。

## 5. 音频边界裁剪（生成侧修复：开头/结尾多出的音符）

针对"开头静音处却有音符、音乐结束后仍有音符"新增，默认开：

| 参数 | 默认 | 说明 |
|---|---|---|
| `--audio-bounds-trim` / `--no-audio-bounds-trim` | **开** | 把谱面限制在"音乐真正在响"的区间内；完全无音乐的窗口输出空窗、不解码 |
| `--audio-bounds-lead` | **0** | 边界余量（秒）。**必须默认 0**：设成 0.5 s 时实测音乐 2.40–142.96 s，谱面首音符却落在 1.94 s、末音符 143.29 s |
| `--silence-threshold` | 0.15 | 响度低于"全曲中位 × 该值"算静音（实测 0.10–0.40 结果一致，不敏感） |
| `--silence-window-share` | 0.05 | 可听帧占比低于该值的窗口直接输出空窗 |

**边界用"响度 ∪ 起音"两条证据**，不能只用响度：实测该曲首个起音在 **1.98–2.04 s**，而响度到 **2.40 s** 才过 15% 阈值；
只按响度会把模型正确落在弱拍上的 2.12/2.21 s 音符一起裁掉，开头空出 3.25 s。

### 5.1 实测（同曲、同 seed、同参数，只差裁剪开关）

| 版本 | 事件数 | 首个音符 | 末个音符 | 音乐前 | 音乐后 | **越界合计** | nps | 覆盖率 | 空白 | 贴合度 |
|---|---|---|---|---|---|---|---|---|---|---|
| 裁剪关（原始行为） | 695 | 1.41 | 146.12 | 6 | 9 | **15** | 4.80 | 0.998 | 0.029 | 0.532 |
| 余量 0.5 s | 661 | 1.94 | 143.29 | 1 | 2 | **3** | 4.68 | 0.979 | 0.029 | 0.532 |
| 余量 0 s（只按响度） | 530 | 5.65 | 142.94 | 0 | 0 | 0 | 3.86 | 0.977 | 0.059 | 0.357 |
| **最终：联合边界** | 685 | **2.12** | **142.94** | **0** | **0** | **0** | 4.86 | 0.977 | 0.029 | 0.432 |

金标 52 首参考：覆盖率 p50 0.968 / p95 0.985；空白 p50 0.031；贴合度 p05 0.354 / p50 0.517
→ 最终版三项**全部落在金标带内**，且只裁掉了 10 个越界音符（695 → 685）。

### 5.2 顺带验证的两件事

- **节拍网格相位正确**：92% 的音符落在强起音 ±0.08 s 内，中位偏差 −41 ms（不是网格错位问题）。
- **模型的"提前起音"是真实存在的**：未裁剪时最早的 8 个音符落在 1.41–2.21 s，其中 2.12/2.21 s 对得上起音（合法），
  而 1.41–1.94 s 比首个起音早 0.06–0.59 s（越界，已裁掉）。这部分"模型在窗口开头先写一小段"的行为属训练侧问题。

## 6. 生效方式

- **静态文件（面板）**：刷新页面即可（`index.html` / `app.js` 无缓存）。
- **`server.py` 与 CLI 默认值**：需要**重启 WebUI 进程**（服务端兜底值在进程启动时载入）。
