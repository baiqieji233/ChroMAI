# Composer v2：窗口失败、Radar／Style 和自动节拍修复

更新：2026-11-04。本轮保留原检查点，没有启动训练。

后续更新：新的fresh训练已改为[连续事件方式](../explanations/COMPOSER_V2_CONTINUOUS_EVENTS_20261104_ZH.md)，取消下文所述固定窗口输出边界；本文保留当时的修复背景和旧点行为。

## 当前到底是不是分段生成

**有固定窗口边界。准确名称是“带历史的窗口式自回归”。** 默认每16拍重新组织一次输入，在窗口内逐组件续写；下一窗口会重新读取前16拍的具体音符、尚未结束的Hold／Slide，以及一个更早的参考片段和全曲音乐。

因此它不是各段互不相干地生成后拼接，也不是完全没有固定边界的连续解码器。窗口边界会重建解码缓存，可能影响跨窗延续能力。本轮保留现有模型的输入合同，没有通过改日志名称掩盖这个取舍。若要彻底去掉固定边界，需要配套改训练样本与时间表示，不能只删除窗口循环。

## 第64拍失败的直接原因

失败任务为 `585bca2479ac`，使用 `checkpoints/chart_composer_v2_v1/composer_v2_last.pt`，温度0.9、Top-p 0.95、单候选、种子20261103。

旧实现先写完16拍，再检查物理冲突。只要其中一处有同拍重复键，或原生检查确认不可执行，整段就丢弃重写。日志中32～48拍重试了8次，64～80拍16次全部失败。`rollback_budget_used=0/2`不表示预算没接通：旧跨窗撤回仅针对跨过窗口边界仍未结束的持续动作，这次没有触发该条件。

修复后的处理：

1. 同拍配置结束时立即检查，合法前文就地保留。
2. 局部失败时只重采当前拍的配置，已经选定的时间和合法前文不动；解码缓存同步回退到该拍，音乐缓存继续复用。
3. 在语法层排除同拍重复起点。Slide的终点不当作新起点，按钮1与Touch A1仍是不同位置。
4. 局部修复耗尽后，才使用原有整窗重试和必要的持续动作撤回。没有放宽物理检查，没有强制补音，也没有强制结束休止。
5. 最终仍失败会写 `.failure.json`，记录合法前文和失败配置，便于继续定位；不会假装导出了完整谱面。

用原权重、原音频、原种子和相同采样参数复测，完成21个窗口、439个事件。64～80拍只发生两个局部修复，一次通过。保留了3个空白窗口。此结果证明失败恢复路径改善，不证明音乐质量已达标。原检查点SHA256前后一致。

## Radar／Style为什么消失，如何恢复

上一版v2训练时实际只提供等级，另外15维都是零，所以隐藏控件有事实依据，但这也意味着功能迁移没有完成。直接给旧权重输入那些数值，只会改变未训练的输入，不等于获得相应风格能力。

本轮加入明确条件合同：

- 旧点识别为 `level_only_v1`，依然可以生成，只声明等级能力。
- 新阶段使用 `radar_style_v1`，从真实谱面计算各项指标，并使用全音频时长与统一持续动作语义。
- 每项条件区分“已指定的数值”和“自动”。**手动0不是自动**。默认不指定，交给音乐和前文决定；需要控制时单独勾选。
- 训练包含全部自动和部分自动的样本，避免只学会读取答案谱面的统计。新合同的主验证指标也使用默认自动条件，不把真实谱面统计偷偷传入验证预测。
- “节奏贴合”表示起音匹配代理，不是旋律识别；具体支持情况由检查点合同声明。
- 旧点直接resume继续旧合同；想学习新控制，在新目录finetune，或fresh。迁移不覆盖旧点，新加的缺失条件表示以零初始化。

主界面仍使用原Radar／Style分组，v2保存独立设置，切回v1会恢复v1自己的值。旧点会显示能力说明并禁用不支持的手动选项，不再伪装成可调。

## BPM和起始偏移现在可以自动识别

本次失败任务的命令没有BPM，旧后端实际上用了120，而不是自动分析。这是另一个独立的时钟隐患，不能把它当成第64拍所有冲突的唯一原因。

现在：

- **BPM留空**：在生成子进程内真实分析音频，优先复用本机BeatThis和缓存；不可用时用声学起音检测，并明确报告来源。
- **自动识别首拍相位**：独立选项，默认关闭。关闭时保留手动“起始偏移”，包括显式0；开启时估计拍位对齐相位。
- 手动变速表优先于单一BPM；手动BPM和偏移都已给出时，不运行自动检测。
- 检测失败明确报错，不回退120。结果写入日志和 `.composer_v2.json` 的 `timing` 字段。
- 检测缓存只保存音频拍点，修改手动BPM或偏移不会误用上次的最终时钟。

这次音频得到约94.9992 BPM，自动相位约0.01055秒；229/304个检测峰符合该网格，符合网格的峰残差P90约18.38毫秒。其余峰包括更细的节奏，因此报告同时保留全部检测峰的误差，不能只看较好的子集。

**95与190可能是同一音乐脉冲的两种计数方式，自动分析不能保证恢复原谱采用的那一种。** 报告列出半速／原速／倍速候选，用户仍可手动填写190等值。自动相位也不是“第一颗音符出现时间”，更不代表识别出了小节或主副歌。当前自动分析只估计全曲常速，不会把检测抖动制造成一串变速。

接线后的自动时钟生成已完成整曲，514个事件。这是另一组时钟设置的接线验证，不能与439事件那份直接当成质量优劣比较。
