# 这次项目更新了什么，接下来怎么使用

核对日期：2026-10-27。适用当前开发分支`codex/composer-causal-motif-touch-20261025`，基于`6c4d24a`之后的改动整理。

> 后续复核已修复Beat This信号在输入前被过度削弱的问题：新训练默认51维增强版，旧v15仍为48维；默认新目录也已改为`prism_composer_v16_signal`。本文v15训练和性能数据保留为对应版本记录，最新变化见[信号复核与修复](COMPOSER_BEAT_THIS_FIX_20261027_ZH.md)。

项目仍是“输入音乐和目标条件，生成Simai谱面”。这次没有把它改成另一套生成器，重点是让模型能看到更长的音乐结构，让训练结果更容易检查，并减少准备数据和GPU计算之间的等待。

## 1. 最主要的变化

**模型现在多看一份音乐结构提示。** 原来主要知道当前拍内的位置和附近声学内容；现在还提供4、8、16拍的周期位置，以及从音频估计的重音周期、段落变化。遇到三拍、复合拍等情况，会保留多个候选，而不是把所有歌曲都强行解释为四拍小节。

这里的“小节结构”是分析器的估计，可能判断错误。它给模型参考，不会在分析到的边界强制换键、换手、结束重复或清空历史。原有按音频相似段检索配置的“动机记忆”也继续保留；两者作用不同。

**训练和验收使用不同歌曲。** 新训练默认把约5%的歌曲留出来，再分为开发验证与最终验收两部分。同一歌曲或完全相同音频不会被拆到两边。验证集不能给模型扩充音符词表；遇到模型不认识的音符，会报告实际覆盖缺口。因此验证数字必须连同“覆盖了多少事件”一起看。

**每轮除了算验证误差，还会固定歌曲与种子实际生成。** 这能检查真实续写中的重复、Touch和冲突，补上“单步答得对，但连续写就绕圈”的评估缺口。原谱只是同歌参照，某项比例超过原谱两倍会提示复查，不会直接判成坏谱。

**Touch保护修正了一个实际采样漏洞。** 现在先确认这个槽位有哪些合法选择，再比较主模型与音频参照；后续槽还会把“本组结束”纳入比较。这样既不会把概率转移给随后被过滤掉的按钮，也能限制模型因为自己的历史而不断续加Touch。它仍然不是固定的Touch配额。

## 2. 主界面里新增的参数

入口仍是主页面`/`的训练和生成面板。独立Composer页面属于旧入口；这次也同步了相关字段，但日常操作使用主页面即可。

| 主界面术语 | 作用 | 当前默认 |
| --- | --- | --- |
| 音乐结构条件 | “关闭”可作基线；“周期结构”提供固定周期位置；“节拍与小节结构”再加入音频估计 | 新训练“自动”使用节拍与小节结构 |
| 结构分析后端 | “内置分析”只用项目现有声学；“Beat This”使用额外的节拍分析模型 | 自动：本机依赖与权重可用时选Beat This，否则内置分析 |
| 结构条件遮挡概率 | 训练时有时隐藏结构提示，降低对估计结果的过度依赖 | 0.15 |
| 接触预算策略 | “仅诊断”记录有限接触模板的结果；“按几何假设拦截”会过滤部分组合 | 新训练仅诊断 |
| 学习率变化方式 | 恒定，或先预热再逐渐降低 | 新训练自动保持恒定，续训继承原计划 |
| 学习率预热更新数 | 用多少次真正的参数更新逐渐升到基准学习率 | 留空自动选择；余弦方案最多500，恒定方案0 |
| 末尾学习率比例 | 训练末尾降到基准学习率的多少 | 余弦方案留空为0.1；恒定方案为1 |

“接触预算”还不是完整的双手模拟。官谱审计发现，简单的“远距双按钮加中央Touch”模板也会命中已有配置，因此默认只诊断。不要把它的通过结果理解为已经保证玩家可以顺手完成。

当前v15是在新结构下从头建立的模型，后来从完整保存点接续。它没有继承v14权重。本轮审核保留了运行中的训练和所有原检查点，没有替它重新开训。

64×4变成128×2虽然保持样本总量一致，浮点计算、Dropout和按批归约仍会变化，所以不能称为逐位等价。此设置已经在本机测过容量和速度；换硬件时应重新检查显存。

默认按钮仍可能填入早期的`prism_composer_v14`目录。**新实验必须另填一个新目录，已有v14、v15目录不要用fresh覆盖。** 需要接续当前任务时使用完整`composer_last.pt`和它记录的数据划分、学习率计划；`composer_inference.pt`主要用于生成。

## 4. 看训练界面时，重点看哪些数字

- **配置首槽与后续真音符CE**：分别看第一颗音符和同拍后续音符是否学会；后者排除了“结束”与补齐位置。没有相应样本时，空值不代表误差为零。
- **近期均值与整轮累计均值**：前者更容易看出刚发生的变化，后者会被较早的批次拉住。
- **实际优化目标均值**：包含触发恢复训练时额外反传的恢复损失。基础loss仍保留原口径，二者含义不同。
- **当前学习率与梯度范数**：帮助识别是否还在预热、是否出现异常的大更新。它们不能单独说明谱面更好。
- **验证集指标（教师强制）**：输入真实谱面历史，检查对留出歌曲下一步的预测。
- **固定歌曲闭环验收**：模型持续读回自己的生成结果；打开对应报告，与同歌原谱比较重复、Touch、物量和冲突，再试听、试玩。

自动留出比例、每轮验证批数和固定生成歌曲数目前使用训练后端默认值，API/CLI可调整，主界面主要展示结果。不要把其他模型族的同名验证输入误当作Composer专属控件。

## 5. 性能结果与它的范围

核对了前一轮保留的原始测量文件：结构查询中位耗时约从1.98毫秒降到0.30毫秒，返回特征逐位一致；这是局部查询提速。固定输入GPU测试中，合并数值检查并把微批扩大后，约从471升到578样本/秒。

真实训练的匹配样本短窗口约从197升到228样本/秒，提升约15.8%。这不是整轮保证值，歌曲内容、CPU准备和系统负载仍会影响速度。GPU计算变快后，“等数据”的占比可能上升，同时总体吞吐仍提高。

上述GPU数据来自已有独占测量记录，本轮复查了文件与计算口径，没有在正式训练旁边重跑竞争GPU的基准。最终模型的音乐质量也不能由速度提高推出。

## 6. 本轮审核补上的问题

1. **Windows并发结构缓存发布。** 原始节拍结果有文件占用保护，后续结构数组却遗漏了同一场景。现在另一进程已写完并映射相同缓存时，会校验并复用；不完整或含无效数的结果、真实权限失败仍报错。没有改变结构特征版本和数值含义。
2. **旧诊断入口遗漏结构输入。** 已补上结构策略、后端和特征传递；省略上一事件时重新计算候选及结构差值。音频扰动探针保留记谱周期位置，只重排音频派生结构，避免错误解释敏感性。
3. **启动器范围提示。** 提示与版本检查统一。启动器允许的版本范围不代表对应PyTorch一定可安装；仍需依赖导入通过。本机核验环境是`.webui-python`指向的Python3.12。
4. **前端测试夹具。** 全部JS检查中发现旧夹具缺少任务状态变量，已补齐后重跑；没有把测试环境缺依赖误记为实际页面故障。

## 7. 怎样复现和继续排查

普通启动仍用`START_WEBUI.bat --port 7860`。已有训练运行时保留其终端。更换源码不会自动替换已加载的Python模块，下一次启动会加载新代码。

本机已有记录显示1787份谱面的结构准备全部完成，无需为本次审核重复准备。下面仅供新环境首次使用：先在同一个项目Python环境安装可选依赖，并显式准备权重；训练和普通生成不会自行下载。

```powershell
# 在项目根目录，使用 .webui-python 所指定的环境
& .scratch/python312_runtime/Scripts/python.exe -m pip install -e ".[music-structure]"
& .scratch/python312_runtime/Scripts/python.exe tools/prepare_composer_structure.py --manifest "E:\全量官谱\training_manifest.json" --cache-dir cache/chart_composer_v1 --backend beat_this --device cpu --workers 1 --download-beat-this
```

CPU或GPU预处理都可选择；GPU预处理应安排在正式训练空闲时。训练后的结构模型会检查分析器版本与权重身份，换电脑时需准备同一版本，不能无声地改用另一个分析器。

代码入口：`composer/structure.py`负责结构证据，`structure_backend.py`负责可选分析器，`evaluation.py`负责划分与评估，`learning_rate.py`负责学习率计划。`tools/evaluate_composer.py`提供固定生成及原谱对照；`tools/probe_composer_touch.py`用于同输入概率探针。旧合同探针输入不能随意补零后冒充新合同数据。

仍待验证的是：长时间训练后是否减少单键长链、交替堆砌和错误细分；结构估计在特殊节拍上是否可靠；Touch与双手是否自然。当前只对有限接触模板做诊断，完整手部轨迹仍未实现。训练loss、合法性检查通过、人工听感是三种不同的证据。
