## 2. 为什么总 loss 仍是4点多

总值是多个任务的加权和。以完整第3轮为例：

| 部分 | 加入总值的约数 |
| --- | --- |
| 精确动作配置 | 2.6524 |
| 候选选位 | 0.9930 |
| 纯音频动作 ×0.15 | 0.4579 |
| 纯音频选位 ×0.15 | 0.1676 |
| 结束、未来意图、负荷、占用、规划等其余项 | 合计0.0869 |

动作及其音频辅助占总值约71.4%。它不是某一个任务的错误百分比，也不能套用其他模型“loss 应低于1”的阈值。仅减小辅助权重会直接降低总数，却不证明模型学得更好。

动作词表含STOP共18,454项，完全均匀预测的交叉熵约为 `ln(18454)=9.82`。大词表解释起始标尺，但**不能据此断言当前精确配置已经学好**。旧合同曾平均大量STOP填充槽，旧模型约0.44的动作loss与当前有效槽loss约2.65不是同一标尺。之前v8还继承了训练过的v7权重；本次v9从随机权重开始，不能按微调的起点来预期fresh曲线。

## 3. 精确配置与类型预测是不同问题

当前epoch3/step6800的8个固定真实训练样本（Tap/Hold/Slide/Touch各挑2个，**不是全量代表性分布**）中，动作CE为3.702，可分解成：

- 类型选择CE：约1.094；
- 类型内部的精确原子CE：约2.608。

例如目标 `2V48[8:1]`：Slide大类概率约79.4%，但精确原子NLL仍为8.63，其中约8.40来自Slide类别内部。词表有16,096种Slide原子；轨迹、位置、时长和修饰的精确选择仍较弱。仅预测对类型并不能得到低原子CE。

音频与全局条件也通常不能唯一指定谱师的键位布局；因此纯音频精确动作目标可能有较强歧义。但本轮**没有测出不可约误差下界**，不能把所有高loss都归结为“任务多解”。共享结构因子有梯度也不代表条件已经被充分利用。

## 4. 固定输入与拟合实验

### 同样8个输入比较两个检查点

CPU FP32、eval模式，候选、音频、历史、条件、目标和代码均相同：

| 指标 | epoch2 / step4944 | epoch3 / step6800 |
| --- | --- | --- |
| 总 loss | 6.9714 | 6.2020 |
| 精确动作CE | 4.1492 | 3.7018 |
| 选位loss | 1.8219 | 1.5229 |
| 纯音频动作CE | 4.1501 | 4.2348 |

完整分支在这组固定输入上有约11%的总loss改善，说明进展不仅是换了更容易的歌曲。音频动作在这8个样本上反而变差，进一步说明该支路需要关注；不能把小样本结果外推全量或泛化。

### 能否拟合固定小批次

从step6800的独立CPU副本出发，加载真实Adam状态，核实学习率为`1e-4`、参数优化器step为6800，保持clip=1，关闭dropout以做可重复诊断。只在同样8个样本上重复更新：

| 更新次数 | 总loss |
| --- | --- |
| 0 | 6.2020 |
| 8 | 3.1521 |
| 16 | 0.9322 |
| 32 | 0.0776 |
| 48 | 0.0637 |

精确动作CE最终约0.00091。这个结果排除了这些输入上“优化链完全无效/无法拟合”的情形；不是全量收敛或音乐质量证明。实验使用CPU FP32、eval关闭随机遮挡，与正式BF16随机训练不同，不能承诺正式loss也会达到0.064。没有把该实验权重写回正式模型。

## 5. 已排查与尚未确认的事项

- 正式各阶段实际学习率均为`1e-4`；所有日志更新计数匹配梯度累积，未发现漏更新、nonfinite或跳过更新证据。
- 首STOP后的槽梯度为零；有效槽数改变不稀释原梯度。结构因子和条件输入存在梯度，未发现完整通路断开。
- 数据准备记录中1,787个`(source,difficulty)`均唯一；同曲不同难度是既有分布，没有同难度重复导入证据。
- 小样本会触发clip，但正式384样本更新窗口的剪裁前范数和命中率没有记录。**不能据4或8样本的范数就判断clip过强，或直接提高学习率。** 当前设置不等于已经证实最优。
- 没有独立、歌曲不重叠的验证loss，因此无法单凭训练曲线判断泛化、何时收敛或20轮是否足够。后续应结合分项、固定输入与固定音频生成验收，而非只追求总数低。
- Touch历史保护属于生成阶段，不改变本训练目标，不会直接使训练loss下降。

## 6. 本轮改动：让页面显示真正的近期窗口

原曲线使用累计平均，却标作“最近总loss”。现在明确标为**累计总loss**，并新增**最近约250个有效batch**的总/选位/动作/音频动作均值，展示实际窗口大小。窗口从累计和的差值恢复，不跨epoch或续训阶段，不伪造缺失字段。

例如前100批均值10、到200批累计均值6，则后100批实际均值是`(6×200−10×100)/100=2`。累计值6并不是近期仍为6。歌曲切换仍会造成窗口波动，窗口值也不是验证loss。

工作台刷新即可看到更新，无需重启当前训练。前端19项回归通过，新增覆盖累计差值、阶段边界和窗口大小；主代理另复核3项Python梯度/续训回归。原训练参数与检查点继续保留。
