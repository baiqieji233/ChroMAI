## 这次确认的问题及修复

### 1. 模型写错前文后，通常没有收到配置接续训练

v50到8000步时，609个恢复目标只有68个带可信配置标签，其余541个只训练选时。这个遮罩原本是必要的：不能把另一种前文强行贴回唯一的原谱答案。但只生成几步、随后看一颗音，导致模型很少练习“面对不同的旧前文，怎样接好一整段”。

新增“可信接缝与连续配置恢复”：

1. 保留模型真实生成的前文。
2. 在一个私有训练分支中，尝试接上原谱中真实存在的短接缝。每颗都检查实际占用，不能提前释放模型已经写出的Hold／Slide。
3. 只有最近至少三颗真实音符及时间与原谱对应、不同的旧动作已经离开原生交互范围，才监督之后的连续配置。
4. 默认最多搜索8个接缝步骤，随后最多监督8个实际决定。接缝本身只作已发生的训练前文，不冒称模型自己生成，也不把未认证配置当答案。
5. 失败时保留可信的时间监督。真实生成轨迹和保存的恢复episode不会混入教师接缝。

每条轨迹仍只占一份预算，8个目标共享这份权重，不会因为标签变多就把恢复损失放大8倍。该设计只改变训练，没有在生成侧强制回到官谱。

### 2. 整段证据被平均得过弱

旧目标先把整段错误平均成近似一颗音的错误，再决定哪一种写法负责解释。这削弱了连续多个事件共同支持一种写法的证据。

新版让同一种写法解释完整观察段。真实决定的证据可以累积，窗口接缝重复看到的同一决定会去重；采样重要性单独计费。已经由实际生成前文选定的写法，仍按该写法训练，不允许损失函数另挑一个更容易的写法代答。

单模式时严格退回原来的加权时间＋配置目标。它仍是流式执行，没有规定“第二段必须镜像”，也没有加固定模板。

### 3. 音乐类型分支没有直接进入实际选择

旧策略把25%的类型监督交给音频分支，但生成主要使用历史续写分支。音频分支学到的类型概率没有直接承担实际类型决策。

新版默认把音乐概率与历史续写概率按25%／75%混合，训练和生成使用同一份最终分布。混合发生在短句写法修正之后，具体键位、路径和同类配置仍由执行器决定。Touch没有被设上限，各环区也没有强制配额。

### 4. 多Touch的同拍展开顺序不一致

训练总按字典序读同拍音符，生成却允许先写任意一个位置。后续位置与STOP判断会遇到训练没见过的前缀。训练归一化还包含生成时已经禁止的重复头位置。

新版用可复现的无序排列训练同拍集合，保留全部音符和末尾STOP；训练的已用头位置支持与现有生成支持一致。没有通过字典序硬截断、削减Touch组合或惩罚重复来遮盖问题。

### 5. 明确条件的执行训练不足

旧训练几乎没有完整条件行，大量执行条件来自模型自己补全，削弱了“用户给了某种类型倾向，就按这种倾向写”的训练。

新阶段默认约75%的谱面组使用明确的原谱控制，25%模拟只给定数或部分条件的自动生成。明确偏好按原向量执行；自动分支仍使用实际补全。风格补全自身继续在全部谱面组上接受遮罩监督，不会因为完整条件行增多而丢掉学习。

恢复前文已经使用过的整曲选择和控制保持固定。没有把未知真实控制泄漏到部署模拟行，也没有增加整曲编码器。

### 6. 异常长Hold需要时值分布本身的学习信号

46拍Hold没有被错误解码。原分类目标只关注真实类别的概率，对同样总量的错误概率落在邻近时值还是很远的时值，缺少直接区分。

新版对**实际执行的最终Hold时值概率**增加分布校准：错误概率离真实时值越远，产生的校准误差越大；真实标注为长Hold时，长时值仍可达到最优。相同时值的不同修饰符会合并为同一时值质量。该分数进入实际落地短句的配置目标，没有新增最长时值限制。

实词表验证覆盖v50全部23个常规Hold槽、2154个候选，包含合法零时值Hold。旧音频打分器的行为未改。当前校准没有覆盖literal TouchHold，秒数采用头位附近的局部拍速估计，不能当作跨变BPM的精确生命周期检查。

fresh还按真实加权频率初始化细节先验，降低罕见时值从均匀概率开始乱抽的风险；这些仍是可学习偏置。加强训练和续训均不重置已学先验。

### 7. 曲线为什么生成后立刻又失效

后端返回`E:\simai_transformer\checkpoints\...`，界面常填`checkpoints/...`。旧代码直接比较这两种写法，每次新曲线都会被判成换了检查点；后来身份匹配时，旧的失效标志又没有清除。

现在按后端提供的项目根目录规范完整路径，再比较实际epoch／step。真正更换模型仍会失效；等价路径和新分析返回的当前身份会解除旧的检查点告警。节拍变化的告警独立保留，不能被清掉。不会仅按文件名宽松匹配不同目录的模型。

另修复了加强训练沿用父阶段最佳验证分数的问题。新目标和旧目标分数不可直接比较；现在加强训练建立新的验证基准，直接续训才继承旧游标、调度与最佳分数。

检查服务时还发现了一条验证失败后残留的“等待启动”任务，既没有日志，也没有子进程。生成API现在先验证完整请求，再创建任务；输出文件创建失败会明确记为失败。真实HTTP验证返回400时，任务数保持不变，不再留下假队列。
