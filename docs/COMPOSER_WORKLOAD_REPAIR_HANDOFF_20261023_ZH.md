## 本次修复的已确认缺陷

1. `future` 头率（head-rate）标签此前将累积偏移量（cumulative offsets）而非相邻事件间隔（adjacent gaps）相加，导致低估了真实密度并将连续乐句误标为长休止。
2. v3 的相位过滤拒绝了常规的 `1/6` 和 `1/12` 乐句；其回退逻辑可能超出配置的候选预算，或继续困在死锁相位中。
3. 基于节点距离的衰减在压低 `attack` 的同时也压低了相对 RMS、能量斜率和色度（chroma）变化，且并未测量真实源音频。
4. Slide 等待起滑区间此前被无条件视为独占手数/按键；双 Hold 动作失败可能导致整首歌提前终止，而此前放宽的事件数测试掩盖了这一退化问题，本次将予以恢复。
5. 被排除区域（excluded regions）标签与非零质量权重此前被 Composer 忽略。

## 实现记录

1. `acoustics.py`, `audio_bank.py`, `candidates.py`：在 20ms 背景网格中心叠加原生证据峰值上执行源采样率前缀能量测量，无需在每个样本上重复计算 FFT 即可修复 `attack`/RMS/细节/斜率特征；稀疏的 Mel/Chroma 保持插值。通过版本化的 `mmap` 映射特征库防止新旧缓存混用。上下文池化按真实时间加权，涵盖 `.5s/2s/8s/全曲` 窗口，不设振幅硬门限。
2. `candidates.py`：保留全部合法相对偏移，并增加绝对网格恢复锚点以提供脱离 `/48` 相位的出口。候选选择仅缓存分数相位（`phase % 1`）而非全曲绝对拍位，且候选预算严格有界。引入高频音乐相位特征以区分不同细分的候选时刻。
3. `workload.py`, `data.py`：提供 5 个原谱负荷通道（事件/头对数速率，以及 Hold/Slide/Touch 占比），均匀全曲探针涵盖休止段落，时间轴采用绝对音频秒数。6 个因果台账（ledger）通道覆盖最近 `1s/4s` 的实际生成密度。靠近排除区域的曲线会被掩码屏蔽，防止把质量排除区错误学成休止。
4. `data.py`：`future` 速率改为使用相邻间隔计算；保留完整原始历史上下文，同时剔除被排除的目标事件。正的谱面/区域质量权重传递至各项损失。稳定节奏的退出样本（exit examples）获得有界的 2 倍转换权重。
5. `model.py`, `train.py`：仅依赖音频+条件的负荷预测头在全部候选点与均匀探针上接受监督；其预测值（绝不使用原谱真实值）输入非线性候选融合层。原谱斜率变化作为学习目标，而非无条件平滑惩罚。动作槽位解码以前序槽位动作为条件（训练时使用 Teacher 标签，生成时使用当前拍已选出的槽位）。历史时间 Dropout 保留最近两个锚点。
6. `generate.py`, `guard.py`：移除对 Slide/等待期手数的无条件一刀切封禁；恢复双 Hold 候选检查；失败的候选事务会重试其他配置/候选时间，绝不提前终止整张谱面；动作结束时间不得超出音频文件末尾；新增的运行时 `MiaCode` 硬冲突会拒绝未提交的候选提案，软冲突保留在报告中；后处理修复结果为空时不再静默回退到未修复谱面；导出预测负荷曲线供复核。
7. `checkpoint.py`, 训练语义：显式区分旧版与新版架构 profile 及特征维度；旧版检查点保持生成兼容，但禁止静默续训（resume）到新架构中，需启动全新训练或显式参数迁移。
8. `generate.py`：在计算时间差特征时将搜索游标（search cursor）与上一已提交事件分开维护；限制重试次数且不中断整曲生成；预计算并向量化原生键位掩码；移除训练/推理中多余的全词表动作投影。
9. 生成报告导出预测与实际生成的负荷曲线、平均头率偏差及相关系数；这些指标仅描述对学习计划的跟随程度，不代表音乐质量，也不会拦截谱面输出。

在完成全部 38 项 Python 测试与 9 项 Node UI 测试后，启动了全新的 `Prism_composer_v4` 训练（WebUI 任务 `4629a789b2c4`，准备 1,787 张谱面 / 949,046 个样本，候选召回率 `0.996154`）。

## 质量边界

学习负荷在绝对音频秒数时钟（含休止段）上由原谱监督。波形响度只是证据，绝非硬性密度目标。参考曲线仅作标签；训练与生成均使用模型预测出的曲线。旧检查点保留其原有的特征策略。

## 数值稳定性修复与尾部积分修正（2026-10-23）

首次 v4 BF16 训练使用 `2e-4` 学习率，在约 2000 步时出现非有限损失与 NaN 权重。定位发现一处具体的数据路径缺陷：`AcousticContext` 此前使用 `unique(searchsorted(...))` 后再做 `clip`，当音频时长超出最后一个声学节点时，两个不同索引在 `clip` 后坍缩为同一行，产生零宽度尾部区间与除零警告，直接引发非有限批次。修复后改为先 `clip` 再去重，并合并重复时间戳；同时将新版 workload 架构的有效学习率上限设为 `5e-5`，在优化器更新前后拒绝非有限梯度/参数，绝不写入损坏的检查点。

修复后重新启动任务 `049d03897dde`，前 100 个批次无任何非有限损失、梯度、参数或除零警告。

## 数据吞吐修复与上下文缓存扩容（2026-10-23）

针对随机跨曲采样反复重开 `mmap` 文件及重建 `AcousticContext` 导致的 CPU 等待问题：
1. 新增容量有界（默认上限 768）的只读 `mmap` 视图二级 LRU 缓存，并在有序预取器后启用 4 个并行样本准备线程（`sample_workers`，1～8，默认 4），随 Windows 物理/提交内存余量动态收缩；
2. 将 `AcousticContext` 缓存上限从 64 扩容至内存感知的 256（高余量下最高 512），消除了积分前缀的重复重建。稳定后吞吐提升至 `1.62 ~ 1.87 batch/s`，主机空闲物理内存保持在 `6.1 ~ 6.9 GiB`。
