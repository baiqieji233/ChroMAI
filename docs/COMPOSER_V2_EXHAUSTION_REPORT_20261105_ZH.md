# Composer v2：恢复失败后继续生成并报告

## 使用方式

主界面 → Composer v2 生成 → **高级生成设置 → 恢复仍失败时**：

- **继续生成并报告（连续模型默认）**：正常重试、时值修复和撤回仍先执行；预算耗尽或没有可用恢复办法时，保留一个可导出的模型候选，继续写后面，并保存冲突报告。
- **严格停止**：维持此前行为，恢复失败后停止并保存独立失败快照。

默认项内部使用 `auto`：当前连续事件模型执行继续并报告，旧固定窗口检查点保持严格停止。CLI 可显式指定 `--exhaustion-policy report` 或 `--exhaustion-policy stop`；强制报告模式仅支持连续事件模型。

已经运行的旧后台可以立即使用默认继续模式，因为新启动的生成子进程会加载更新后的代码。旧后台还不能可靠传递新增的严格选项时，界面会阻止该选择并提示在训练结束后重启后台，避免用户选了停止却被静默忽略。本轮没有为此停止训练或另开生成页面。

## 放行时具体做什么

从当前已被原生检查拒绝的完整候选中，保留第一份能够解析、时间向前推进、动作没有超出音频的候选。只放行物理冲突；重复音符头、无法解析、没有完整候选、时刻不前进或动作超出音频等问题仍会停止。

放行后，该事件会真正进入谱面、模型历史和检查器的占用状态。正在持续的 Hold／Slide 不会被当成已经消失，后续也不会重新卡在同一拍。

“单处冲突恢复次数”为 0 时，关闭修复与撤回；是否最终放行由本选项决定。放行后只有真正超过此前最远拍位，才按原逻辑重置下一处恢复预算。

## 报告与界面提示

结果会明确显示“放行 N 个冲突事件”，使用提示状态，并提供“下载未解决冲突报告”。完成任务表示文件已经导出，不表示谱面没有无理。

文件包括：

- `maidata.composer_v2.json`：有效策略、放行事件数、每次放行内容和报告位置。
- `maidata.<唯一编号>.conflicts.json`：独立冲突报告，后续生成不会覆盖。
- `maidata.conflicts.json`：最近一次报告的兼容副本。

独立报告保存整份事件列表、节拍设置、检查点信息、逐次放行原因，以及最终整谱原生检查结果。“放行事件数”与“最终硬冲突数”分别统计；两者不必相等。最终分析发生异常也会写入报告，保留已导出的谱面。

自动巡检应读取 `accepted_with_conflicts_count` 和报告中的 `assessment`，不能仅凭进程退出码 0 判断物理检查通过。

## 验证

138 项 v2 Python 检查、10 项界面检查通过。验证覆盖报告模式、严格停止、结构错误不放行、时间必须前进，以及放行后的历史与占用状态一致性。

另用受控四事件谱实际执行原生检查：一颗持续 Hold 期间，同键两次 Tap 均发生真实硬冲突。恢复预算设为 0，程序仍导出四个事件，明确记录放行两个事件和最终两项硬冲突，后续历史保留原 Hold 与两次 Tap。通过当前运行后台下载独立报告，返回 HTTP 200，内容与本地文件一致。

这是功能测试，不是模型音乐质量验证。测试没有使用 GPU，也没有停止训练或改动检查点。
