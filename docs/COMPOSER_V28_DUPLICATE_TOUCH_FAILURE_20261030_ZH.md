# v28首轮结束后的任务失败与修复

直接错误是导出谱面时发现同拍重复Touch：第66拍 `E5` 两次，第228拍 `E6` 两次。严格谱面解析器拒绝整张谱，异常从抽检一路传回训练主进程，使20轮任务在第1轮结束后退出。

## 两处原因

1. 字面回退解码器可以重复选同一个音符头。原事件元数据为统计方便对heads去重，局部原生判定也没有拒绝这些Touch重复，所以候选被提交，直到严格导出才报错。
2. 自动抽检的谱面导出错误没有单独记录处理，一个抽检样本失败就终止训练。

## 修复

- 字面解码每选一个原子，就屏蔽与已有原子重叠的起点，包括同键不同修饰、Touch与TouchHold；按钮和Touch仍分别标识。共享星星头的多分支Slide按原生解析为一个头，不会被误封禁。
- 提交前守卫使用与严格导出一致的完整音符解析，拒绝同事件重复head及不支持的语法。没有删除已生成音符或放宽严格导出。
- 单次自动抽检若产生无效谱面，会写 `generation_failure.json`，整组报告 `completed_with_failures` 和失败数，继续其余种子及后续训练。其他运行错误仍正常抛出。

49项相关测试通过，覆盖原始E5/E6反例、不同修饰的重复、合法Touch组合、多分支Slide、解码器源头屏蔽和抽检失败记录；包含模型、恢复、零Hold、训练恢复相关回归。
