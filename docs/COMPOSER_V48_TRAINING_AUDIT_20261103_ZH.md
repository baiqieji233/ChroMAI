## 3. 用真实开发谱检查留白和重新出音

冻结并比较 v48 **step 0 和 step 584** 的推理权重。使用 CPU、单线程、较低进程优先级，不调用训练 GPU，不运行优化器，不导出谱面。

覆盖全部 **48 首开发曲目、57 份谱面**，每份抽取：音频能量最高的 3 个真实内部 WAIT、分散的 3 个真实 NOTE、最前面的 2 个休止后入口。内部 WAIT 后仍有真实音符，避免只检查歌曲结束后的静音。共 456 个判断位置，每个检查点各测“原谱统计条件”和“只给难度、自动推断其他条件”两套输入，总计 1824 次判断。

这里检查的是未来两拍出音／休止概率，不是整谱质量。抽到的内部休止也不是所有可能休止的无偏样本，而是刻意偏向音乐仍较响的难例。

| 原谱条件下的检查 | step 0 | step 584 |
| --- | ---: | ---: |
| 171 个内部休止：平均 WAIT 概率 | 17.45% | 22.82% |
| 同一批休止：平均负对数概率，越低越好 | 1.9311 | 2.0354 |
| 同一批休止：WAIT 为最高概率的数量 | 3／171 | 17／171 |
| 171 个正常出音：平均 NOTE 概率 | 68.69% | 76.64% |
| 114 个休止后入口：平均 NOTE 概率 | 58.42% | 60.57% |

自动条件下方向一致：内部休止平均 WAIT 概率从 16.31% 升至 21.87%，但平均负对数概率从 2.0200 升至 2.1171；WAIT 最高概率从 3／171 增至 19／171。

平均概率提高而负对数概率变差并不矛盾：部分休止明显改善，另一些休止的概率被压得很低。原谱条件下有 89 个改善、82 个变差。**目前不能说主动留白已经学稳，更不能把“没有陷入空白循环”当作“正常留白已保留”的证明。**

此外，在相同音乐、拍位和 NOTE 统计下，把历史中的 WAIT／间隔／被 WAIT 重置的运动统计改成极端值，1824 次判断的 NOTE 概率差均为 0。这确认当前出音接口没有重新读回这些空白反馈字段；没有覆盖所有可能的生成故障。

漏写恢复另作检查：删除真实入口前一段的 NOTE，用合法的两拍 WAIT 回放，再按最高概率连续决定 NOTE／WAIT。每次真正提交 WAIT 后重新读取状态，不强行补音。50 份可完整编码前文的谱面均在 **0–4 拍** 内重新选择 NOTE，两点均未出现持续 WAIT 锁死。初始化有 49／50 个立即重新出音，step 584 为 41／50 个，说明部分恢复变慢。另 7 份谱面的前文不满足此探针直接调用 `codec.encode` 的完整编码要求，未用于此项回放；没有偷偷删除它们后冒充同一前文。这些谱面仍参加前面的真实历史概率检查。

恢复探针的最多 16 拍只是观察预算，不是生成限制。这里只走出音判断，不继续采配置或经过物理搜索，所以不能替代整谱试玩。优化后的概率读取与完整模型在每个检查点各核对一次，NOTE 概率差为 0。
