# 整拍集合 Composer 主界面参数指南

适用日期：2026-11-01更新。本文只解释主界面选择 `event_set_stream_v1 整拍集合连续生成` 时的训练与生成设置。独立 Composer 页面已经弃用；旧候选动作架构的参数不适用于这里。已有用户自定义输出目录会保留；空目录或旧系统默认目录会切换到此路线的默认目录。

第一次训练可以先点“应用重训默认值”，确认素材、输出目录和验证设置，再保持高级参数默认。默认配置是20轮、每批16个短段、梯度累积1次、学习率0.0002。这里的批大小按短段计数，不是歌曲数。已有自定义设置时，这个按钮会替换训练默认值，点击前先保留自己的实验记录。

## 六类训练设置怎么用

### 基础运行

这一组决定任务怎样开始、每次处理多少数据，以及学习率怎样变化。素材、模式、训练轮数、单批大小、梯度累积和输出目录位于主流程上方；组内补充精度与学习率曲线。

- **训练轮数 epochs**：整拍集合使用“总目标轮数”。从第4轮中途恢复，希望最终到第20轮，仍填写20。目标小于恢复起点时不会自动追加训练。
- **单批大小与梯度累积**：显存不足先降低单批大小。累积让多个小批次合成一次优化器更新，但会改变更新节奏；正式对照要记录两项，不能只记乘积。
- **学习率变化方式**：默认预热后余弦退火。预热步数控制刚开始的缓慢升温，最低学习率比例控制曲线末端；新手先保留默认。
- **数值精度**：CUDA训练通常保留BF16；CPU使用FP32计算。整拍集合不提供FP16训练选项。改变精度主要影响数值与资源行为，不等于改善谱面质量。

### 学习目标与短句记忆

这一组控制模型学什么，以及怎样结合音乐、刚写过的配置和较长的写法。先使用“连续生成训练修复”的自动预设。高级策略的中文名称解释作用，括号标版本；鼠标提示保留代码标识，便于对照日志。

- **事件类型学习**：新阶段默认“共享续写状态”，让音乐、已经写出的配置、短句进展和落点占用共同决定类型；形状、走向与细节读取同一续写状态。独立音频头只作辅助学习，不再替主解码器独自决定类型。
- **恢复目标**：默认“时间恢复与可信配置分开”。错误前缀后仍学习正确时间与休止；只有原谱关系仍成立，或观察到严格一致的旋转关系并同步转换目标时，才学习完整配置。物理上能接不等于配置上接得顺。
- **音频类型学习比例**：默认0.25，分配类型学习预算。它不是“生成时25%按音频、75%随机”，也不是强制音符类型占比。除非专门比较训练目标，先保留默认。
- **短句组织与呼应**：默认启用拍位对齐短句，读取已完成参考段对应相对拍位附近的配置，并在写入新段时使用落点所属段意图；允许选择不参考旧写法。实际呼应效果仍需生成、听歌和试玩确认。
- **类型与模板保持**：保留类型内保持的合同；新默认关闭独立“重复段转折学习”覆盖，因此不会额外重新分配模板保持概率。类型与形状仍按共同状态自然延续或改变。旧模板和转折策略放在高级设置，仅供历史模型与对照使用。
- **候选落点持续状态**：默认选定落点原生状态，按已经写过的Hold/Slide在实际落点的存活与路径计算，不能把游标处占用当作稍后仍占用。
- **持续动作区间音频**：让支持的Hold、Slide时长细节读取对应音乐区间。先保留自动。
- **短句辅助损失权重**：默认0.05，0关闭该项辅助监督；短句能力还取决于相关输入、主目标和训练结果，不能只看这个数字。
- **转折学习权重、音频规划损失权重**：新默认分别为0、0.1。前者不再额外加重重复出口；后者继续学习共享音频上的休止、头数率、事件率。旧实验可显式恢复出口加权；改变后总loss不宜直接与旧实验横比。

其他高级单项包括拍位输出、候选拍位与音乐匹配、节奏分组、持续配置、Touch与按钮负荷等。通常只在定位到具体问题、需要做固定条件对照时单独调整。

**预设与单项的优先级**：单项显示“随预设（自动）”时，由总预设决定；明确选择某个版本时，该单项优先。切换总预设会保留已经手改的策略，因此“旧策略基线＋一个新版单项”确实是一种混合实验，不是纯旧版基线。要取消覆盖，把对应单项改回“随预设（自动）”。短句组织和持续动作复用各自的原有控件，没有第二份同义控件。resume始终继承检查点策略。

### 恢复与鲁棒性

模型生成时会遇到自己写出的错误历史。这组设置让训练接触这些情况，练习回到可信后续。

- **循环历史训练比例**：默认0.15，表示在训练短段中尝试构造错误历史的比例。它不是每首歌删掉15%，也不是生成时强制改写15%。
- **错误历史构造**：高级版本选择决定练哪些错误。v7覆盖较长循环；v8加入长循环出口训练和正常历史对照。新手保持随预设，专门比较时只改这一项，并记录其他条件。
- **自主生成恢复**：控制恢复样本如何来自自主生成与构造历史。当前默认模式混合确定性生成与构造出口；它与上面的错误历史构造是两个相关但不同的设置。
- **恢复间隔、样本数、展开步数、权重**：决定多频繁做恢复训练、每次练多少和占多少损失预算。提高这些值会增加训练工作量，不能据此推断质量一定更好。
- **谱面预训练轮数**：默认0，直接进行音频条件训练；只有明确安排两阶段实验时再改。

### 验证与检查点

训练loss回答“给定真实历史时预测得怎样”，自由生成回答“接上自己写的历史后会怎样”。两者都需要看。

自动留出先排除没有符合本路线训练范围的谱面记录，再按歌曲和音频分组。验证批数有限时会分散覆盖整个验证集。微调中的留出只保证本阶段数据隔离；父模型可能已经见过这些歌，不能因此宣称完全未见过的泛化结果。

**自动留出比例默认0.05，是开发集dev与最终留出集final合计约5%，不是各5%。** 切分按歌曲身份和音频内容分组，同曲或相同音频不会故意分到训练与留出两侧。小数据集至少需要三个独立组，实际留出比例可能高于填写值；请看切分报告的真实比例。

- 独立验证集清单留空、比例大于0：自动生成train/dev/final清单；训练期误差与自由生成面板使用dev，final保留给最终检查。
- 清单留空、比例为0：关闭自动留出，也没有开发集验证。
- 填写独立验证集：使用这份清单，不再自动切分；训练与验证之间的同曲、同音频重叠会被检查。
- **每轮验证批次上限**默认32；0表示验证全部留出样本。**验证批大小**默认4，主要影响验证资源开销。
- **每轮闭环生成抽检曲数**默认2，**固定生成随机种子**默认0,1，即每首抽检歌默认生成两份。曲数0只关闭自由生成抽检，已有dev时仍可做预测误差验证。
- **验证自由生成设置**可以分别调整选时／配置温度、候选数、短句跨度、物理判定和预算等。它们独立于手动生成页；比较两边结果时，要对齐实际设置。
- **checkpoint保存间隔**按优化器更新步计数，默认500；0关闭这种步间保存，不应理解成禁用所有保存。`composer_last.pt`用于完整恢复，`composer_inference.pt`用于生成，不要拿推理文件当完整续训断点。

验证面板的条件来自各验证真谱，使用该歌曲原节拍，不套用手动页面的外部条件文件或强度曲线。因此它测的是“参考条件下的自由生成”，不等于所有手动Style设置下都表现相同。

### 模型骨架

模型宽度、层数、注意力头数和前馈宽度控制模型规模；历史事件数决定最近能回看多少事件，短段展开事件数决定每个训练短段监督多少步。音频窗口决定局部音乐输入跨度，音频共享网格决定音频时间分辨率，休止监督窗口决定休止标签读取的时间范围。

新训练默认宽度256、4层、8头、前馈768、历史64、展开16、音频窗口8秒、共享网格0.01秒、休止窗口0.5秒、dropout 0.1。更大模型、更长历史或更细网格会增加资源需求；先建立可复现基线，再一次改变少量因素。

继续已有模型时，骨架、历史／展开、共享网格、休止窗口及普通dropout继承检查点。界面锁定并解释原因；不能通过修改网页输入值把旧权重当成另一种结构。旧检查点缺少字段时按兼容规则解释，不能拿新训练默认值猜它原来的配置。

### 性能与诊断

准备线程、CPU算子线程、后台预取、音频缓存影响供数和资源占用。共享歌曲缓存要求样本准备线程固定为1；准备线程与CPU算子线程另有用途，不应混为一项。

默认准备线程1、CPU算子线程2、预取2批、音频缓存2GB。CPU线程0使用自动规则。线程更多未必更快；只有实际吞吐与等待数据支持时再调。日志间隔、短程batch限制和谱面数量限制用于诊断；正式全量实验前确认这些限制是否归零。随机种子用于复现，不是质量调节旋钮。

“每轮 batch 上限”限制的是每一轮读取的批次数，不是整个任务的累计优化器更新数。梯度累积还会改变批次数与更新数的对应关系；例如上限512、训练50轮，并不表示总共只更新512次。

## fresh、finetune与resume怎样选

| 模式 | 什么时候用 | 参数与状态处理 |
|---|---|---|
| fresh 从头训练 | 新骨架或建立全新基线 | 随机初始化；可以选模型骨架和学习目标；使用新目录 |
| finetune 微调 | 保留已有权重，改变素材或学习策略 | 新建优化器、从阶段第1轮计数；骨架与输入兼容项继承；可改允许迁移的学习策略；使用新目录 |
| resume 继续训练 | 完整恢复同一次实验 | 恢复优化器、随机数和数据游标；沿用数据切分与训练合同；epochs仍是总目标轮数 |

resume会复用原有效训练／验证清单，并核对音频、maidata、质量侧车及准备后监督内容。旧完整点没有内容身份记录时，不能直接resume，应保留旧点并在新目录finetune。选择另一份新数据，或原自动切分来源发生变化时，同样应改用finetune。恢复后看任务实际设置，确认继承值与自己预期一致。

## 手动生成先看这几项

总温度控制采样随机程度；“候选拍位温度”和“动作配置温度”留空时分别继承总温度，填数字后独立覆盖。显式填0就是0，不表示留空。验证自由生成也有自己的总温度与两项覆盖设置。

**温度0表示优先采用确定性首选。** 如果首选配置违反物理约束，生成器仍可在有限预算内尝试替代；它不会为了处理这种失败偷偷把温度改成正数。因此“温度0”不等于“禁止一切合法替代”，也不保证首选永远可以落地。具体替代次数与结果以本次生成报告为准。

“短句生成与选优”默认候选数1、试写8拍、提交预算4拍。提交只在真实事件边界完成，这些预算不把每4拍强制变成一个音乐段落。候选数2或4会比较更多同跨度写法，也增加开销；单候选的手感软评分主要用于记录。采音连续性默认0关闭，能力还取决于检查点是否训练相应输入。

每候选最大步数、全曲历史编辑预算、撤回预算和每短句时间预算是不同上限。遇到失败时先看报告中的耗尽原因、旧Hold／Slide修改和物理冲突，再决定是否调整对应预算。最大事件数0表示按音频边界自动结束；设成正数适合短跑检查。Touch布局与同键最短间隔会影响约束，比较训练验证与手动生成时也需要对齐。

## 去哪里核对实际生效值

| 想确认的内容 | 可追溯位置 |
|---|---|
| 主界面名称、分组与提交字段 | `src/maichart/webui/static/index.html`、`app.js`中的整拍集合分支 |
| API接收、继承、有效清单与CLI参数 | `src/maichart/webui/event_set_api.py`；任务结果的`effective_settings` |
| 当前学习策略可选项与默认解析 | `src/maichart/composer/stream_train.py`的`LEARNING_POLICIES`和`resolve_learning_policies` |
| 自动切分的来源、比例、音频身份与三个清单 | 输出目录`data_split/split_report.json`；任务结果`data_split` |
| 运行中的真实轮次、设备、训练与验证配置 | 日志`composer_runtime`，以及完整检查点的`args`和`model_config` |
| 验证生成默认值与传递合同 | `src/maichart/composer/stream_evaluation_settings.py`；`generation_eval_epoch_*/summary.json` |
| 手动生成的实际设置、结束原因与诊断 | 输出谱面旁的`.composer.json`；失败时的相应诊断报告 |

先比较实际设置、固定音频和随机种子，再解释loss或生成差异。一次成功运行、较低loss或零个已知硬冲突，都不足以单独证明谱面具有音乐性和可玩性；最终仍需听歌、看谱和试玩。
