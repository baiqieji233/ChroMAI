# Composer 检查点体积、运行效率与训练反馈交接

日期：2026-10-22。分支：`codex/chart-composer-v1-20261022`。

## 实际体积原因

读取 `checkpoints/Prism_composer_v1/composer_last.pt` 的 CPU 张量统计：文件约 979 MiB，FP32 模型状态约 326 MiB，Adam 一阶/二阶状态合计约 652 MiB。没有把音频、训练样本或特征缓存保存进 checkpoint。

该模型为宽度 384、两套 6 层编码器、FFN 1536、8 动作槽位，实际动作词表 18,454 类（含 STOP）。此前约 2246 万参数估算使用 256 类演示词表，不能代表真实语料。大词表使动作输出层约占 5700 万参数，完整模型约 8550 万参数。保留完整动作原子有容量成本；本轮没有裁剪词表、减少模型层数或做有损量化。

## 接续了哪些已有改动

开始工作时有其他智能体未提交的候选索引缓存、向量化时间/插值、原始 RationalAudio 特征库、逐曲标签表、音频边界缓存、双 Hold 候选屏蔽和准备日志修改。已先将源文件及工作区 diff 备份到 `backups/composer_runtime_before_20261022_144202.zip`，后续修改建立在这些实现上。

其中把 detail queries 换为原始音频节点是本轮开始前已经存在的特征表示变化，不能冒称与更早版本的音频输入逐值一致；本轮保留该变更并继续保证训练和生成使用同一个 `composer_audio_nodes`。

## 本轮实现

- 保留所有候选的编码与选位分数，只对监督目标/生成选中的候选运行大型动作头。参数名称和形状不变，避免为 96 个候选重复构造 `8 × 18454` 动作 logits。
- 移除历史编码中 `empty.any()` 引发的逐批 GPU→CPU 布尔同步，空历史仍通过掩码处理。
- 有界单线程 batch 预取、CUDA pinned memory 和非阻塞传输；保留样本顺序和共同数据集内存，不复制多个 Windows worker 数据集。
- 接通此前界面存在但 Composer 忽略的梯度累积。默认为 CLI 1，主界面按实际控件值传入；改变该值会改变优化器更新节奏。
- CUDA 自动选择 fused AdamW，提供 standard/foreach/fused 对照开关；数学目标相同，但内核浮点归约不保证逐位一致。
- 每轮另存 FP32 无损 `composer_inference.pt`；`composer_last.pt` 保留 Adam 状态用于 resume。推理权重允许生成/finetune，明确拒绝 resume。
- CPU mmap 读取检查点，生成时丢弃优化器引用，不把 Adam 状态搬到 GPU。提供 `python -m maichart.composer.checkpoint SOURCE DESTINATION` 导出已有模型，无需训练或重建模型。
- 新 checkpoint 保存轮内 batch 游标、shuffle generator、torch RNG、CUDA RNG、FP16 scaler。resume 跳过已消费索引，不重新准备对应样本；旧 checkpoint 缺少这些记录时无法声称精确恢复原轮内进度。
- 特征缓存与底层音频缓存共享总音频预算，75%/25% 分配；标签/历史表是另计的 CPU 内存。
- 主界面增加 loss 分项、选位准确率、候选召回、模型与词表规模、batch/s、事件/s、ETA、缓存命中与显存；历史曲线保留最多 200 个进度点。
- 主机累计数据等待、传输提交、计算提交和保存计时单独展示，不把它们解释为 CUDA 内核精确计时或音乐质量评分。

## 控件与建议

主界面 `chart_composer_v1`：新增后台预取（默认 2）、日志间隔（25）、每轮 batch 上限（0）、优化器实现（auto）、额外推理文件（开启）。原有模型结构、候选数和历史长度不因速度优化被缩小。

用原 batch 做对照时，梯度累积应明确填 1（此前它没有实际生效）。若要每次更新 32 个事件，可以用 batch 16、累积 2。日志里将报告实际值。先观察等待数据占比和吞吐，再调整缓存和 batch；不能仅靠任务管理器单张 GPU 图判断瓶颈。

## 验证边界

编码结束后集中验证：选中候选和完整候选的 loss/梯度对照、无损导出、轮内中断恢复、实际 CPU 训练/生成、Composer 进度解析、Node 控件/指标回归。没有启动用户正式训练或 GPU 长训练；实际整轮 GPU 吞吐提升需要下一次真实训练确认。

实测结果：42 项 Python 回归通过；随后补充的历史窗口前驱/音频 first 一致性测试及断点恢复/导出定向检查通过。31 项 Node 测试通过；临时 HTTP 服务验证新控件存在、runtime 标识 `selected_candidate_head_v1`，推理文件可生成且不能 resume。

CPU 微基准：2 线程、batch 2、96 候选、4096 类、宽度 64、单层、固定输入，预热后 5 次前向中位数：原路径 13.75 ms，所选候选路径 2.02 ms，约 6.8 倍。动作 logits 元素数 6,291,456 → 65,536。此为小型 CPU 前向对照，不能作为实际 GPU 整轮训练的加速承诺。

已从现有真实模型导出 `checkpoints/Prism_composer_v1/composer_inference.pt`，326.59 MiB、85,499,706 个参数；原 979.04 MiB `composer_last.pt` 的大小与修改时间保持不变。

新增修复：生成历史窗口首个事件的间隔现在使用窗口之前的真实前驱拍位，并计入 `first`；此前在窗口滚动后会错误地从歌曲起点计算。

服务状态：原 7860 后端缺少新 runtime 标识，且检查时没有活动任务。自动审批审查拒绝停止并重启该服务（返回 blocked by policy），未用其他方式结束该进程。新页面/API 已用独立临时 HTTP 服务验证。7860 需由用户手动重启，新前端也会拦截旧后端以避免默默忽略新参数。
