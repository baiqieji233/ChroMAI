# 稳定配置协同：本轮修改与使用说明

本轮优先减少“某个选择其实很勉强，但过滤和重试把它强行写出来”的情况。新增策略为 `cooperative_v2`，主界面名称是“稳定配置协同：采音分档、类别守恒与动作支持检查”。原检查点、前两轮实验和证据保留。

## 先验证了什么

修改前做了小型机制验证，结果保存于 `.scratch/composer_stability_20261029/validation.json`。这些是用于定位代码行为的合成输入，不是对真实语料发生率的统计。

- 当合法音符原本只占约 **0.000083%** 概率，而高概率音符被占用规则屏蔽时，旧采样器仍会把那个极弱的合法选择变成必选。
- 把同拍位置关系分数设成统一的较大正值后，旧分支会把 STOP 和 Touch 从各16.7%压到几乎零。位置修正因而不仅选位置，也会改变多押停止和类型选择。
- BF16路径先转换时间再相减，能把64拍与64.125拍看成同一个时间，破坏近邻比较。
- 旧微前瞻只比较未来收益；只要替代方案同类型同物量，即使当前模型几乎不支持它，也没有相应约束。这一项随后通过新增当前概率输入和反例测试验证。

## 已经完成的修改

### 1. 合法选择也必须有基本支持

稳定版在首槽检查：按照原始温度1的非STOP分布，合法选择还能保留多少概率。低于 **1%** 时，不把极小残余强行归一化成必选，而是返回已有拍位重试流程。

STOP不计入首槽分母；后续槽位仍可正常STOP。正常选择的类型比例、温度和随机抽样方式不变。训练中的自产历史恢复使用同一检查，避免训练与生成走两套规则。生成报告与恢复诊断会记录低支持拒绝数和最小保留量。

这项检查不会证明某个配置“好听”，也可能减少模型很不确定的地方的物量。下一阶段必须一起看拒绝次数、空白区和物量，不能只看错误配置变少。

### 2. 同拍位置修正不再顺带决定音符类型和多押数量

稳定版在Tap、Hold、Slide内部各自调整位置，保留每类总概率以及STOP/Touch的概率。完整训练、打包训练、纯音频辅助和逐槽生成共用同一计算。

这一变化属于模型学习规则的调整，因此放在新策略中。旧版 `cooperative_v1` 和未启用协同的检查点保留原来的同拍几何语义；不要把已有权重手工改名为稳定版。已有权重可以在新目录显式微调，也可以从头训练。

### 3. 微前瞻要同时尊重当前和后续

原微前瞻已能比较“当前动作让下一步丢掉多少可选概率”。现在增加当前方案的支持度：用同一份、没有强制排除原方案的真实采样分布，重算两个当前方案的逐槽概率，包含首个STOP。

- 替代方案的当前概率不得低于原方案的 **四分之一**。
- 两边后续都合法时，要求“当前相对概率 × 后续保留概率比”至少有 **10%** 的提升。
- 原方案后续不合法时，可优先考虑有足够当前支持且后续合法的替代方案。

这只是两种同意图方案的局部比较，不做全曲最大似然搜索，不优先奖励更少音符。没有额外主干前向，试探仍不消耗主采样随机流。策略记录为 `current_supported_retained_mass_v3`，默认强度仍为0。

### 4. 未来采音分档摘要已经接入

这项建议可行，本轮采用低成本版本。对每个候选点，将已算出的未来候选按七个间距档汇总，分别提供：

1. 这一档最强的事件出现概率；使用专门的presence通道，不用某个类型或Break/EX的高概率冒充声音出现。
2. 这一档的瞬态强度峰值。
3. 这一档是否真的有观测候选。

共21维，进入下一事件间距预测。不存在候选与存在候选但证据弱分开表示；最后的“大于4拍”档也不宣称覆盖了整个剩余区间。只读取音频及模型预测，不读取真实未来音符。

新投影从零开始，刚加入时不改变预测。汇总输入不接收新增梯度，防止间距任务反过来把原采音预测扭曲。采音指针不直接受这条新分支影响。计算只使用候选之间的标量关系，没有复制完整历史或重复运行音频编码器。

### 5. 时间差保留FP32精度

近邻比较现在先用FP32计算拍距、秒距和距离权重，再转换为网络计算精度。这是所有相关模型共用的数值修复，不需要开启稳定版。测试确认较大时间偏移下的相邻候选不再被误当成重合。

## 哪些建议没有一起堆进去

| 建议 | 本轮处理 |
|---|---|
| 未认领历史键位路由 | 思路保留，但不做最近邻硬消去。将来可学习软对应，并允许不匹配；当前先避免把交叉、换手误判成错误承接。 |
| Break/EX相对显著度 | 有可行性，但当前已有相关预测和分类因子。本轮没有再加一个修饰偏置，以免同时改变过多写法倾向；需要同音频的独立对照后再接。 |
| 预测短间距便强制当前单Tap | 不采用。下一拍还没真正选定，应保留合法Touch、多押及短时值动作，通过实际间距和物理状态判断。 |
| 给所有关系分支硬限幅或增加很多门控 | 本轮未采用；优先修正概率含义、数据精度和明确的低支持退路。 |

## 主界面怎么设置

重启更新后的WebUI后，在新建训练阶段选择：

| 界面术语 | 起始设置 |
|---|---|
| 配置质量架构 | **稳定配置协同：采音分档、类别守恒与动作支持检查** |
| 配置关系强度 | **1** |
| 短句计划影响 | **1** |
| 微前瞻强度 | **0**，先完成基本模型对照，再单独开启试验 |

“自动”暂不把既有实验强行升级。训练仍应使用新目录；同拍几何学习规则改变，不能拿旧训练状态当成完全相同的续训。生成三个强度仅在相应结构的模型中生效。

本轮没有运行正式长训，没有改写原v21检查点，也没有再次尝试绕过此前被审批阻止的服务重启。新结构的实际音乐效果仍需训练后的固定音频、条件和双种子对照。

## 验证记录

按要求，先运行验证修复思路的小型探针，所有实现完成后再集中测试。

- **1015项Python测试通过，1项跳过；164项前端测试通过。** 包括稳定版实际生成循环、当前方案概率评估、低支持退路、几何类别守恒、BF16时间精度、未知候选掩码及旧版行为保持。
- 使用2张真实谱、25,491个音符词条，在CUDA上完成监督更新、实际自产历史恢复更新和检查点重载。检查点仅写到本轮`.scratch`目录。新分支取得有效梯度；恢复标签遮挡保持正确。
- 真实小型验收中低支持拒绝为0，最小保留量约95.8%；这说明该样例没有被新退路大量删减，不代表所有歌曲的拒绝率。
- 计算开销见本轮证据文件；性能测试不包含供数、优化器、恢复和完整歌曲生成，不能当作一轮训练耗时。

性能补充：RTX5070Ti Laptop、BF16、宽度384/6层/96候选/128历史/33槽、真实词表下，B64交错顺序ABBA的固定输入前后向为 **152.38 → 182.37 ms每步（+19.7%）**，峰值已分配显存 **3332.74 → 3559.36 MiB（+226.62 MiB）**。这是完整稳定协同分支相对关闭协同的开销，不是仅本轮新增的开销。B8单向对照约+25.3%，也保留在证据中。原来约10%的工程目标尚未达到；本轮优先正确性与产出稳定，没有通过删标签或缩短有效历史制造提速。

证据汇总：`docs/evidence/COMPOSER_STABLE_CONFIGURATION_20261029.json`。

后续优先检查：首槽/后槽误差是否同步下降，间距预测是否校准，低支持拒绝是否集中在特定谱型，完整歌曲是否因此过度留白，以及听谱中的双押衔接与Touch使用是否更稳定。不要把本轮工程验收当成已经证明成谱质量提升。
