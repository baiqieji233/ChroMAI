## 为什么从配置结构修改

模型先选时间，再选同一时刻的音符。选时能跟随音乐，不代表配置也能稳定续写。原谱历史上的单步预测没有明显过量复制，但生成时会不断读回自己的输出；原来的训练只接触极短的这种历史。因此，不能靠压低所有重复配置，或仅调整Touch占比来代替训练修改。

独立审查指出的以下缺口已在源码中确认，本轮直接处理：

| 缺口 | 本轮修改 | 能解决什么，仍不能说明什么 |
| --- | --- | --- |
| 按钮1与Touch A1等共用计时记录 | 从33个位置拆为41个，计时输入99→123维 | 不再把两类位置的最近使用时间混为一谈；不能据此量化旧模型Touch偏高的贡献 |
| 原相对键位因子只看同拍已选音符，首槽用不上 | 首槽新增相对上一事件按钮头的位置分支 | 给跨拍配置一个直接可学习的关系；不是固定处罚1/8或4/5，也不保证训练后自然消除循环 |
| 恢复采样每次只在原谱后写2–4步，又重新开始 | 保留已生成轨迹，每次再写2–4步，逐渐覆盖历史窗口 | 模型实际接触较长自产历史；不需要每次展开128步或保存128步反向计算 |
| 恢复选时、Touch保护及重试与生成不一致 | 共用分组选时、动作采样、Touch保护和最短失败前缀重试 | 缩小训练与生成采用不同规则的差距；用户自定义生成温度仍可与训练参考值不同 |
| 动机每个时间格只看一个瞬间，容易错过短促起音 | 20ms频谱、5ms动态查询，在每格内平均 | 读取整段的内容；频谱仍受既有缓存节点分辨率限制 |
| 延迟创建音频缓存时，bank路径的空结果会被永久记住 | 源缓存建立后重新确定bank路径并发布mmap | 避免后续反复构建同一首音频bank |
| 过滤后的条件统计使用不同歌曲时长分母 | 统一使用完整音频文件时长 | 与正常条件路径一致；不是“冷热缓存随机改变条件” |

旧配置评分还会把结束标记降权，再按同拍长度平均；此前已经用50%结束概率被推向约38%的例子证实偏差。本轮让 **fresh的“自动”真正使用完整事件联合目标及配置恢复**，避免新增恢复机制默认只训练选时。

## 具体实现约束

按钮的跨拍分支只作用于Tap、Hold、Slide；在每一类内部保持总概率不变，Touch及STOP分数不被该分支直接改动。修改过程中曾发现使用通用角度表会把按钮转移分数加到Touch上，已在提交前改为按钮专用表，并加入概率守恒回归。**这是本轮草稿中发现并修正的问题，不能倒推为旧v13一直存在的同一bug。**

新计时细节投影和跨拍参数从零开始。已有99维投影仍保留，新输入可以重建其原有视图；迁移初始化的输出等价已测。以384维模型计，两分支合计新增50,304个参数，不扩大音符词表，也不加入另一个Transformer。

恢复轨迹最多为历史窗口长度与128中的较小值，再向上对齐本次展开步数（最小4；步数3时128对应129）。保存的只是实际通过检查的事件和原谱起点。每次重新用当前权重预测；检查点保存轨迹，梯度异常跳过更新时回退轨迹。合法原谱续接才参与配置监督，其他原谱辅助标签仍屏蔽。日志新增自产历史长度，以及按钮/Touch/混合参考目标的接受、拒绝和权重统计。

这仍有明确限制：原谱中某个合法续接，不一定是新历史后的最佳音乐选择；合法性筛选也可能对不同类型有不同接受率。新增统计让这些问题可观察，本轮没有凭空设定类别补偿权重。

失败重试先找到最短违规前缀。首颗自身非法时封禁首颗；首颗合法、第二颗非法时保留首颗的其他搭配。仅在拒绝后增加最多“槽位数−1”次前缀检查，并单独记录次数，不增加搜索分支树。

## 动机和缓存：本轮测试又发现的一处问题

初版区间积分在段落末尾插值时，会读取下一段的第一个频谱节点。一个很小的跨段变化经归一化后被放大，使相同乐段的相似度从1降至约0.577。最终版把插值节点限定在本段内，边缘使用本段最近节点，已恢复重复乐段测试。

频谱直接复用缓存节点，不重做FFT；原生动态读取波形前缀和。动机输入版本为`interval_integrated_temporal_v3`，频谱来源设置为`span_bounded_cached_nodes_v2`，片段拍数比例限制为0.75至4/3。

准备缓存按显式的分段参数、复现参数和组件语义版本区分。**没有采用27个文件整文件AST哈希，也没有新增全局准备策略来封杀所有旧检查点。** 仅日志或注释变化不触发全库重建。首次使用新动机输入需要对应的新准备结果；未改变的旧设置仍复用旧缓存。`_release_index=None`也已显式补齐，但原代码已有惰性初始化，这不是本轮证明的运行崩溃原因。
