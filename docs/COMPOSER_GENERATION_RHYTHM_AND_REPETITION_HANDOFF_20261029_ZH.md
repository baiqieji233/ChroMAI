## 一、结论摘要

| 问题 | 原因 | 处理 |
| --- | --- | --- |
| 三连音几乎消失（官谱4.3%，生成0.4%） | 选时温度在整个时间区间内起作用，低温把少数节奏网格整组删除 | 新采样 `grid_level_mass_v1`，已修改 |

| 训练恢复采样与生成不一致 | 恢复采样沿用旧版生成采样 | 新恢复协议 v5，fresh 默认，已修改 |

## 二、实测依据

官谱取自 `checkpoints/prism_composer_v22/data_split/train_manifest.json` 的前400首里有 Master 难度的谱面，可解析341首，共24,415小节、192,250事件。生成谱是 `webui_workspace/generated/` 中最近6次 v23 生成。

| 指标 | 官谱 | v23 |
| --- | ---: | ---: |
| 拍位：整拍 / 半拍 / 16分 / 32分 | 51.8 / 29.1 / 12.8 / 1.5% | 60.9 / 31.8 / 6.6 / 0.3% |
| 拍位：三连音 / 六连音 | 3.1 / 1.2% | 0.4 / 0.1% |
| 小节节奏与前面某小节相同 | 55.6% | 31.8% |
| 小节键位呼应（相同 / 左右镜像 / 180°） | 15.2%（4.8 / 9.2 / 1.2） | 0.2%（0 / 0 / 0.2） |
| 同键连打 AA | 15.7% | 9.2% |
| 两键来回 ABAB | 4.5% | 0.5% |
| 楼梯双押延续（4,4,5 之后接 5） | 42.5% | 8.5% |

候选规则不是三连音消失的原因：官谱三连音事件中有96%能通过生成时的相位规则和规范间隔规则。拍位分布显示所有少数网格同时萎缩（16分减半，32分和三连音降到原来的1/5到1/10），多数网格变多，这正是温度锐化造成的特征。v23 这6次生成的选时温度都是0.5。

## 三、修改一：节奏网格采样 `grid_level_mass_v1`

**原理。** 选时先按距上一事件的时长分6个区间，保留模型给每个区间的原始概率，再在区间内用温度和截断选拍位。同一区间里不同节奏网格的拍位互相竞争，例如半拍到一拍区间里有 2/3、3/4 和 1。温度0.5相当于把概率平方，再按相对最大值5%截断，于是任何低于领先者约22%的拍位都被删掉。三连音、16分在多数段落里正是这种少数选项，所以整组消失。

**修改。** 在每个区间内，再按节奏网格把候选分为整拍、半拍、16分、32分、三连音、六连音、其他七组。各组保留模型在温度1下的总概率，温度和截断只在组内起作用。总概率低于本区间最强组5%的组仍视为噪声删除。这样温度依然控制"在同一种节奏里选哪个位置"，但不再改变"用哪种节奏"。

**效果（单元测试中的固定分布）。** 三连音在温度1下的真实占比为15.4%：

| 温度 | 旧采样 | 新采样 |
| --- | ---: | ---: |
| 0.5 | 3.7% | 15.4% |
| 0.8 | 10.4% | 15.4% |
| 1.0 | 12.7% | 15.4% |

**风险。** 新采样完全信任模型对节奏网格的校准。如果模型在直拍段落也给三连音一点稳定概率，就可能出现零散、不成句的三连音。试玩时请重点检查这一点。对照时在主工作台的"节奏网格采样"选旧版，或在命令行加 `--pointer-grid-policy off`。

**位置。** `candidates.py` 新增 `candidate_grid_levels`。`generate.py` 新增 `_grid_level_conserved_within`，`_grounded_pointer_probabilities` 增加 `levels` 参数；不传该参数时行为与原来完全相同。报告中的选时策略名由 `local_bin_ratios_far_tail_pruned_v3` 变为 `local_bin_grid_level_mass_far_tail_pruned_v4`。

### 第二轮补充：按段落保持节奏 `grid_family_coherent_v2`（新默认）

**试玩问题。** `grid_level_mass_v1` 的同曲生成出现了 `{12}7h[8:1],8,7,1,2,{24}3,4,{4}5,…,{6}…,{12}4,{4}6` 这类零散三连音。该谱三连音占2.9%（接近官谱4.3%），但其中27.8%是"零散"的（前后1拍内没有其他三连音拍位），官谱只有6.2%。

**原因。** 官谱的三连音成段出现：

| 前2拍内最近的非整拍音 | 下一音是三连音 |
| --- | ---: |
| 三连音 | 41.6% |
| 直拍（半拍、16分） | 1.6% |
| 只有整拍 | 1.8% |

模型给"转入三连音"的概率大致对，却没有判断准时机。`grid_level_mass_v1` 在温度1下保留各网格的总概率，于是每个直拍位置都以约2%的机会随机转入三连音，形成零散三连音。

**修改。**

1. 根据已提交的最近前缀判定节奏族状态：前2拍内最近的非整拍音若是三连音或六连音，状态为三连音；若是半拍、16分或32分，状态为直拍；只有整拍时为中性，按直拍处理。
2. 在每个时间区间内，把"会切换节奏族"的网格作为一侧，其余作为另一侧，在两侧之间施加温度（温度0.5时为 M^2 比较）；各侧内部比例不变。
3. 整拍两族通用，从不算切换。噪声网格先按模型原始概率删除，再做这一步。

效果：

- **直拍段落中：** 模型给20%把握的三连音入口降到约6%，给2%的降到约0.02%。只有模型很有把握时才转入三连音。
- **三连音段落中：** 转回16分同样需要把握，继续三连音的概率略高于温度1。
- **温度为1时：** 与 `grid_level_mass_v1` 完全相同。
- **16分（检查后确认不需要处理）：** 新采样下16分零散占比15.1%（官谱14.4%），段落转移表也与官谱一致（粗直拍之后接16分：15.1%，官谱15.0%）；旧采样下零散占比反而高达58.6%。
- **温度可调：** 温度越低，零散三连音越少。

**位置。** `candidates.py` 新增 `rhythm_family_state`、`family_switch_levels`。`generate.py` 中的 `_grid_level_conserved_within` 增加 `switch_levels` 参数，新增 `pointer_switch_levels`。训练恢复使用同样的逻辑。报告中的选时策略名为 `local_bin_grid_family_coherent_far_tail_pruned_v5`，`sampling_diagnostics.rhythm_family_states` 记录各状态出现次数。主工作台"节奏网格采样"下拉框提供三档：新版、`grid_level_mass_v1` 和旧版。

**仍需试玩确认：** 零散三连音应明显减少，同时整段三连音不应被压掉。生成摘要会显示"零散"比例，官谱约6%。

## 四、修改二：重复抑制 `official_tail_v2`

**原理。** 旧抑制（现名 `legacy_v1`）的初衷是打断自我强化的死循环，但它在重复刚出现时就压制：

- 同键已连续两次时，第三次扣1.65（官谱 p95 正好是3次）；AAA 还会同时被当作来回，再扣1.75；
- A、B、A 之后接 B 扣1.75；单键在1拍内弹回（A、B 之后接 A）扣0.85；
- 楼梯双押延续（4,4,5 之后接 5）扣1.35。

这些在官谱中都是常规写法，因此生成谱的 AA、ABAB 和楼梯双押明显偏少（见第二节）。

**修改。** 只有继续当前重复会超出官谱长度分布的尾部时才压制：超过官谱95%分位用原来的中等强度，超过99%分位用原来的强强度。分位数由 `.scratch/repeat_runs.py` 在400首官谱 Master 上测得：

| 模式 | 官谱 p95 / p99 | 超过 p95 | 超过 p99 |
| --- | ---: | ---: | ---: |
| 同键（同一键位组合）连续 | 3 / 5 | −1.65 | −2.35 |
| ABAB 来回（按事件数） | 6 / 9 | −1.75 | −2.45 |
| ABC 三键循环 | 5 / 6 | −1.50 | −2.35 |
| 4拍内6事件中单键命中次数 | 4 / 5 | 每超1次 −0.40 | 同左 |

真正的长循环仍会被打断。例如同键连打第4下扣1.65，第6下扣3.15（同键与单键饱和两项累加）。回看窗口从8个事件放宽到12个，以便识别9事件以上的长来回。三种设置可在主工作台的"重复抑制"中切换，命令行为 `--repetition-guard official_tail_v2|legacy_v1|off`。

**风险。** 如果某次生成又出现死循环，先切回 `legacy_v1` 对照，并把那一段报给我。

**位置。** `generate.py` 中 `_anti_repetition_logit_bias` 改为按策略分派；新逻辑在 `_official_tail_repetition_bias`，旧逻辑保留为 `_legacy_anti_repetition_logit_bias`。

## 五、修改三与四：训练恢复协议 v5、结构指标

**恢复协议 v5（`generation_matched_recovery_musical_tails_v5`）。** 训练中的恢复采样是让模型从自己生成的前缀继续写，原则上应与真实生成同款。v5 在 v4 的基础上改用上面两项新采样。

| 训练方式 | 使用的协议 |
| --- | --- |
| fresh 训练 | 默认 v5 |
| resume | 继承检查点原协议（v23 为 v4，按原规则不能在 resume 中改变） |
| finetune | 可在"恢复采样策略"中选择 v5 |

v4 及更早协议的行为不变。这只改变训练时恢复样本的采样方式，不改变模型结构，也不影响已有检查点的加载。v5 使用当前默认的 `grid_family_coherent_v2` 和 `official_tail_v2`。

**结构指标（`composer/structure_metrics.py`）。** 统计第二节表中的全部指标，并附官谱参考值。

- 生成报告新增 `structure_metrics` 字段，主工作台的生成摘要直接显示呼应、三连音和交互比例。
- 已有谱面可运行 `python -m maichart.composer.structure_metrics maidata.txt`，无需加载模型。
- 数据变化后可运行 `--manifest 清单.json --limit 400` 重新计算官谱参考。
- 小节按4拍分组（项目里不存在拍号推断），非4/4歌曲只能同曲对照。
- 这些指标是诊断，不是训练目标。
- 第二轮新增 `ternary_isolated_rate`（零散三连音占比，官谱6.2%）。
- **训练轮末抽检同曲对照（第二轮新增）。** `tools/evaluate_composer.py` 对参考谱和生成谱都计算结构指标，`compare_chart_reports` 输出 `structure` 对照。训练日志每个种子打印一行 `composer_structure_observation`。仅在训练开启"每轮闭环生成抽检曲数"（大于0）时运行；v23 训练时这一项为0，所以没有抽检记录。

**界面与接口。** 主工作台新增"节奏网格采样"和"重复抑制"两个下拉框，"恢复采样策略"新增 v5 选项。`composer_api.py` 校验并转发这两个参数，记录在 `effective_settings` 中。

**没有修改的部分。**

- **抽中再退回（约30%）。** 147次退回全部是事件写完后由 miacode 运行时模拟发现的硬冲突（105次）或 Touch 引导后新增的硬冲突（42次），不是单个动作不合法。要在抽样前排除，就得对每个候选动作都跑一遍运行时模拟，代价和风险都不值得，所以保留重试机制。
- **历史拍距累加漂移（撤回此前的疑点）。** 训练、恢复、生成和诊断都提供精确的 `history_beat_ages`，累加路径实际不会执行。

## 六、照抄通道重新评估

### 先更正我此前的两处描述

1. **原说法"键位层只能精确看到最近几个事件"在 v23 中不成立。** `cooperative_v2` 的键位通路里有逐候选的历史注意力 `history_attention`，能读完整128个已编码历史事件。真正的问题有两个：
   - 门控 `history_gate` 从初值0.1只变到0.097，这条路一直以约10%的强度工作；
   - 历史事件的键只有"倒数第几个事件"和与前一事件的间隔（间隔超过4拍截断），没有拍位。所以这条注意力无法直接定位"一小节前同一拍位的那个事件"。
2. **`_LocalLeadInContext` 其实已经精确定位了同相位事件，只是没有读键位。** 它为每个候选计算了恰好4、8、16拍之前的事件权重（`w_4b`、`w_8b`、`w_16b`），但只从这些位置取了音符类型（`all_feats[..., 2:7]`，即和弦、Hold、Slide、Touch）。真正决定呼应的键位 `all_heads` 从未被读取。对称模板 `sym_template` 则是上一小节键位直方图的镜像，对所有候选都相同，而且只进入跨事件几何。它不包含"这个位置该是哪一键"的信息，所以对称门控停在0.01并不意外。

`song_paired_v3` 在配置通路中扣除了 `history_attention`，改用 `QualityContext` 的配对读取。新读取使用精确拍距，但相对时间特征只有 `log1p(d)`、`exp(-d/4)`、`sin(πd)` 和 `cos(πd)`，周期是2拍，无法区分 d=4（一小节）和 d=2、6。

### 数据：呼应结构集中在小节对齐的位置

`.scratch/echo_predictive.py` 对每个按键事件检查恰好 k 拍之前是否有事件，以及当前键位是否等于它的 D8 变换。最后一列是"上一事件已按某种变换呼应时，当前事件继续同一变换"的比例。

| k（拍） | 官谱：任一变换 | 官谱：左右镜像 | 官谱：延续同一变换 | v23：任一变换 | v23：延续 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 3（对照） | 33.7% | 9.8% | 29.6% | 28.3% | 13.2% |
| **4** | **39.7%** | **14.2%** | **45.6%** | 28.8% | 9.9% |
| 5（对照） | 30.3% | 8.8% | 23.0% | 29.3% | 9.5% |
| 7（对照） | 29.7% | 8.5% | 22.9% | 29.5% | 10.4% |
| **8** | **38.8%** | **14.5%** | **46.6%** | 27.6% | 7.5% |

- **官谱：** 只有小节对齐的位置（4、8拍）明显高于非小节对照，主要体现在"延续"：一小节开始呼应前一小节后，后面的事件有约一半继续沿用同一变换（左右镜像约60%）。
- **v23：** 所有偏移完全一样，k=4 与 k=3、5、7 没有区别。

### 结论：放弃原方案，改为小型"相位对齐呼应先验"

> **已被第十节取代。** 本节是第一轮的初步设想（只做键位、固定4/8/16拍滞后）。用户确认的最终方案是第十节的 `phase_echo_v1`：由证据驱动、覆盖多个滞后、键位与节奏同时做。实现时以第十节为准。

原方案是对128个事件逐个打分的指针，加自动推导的辅助标签和新的输出头。这个方案不需要，原因有三：

- **定位能力已经存在。** `w_4b`/`w_8b` 已经精确找到来源事件，缺的只是把键位读出来。
- **非小节偏移的结构接近随机水平。** 允许从任意历史事件照抄，只会增加噪声来源。
- **信号足够强，不需要辅助标签。** "延续同一变换"约46%，远高于约12%的单键随机水平，普通逐事件 NLL 就有足够梯度。不加辅助标签也避免了任何类似数据标注的做法。

建议方案（**未实现**）：

- **读出同相位键位。** 在 `_LocalLeadInContext` 中，为每个候选读出恰好4、8（可选16）拍之前事件的键位和 Slide 终点，并计算相同、左右镜像、180°、上下镜像四种变换。
- **延续证据。** 用最近已提交事件与它们各自的同相位来源比较，得到"当前小节正在沿用哪种变换"。
- **信任权重。** 由证据和候选上下文产生一组小的权重，按动作所含键位给第一个动作槽加 logit 偏置。权重从零初始化，因此从 v23 finetune 时初始输出完全不变，最终用多大权重由数据决定。
- **song_paired_v3 的配对读取。** 给相对时间特征补上1拍和4拍周期，使其能区分一小节与半小节。

**代价与风险。**

- **训练与检查点。** 这些改动需要训练，会改变 `song_paired_v3` 的检查点结构。v3 还没有正式训练，现在改不损失已有成果。
- **过度照抄与自我强化。** 照抄后的小节会成为下一次照抄的来源。缓解手段：零初始化、NLL 校准、新重复抑制，并用 `structure_metrics` 验收。目标是键位呼应接近15%、延续接近46%，超过就说明照抄过度。
- **只用4拍小节。** 方案依赖4拍小节（与现有 `w_4b` 相同），非4/4歌曲只能部分受益。

**不建议做纯生成侧的呼应加分。** 没有模型校准的信任度，它会不看音乐机械照抄。我对它没有把握，因此没有做。

是否按上述修订方案实现，请你决定。实现后需要从 v23 finetune，或与 song_paired_v3 合并做一次训练。

### 10.2 要解决的问题，以及为什么必须动训练侧

**现象。** 官谱经常用"呼应"来编排小节：后一小节照抄前一小节的键位，或作左右镜像、180°旋转。v23 几乎从不这样写：

| 指标 | 官谱 | v23 |
| --- | ---: | ---: |
| 小节键位呼应 | 15.2% | 0.2% |
| 小节节奏重复 | 55.6% | 同一首歌：旧采样21.5%–47.1%，新采样11.7% |

新采样下节奏重复更低，原因见第九节：旧采样的"重复"其实是整拍、半拍的单调。

**决定性测量：`.scratch/echo_evidence.py`。** 定义如下：

- **键位证据 E（0–4）：** 对每个按键事件，在滞后 k ∈ {2,3,4,6,8,12,16} 拍、变换 T ∈ {相同, 左右镜像, 180°, 上下镜像} 下，前4个按键事件中有几个恰好是"它们各自 k 拍前那个事件的 T 变换"。
- **键位结果：** 当前事件的键位是否等于"k 拍前事件的 T 变换"。
- **节奏证据 R（1–4）：** 前4个起拍中有几个在恰好 k 拍前也有起拍。
- **节奏结果：** 当前起拍是否落在"源段落节奏的下一拍 + k"。

键位结果（官谱，341首 Master；v23 为同一首歌）：

| 证据 E | 0 | 1 | 2 | 3 | 4 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 官谱，滞后 4/8/16 拍：P(继续复制) | 6.1% | 14.3% | 27.9% | 48.1% | **83.3%** |
| 官谱，滞后 2/3/6/12 拍：P(继续复制) | 6.3% | 13.8% | 24.7% | 41.7% | **71.9%** |
| 官谱：每个事件的最强证据分布 | 11.0% | 37.7% | 24.4% | 10.6% | 16.3% |
| v23 新采样：P(继续复制)，4/8/16 拍 | 5.4% | 8.0% | 12.5%（n=40） | 0%（n=4） | 从未出现 |
| v23 新采样：每个事件的最强证据分布 | 26.6% | 57.4% | 14.6% | 1.4% | 0% |

节奏结果：

| 证据 R | 1 | 2 | 3 | 4 |
| --- | ---: | ---: | ---: | ---: |
| 官谱，滞后 4/8/16 拍 | 33.9% | 38.4% | 51.8% | **70.0%** |
| 官谱，其他滞后 | 33.6% | 37.8% | 48.8% | 65.6% |
| v23 新采样，滞后 4/8/16 拍 | 33.9% | 32.6% | 39.0% | **47.6%** |
| v23 旧采样，滞后 4/8/16 拍 | 36.1% | 39.6% | 41.9% | 45.9% |

从这两张表得出三个结论：

1. **信号很强，且随证据单调上升。** 官谱中约27%的事件处在 E≥3 的状态，并以44%–79%的概率继续复制；v23 几乎从不进入这种状态，偶尔进入也立刻中断。
2. **信号在非小节滞后上同样存在。** 因此呼应先验可以由证据驱动，所有滞后共享同一张"证据→强度"表，不需要假设4/4拍。项目里没有拍号推断（只有 Beat This! 逐候选的拍和强拍概率，没有小节长度），这个设计正好避开了这个缺口。
3. **问题不在于看得不够远。** 87.6%的官谱呼应来源在最近128个事件以内，现有历史窗口已经够用；缺的是让模型直接利用"同相位事件"的通路。

**为什么现有结构做不到（代码事实，已核对）：**

| 现有通路 | 为什么不行 |
| --- | --- |
| `_LocalLeadInContext`（`grounded_model.py`） | 已算出每个候选恰好4/8/16拍前事件的权重 `w_4b`/`w_8b`，但只读取了音符类型列 `all_feats[...,2:7]`，**从未读取键位 `all_heads`** |
| `_LocalLeadInContext` 的对称模板 | `sym_template` 是上一小节键位直方图的镜像，对所有候选相同，只进入跨事件几何。训练后对称门控只有0.0105，落地门控0.053，反重复门控−0.005 |
| 逐候选历史注意力 `history_attention` | 能读全部128个事件，但键里只有"倒数第几个事件"和截断在4拍以内的间隔，**没有拍位**，无法定位"恰好一小节前的那个事件"。门控 `history_gate` 从初值0.1只变到0.097 |
| 动机档案 `motif_memory.py` | 故意排除128事件窗口内的内容，最多取16个事件 |
| `song_paired_v3` 的配对读取 | 相对时间特征只有 `log1p(d)`、`exp(-d/4)`、`sin(πd)`、`cos(πd)`，最长周期2拍，区分不了一小节和半小节 |

**为什么不采用其他方案：**

| 备选方案 | 不采用的理由 |
| --- | --- |
| 最初设想的完整128事件指针 + 辅助标签 + 新输出头 | 定位能力已经存在，缺的只是读出；非指定滞后上的任意照抄只会增加噪声；直接对动作 logit 加偏置，NLL 本身就有足够梯度（证据 E=4 时复制概率83%，基线6%），不需要辅助标签 |
| 纯生成侧的照抄加分 | 没有经过学习的校准，不会根据音乐判断何时该呼应，会机械照抄 |
| 继续训练现有模块 | v23 用5轮训练后，E≥3 的事件只占1.4%（官谱26.9%）；相关门控停在零附近。原因见下一段 |

**为什么零初始化门控学不动，以及新模块如何避免。** Adam 每步的更新幅度约等于学习率，与梯度大小无关。学习率2e-4、3030步，一个标量参数最多移动约0.6。而官谱中 E=4 相对 E=0 的复制对数几率差约为 logit(0.83)−logit(0.06)≈4.3。因此新模块必须做到以下三点：

1. **线性参数化：** 偏置对参数是线性的，零初始化时梯度不为零（不能是"零门控×零模板"的乘积结构）；
2. **特征尖锐：** 特征是逐候选、逐键位的精确来源，不是直方图；
3. **参数缩放：** 实际权重 = s × 原始参数，取 s = `ECHO_PARAM_SCALE = 8.0`，有效步长随之放大8倍。

### 10.4 模块设计：`PhaseEchoPrior`（新文件 `src/maichart/composer/phase_echo.py`）

**策略开关。** `echo_prior_policy` 取值为 `off` 或 `phase_echo_v1`：

- 旧检查点缺少该字段时一律视为 `off`；
- fresh 训练默认 `phase_echo_v1`；
- finetune 时，`auto` 不继承父模型的 `off`，取 fresh 默认值（与 `future_horizon_policy` 相同的处理）；
- resume 继承原值；
- 只支持 `audio_grounded_v3`。

**输入。** 全部是现有前向已有的张量，**不改数据集、缓存或数据字段**：

| 张量 | 来源与形状 | 注意事项 |
| --- | --- | --- |
| 历史键位 | `atom_head_lanes[history].any(-2)`，[B,H,8] bool | Slide 取起点；Touch 没有键位，按非按键事件处理 |
| 历史拍距 | `history_beat_ages`，[B,H] float32 | 由 float64 相减得到，是精确值，最新事件为0。**padding 位置也是0，必须用 `in_bounds` 掩掉，否则会误匹配** |
| 历史有效性 | `in_bounds = arange(H) < lengths` | **不要用 `safe_padding`**，原因见下文"一致性要求" |
| 候选间隔 | `candidate_features[..., audio_dim]`，[B,C] | 与 `bins` 使用的是同一列 |
| 候选上下文 | 选时完成后的 `audio_context` [B,C,D] | 仅用于音频调节项 |
| 符号保留 | `symbolic_keep` [B,1] | 用于一致的符号丢弃 |

**常量。** 滞后 `ECHO_LAGS = (2,3,4,6,8,12,16)` 拍（K=7）。变换 `ECHO_TRANSFORMS` 共4种（T=4），为0基键位置换：

| 变换 | 置换 |
| --- | --- |
| 相同 | `i` |
| 左右镜像 | `7-i` |
| 180° | `(i+4)%8` |
| 上下镜像 | `[3,2,1,0,7,6,5,4]` |

与现有 `_d8_alignments` 和 `structure_metrics` 的定义一致。匹配容差为 `1e-3` 拍。

**纯函数 `phase_echo_features(lanes, ages, valid, cand_gap)`。** 供模型和 `echo_metrics` 共用，保证训练、评估和生成用同一个定义，全部为张量运算：

1. **同相位配对。** 对每个滞后 k，`pair[b,k,j,i] = valid_i & valid_j & |ages_i − ages_j − k| < tol`，表示事件 i 恰好比事件 j 早 k 拍。拍位唯一，因此每个 (j,k) 最多有一个 i。由此得到 `src_lanes[b,k,j,:]` 与存在标志。
2. **复制标志。** `copy[b,k,t,j] = 存在 & lanes_j 非空 & (lanes_j == T(src_lanes))` 在8个键位上全部相等。
3. **键位证据。** `E[b,k,t] = Σ_{j ∈ 最近4个按键事件} copy`，取值0–4，用累加计数选出最近4个键位非空的有效事件。
4. **候选来源。** 对候选 c，源事件的拍距须恰好为 `k − cand_gap_c`，且该值 ≥ 0；源事件需有效且键位非空。得到 `cand_src[b,c,k,:]` 与存在标志。
5. **节奏证据与预测。** `R[b,k]` = 最近4个**有效事件**（含纯 Touch 事件）中，恰好 k 拍前也有事件的个数。若存在拍距恰为 k 的锚事件 i*，取它之后的下一个事件 n（拍距 a_n，可能就是最新事件，此时 a_n=0），预测间隔为 `g*_k = k − a_n`。凡满足 `|cand_gap_c − g*_k| < tol` 的候选为节奏预测候选。

显存估算：[B,K,H,H] ≈ 96×7×128×128 ≈ 11M，[B,C,K,H] ≈ 8.3M，均可接受。不得出现逐样本的 Python 循环。

**键位偏置（作用于动作头）。**

```
w[b,c,k,t] = s * ( table_E[E[b,k,t]] + lag_bias[k] + tf_bias[t] + ctx(audio_context)[b,c,k,t] ) * has_cand_src[b,c,k]
lane_bias[b,c,:] = Σ_{k,t} w[b,c,k,t] * T(cand_src[b,c,k,:]).float()
lane_bias *= symbolic_keep
```

- **参数：** `table_E` 为 [5]（所有滞后、所有变换共享，这是不依赖4/4拍的关键）；`lag_bias` 为 [7]；`tf_bias` 为 [4]；`ctx = nn.Linear(D, K*T)`，作为音频调节项，让音乐决定是否呼应。
- **初始化：** 全部零初始化，因此 finetune 开始时输出与 v23 **逐位相同**。
- **缩放：** `s = ECHO_PARAM_SCALE = 8.0`。
- **输出：** `forward` 返回 `result['echo_lane_bias']` [B,C,8]。`decode_candidate` 在 `candidate_indices` 处取值，得到 `result['echo_heads']` [B,8]，与 `previous_heads` 一样随决策传递。

**施加位置。** 新增 `_echo_logits(logits, echo_heads)`，写法与 `_cross_event_logits` 相同：

1. 把键位偏置转换为动作偏置：`atom_bias = echo_heads @ atom_head_lanes.float().T`；
2. 只在按键三类（Tap、Hold、Slide，使用 `cross_event_kind_{0,1,2}`）的每一类内部加偏置，再用 logsumexp 平移，**保持每类的总概率不变**；
3. STOP 和 Touch 不变。

施加时机与范围：

- **`decode_candidate`：** 在所有动作槽上施加，位置在 `cooperative_geometry` 之后、写入 `result['action_logits']` 之前。packed 路径用 `row` 索引取对应行。
- **`action_slot`：** 在 `return` 之前施加，位置与 teacher-forced 路径完全一致。新增参数 `echo_heads=None`。
- **不施加于** `audio_action_logits` 和音频参考调用，保持"音频分支不读历史"的约定。

**选时偏置（作用于选时头，必须留在现有历史修正上限之内）。**

```
p_echo[b,c] = s * Σ_k ( rtable[R[b,k]] + rlag[k] + rctx(audio_context)[b,c,k] ) * is_pred[b,c,k] * symbolic_keep
bin_echo[b,bin] = 该 bin 内成员候选 p_echo 的最大值（scatter_reduce amax，空 bin 为0）
proposed = hierarchical_log_probs(fine + fine_res + p_echo, coarse + bin_res + bin_echo, bins, valid)
```

- **参数：** `rtable` 为 [5]（共享）；`rlag` 为 [7]；`rctx = nn.Linear(D, K)`；全部零初始化。
- **上限：** 后续的居中和 `history_residual_bound*tanh(...)` 夹紧**保持原样**。总的历史修正仍然不超过 ±1 logit，音频驱动选时的约定不变。
- **需要在汇报中写明的局限：** 对单个候选，夹紧后最多约 +0.76 logit，可把47%左右提到约65%（官谱70%）。如果第一阶段证明上限不够，放宽 `history_residual_bound` 属于架构约定的改变，**必须先问用户**，不要自行修改。

**一致性要求（每条都要写测试）：**

1. **证据用未丢弃的历史（`in_bounds`），不用 `safe_padding`。** 训练时历史丢弃（每个事件30%）会让 E 偏低，于是"观察到 E=2 时的复制率"会高于真实的 E=2，学到的权重偏大，生成时历史不丢弃，结果就是过度复制。整体的 `symbolic_keep` 照常作用：被丢弃时，整个符号分支连同呼应先验一起关闭。
2. **严格因果：** 只读取已提交的历史，候选来源拍距必须 ≥ 0。
3. **teacher-forced 与生成一致：** `decode_candidate` 与逐槽 `action_slot` 在相同输入下，第一槽 logits 必须完全一致。
4. **零初始化等价：** 从 v23 迁移后、训练之前，所有输出与原模型逐位相同。
5. **类别质量守恒：** Tap、Hold、Slide 和 Touch 各自的总概率不变。

### 10.7 风险与预案

| 风险 | 说明与预案 |
| --- | --- |
| 自我强化、整段照抄 | 复制本身会产生下一次复制的证据。官谱中呼应会在乐句和音乐变化处结束，因此需要 `ctx` 音频调节项学会"音乐变了就停"。用防过度复制指标和试玩验收。若出现整段照抄：先检查 `ctx` 是否学到东西；再考虑在第二阶段用 v3 的音乐相似度作为调节；不要在生成侧加硬性上限，那是规则补丁 |
| 权重学不动 | 预案：用官谱校准表的对数几率差作为 `table_E` 的初值：`table_E[e] = (logit(P_e) − logit(P_0))/s`，P 取第10.2节小节滞后一行。这样初始输出不再与 v23 相同，要在汇报中写明 |
| 第一阶段不复制音符类型和和弦大小 | 类别质量守恒保护了 Tap、Hold、Slide 和 Touch 的配比，所以复制 Slide 时只复制起点键位。若第一阶段通过后仍需复制类型，再单独评估 |
| 非4/4歌曲 | 证据表在所有滞后间共享，3/6/12拍滞后同样能触发；`lag_bias` 会学到语料中占多数的4/4偏好，这是可接受的偏差 |
| 选时上限 | 见10.4节"选时偏置"，放宽上限必须先问用户 |
| 并发改动 | 工作区中有其他智能体未提交的大量改动，不要回退不属于本任务的修改；本分支是 `codex/composer-causal-motif-touch-20261025` |
