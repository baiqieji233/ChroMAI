# 全曲段落关联与草稿修订架构重构

日期：2026-10-12。旧架构基线：`af440da`。工作分支：`codex/song-form-rebuild`。
修改前源码备份：`backups/form_rebuild_20261012_af440da/project_before_rebuild.zip`。

## 用户需求与优先级

1. **第一优先级：相似主歌、副歌、旋律走向之间存在关联。** 模型要知道此前对应段落写过什么，并学习呼应、变奏或有意拉开区别，不对全曲机械套用同一种配置。:codex-annotation{index="6"}
2. 三拍子、复合拍、混合细分和变 BPM 必须独立表示。保留规则歌曲的规律性，不让固定 16 拍窗口暗中代替拍号。
3. 避免无理后大量盲目重生成，减少耗时、删音和表达退化。问题源可能是很早之前的 Hold/Slide，定位与编辑范围不能被当前窗口锁死。
4. 草稿、检查、修改、复检形成可学习流程。先训练明确的局部重建和修改，再谈审美升级与多轮自主改稿。:codex-annotation{index="3"}
5. 比较现有声学特征与多尺度/声部特征的共性差异，先建立可用且可评估的分支，不直接把大型预训练模型作为强制依赖。:codex-annotation{index="2"}
6. 用户采纳的真实修复可作为后续训练证据；不能把错误前缀与不再兼容的原谱后续拼成正确答案。:codex-annotation{index="4"}
7. 双手体感建模必须先证明可行性，当前不作为硬约束或重构前置条件。Majdata Unity 实时预览延后。:codex-annotation{index="1"} :codex-annotation{index="5"}

允许独立新模型、新训练合同和必要破坏性改造。旧模型的兼容性指保留原加载/生成路径，不要求旧权重无损变成新架构。

## 已确认的问题

- 现有事件拍位用 Fraction，能表示三连音；所以“16 拍窗口导致所有三拍子不可玩”不能直接作为已证实因果。风险是切段和音频里的小节/乐句周期默认 4/16 拍，没有真实拍号输入，而不是精确时钟不能换算变 BPM。
- Simai `{12}` 表示一整音符的十二等分，相邻格为 1/3 四分音符拍；它不是 3/4 拍号。`{20}` 同理为 1/5 拍。拍号必须来自显式标注或带置信度的推断。
- 当前全曲压缩音频没有“这一段对应之前哪一段”的显式连接，短前缀也无法检索很早之前的副歌配置。
- 无理的有效来源归因已经存在，但循环中有整窗重生成和后续重放。只优化剩余无理数，会偏好安全但平庸的输出。
- 当前辅助采音标签来自谱师实际选中的音符，并不是歌曲中所有真实声音起点的标注；不能把未采音时刻等同于“没有音乐事件”。

## 新路径：song_form_v1

### 精确时间与音乐组织

底层统一使用四分音符拍 Fraction 与独立 tempo map；上层增加显式 meter map（拍号、分组、置信度、来源）及段落边界。用户进一步明确可丢掉 `segment_beats`：新主路径不采用固定 16 拍，也不简单换成固定四小节。先由完整音频建立全曲采音草稿，再由音乐内容识别结构区域；拍号用于候选边界与相位，不强迫切成同样长度。BPM 改变不等于拍号改变，也不自动重置小节。

没有拍号证据时标记为 unknown，不伪称已经识别四拍子。新增音频时间特征用正确的小节/分组相位；旧特征中的 4/16 周期在新路径清零并由独立拍号特征替代。计算资源上限按音频秒数、token 和内存约束；超过时可以继续处理，但不重做全曲节奏草稿，也不把资源边界命名为新乐句。

选择“全曲草稿 + 条件化配置 + 修改”而不是一次对整曲所有 token 做全注意力：音乐决策必须看全曲，但计算不必产生整首事件序列的平方级注意力矩阵。第一版全曲草稿采用时间卷积和全曲声学/结构摘要；布局模型使用草稿中的全局起音位置、相似段落和持续动作状态。后续需要验证全曲摘要的压缩损失和误采音容错，不能凭架构名称声称已经理解乐曲。

拍位采用可组合有理数表示，摆脱每一个具体拍位都必须存在于 checkpoint 词表的限制。解码仍限制在明确候选节奏和合法 simai 原子内；原始精确事件编译器继续使用。

### 同曲段落关联记忆

第一版用已有音频特征构建按节拍归一化的色度、瞬态形状和音色描述，生成非相邻段落关联及置信度。无音乐或平坦特征不形成强关联。此处发现的是相似性证据，不宣称正确识别“副歌”。

全曲音频均可见，但送给模型的参考谱面只能来自已完成的前段。训练不读当前或未来目标；修改较早片段后，依赖它的后续缓存失效并重建。参考谱面作为独立输入，不是直接复制进输出。

新模型区分本地历史、相似段落参考、全曲音频组织和仍未结束的动作。参考强度可柔性控制；输入保留段落位置和出现次序，使同一音乐在不同位置可以有不同写法。

### 草稿与修订

统一条件编码器支持从空草稿生成和从受损草稿重建。修订能看见编辑区两侧已存在的谱面；这与从头自回归生成的因果边界不同，训练合同必须区分两种任务。

训练数据分三类：

- 优质真实谱面的局部遮蔽/少量损坏 → 原始局部内容：只证明重建能力，不宣称审美更好。
- 干净片段 → 原样保留：让编辑器学习可以不改，避免总在破坏正确配置。
- 经过谱师采纳的前后版本与原因 → 修改结果/偏好：用于审美与表达优化。当前未收集到的监督不伪造。

不用长篇自然语言“思考”作为成效指标。中间决策应可验证：选哪个前段作参考、编辑哪里、问题来源是什么、候选是否改善、为何停止。

### 有预算的原因修复

从少量 note 编辑开始，再扩大到来源片段，最后才允许整段重生成。源长音与受影响后段共同构成复检范围；检测缓存随音符与参数指纹失效。设置检测次数、编辑次数和时间预算，同一失败修改不反复尝试。

候选先满足解析与检测覆盖，再减少参与处理的硬无理；默认保留原有起音集合和编辑区外内容。不能通过大量删音“优化质量”。冲突相等时，只有另有可信质量比较证据才接受改稿。预算耗尽保留最佳版本及剩余问题。

## 延后与可行性门槛

双手动作模拟：没有经过专业玩家校准之前不进入自动拒绝或训练奖励。Majdata Web Unity 预览与人工修改收集：后续独立阶段，不阻塞新的段落记忆与训练核心。

音频升级：MERT 可提供较慢音乐表征，MT3/声部分离可提供不完美的声部事件证据；这些都不能代替精确节奏与原始瞬态。先比较当前特征在重复段落检索、细节对齐上的失败样本，再决定额外模型和缓存成本。
