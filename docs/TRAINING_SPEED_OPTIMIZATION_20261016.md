# 训练速度排查与等价优化

本轮针对任务 `369b0f3f3972`（Prism_Re_v6，exact_fraction_v2）排查，不改变模型结构、损失定义、数据、随机扰动、batch 或优化器参数。没有停止、重启或热替换正在运行的训练。工作区原有未提交的几何/物理约束改动全部保留。

## 实际证据

配置阶段 456 批快照：累计 phase_elapsed=284.89 秒，data_wait=81.50 秒，compute=195.05 秒；吞吐约 12.81 samples/sec。这里是主机墙钟计时，compute 包括损失构建和反传提交，不能直接等同 GPU 忙碌时间。

音频 entries=2284、bytes=7,070,558,800、evictions=0、disk_loads=2284；后续仅 hits 增长。因此当前瓶颈不是继续重建或加载整曲音频。resident + loader_workers=0 让动态样本在训练主进程中逐批构建；prefetch_factor 只影响非零 worker 的 DataLoader，并不会在该模式下自动启动 CPU 批次预取。

样本缓存计数为零也不是故障：曲线/历史扰动开启时，现有实现有意绕过完整样本缓存，避免把某次随机结果永久冻结。增大 sample_cache_mb 无法解决这个条件下的开销。

## 修改与目的

1. `rhythm_geometry.position_event_loss` 原实现逐 token 更新状态、逐行执行动态 unique，再逐事件构建均值。现在使用前缀累计/最大值还原相同状态，用 scatter_add 一次聚合每个事件的和与数量。不再为每个字符发起一组小 CUDA 算子，仍按“拍位拼写平均，再按事件平均，再按样本权重”计算。
2. `train.layout_loss` 将已经计算的逐 token CE 传给拍位辅助损失，不再重新计算同一份交叉熵。不删除或下调拍位均衡目标。
3. `data.input_example` 每个样本只解析一次 `_LazyAudio`，使用局部 FormSong 副本引用已驻留的音频对象，减少属性读取反复触发源文件 stat、LRU 更新和加锁。原始 song 继续保持 lazy，不在每个 FormSong 上永久复制音频，也不改变生成侧时钟或任何几何 profile。

## 验证

49 项定向测试通过，覆盖几何/损失、训练运行时、检查点迁移和数据性能。新增测试对比独立状态机参考的损失值与完整 logits 梯度，覆盖 batch 1/4/8、不同拼写长度和 padding；验证复用 CE 不会重复计算，以及 lazy/直接音频输入张量逐值一致。

单线程 CPU 小基准，8 个样本、595 token、64 事件，5 次前向+反向的中位数：

| 实现 | 时间 | loss |
| --- | ---: | ---: |
| 修改前 | 66.265 ms | 4.4664106369 |
| 向量化后 | 1.425 ms | 4.4664111137 |

该子函数约快 46 倍，仅说明辅助损失实现开销下降，不能外推整轮/GPU 的加速幅度。微小差值来自浮点归约顺序，梯度一致性测试使用 FP32 容差，未承诺逐位相同。未在仍运行的正式任务上做额外 GPU 基准。

## 生效边界

修改前主体备份：`backups/training_speed_20261016_145105/{rhythm_geometry.py,train.py,data.py}`。

运行中的 Python 进程不会热加载修改。排查时最近已保存的配置断点还是 batch=0、optimizer_steps=0；直接终止会损失本轮未保存更新，因此没有为性能优化中断当前任务。后续从新保存的 `form_last.pt` 执行严格 resume 时可使用优化，不需重练或几何迁移；不要通过 finetune 重置优化器来仅获得这项性能修改。

进一步潜力在于同进程有界 CPU 批次预取、确定性中间特征缓存；需要保持逐样本扰动、样本顺序和 resume 游标一致。本轮没有擅自关闭扰动、增大缓存内存或改动 DataLoader 并发策略。
