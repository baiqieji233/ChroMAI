## 原来的问题为什么会出现

### 休止和密度只被当作提示，没有成为选时概率的一部分

旧主任务每次在候选中选一个下一事件。密度回归、逐时刻起音存在监督虽然已经包含空白段，但主要通过辅助损失和隐藏向量影响指针。指针可以继续依赖其他输入，绕开密度预测。

最新生成使用 `follow` 曲线，曲线没有明确休止区，而且控制点与参考预测完全相同，触发未编辑曲线透传。这是保留“未改曲线不改变结果”的既有行为；单纯显示曲线或调高强度不能修复模型本身的选时。

另外，8拍 `future_horizon` 原先在选时计算完成后才加入，仅直接服务于配置。旧解码还会按规划结果删除长休止候选、修剪小概率的远距离时间桶，可能与新的休止预测冲突。

### 整组配置变化掩盖了持续键

实际产出48.63秒附近有 `5/6 → 5/6 → 5/7 → 5/7`，间隔均约79毫秒。5键在持续16分连打，但整组键位变了。整组重复统计无法完整描述逐键负担。

数据中并未丢掉逐键最近间隔：123维计时已经包含每个pad的最近秒距、拍距。缺口是它只被投影到共享隐藏向量，没有直接告诉输出分类器“这是第5键自己的间隔”，也没有表达连续多次击打的累计负担。现有几何分支主要描述位置关系，平均多头位置还会削弱持续键的信号。

## 修复一：允许模型明确选择继续等待

新增 `event_survival.py`，复用已有 `workload` 的事件率，不再新增独立音频编码器。

按实际秒数为候选分配互不重叠的时间区间，计算区间内的事件风险。某候选成为下一事件，要求此前所有区间都没有事件，并在本区间发生第一个事件。窗口末尾还保留“整个窗口没有下一事件”的概率。

这带来三项变化：

1. 主训练使用包含无事件尾部的联合负对数概率，不能再只对候选重新归一化，把等待概率抹掉。
2. 生成抽到无事件尾部时，推进查询游标重新读取后续音乐，不提交假音符，也不把它当作歌曲结束。查询游标与最后已提交事件分开计时，避免重复计算已经搜索过的时间。
3. 空白段通过均匀时间探针的精确起点计数监督事件率。每个探针使用实际裁剪后的0.25秒区间，未知谱区不监督；一组三押计一个事件起点，不计三个事件。

基础生存分布仍接受有界的声学和历史重加权，因此最后输出是一个有效的联合概率分布，不应声称它仍严格等于未经修正的泊松分布。

新架构把现有8拍前瞻移到选时之前，并取消旧的长休止删选和远桶最小概率修剪。原有相位、语法、占用和碰撞检查保留。旧检查点默认继续使用原分层分布，不会静默切换概率含义。

## 修复二：让每个按钮单独知道自己已经被打了多少次

新增 `button_load.py`，使用已有历史和计时张量，在模型内部计算：

- 该按钮的最近秒距和拍距；
- 短时间重复程度的平滑表示；
- 0.5、2、8拍尺度的累计击打负担。

双押里的每个按钮分别记一次击打，不除以同拍按钮数。共享小网络结合当前动作槽上下文，为8个按钮给出可正可负的得分，并在所有动作槽使用。输出放在宏观桶归一化之后，避免起点偏置在桶内被代数抵消。

Tap、Hold、Slide分别保持类别总概率，Touch和STOP不受直接加分。没有指定左右手，没有设新的同键速度禁令，也没有把所有重复配置判为错误。新输出层零初始化，最终如何调整由真实谱面学习。

普通训练、packed解码、逐槽生成、恢复采样与微前瞻均已接线。整体符号输入关闭时负担分支关闭；音频参考不读取真实历史负担。微前瞻仍复用当前前缀的缓存，是提案近似，不是重新运行下一步主干后的完整预测。

## 学习困难和loss口径

v24日志显示宏观类型/起点选择的交叉熵明显高于桶内细节，不能主要归咎于滑条变体数量。本轮直接补齐逐键特征到输出键位的对应关系，减少分类器必须自行从混合向量发现的关系；没有随意降低配置损失权重或更改它的统计口径。

在接入新事件率后，复查发现同一输出会被两种标签拉扯：旧的±1秒平滑事件率，与新增0.25秒区间计数。新架构将旧物量回归和斜率损失的事件率第0维移交计数监督，其余四维继续保留，避免同时追逐不同时间尺度的目标。

总loss中增加了权重0.2的计数似然，选时也从条件交叉熵换为联合负对数概率。因此新旧总loss、选时loss不能直接横比；配置 `action_joint_nll`、宏观CE、细节CE的定义保持不变。新日志记录 `rawrate_loss` 和 `rate_loss_contribution`。不能把小模型两次更新或新训练初期下降当作已解决长期收敛问题。

## 128事件历史与8拍前瞻

它们不是替代关系。两份最新生成中，128事件历史最短覆盖约57拍，中位覆盖约89–91拍。这次并非历史太短；直接换为8拍后向窗口反而会丢掉大量已写内容。

保留128事件历史、全曲配对与更早动机档案；固定8拍的未来音频用于判断接下来进入、退出或休止。现有8拍前瞻仍从候选声学表示读取，本轮改变的是它对选时的作用位置，没有额外建立一套密集音频编码器。

从 `event_ctx` 借鉴的是完整时间覆盖、明确等待与续写边界、带前后音频的上下文组织，没有搬回长字符解码或窗口接缝。Composer原有均匀探针已经覆盖全曲，不能错误描述为过去完全没有静音监督。

- 受控低事件率测试：只修改临时小模型的事件率输出，在整首输入音频中连续6次等待，输出0个事件，按 `audio_range_exhausted` 正常退出；没有强行补音符，没有把第一次等待当作EOS。这是功能测试，不是音乐质量对照。

计算没有增加分支搜索或新编码器。生存分布是线性前缀运算；逐键特征在8个按钮上共享参数。不过早期运行记录显示速度代价，不能只按参数少就宣称免费：相同批大小和累积下，第1轮第25–325批，v24为250.47样本/秒，v25为188.29样本/秒；GPU峰值分配约3.534/3.539GiB，数据准备耗时约0.262/0.343秒。跨运行并非严格性能A/B，不能全部归因于新模块，但训练时间增加应继续监测。没有据此盲目增大批大小或历史长度。
