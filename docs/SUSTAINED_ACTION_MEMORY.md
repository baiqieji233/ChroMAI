# 持续动作摘要与已有模型迁移

日期：2026-10-12。相关修改记录：[INPUT_CONSISTENCY_CHANGELOG.md](INPUT_CONSISTENCY_CHANGELOG.md)。

## 为什么前面的长 Hold 没有影响后面的规划

上轮将前置 Hold 从 1 拍改成 20 拍，是用来检查模型输入和目标是否感知持续动作的对照实验。

原实现有三层缺口：

1. `MusicPlanTargets.window()` 主要按音符起始拍选取窗口内容。窗口之前开始、此时仍在持续的长音，没有独立的占用目标。
2. planner 读取音频和条件编码，文字谱面前缀进入 decoder。因此即使前缀还保留着 Hold，planner 也没有直接读取该前缀。
3. decoder 的文字前缀同时受拍数和 token 预算限制。起点足够早的 Hold/Slide 会离开前缀，即使其尾部仍覆盖当前片段。

增加文字上下文能帮助局部配置衔接，但不能独立解决持续动作遗忘。本轮增加一个小型、可选的状态输入，将仍未结束的动作同时送给编码器、planner 和 decoder。

## 本轮实现

`sustain_state_v1` 为每个窗口开始时的持续动作建立快照。它只读取该边界之前已经写下的音符，不读取待生成的目标。

每个动作有 50 维特征：类型、当前路径接触区域、终点键位、等待起滑标记、剩余时值、距离起滑的时间、路径进度及 EX 标记。包括 Hold、Touch Hold、Slide、Wifi。几何路径来自已内嵌的 MiaCode 参考数据，时间使用真实 BPM 变化和 `first` 偏移。

最多携带 32 个动作；超出时按结束时间优先保留，并在日志与质量报告中记录截断。没有动作时使用一行被 padding mask 排除的零向量。

新投影层和类型嵌入增加 `52 × d_model` 个参数；`d_model=320` 时为 16,640 个。音频 encoder 内存会增加最多 32 个状态位置。没有进行 GPU 吞吐基准，不能将参数增幅直接解释为实际速度变化。

事件词表、planner 的 13 维输出和主要 Transformer 层不变。原模型配置缺省为 `none`，不会创建新参数；只有明确选择启用的训练会新增模块。

生成跨窗口回溯后，下一次窗口生成从更新后的已接受谱面重建摘要。无理检测、规则档次、少量 note 编辑和源长音修复继续按现有可选策略工作。

## WebUI 使用

已有 Prism_v3 可以继续直接生成。本轮没有修改其权重，也没有自动启用新模块。

若要让已有模型学习新摘要：

1. 重启 WebUI 服务并刷新页面，使后端和静态页面加载本轮代码。
2. 在“训练模型”中选择“已有模型加强训练（finetune）”，加载原 checkpoint，使用新的输出目录。
3. “音频池化策略”选择“自动”或“逐样本池化（per_sample_v2）”。这是输入对齐修正，不要求启用局部采音头，不需要从头重练；已有权重仍需通过加强训练适应输入变化。
4. “持续动作摘要（action_state_profile）”选择“启用：记住仍未结束的 Hold / Slide / Wifi”。默认“自动”会继承原模型；原模型没有摘要时，“自动”继续关闭。
5. Prism_v3 可保留“最大事件 tokens max_tokens”为 1024，将“跨窗口：上下文 token 预算”设为 768。保持 checkpoint 的窗口 16 拍、音频边距 8 拍和其他模型形状。上下文上限是最大允许值，短片段不会填充到 768；超过总预算的窗口直接丢弃并统计。
6. 保持需要的训练素材与质量权重。验证集可以留空；无验证时 best 和学习率调度继续使用训练 loss。

本轮只验证迁移可运行，不以 CPU 微型实验给出真实训练所需轮数。先用新的输出目录保留实验，再在同一批歌曲上比较旧模型与加强训练结果。不要将 loss 降低等同于谱面更好。

训练方式区别：

| 操作 | 持续动作摘要 | 池化与数据输入策略 | 上下文 token 上限 |
|---|---|---|---|
| 旧模型直接生成 | 原路径，关闭 | 继承 checkpoint | 继承 checkpoint |
| 原 checkpoint 断点续训 | 严格继承 | 严格继承 | 严格继承 |
| 已有模型加强训练 | 可明确新增；已有摘要必须保留 | 自动使用修正策略，可选择旧池化 | 可在原模型总容量内调整 |
| 新训练 | 自动默认关闭，可明确启用 | 自动使用修正策略 | 默认 768 |

CLI 对应参数：`--action-state-profile sustain_state_v1`、`--local-pooling-policy per_sample_v2`；已有模型迁移使用 `--init-checkpoint`，不要以 `--resume` 切换模块或输入策略。

## 日志与兼容性

- `training_input_policies`：实际使用的音频池化、上下文预算、谱面过滤版本。
- `action_state_profile`：本次训练的实际摘要设置。
- `action_state_epoch`：含有效动作的窗口数量、累计有效优化器更新次数。
- `action_state_window`：生成窗口携带的动作数和截断数。
- checkpoint 的 `action_state_training` 与 `data_contract.action_state_params` 保存训练有效性和特征合同。
- 新模块如果没有遇到有效动作并完成更新，可以继续训练，但生成入口会说明尚未有效训练；不会把随机初始化模块当作已学会的能力。
- `?` 星星在新读取策略中按完整原子过滤，保留同刻兄弟音符和节拍。普通训练和偏好修正版都记录过滤明细，不更改原始 maidata。
- 旧模型保持关闭时，权重键、前向布局和训练签名中与摘要相关的部分保持原有行为。

## 需要清楚区分的能力

摘要提供已存在的持续动作信息，尚不是逐音符的人体模拟器。它没有确定左右手、肩肘姿态、腕部旋转或玩家具体动作策略；等待起滑的区域特征也不表示这一段必须持续按住。后续是否合理，仍需要训练和无理检测共同作用。

现阶段没有新增手感监督目标，也没有强制 planner 必须因占用而减密；模型获得了学习该关系所需的输入。极长音的剩余时间特征在 60 秒处截断，细节随对数压缩，日志保留实际秒数。

单独点击“生成强度曲线”时，谱面尚未生成，因此曲线预测使用空摘要。实际谱面逐窗口生成时使用已经写下的真实动作。曲线是预先规划的参考，不能提前保证后续每一种落点配置都可玩。

未来要进一步改善手感，应加入可比较的动作安排、音乐意图与局部修改评估。本轮没有在实际训练集上进行长期训练或实机质量验收。
