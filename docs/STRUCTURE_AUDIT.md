## 0. 摘要：5 个高杠杆问题 + 1 个最大机会

| # | 问题 | 一句话 | 代价 |
|---|---|---|---|
| 1 | **条件是"每曲一份"** | 372 拍的谱面 24 个窗共享同一条 16 维条件 → "这一段该难"在接口上无法表达 | 管线已支持逐窗（`collate_events` 按样本堆叠、模型按 `[B,C]` 投影），**只差缓存键**；需重训 |
| 2 | **条件与音频冗余**（非"没见过"） | 实测 `condition_mask_prob=0.5`（ep18/21/23 三个 checkpoint 一致），即一半样本给真值——模型**见过**变化的 density 却仍只响应 **1.2%**；而 `level` 不可从音频推出 → 响应 **19.1%**。雷达/风格是"谱面统计量"，而谱面跟随音乐，编码器本就能从局部音频推出 → 模型学会把它们当**冗余**而非**权威** | 需重训（数据侧设计） |
| 3 | **59% 窗口音频被均值池化** | 窗 16 拍 + 两侧各 8 拍 = 32 拍，帧数 p50 **533** > `max_audio_tokens=512` → `adaptive_avg_pool1d`（中位压缩 4%、p90 27%、p99 47%、max 4.3×）；同一首歌因窗长不同得到不同表示 | `audio-margin-beats 8→4`（≈400 帧）可完全消除；属**契约**，需重训 |
| 4 | **早停与降 lr 互相掐** | best 0.7384@ep18；val 抖动 σ=0.0403；停机裕度仅 **0.0053 = 0.13σ**；lr 到 ep22 才减半、ep23 即被 patience=5 叫停 | 改参数，无需重训 |
| 5 | **没有"留白"样本，也没有辅助损失** | 语料空窗 **0.33%**、≤3 音符窗 2.86%；损失只有 token 交叉熵 | 需重训 |

### 最大机会：把被排除的低难度档加回来

`difficulty_index` 2/3/4/5/6 = **Basic/Advanced/Expert/Master/Re:Master**，实测：

| 槽 | 名称 | 可解析 | 等级范围 | 16 拍窗数 | 当前是否使用 |
|---|---|---|---|---|---|
| 2 | Basic | **1,577** | 1.0–14.0 | 35,556 | ✗（策略排除） |
| 3 | Advanced | **1,572** | 5.0–11.5 | 35,494 | ✗（策略排除） |
| 4 | Expert | 1,573 | 8.2–13.9 | 35,534 | 仅 lv≥12 |
| 5 | Master | 1,586 | 10.7–14.9 | 35,908 | ✓ |
| 6 | Re:Master | 153 | 12.3–15.0 | 3,190 | ✓ |

**1,572 首歌同时拥有可解析的多个难度档** → 可以给出**"同一段音频 + 不同难度请求 + 不同目标谱面"的成对监督**。这是让"难度/密度条件"变得**权威**而非与音频冗余的**唯一数据来源**，同时把等级范围从 12.0–15.0 扩到 **1.0–15.0**（面板的 1–15 才真正有意义），并把密度动态范围从窄带 **0.24–0.37**（80% 区间）扩到全谱。

## 1. 已复核并修正的三处误判

| 说法 | 复核结果 |
|---|---|
| "CFG null 不一致是 density 只动 1.2% 的根因" | **不成立**。CFG 放大的是 `(cond − null)` 的**差值**，两臂共享同一 null → 差值恰被放大 s 倍；实测换成训练一致的 null 后密度对比 **0.0348 vs 0.0347（不变）**。null 不一致本身为真（与训练掩码输入的 memory 距离 **0.215**），值得修，但不是弱响应的原因 |
| "训练时 15/16 条件维恒为 0.5" | **不成立**。三个 checkpoint 的真实 args 均为 `condition_mask_prob=0.5` → 一半样本拿到真值。归因应改为**冗余 + 动态范围窄 + 每曲一份** |
| "损失是批均值的均值，稀疏批权重偏高 1.5×" | **指标不是**：`raw_loss[valid].sum()` / `valid.sum()` 是 **token 加权**（`train_events.py:251-284`）。只有**梯度**是批均值（`loss = raw_loss[valid].mean()`，L236），分桶后偏差很小 |
| "池化把 20ms 级对齐整体抹平" | **程度被夸大**：中位窗 533→512 仅 4%；受损的是长窗尾部（p90 27%、p99 47%） |

## 5. "让模型知道哪里该难" —— 路线与推荐

| 路线 | 做法 | 改契约 | 预期收益 | 成本 |
|---|---|---|---|---|
| **D1 逐窗条件（推荐）** | 条件仍 16 维、取值域不变，只把"每曲一份"改成"每 16 拍窗一份"，窗值由该窗音频派生（`relative_rms`/`intensity_slope` 缩放 `note_density`/`peak`，风格量留语料中位） | 否 | `rms_density_correlation` 0.095 → 0.30–0.45（上限≈金标 p50 0.517）；密度 CV 0.22 → 0.30–0.40 | 低 |
| **D1' 成对难度监督（与 §0 机会合并，最强）** | 纳入 Basic/Advanced/低档 Expert：同一音频、不同难度请求、不同目标 → 让"难度/密度"条件成为**权威** | 是（`dataset_signature`） | 等级可控范围 12–15 → **1–15**；密度动态范围 0.24–0.37 → 全谱；条件响应从 1.2% 提升到可用 | 中 |
| **D2 难度曲线参数** | 整曲条件作基线 + 一条曲线（起点/峰值位置/峰高/尾部衰减/段落数），逐窗乘到 `note_density`/`peak` | 否（请求/UI 加字段） | 改善包络形状与收尾；**改不了"难段用和弦还是连打"** | 低 |
| **D3 纯音频派生（现状）** | 靠逐窗音频 + 256 帧全局记忆 | 否 | 实测失败（CV 0.22）：损失里没有项奖励跟随包络 | 零 |
| E1 条件扩维 16→16+K | 追加窗位置/段落 one-hot | 是 | 可显式说"这里是高潮" | 全部 checkpoint 作废 |
| E2 条件序列化 `[B,C]→[B,T,C]` | 条件与时间对齐 | 是 | 唯一能表达"任意段落 + 段落性格" | 接口/契约/checkpoint 全改 |

**推荐组合**：D1'（数据侧权威化）+ D1（逐窗粒度）+ D2（用户可画曲线）+ T13 辅助损失（逼出跟随能力）。

## 6. 难度区间精细化：数据怎么说

| 结论 | 数字 |
|---|---|
| 等级只解释"强度" | η²：`note_density` **0.552**、`peak` **0.444**；其余 13 个量 **≤0.071** |
| 等级不是"难度性格"旋钮 | ρ：密度 0.747、峰值 0.644；`chord` **−0.265**（等级越高和弦越少）、`jack` −0.145；其余 \|ρ\|≤0.13 |
| 细分等级收益小 | 档内 p10–p90 跨度 ÷ 档间中位差：密度 **2.5×**、峰值 3.3×、chord 8.7×、jack 15.1×、directionality/pattern_reuse **24×** |
| **真正缺口是曲内起伏** | 真实谱面 16 拍窗密度 CV 中位 **0.365**（p10 0.25/p90 0.534）、最难窗÷最易窗中位 **7.08×**；生成侧 CV 仅 **0.22**、相关 0.095–0.147 |
| 等级范围限制 | 语料仅 lv 12.0–15.0；面板允许 1–15 → **<12 属分布外**，应提示或 clamp |

**建议**：① 面板文案改为"12.0–15.0 有效（纳入低档后可扩到 1.0）"；② `level` 当唯一可靠旋钮（19.1%），雷达/风格在重训前只当弱提示；③ 不做更细等级分档，把精力放在**曲内起伏**与**低档纳入**。

## 7. 参数建议总表

### 7.1 现在就能改（无需重训）

| 参数 | 现值 | 建议 | 理由 |
|---|---|---|---|

| `tgt_key_padding_mask` | 保留 | 删除 | 零语义损失 |

| 参数 | 现值 | 建议 | 收益 |

| `weight-decay` | 0.02 | 0.05 + EMA | 缓解 0.226 nat gap |
| 引子丢弃 | 构图时一次 | **每 epoch 重抽** | 消除 15% 永久无引子 |
| 验证集 | 42–52 首、dropout 0 | **≥150 首 + 同 dropout** | val_loss 不再乐观 |
