## 当前已经完成什么

原计划第十节的两阶段代码都已完成。下一位协作者不需要再实现相位呼应分支，也不需要再补全 `song_paired_v3` 的周期特征。当前没有启动真实数据训练，没有生成新的训练检查点，没有修改 v23，也没有重建缓存。

第一阶段让模型直接读取“几拍之前对应位置”的键位和节奏，学习何时继续原样、镜像或旋转呼应。第二阶段让全曲配对分支在读取历史时，同时分辨 1、2、3、4 拍周期，避免只靠笼统时间距离寻找相关事件。这两者结合后，模型既有明确的呼应证据，也有音乐与历史配置的配对通路。

此前 v23 的实测结论保持有效：强呼应证据下，首槽续写概率只有 31.6%，官谱同口径约 79.9%。本轮没有重复这次数据扫描。详细基线见 [第一阶段说明](COMPOSER_PHASE_ECHO_IMPLEMENTATION_20261029_ZH.md) 和 [原始证据](evidence/COMPOSER_PHASE_ECHO_STEP0_20261029.json)。

## 本轮的具体改动

### 1. 全曲配对能区分不同拍距的对应位置

`quality_context.py` 中的 `relative_time_query` 从 4 维扩为 10 维：保留距离、衰减和 2 拍周期，再增加 4、1、3 拍周期，每个周期由一对正弦/余弦表示。归一化从除以 2 改为除以 √10。没有引入主歌、副歌标签，也没有增加数据集字段。

隐藏宽度 64 时，只多出 384 个参数；没有增加 Transformer 层或独立编码器。`cooperative_v2` 的时间特征保持原状。检查点的训练说明会记录 `relative_time_features=log_decay_and_1_2_3_4_beat_sin_cos_10d`。

这里使用三角函数的加法公式，把逐候选和逐历史的计算拆开后相乘，避免构造 `[批大小,候选数,历史数,10]` 大张量。输出与直接构造 10 维特征在数学上相同，浮点运算顺序不同，不能称为逐位一致。

### 2. 呼应统计不再两两比较全部历史

之前为了统计最近四个事件，却先计算了历史窗口内所有事件之间的配对，临时张量为 `[B,7,H,H]`。

现在先选出最近四个按钮事件和最近四个全部事件，再分别查询它们的来源，最多只需要 `[B,7,8,H]`。保留了所有滞后、四种变换、Touch 处理、padding 屏蔽和严格因果定义。旧实现作为测试参照保留，随机输入和 GPU 输入均逐字段比较。

历史证据部分由随 H² 增长变为随 H 增长；候选来源查找仍为 `B×C×7×H`，没有为了速度近似掉对应拍位。

### 3. 删除重复投影，补齐完整组合验证

- 全曲上下文的一次线性投影原先重复计算三次，现在计算一次供各分支使用。
- 已复核 `cooperative_v2`、`song_paired_v3` 与 `phase_echo_v1` 的组合，包含训练、逐槽生成、恢复采样、微前瞻、packed 解码和音频参考隔离。
- 主界面“相位呼应先验”说明已更新，两种质量架构均可使用。新训练默认仍为 `song_paired_v3` 加 `phase_echo_v1`，没有新增一组需要用户手调的性能开关。
- 没有修改损失权重、历史选时上限、学习率、批大小，也没有新增硬性照抄限制。

## 性能实测与取舍

设备是 RTX 5070 Ti Laptop GPU。固定合成输入，批大小 64、候选 96，FP32；预热后按旧、新、新、旧顺序比较，每种实现计时 60 次。下表是组件耗时中位数与增量峰值显存，**不是完整训练一步耗时，也不是实际样本/秒**。

| 组件 | 历史事件数 | 对照实现 → 当前实现 | 增量峰值显存 |
| --- | ---: | ---: | ---: |
| 呼应特征 | 128 | 1.513 → 1.445 ms | 56.0 → 43.7 MiB |
| 呼应特征 | 512 | 11.974 → 2.726 ms | 896.0 → 170.1 MiB |
| 10维时间得分，前向加反向 | 128 | 1.011 → 1.266 ms | 77.0 → 22.7 MiB |
| 10维时间得分，前向加反向 | 512 | 7.371 → 1.271 ms | 300.0 → 85.8 MiB |

时间得分的对照是直接堆叠相同 10 维特征，**不是旧的 4 维模型**。128 事件窗口下，省显存实现多约 0.26 ms，换来约 71% 的组件显存下降；长历史下则明显节省时间和显存。保留这个取舍是为了降低大批次的显存压力，不宣称它在所有尺寸下更快，也不建议仅凭本微基准提高默认批大小或历史长度。

呼应统计在 GPU 上的全部返回字段与旧实现逐位一致。10 维得分在 128/512 历史时输出最大绝对差约 3.9e-5/1.1e-4，查询梯度相对 L2 误差约 2.1e-6/5.4e-6。时间输入在实际训练中不求梯度，计时只对查询求梯度；额外校验也覆盖了时间输入的导数。

复现工具：`scripts/benchmark_composer_echo.py`，使用 `.scratch/python312_runtime/Scripts/python.exe` 执行。只生成合成张量，不训练、不改检查点、不访问数据缓存。原始性能记录见 [GPU 微基准 JSON](evidence/COMPOSER_PHASE_ECHO_STAGE2_BENCHMARK_20261029.json)。

## 训练与验收怎么继续

代码实施已经完成，训练和音乐质量验收仍需执行，不应再次等待实现第二阶段。

若希望先明确呼应分支本身的收益，主界面选择“微调”，用 v23 完整点、新输出目录；“配置质量架构”明确选“稳定配置协同”，“相位呼应先验”选启用，“恢复采样策略”选 v5。如果直接开始全曲配对路线，“配置质量架构”选“全曲音乐与历史配对（新版）”；其默认时间特征已经是本轮 10 维实现。

两条路线均保留原训练/开发集划分，每轮闭环抽检 2 首、种子 `0,1`。对比第 0 步全开发集基线时，把“每轮验证批次上限”设为 0。不要拿少量抽样结果当作全开发集的同口径变化。

迁移到 `phase_echo_v1`、保持 `cooperative_v2` 时，零初始化仍保持原输出。**从 v23 改为 `song_paired_v3` 是架构迁移，不保证初始输出不变，必须训练。** 第一阶段已经学到的呼应参数会随相同形状权重一起迁移。既有 v23 文件完全保留。

本轮直接扩展了尚未正式训练的 v3 时间投影形状，没有为旧的 4 维试验性 v3 权重增加兼容分支。这类试验文件不能直接按新版形状续训；正式基线 v23 是 `cooperative_v2`，不受此限制。

原计划第 10.5 节的标准仍然适用：强证据下的键位与节奏概率提高、动作损失不变差，同时避免机械照抄和零散三连音。还必须做三首固定歌曲、双种子对照以及用户试玩。本轮没有把这些尚未发生的结果宣称为通过。
