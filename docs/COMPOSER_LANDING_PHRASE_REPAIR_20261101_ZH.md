# 短句落点、持续状态与模板保持修复

本轮依据[全链路诊断](COMPOSER_FULL_DIAGNOSTIC_20261101_ZH.md)，先修复已确认的实现错误，再调整同一个动作决策所使用的时间和记忆。当前原v38已停止，原检查点保留，并复制到 `.scratch/phrase_contract_repair_20261101/baseline_v38/`，复制前后SHA256一致。没有覆盖原检查点或修改原训练材料。

## 核心改变

以前模型站在旧段末尾选好了下一拍的位置，动作部分仍可能用旧段意图和旧占用状态来决定怎么写。现在选择音乐落点之后，动作分支读取落点所属短句、参考段对应拍位，以及此刻仍真正存活的持续动作。选时仍只使用出发游标的因果输入；真实目标落点只在训练的条件动作阶段使用。

新训练合同有三个独立策略：

| 主界面策略 | 新值 | 作用 |
|---|---|---|
| 短句组织与呼应 | `aligned_phrase_v3` | 读取参考段与当前落点相对拍位邻近的有序配置 |
| 类型与模板保持 | `family_preserving_v1` | 先决定类型族，再在该类型内部延续或改变模板 |
| 候选落点持续状态 | `selected_native_v1` | 按已提交前缀计算实际落点的原生Hold/Slide状态 |

旧检查点缺少这些字段时沿用旧合同，仍能生成。启用新能力须在新目录fresh或finetune。旧点没有素材内容身份记录时，不能宣称其素材已经被验证为原样，resume会明确要求进入新阶段。

## 如何保持计算成本可控

- 整曲音频编码继续共享，不为每个拍位重复跑Transformer。
- 拍位对齐只读取每个参考段附近的两个事件，并保留一个可学习的“无参考”选项。不会展开每个训练位置×4参考×32事件×隐藏宽度的大张量。
- 出发和落点分支的唯一参考段合表，同一次forward共用GRU状态和投影；缓存不跨优化器更新保留计算图。
- 训练目标的原生候选状态与出发状态一起缓存，纳入同一内存预算；推理只查询实际尝试的少数落点。原生路径查询处理Slide等待、路径和释放，不能用简单减剩余秒数冒充完整几何推进。
- 恢复训练与普通生成复用选中落点的同一函数，历史增强同步重建候选状态与短句输入。

## 同时修复的确定错误

| 诊断项 | 实施方式 |
|---|---|
| A01 拒绝训练前覆盖切分 | 请求目录跨进程预留、已有实验检查前移、切分暂存后提交，工作进程结束释放预留 |
| A02 续训忽略素材内容变化 | 检查点记录音频/maidata/质量侧车及准备后事件、权重、条件的内容身份；复用源文件哈希缓存 |

| A06/A07 loss口径 | 界面明确总loss包含恢复贡献；训练recipe如实说明退出目标额外加权 |
| A08 旧逐帧变速导出 | 细化输出格以表达非原帧格点BPM变化，保留IR与文本同一时钟 |

## 本轮范围与剩余问题

本轮没有把“excellent全为正标签”擅自改成负标签，也没有重写损失权重、增加硬性复制规则、把启发式两手分配当真人标注。完整谱面的艺术质量、参考检索召回、短句多解表达和人工偏好仍需后续验收。

新结构给模型增加的是可用信息和一致的决策顺序，不保证未经训练就能显著改善呼应。新点需要经历有效学习，再用相同歌曲、条件和种子比较。保留当前基线是为了能判断这些修改实际带来了什么。

## 统一验证

所有源码修改完成后才开始测试。验证中又发现并补上两条增强训练回退接线：改拍后同步候选拍位；完整前缀回退重建时重新查询候选持续状态，不能沿用修改前的状态。

原v38实际保留点是第1轮、优化器第1000步、batch2000的完整保存点，包含优化器/RNG/数据游标。停训前未保存的后续更新不在该点中。

### 实际数据短训与计算开销

两个实验从同一个保留权重出发，使用相同64张谱、seed73、batch16、学习率0.00005和10步预热，各更新48次；每25更新执行2样本×2步恢复。学习率曲线按实际CLI默认采用余弦，不能将它记为恒定。只切换短句、候选状态和模板策略，主loss预算、数据顺序和原检查点保持一致。

| 指标 | 原合同短训 | 新合同短训 |
|---|---:|---:|
| 第一批配置loss | 1.33400 | 1.33283 |
| 结束累计配置loss | 2.28166 | 2.28459 |
| 结束累计选时loss | 0.37316 | 0.37324 |
| 非有限跳过更新 | 0 | 0 |
| 训练循环吞吐（窗口/秒） | 27.39 | 23.24 |

这不是“48步后loss从1.33升到2.28”的同样本对照：第一批与全阶段累计包含不同样本；两组结束指标基本相同，不能据此声称音乐质量已提高。新增候选状态投影、拍位参考输出的初始权重均为零，48步后范数分别约0.05371、0.05331，说明新通路确实参与学习。

另在相同真实batch上，不加诊断hook，5次预热、8次测量，包含前向、反向、梯度裁剪和优化器更新：每步均值约0.3220→0.3705秒，增加15.0%；峰值GPU分配2.921→2.953GiB，增加约33MiB。这是明确的新增成本，不宣称提速；不包含数据准备和恢复。两次短训的总墙钟因缓存冷热不同不能直接比较。

### 固定歌曲生成与暴露的问题

使用此前固定129.18秒音频、BPM185.1、等级13.4、原条件文件，选时/动作温度均0.65，单候选，种子1318735400和1618281921。首次四次试验中，原合同两份完成（484/332事件），新合同第一份完成（486事件），第二份在第277拍因搜索耗尽失败。

失败原文保留。原生冲突明确指向第275拍已经提交的长Slide `1b>8[4:13]`，但搜索先做完当前事件与私有尾段重试，30秒预算被耗尽，历史编辑/撤回次数仍为0。修复调度为：只有原生执行冲突全部命名已提交、可编辑的持续原子时，优先使用已有的历史编辑/撤回；否则保留原顺序。没有放宽物理检查或增加超时。同时修正“推进”按事件数量判断的问题：撤回重写后事件更少也可能在时间上前进。

这轮生成只能检验运行、回退和边界行为；48步训练不足以证明高质量呼应。首次失败和修后复验将分别保留，不能用后一次覆盖前一次记录。

四份均完成到音频结尾。新合同第二个种子使用了一次有明确冲突证据的历史撤回，没有提高时间或修改预算；其余三份没有历史撤回。按表格顺序，仍保留4/2/1/4项仅报告硬提示，不能解释为“完全无理为零”。

**这组短训没有证明质量提升：配置呼应仍为0，新合同的节奏呼应指标更低，第一个种子的三分系起音更多。** 三分系本身不等于错采音，呼应统计也不能单独判定艺术质量；本轮没有人工听谱/试玩。这些结果不应包装成已经写出高质量谱面，也不应通过改温度或加复制奖励抹去。它们说明新的可学习路径和历史修复已经能完整运行，是否形成期望写法仍需后续充分训练与验收。
