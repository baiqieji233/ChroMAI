# 连续等级基准与叠加偏好（2026-10-09）

生成页现在按「选择等级 → 勾选偏好 → 调整偏好力度」操作。目标等级支持 12.0–15.0 的全部 31 个 0.1 档；13.45 等数值在相邻档之间插值。每档同时提供完整 Radar / Style。键盘、星星、技巧、和弦、Hold、Touch、移动可以多选，原来的参数列表放入折叠的高级微调区。

## 为什么改成两层

原先等级只改变条件向量的第一维，0.1 等级只造成约 0.00667 的归一化输入变化；Radar / Style 保持原值时，模型仍会收到相同的密度和配置要求。旧风格模板则可以一次改变许多条件，所以不能把用户看到的效果差异简单归因于模型「完全不听等级」。CFG null 分支保留等级，也不能把 guidance scale 当作等级放大器。

本次没有更改模型输入维度、训练合同、已有 checkpoint 或正在运行的训练。改动是让生成请求内的等级和统计目标相互一致，再单独叠加写法偏好。它不是官方定数估计器，也不能保证 13.4 和 13.5 的自由生成谱面有严格可辨的定数差别。

## 真实谱面校准

维护工具：`python -m maichart.generation.preset_calibration --manifest webui_workspace/datasets/full训练集/pretrain_manifest.json --output src/maichart/webui/static/generation_presets.json --audit .scratch/preset_calibration_audit.json`。

用户无需运行脚本或编写 manifest，WebUI 自动读取已经生成的校准文件。

本次使用 1858 份可解析原谱，14 份因源文件或谱面问题跳过。时长读取音频文件头，未解码波形或占用 GPU；密度分母与训练使用的音频实际时长保持一致，取消旧调查的谱面结束时长近似。各条件通过原谱的 `condition_from_events` 统计计算，`melody_following` 无音频起音分析时保留已有 0.9，而非使用不可测的零占位值。

标签共 1787 份明确小数、41 份加号、30 份整数。明确小数权重 1；显示整数/加号权重 0.35，避免把 13+→13.7 这种项目映射当作精确标注。明确小数也只是原谱元数据，未通过官方曲库核验。

每个等级使用邻域高斯加权中位数与 p10 / p90，初始带宽 0.15，有效支持不足 45 时逐步扩大，最大 0.45。整体密度与峰值额外作加权单调拟合，避免稀少样本让更高等级的常规密度目标反而降低；配置比例保留真实非单调趋势。没有把 Slide、Touch、和弦等参数机械地随等级放大。

15.0 只有 3 份直接参考，其附近有效支持约 47 份；界面明确显示直接小数标签数和稀少参考提示。各项分别统计的中位组合不等于某一份官谱。数据筛选遵循事件谱语法/等级范围，但未复现训练窗口 token 上限和增采样，统计的是完整可解析谱面而非增采样后的窗口分布。

校准数值举例（仅供核对，用户入口不显示大表）：12.0 / 13.5 / 14.5 / 15.0 的整体密度约为 0.240 / 0.308 / 0.417 / 0.458，Slide 倾向约为 0.108 / 0.144 / 0.104 / 0.089。等级提高主要提高密度预算，不能推出更多星星。

## 偏好如何叠加

偏好是当前条件能表达的代理，未新增「键盘」或「技巧」训练标签：

- 键盘：偏 Tap 与和弦，减少 Slide / Touch，仅轻调 Jack；不是连打模板。
- 星星：偏 Slide 使用量、运动量与连续 Slide。
- 技巧：偏复杂 Slide、连续 Slide 与一定方向组织；无法明确指定错位、换手、撞手或准确人体动作。
- 和弦 / Hold / Touch / 移动：按各自卡片说明调整对应占比或方向代理。

偏好力度将当前等级基准向该等级邻域的 p10 / p90 倾向靠拢，多选取平均偏差，不按点击顺序累加。反向偏好可能互相减弱。每次都从等级基准重新计算；重复点击「重新应用」不会越叠越强。

整体密度、峰值、等级、节奏贴合、模式复用保持基准，不因选择偏好而额外提高。Tap / Slide / Hold / Touch 的总占比质量保持基准后重新分配，避免所有类型一起膨胀。Touch Hold 在现有统计中可同时计入 Hold / Touch，因此总和不必恰好为 1。和弦与 chord_bias 同步；复杂/连续 Slide 占比不超过总 Slide 占比。

这保留的是密度预算，不是严格等难度保证。相同密度下改变和弦、路径与时间组织仍然可能改变实际难度。用户需要具体手法时，仍应编辑生成结果并试玩。

## 页面状态

改变等级、勾选偏好或改变力度立即重算；「清除偏好」恢复当前等级基准。高级微调直接写入生成条件并持久化，之后改变组合会覆盖这些微调，页面会提醒。刷新页面保留已保存的手动值，避免自动重置。生成默认值重置清除偏好并回到 13.3 校准基准，训练参数和音频/模型路径不变。

使用模型来源强度曲线时，等级与风格变化后应重新生成曲线；原有时序/条件身份校验仍然保留。校准数据载入失败时可重试，也可继续使用高级微调，不会悄悄换成全 0.5 条件。

## 模型响应证据与限度

CPU 探针读取第 12 轮 music_structure_v2 checkpoint，在同一真实音频的三个窗口、相同起始 token 上进行条件对照。单改 13.4→13.5，下一拍位概率分布的 L1 变化约 0.0025–0.0034；单改 13.4→14.4 约 0.0246–0.0336；同时应用 14.4 的 Radar / Style 后约 0.0328–0.0451。等级不是完全无效，联合请求在这三个窗口的分布变化更明显。

planner 的局部密度响应没有在所有窗口严格单调：较高等级也可能让某个段落的预测密度降低。因此上述数值不能证明整首难度随等级严格单调，不能证明可玩性，更不能验证官方定数。后续质量评估应固定歌曲、种子、曲线和偏好，比对完整谱面的密度走势、配置、重复、边界和人工试玩。
