## 实现合同与兼容性

`selected_prefix_v3`只增加输入张量和状态解释，没有增加模型权重。训练在目标候选已知时查询一次；生成在指针选择后查询一次；恢复采样按真实生成前缀推进。全谱索引通过提交数量限定可见边界，未读取未来谱面事件。新状态受同一个`symbolic_keep`控制；EOS、future及音频动作参考在状态替换前计算，选时仍使用原committed状态。

新策略不是旧`candidate_prefix_v2`的别名。前者只改变动作输入；后者对所有候选提供状态，也改变选时输入。状态策略进入模型配置和数据指纹；旧模型`auto`继承、fresh仍默认`committed_causal_v2`。resume不能静默改策略，必须finetune到新目录。

新增生成参数均已接入CLI、API、主界面、浏览器保存/重置、任务摘要与最终报告。独立`/composer`页面仍弃用。能力标识为`causal_motif_runtime_controls_v5_selected_state`及`composer_generation_controls_v11_history_type_sampling`，防止新界面向旧后端静默提交不生效的参数。

默认类别温度1、min-p 0沿用旧大类概率。仅动作历史独立会改变过去把pointer设为小于1的结果；严格复现需显式同值。动作配置温度0仍采用原联合贪心，不经过类别控件。类别温度0只在正配置温度下选择最高类型，STOP概率仍保留；两者不能混为一谈。

## 实际loss诊断

脚本与结果：`.scratch/composer_review_20261026/loss_audit.py`、`loss_audit.json`。固定父模型及64行输入，CUDA BF16 eval、dropout关闭，无优化器更新。词表哈希及训练语义匹配。以下仅代表这一个batch：

| 分项 | 计入总loss的数值 |
| --- | ---: |
| 主选时 | 0.937095 |
| 主动作 | 2.844707 |
| 音频选时辅助（已乘0.15） | 0.159273 |
| 音频动作辅助（已乘0.15） | 0.558781 |
| EOS / future / workload / slope / trailing / placement / planner 合计 | 0.080046 |
| 合计 | 4.579902 |

加权和与总loss一致，没有发现额外重复计分。slot0 CE为3.79835，STOP CE为0.33349，非STOP CE为3.52605，说明“整体动作平均”确实不能代替首槽难度；这些数值也不是模型有多少种配置没学会的直接测量。

音频动作参考不读取此前事件的符号上下文，但训练中的后续动作槽仍读取同拍teacher forcing前缀，生成时也可读取同拍已选动作。因此不能把整个辅助任务直接等同于每个槽都在8个键上独立均匀盲猜。

同一输入屏蔽symbolic后总loss为5.586237，主动作由2.844707变成3.72521。共享`action_head.weight`的主任务与未加权音频动作梯度余弦为 **+0.4833**；加权音频梯度范数0.10401，主梯度0.89068。没有支持“此batch上必然相互冲突”的结论，也不能据一批排除其他batch的冲突。

训练界面展示的是随机遮挡下的累计/近期训练损失；本表为固定eval输入，口径不同。不要把降低辅助权重造成的数值下降当作学习改善，也没有实测依据给总loss指定2.0的不可约下界。

## 下一阶段怎样设置

### 生成

本机v11先保留原任务的选时历史0.65、候选温度0.5、配置温度0.65，动作历史独立设1，类别保持1/0，Touch保护开启、放大上限1、open布局。保持同一音频、条件和固定双种子，避免同时改动已经认可的采音设置。新手没有既有基线时可用选时历史1、候选温度0.55、配置温度0.85。仅调pointer历史来测试节奏时，动作历史仍保持1；动作历史0.65仍可用于保留旧结果的对照。

类别温度1 / min-p 0为基线；本轮不推荐0.85 / 0.02组合。较低类别温度会强化当时最高概率类型，可能正好放大Touch；类别min-p也可能删掉合理的稀有类型。Touch仍过多时，再单独比较保护上限0.5或0；上限不是Touch百分比。TapOnSlide可另做开启对照，观察删音和物量，不与所有参数一起改。
