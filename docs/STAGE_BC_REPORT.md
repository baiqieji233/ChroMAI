## 阶段 B 的实际完成范围

- 全曲合并结果检测使用真实 tempo map 和 first，持续 Hold/Slide 跨窗口仍参与。新增的是窗口生成期间的检测、有限重试以及修复后再检查。
- `none` 只报告；`local` 真正删除来源明确的冲突 Tap/Touch 子音符，并保留其它和弦成员、保护标记和 Slide 分支；`reject` 拒绝仍含确定静态冲突的候选。
- `conflict_retries=0` 默认关闭；1–5 为额外窗口尝试数。换种子时保留已生成上下文，每次尝试仍经过曲线、休止和音频边界过滤；不会无限重试。
- 实际删改时，主输出使用修复后的谱面，同时保存 `.original.txt`、`.original.chart.json` 与 `.repaired.txt`。报告含每条删改的时间、拍位和原因。已有同名结果会先保存到 `.history`，避免被拒绝的新候选留下旧成功结果造成误解。
- JSON 产物增加明确的 tempo map、first、音频长度和 end beat，评估工具无需猜测 BPM。

## 真实生成暴露的额外修复

同一首歌的 9.6 秒摘录，通过 WebUI 分别使用旧 v2（20 轮）和 full v3（1 轮）生成时，两者都曾丢掉首个 16 拍窗口。原因不是只采主音：跨窗口词表允许 `AT:16` 之后的位置，首窗解码也选到了这些位置，最终 merge 静默丢弃。现在在解码位置选择时限定 `offset <= beat < offset + window_span`，含前导上下文时也不许重生成前导区间。

另外，重叠窗口的上下文改为采用与最终合并相同的“前窗拥有重叠部分”规则，防止同拍重复令前缀编码失败后丢弃整段上下文。提交 `2f20aab`，覆盖首窗/前导区/重叠前缀的 3 项新测试，相关生成回归共 44 项通过。

修复前后同种子、同音频摘录实测：旧 v2 最长连续空白从 4.8 秒降为 1.2 秒，v3 也从 4.8 秒降为 1.2 秒；这证明位置丢弃缺陷被修复，不能推导为细碎采音或整体谱面质量达标。

浏览器实查证据在 `.scratch/webui_v3_controls.png`：v3 控件启用，点击“偏细碎”后请求值为 0.75；切换旧 v2 后控件禁用并解释原因。训练页 v3 选项、冲突模式/次数请求值正常，无页面 JavaScript 异常。

## 撤回此前的错误结论

此前把“直线 Slide 是方向不明的半圆”“A 区是中心”“任意星星/Tap 同位置就是硬冲突”“固定左右手编号可验证所有配置”写入代码和报告，这些都不成立。旧的所谓“人工确认 3 条硬冲突”没有实机或独立判定引擎证据。

现在已在线核对固定版本 MiaCode 的源码，移植其 MIT 区域常量、Touch 邻接和约 51% 判定组机制。详见 [判定机制研究](MAIMAI_MECHANICS_RESEARCH.md) 和第三方版权声明。未经完整仿真的 Slide 提前判定仅作为提示，不触发自动删除。检测结果明确区分 `static_only` 与 `partial`，二者都不等于整谱可玩性认证。

完整复杂轨迹/Wifi 的有序判定区运行时模拟、实机判定窗及玩家双手动作验证仍未完成。保留这些缺口，不把减少报警数量当成检测准确率提升。

3. 细碎偏好改为相对于每窗口预测调整，0.5 精确中性，0/1 最多分别将预测 odds 乘以 `exp(-2)` / `exp(2)`。强度曲线对密度的指导力度不会意外削弱或放大这一偏好。检查真正进入 decoder 的 plan-condition 输入，新增 2 项测试通过。
4. `rhythm_bias=triplet/dotted/...` 原先没有实际效果，已明确拒绝非 auto 请求，避免静默接受。v3 一个短间隔比例也不能证明它识别了歌曲声部或三连音类型。
5. 移除未接入的 WebUI/条件调整示例模块；原诊断模块不再凭 onset 密度伪造声部数量，多声部估计返回未测量。

v3 的已训练目标仍保持 `33/128` 拍短间隔比例，以免破坏已有权重语义。它覆盖典型 16/24 分密集间隔，但不能独立表示全部 12 分、附点组合或多声部选择。之前用整曲统计与窗口统计混排得出的 4.2%/27.3%“改善”不具备同口径对照意义，不再用于证明模型效果。

## 进入阶段 D

`webui_workspace/v3_throughput/event_last.pt` 是已完成的 **composed 数据 1 epoch v3**，并非旧 v2 的 20 轮，也不是 full 训练集验收。当前记录：训练 loss 2.1046、验证 loss 2.3726、验证 fine-rhythm MAE 0.1982。该产物保留用于早期链路对照。

后续验收须基于同歌曲、同种子、同生成条件对照，以及真实的边界/休止、空白段、重复配置、节奏细分和可玩性审查。loss、测试数量、token accuracy 与短间隔比例上升都不能单独证明谱面质量提高。
