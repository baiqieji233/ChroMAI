# 50 Hz 起音链路与谱面质量瓶颈审计（2026-10-14）

本轮独立执行，没有使用子代理，没有加载真实模型做推理，也没有启动、中断或重启训练。审查范围为当前 `song_form_v1` 音频、Planner 标签、起音选择、节奏规整及其与配置模型的连接。以下区分实现事实、CPU 复现、架构限制和未量化的质量风险；不以合成样例代替专业试听。

## 1. 20 ms 从哪里来

`src/maichart/generation/event_audio.py` 定义 `FEATURE_RATE_HZ = 50`。默认音频采样率 22050 Hz、hop 441 个采样点，恰好也是 20 ms；随后特征仍重采样到 50 Hz。**只改 hop，最终输出仍然是 50 Hz。**

Git 最早提交 `3252fac`（2026-10-09 22:37:47 +0800）已经采用 50 Hz。新架构提交 `f0b3aa9`（2026-10-12 20:10:29 +0800）继承该特征流，并增加逐帧 Planner。能确定它来自旧架构，不能从仓库最早提交推断更早的设计日期，也未找到证明“舞萌必须采用 50 Hz”的设计依据。已有音频研究文档把它作为工程基线，没有把某篇论文当作精确参数的依据。

需要分别理解这些数值：

| 数值 | 所在环节 | 含义 |
| --- | --- | --- |
| 20 ms 帧间隔 | 音频特征和 Planner 输出 | 每秒 50 个输入/输出位置，当前没有亚帧时间残差头 |
| 约 92.88 ms 分析窗 | 默认 2048 点 STFT、22050 Hz | 一帧频谱观察的音频范围；不是固定输出延迟，也不是起音只能精确到 92.88 ms |
| 20 ms Gaussian sigma | `build_blueprint_targets` | 将谱师起音时刻转成软监督的宽度；与帧间隔是两项独立设置 |
| 约 10 ms 简单拍位推断容差 | `exact_candidate` | 理想帧中心舍入的半帧不确定性；不保证训练后峰值只偏移 10 ms |
| 原始起音允许误差（默认 30 ms） | 生成侧规整 | 限制修正位置离原始峰的距离，不能增加输入精度 |
| 相邻起音合并范围 | 生成侧 NMS | 删除过近的候选，发生在序列节奏规整之前 |

`RationalCodec` 使用精确 `Fraction` 拍位，Simai 并没有被锁定到 20 ms。问题是：更精确的输出格式不能自动补回输入和监督已经丢失的信息。

## 2. 可重复 CPU 审计

新增入口：`scripts/audit_form_timing_resolution.py`。

```powershell
python scripts/audit_form_timing_resolution.py --output backups/onset_resolution_quality_audit_20261014/timing_resolution.json
```

此命令不读取 checkpoint、训练集或缓存，不使用 CUDA。它将真实 `build_blueprint_targets` 产出的标签直接传给真实峰值选择函数，覆盖 7 种 BPM、5 种分音和 4 种帧相位，共 140 个等间隔音列；另做 18 个拍位投影比较和 6 个合成瞬态测量。报告记录被审计实现的 SHA256。

**标签本身不是模型的校准概率。** 这里把标签当作分数，仅用于检验表示和峰值选择能否保留音列；不代表已有 checkpoint 的预测，也不代表这些节奏在实际训练集中的发生频率。

### 2.1 已复现：正确标签仍可能无法形成独立起音峰

每组实际谱面包含 32 个起音。相位是谱面首拍相对绝对 50 Hz 网格的位置，本轮 `first = 0.3 + phase_ms/1000`。

| BPM / 节奏 | 相位 | 起音间隔 | 关闭合并后的独立峰 | 说明 |
| --- | --- | --- | --- | --- |
| 130 / 16 分 | 0、10 ms | 115.38 ms | 32 / 32 | 正常保留 |
| 180 / 16 分 | 0、10 ms | 83.33 ms | 32 / 32 | 正常保留 |
| 180 / 32 分 | 0、10 ms | 41.67 ms | 32 / 32 | 本组标签可区分，合并范围仍可能删除 |
| 187.5 / 32 分 | 0 ms | 40 ms | 32 / 32 | 起音与帧中心对齐 |
| 187.5 / 32 分 | 10 ms | 40 ms | **1 / 32** | 两帧之间的峰形成长平台 |
| 120 / 64 分 | 0 ms | 31.25 ms | 18 / 32 | 密集起音标签合并 |
| 60 / 64 分 | 四种测试相位 | 62.5 ms | 32 / 32 | 低 BPM 的细分并非一律不可表达 |
| 80 / 64 分 | 四种测试相位 | 46.875 ms | 32 / 32 | 同上 |

当前标签对每个音使用 Gaussian，再逐帧取最大值。两个起音足够近时，其间未必留下可识别的谷；生成函数又只保留平台的一个代表。187.5 BPM 的例子中，类型标签仍有 32 个有效帧，起音标签却只留下一个可选峰，显示标签与起音取峰之间的表达瓶颈。

140 个合成测试中有 41 个出现峰数量不足。它不是真实歌曲的失败率，也不能外推为“大部分谱面都会漏音”。

**本轮不将平台按固定间距硬拆成多个 note。** 平台可能代表一个不确定的起音，也可能代表多个音，现有起音标量不能可靠区分。直接补音会违反谱师的采音取舍，并可能在弱段制造密集配置。

### 2.2 已复现：合并参数能删掉完整的快速节奏

180 BPM 的 32 分在标签取峰阶段保留 32 个事件；56 ms 合并后，本轮相位 0 ms 剩 17 个，10 ms 剩 16 个。130 BPM 的 32 分名义间隔约 57.69 ms，仍可能因帧中心舍入使某些候选间隔缩成 40 ms，56 ms 合并后分别剩 28、29 个。

因此，不能只比较理论分音间隔与合并参数：合并时看到的时间已经经历帧中心选择和初次拍位推断。它是明确的参数效果，不是训练漏学的证据。

降低或关闭合并可以保留已存在的峰，但无法补回上节所述的长平台。分音规整同样不会凭空增加起音。

### 2.3 当前序列规整确实可修正一部分帧误差

18 组理想音列覆盖 130/180/187.5 BPM、16/24/32 分和两种相位。其中 17 组保留完整峰；1 组发生上面的平台坍缩，不能进行一一对应比较。

17 个完整音列中，10 组初次单点投影出现不同于原谱的拍位。使用当前序列规整、最大偏移 30 ms、原始峰误差上限 30 ms、合并关闭后，17 组全部恢复精确原谱拍位，包含 24 分音列。

这说明已有序列方法在理想均匀输入上有作用，并非一律强制写成 16 分。但测试没有覆盖真实模型的漏采、加采、错峰和所有混合节奏；上述 30 ms 是这次实验的参数，不是所有歌曲的最佳值。

## 3. 音频通道并不共享同一个“起音峰”

当前安装的 librosa 为 0.11.0。其 `onset_strength_multi` 会按 lag 和 `n_fft // (2 * hop_length)` 补偿内部帧偏移，而本项目 `_spectral_flux` 使用中心化 STFT 的相邻归一化频谱差。二者不是同一个物理量。

使用单采样脉冲和衰减音调，在 1.0 秒起音时：

- 脉冲的 onset-strength 最大值落在 1.0 秒，flux 第一次最大值在 0.96 秒；RMS 因平台取第一个最大值，也在 0.96 秒。
- 衰减音调的 onset-strength 最大值落在 1.02 秒，flux 在 0.96 秒，RMS 在 1.04 秒。
- 不同帧相位又改变这些偏移，六组测试并不支持一个统一补偿值。

这不是“模型必定早 40 ms”的证据。Planner 同时读取频谱、RMS、flux 等，并学习原谱目标；它有机会学习通道与目标间的关系。**不能直接平移整个输入音频或把所有通道统一移 40 ms 来修复。** 若增加精细瞬态分支，应重新定义通道的时间锚点与训练合同，并用实际音频核实。

`_resample_rows(fill_outside=...)` 的扩展范围在边界外会线性外推，本轮两帧输入复现得到 2.5 而非边缘值 2.0。但当前三个调用点都没有传该选项，正常路径在源范围外填零；本轮不把未触发的可选分支当作当前谱面质量根因，也未修改它。

## 4. 除了时间分辨率，还有哪些质量瓶颈

这些是当前实现可确认的设计边界，不是本轮新发现并已修复的退化 bug。

1. **全曲 Planner 的局部时间建模仍短。** 四层 kernel=3、dilation=1/2/4/8 的局部感受野为 31 帧，最早到最晚帧中心相距 600 ms；常说的 620 ms 是按每帧覆盖一个 20 ms 单元计算。全曲音频和段落描述另有汇总向量，不能据此说模型只看到 0.6 秒。不过，所有时间帧收到相同的全曲汇总，没有逐帧查询对应副歌/过渡描述的交叉注意力。段落音色和时间进度可提供线索，细致的跨段采音决策仍是有限表达。
2. **没有显式的亚帧残差与局部节奏网格目标。** 起音头可以学习何处采音，但仍以帧中心输出，再由外部算法推断拍位。训练增多可能改善峰值选择，无法保证消除所有表示与规整歧义。
3. **配置模型不能撤销 Planner 的起音。** 解码器强制输入已经选好的位置，只创作 note 内容。它无法认为“这个副歌采得过满，应少写一个起音”，也不能把错选的 24 分改成 16 分。
4. **配置训练与实际生成条件不同。** 训练看到原谱历史、正确骨架和原谱负荷曲线，生成看到自己的历史、预测骨架和预测/编辑曲线。修订任务的部分内容已知，也比从零布局容易；总体 token 指标会混入容易的位置 token 与修订 token。
5. **增加总参数大多增强了配置模型。** 正在运行的任务日志显示总参数 48,192,070：配置 45,621,306、Planner 2,570,764。配置 d_model=512、6 层，Planner width=256、时间卷积仍为 4 层。总模型更大没有自动增加起音头的帧精度或局部感受野。
6. **Planner 类型与持续时间是有限提示。** 类型监督只有一个优先类别，混合多押被压缩；持续时间存在于预测报告，但不作为解码器必须遵守的时值约束。扩大规模不会自动改变这两个接口。

读取训练任务 `f953c729af16` 时，任务正在第 13 轮配置阶段：总体 loss 约 0.179，草稿配置 CE 约 0.559、草稿配置 accuracy 约 80.5%、草稿首个配置字符 accuracy 约 57.8%，修订配置 accuracy 约 95.2%。它们是训练统计，不能证明谱面已达到质量目标，也不能仅凭首字符准确率证明训练失败——同一音乐位置可能存在多个合理配置。

没有发现需要因本轮审计立即终止训练的新当前路径缺陷。继续保留该任务。

## 6. 下一阶段建议与顺序

### 当前 checkpoint 可继续使用的部分

先继续用已修复的原始峰锚定与局部序列规整，并核对真实生成报告中的合并范围、漏峰诊断和段落关联。快速节奏被合并时优先减小合并范围，不以不断增大规整容差替代证据。继续分别看草稿配置、修订配置和 Planner 指标；沿用用户对实际歌曲的反馈，不要求先建立广泛验证集。

### 优先的后续训练增强：精细时间与可辨别的事件监督

1. 保留现有 50 Hz 音乐语义流，增加直接从原波形提取的 100/200 Hz 瞬态分支；不能将现有 50 Hz 特征插值后宣称获得更多细节。
2. 在精细分支上学习事件存在性及亚帧秒偏移，重新设计密集起音监督，使多个相邻事件不会只剩一个 Gaussian 最大值平台。相位残差单独不能解决平台丢失的事件数量。
3. 加入局部、可混合的节奏结构监督或候选序列评分，让模型根据前后文选择直拍、三连、附点等网格与相位；不得设置全曲唯一 rhythm_type 或硬强制全部 16 分。
4. 用版本化 Planner 合同承载新分支和目标，旧 checkpoint 继续调用当前链路。新 head 需要训练，不能包装成现有模型免训练获得的能力。音频缓存、时钟、帧数预算、sigma、初次投影与配置位置输入需要一起检查。

### 其次：让段落与配置模型获得更真实的条件

将有时间锚点的段落描述提供给对应音频帧，保留全曲摘要及相似段落参考。然后研究配置训练中混合预测骨架、损坏前文与用户采纳修复的方式；答案必须与修改后的上下文一致，不能把错误前文直接拼接原官谱后续当作正确续写。

允许配置阶段提出少量删音、改时或局部修订，是更后续的结构变化，需要编辑监督与预算控制。本轮没有用重写次数、无理规则或硬连点惩罚掩盖配置学习不足。
