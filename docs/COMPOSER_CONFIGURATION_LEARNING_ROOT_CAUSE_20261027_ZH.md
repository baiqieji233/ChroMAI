# 配置为什么容易重复：问题、修复与验证

**日期：2026-10-27。读者：参与项目的独立协作者。** 本文优先解释原因；具体数字和实验限制另存于文末的证据文件。

> **后续实测接续：** 已在step29664复算单步校准，并完成五组历史音频/相对关系修复原型，均未在观察样本胜过基线；动机旧输入抽样命中率约0.23%。落地了动机数值噪声修复和输入身份校验，旧启用动机检查点以后在新版代码接续须finetune和新目录。详见[独立审查复核](COMPOSER_INDEPENDENT_REVIEW_VALIDATION_20261027_ZH.md)。用户要求的全面架构交接另见[全链路排查入口](COMPOSER_FULL_ARCHITECTURE_AUDIT_HANDOFF_20261027_ZH.md)。下文保留此前实验过程。

当前模型已经能在一定程度上跟随音乐选时，但配置衔接仍明显落后。这次查到了两个可以直接从代码和实验确认的问题：**旧训练规则会偏向继续添加音符；模型面对自己生成的历史时，原有恢复训练只纠正时间，没有教它如何继续选择配置。** 两处均已提供新版训练实现。配置恢复分支仍是实验选项：重复有所下降，Touch却明显升高，尚未通过产出验收，不能当作完整解决方案。

## 1. 先理解模型在做什么

ChartComposer 输入音乐、节拍和目标等级，先决定下一组音符放在哪里，再决定这组音符是什么。每写完一组，它会把结果加入历史，供下一次选择使用。

因此，“采音合理”和“配置反复绕圈”完全可能同时发生：选时能从音乐中获得清楚的提示，而具体选哪个键、怎样接上一组，则容易依赖历史。历史本来就应该有用；问题在于，**模型一旦自己写出了单调模式，训练是否教过它从这种情况继续写好。**

此次复核确认，重复并非统计幻觉。对用户指出的那份生成谱，正式解析后得到755组事件；完全相同配置的连续重复为15.25%，ABAB交替为8.91%。真实谱面抽样片段去重后的相应比例为6.98%和2.44%。两边不是同一批歌曲，不能当成严格的质量差值，但足以支持继续调查。

## 2. 已确认的训练规则偏差

旧算法先计算每个音符的预测误差，把“这一组结束”的误差乘以0.35，再对每一组单独取平均。这样，模型此刻该如何选择，会受到这组音符**未来还有多长**的影响。

一个可以复现的例子：相同条件下，原谱一半写“1，然后结束”，另一半写“1，再写2，然后结束”。当模型已经写了1，合理的结束概率应为50%；旧评分规则的最优值却约为38%。也就是说，模型即使正确学到了50%，训练仍会推动它降低结束概率。

这会给继续加音符带来系统性偏向。它与配置物量有关，但**不能单独解释跨拍的1/8、4/5循环**。

新版“完整事件联合似然”把同拍音符及结束标记作为一个完整序列学习，取消上述折扣和逐组长度归一化。旧目标保留，以便继续运行原模型和做对照。两种目标的总loss数值单位不同，不能直接比较大小。

## 3. 更贴近自强化的缺口：恢复训练没有训练配置

通常的训练会把原谱历史交给模型；真正生成时，模型看到的是自己刚写出的历史。这两种输入不一样。模型可能在原谱历史上答得不错，却在自己的重复模式里越走越深。

项目已经有短程“恢复采样”：让模型真实生成2–4组，再找原谱中可以接上的位置。查实的缺口是，后面的训练关闭了配置解码、清空了配置标签，只纠正下一事件的时间。**所以提高旧版“恢复采样权重”，并不能直接教配置头摆脱这种循环。**

新版“联合似然 + 配置恢复训练”补齐了这条链路：

1. 沿用已有采样器，让模型实际生成短历史。
2. 按这份历史重新计算占用、键位间隔、负荷记录和动机输入。
3. 检查原谱后续整组配置是否仍合法、可到达，音符是否完整可表示。
4. 通过后，同时学习续接时间和原谱配置；不合法的样本跳过。

训练目标取自经过检查的原谱，**不把模型刚生成的音符当成正确答案再奖励一遍**。原谱的续接也不等于唯一或最好的音乐选择，所以不把这项训练称为“最优纠错”。旧的负荷、未来意图等辅助标签继续屏蔽，避免将原谱状态硬套到已改变的历史上。

## 4. loss为什么还在4附近

2026-10-27 06:47的v13运行快照中，总loss约3.92，包含配置2.32、选时0.93、加权后的音频辅助任务0.60，其余约0.08。它是几个任务的和，不是一个准确率，也没有“正常就必须低于1”的标准。

但不能因此忽略学习慢。固定样本实验中，配置误差约80%集中在“这一拍先选什么”上。当前词表包含18,454种完整音符；模型必须同时辨别类型、键位、时值和形状。同拍内部的相对位置分支，在第一颗音符尚未出现时也不能直接提供帮助。现有设计能共享部分特征，但不是把这些判断完全拆开学习。

短训能迅速降低参与更新的样本误差，未参与这次更新的样本却没有同步改善。因此，不能说模型完全学不进去，也不能说剩余loss都是降不下去的固有噪声。**能否把学到的配置规律推广到别的历史和歌曲，仍是核心验收项。**

另外，“音频只靠0.15权重学习配置”不符合代码：主配置误差也会传回音频主干。试验中，简单阻断选时对共享音频部分的更新，也没有带来明确的配置改善；本次没有据此拆主干或盲目提高辅助权重。

## 5. 实验说明了什么，没有说明什么

先前四组受控实验共192次更新，保持父检查点、优化器状态和样本顺序一致。修正评分后，参与训练的配置误差下降，但没有证明对其他样本的学习明显变快。

同歌曲、条件和双随机种子的128事件生成对照中，只改评分规则：连续相同配置从14.17%/8.66%降至9.45%/7.87%，ABAB却从3.2%/1.6%升至6.4%/9.6%。这是需要保留的反面结果：**只修正同拍评分，循环可能换一种形式出现。**

随后另做两组各32次更新的对照。4份谱面产生40个真实模型短历史，其中36个可合法续接，4个被拒绝；27个用于更新，9个用于观察。配置恢复使参与更新的历史上的联合误差从6.08降至3.98，只纠正时间的对照为5.95；9个观察样本上的结果却几乎相同，分别为4.50和4.51。普通观察样本也没有改善。

对应双种子短生成如下。双方都使用联合似然，唯一新增训练项是配置恢复；本次为了检验链路，每次更新都加入恢复样本，远高于生产默认的每100次更新一次。

| 指标 | 只恢复时间，种子A / B | 同时恢复配置，种子A / B |
| --- | --- | --- |
| 连续相同配置 | 8.66% / 6.30% | 7.09% / 3.15% |
| ABAB交替 | 0.8% / 8.0% | 0% / 0.8% |
| Touch类音符占比（包含TouchHold） | 22.73% / 11.43% | **52.71% / 46.27%** |
| 总音符数 | 132 / 140 | 129 / 134 |
| 残留硬冲突报告数 | 1 / 1 | 0 / 1 |

这不能判为整体改善。恢复训练集本身只有2个Touch、共33个音符，也不能简单解释成“喂了太多Touch”。因此保留实现用于受控研究，不设为默认，不用这些研究权重替换正式模型。上述冲突是报告读数，仍需试听和试玩。

### 继续追查：问题确实在配置历史参与决策的内部过程

在种子A的坏例里，抽签之前模型原始Touch概率平均约62%，对照轨迹约29%；安全修正将它降下来，采样则基本保留修正后的类型比例。交换两份模型的最后分类部分，概率几乎不变。因此主要偏移不在最后抽签或分类层，而在送进分类层的信息中。

进一步固定16个实际生成时刻，给两份模型**完全相同的音频输入、条件和历史**，两者Touch概率都约58.4%。分别替换历史编码、历史读取、状态投影、配置融合的参数，也没有消除这个反应。这说明不能把它归结为本次32步训练弄坏了某一个模块：旧模型本来就会被这类历史带着继续写Touch。

模型会从两条路看到刚才的配置：一条直接读取音符历史，另一条记录每个键最近何时出现。去掉第一条后，Touch概率仍约40%；同时去掉这两条，才降到约23%。这里只是在定位影响来源，**没有证明23%就是音乐上正确的答案**。这些输入也承担衔接和占用判断，直接删除会损失已有能力。随机遮挡部分历史也没有消除高Touch反应，不能靠盲目提高dropout解释或修复。

更深层的限制因此清楚了：当前配置目标主要学习“给定原谱过去，猜下一项”，尚未充分学习“面对自己连续几十拍形成的历史，怎样维持合理的配置变化”。新增恢复训练补上了入口，但2–4步、小范围原谱续接还不足以证明解决这个问题。下一步更值得验证的是：在有原谱的歌曲上生成较长片段，抽取真实出现的困难历史，检查合法续接后批量复用这些样本。这样可以检验实际反馈问题，也避免每次更新都重跑长段生成；这项长历史训练尚未实现。

本轮没有发现固定样本重现此前历史向量大幅膨胀、趋于相同方向的退化，也没有找到“大量同义时值写法”解释当前loss的证据。这些是排除项，不是整个长程训练永远安全的保证。

## 6. 如何使用，以及计算成本

主界面新增 **“配置学习目标”**：

| 选项 | 用途 |
| --- | --- |
| 自动（已有模型继承；新训练兼容旧目标） | 保持原来的训练解释，避免旧实验悄悄改变 |
| 旧事件均值（兼容） | 复现原训练 |
| 完整事件联合似然 | 只修正同拍评分，用于分离变量的对照 |
| 联合似然 + 配置恢复训练（实验） | 同时训练模型生成历史之后的合法配置续接；短测Touch升高，暂不推荐用于正式长程 |

已有v13切换目标时，选择 **“finetune 微调”** 和新输出目录，保留父检查点。**“resume 继续训练”**严格继承原目标。目录名v13与训练合同编号v13是两回事。

配置恢复沿用 **“恢复采样间隔 / 样本数 / 步数 / 权重”**。先保留100 / 2 / 2 / 0.1建立对照；间隔为0时不会执行任何恢复训练。未验证应当将它们大幅提高。

计算量不会因这次修改指数增长：没有增加搜索树、整曲回放或额外网络。恢复采样原本就存在，新策略只为这批小样本补上配置解码和误差计算，并跳过本次不评分的音频辅助分类输出。真实模型、2个样本、CPU单线程的前向加反向中位耗时从0.539秒到0.760秒；默认间隔100时摊销增加约0.0022秒/更新。次数由间隔控制，单次样本数和步数有固定上限。日志分别记录采样和学习耗时；**该CPU测量不包含采样和优化器耗时，也不能替代实际GPU吞吐验收**。

比较训练时看 **“配置首槽 CE（共同标尺）”** 和 **“配置旧标尺 CE”**；它们是保持同一算法的误差读数，越低表示越接近参考标签。恢复链路看 **“恢复配置 loss（未乘权重）”** 及实际参与配置训练的样本数。最终仍要固定音乐、条件和种子，检查重复、Touch、物量与冲突是否一起改善。

本轮553项Composer Python回归通过，10项跳过；27项前端检查通过。实际主界面完成了两种新目标的fresh、finetune和resume，并检查目标继承、提交时保留所选参数、恢复配置梯度与检查点保存。GPU专项回归未在运行中的训练旁执行。

本轮保留原v13训练和检查点，没有将研究权重替换进正式生成。后续优先验证更广的歌曲范围、真实长历史样本和较稀疏的恢复更新，检查重复与类型分布能否一起改善，再决定是否改变音频与历史的融合方式。不能只加重复惩罚，也不能只凭短训把整个配置分支全部推倒重建。
